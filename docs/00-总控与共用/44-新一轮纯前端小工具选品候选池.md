# 新一轮纯前端小工具选品候选池

日期：2026-09-06。状态：选品建议，未批准立项。本文由本轮“在 docs 目录下选新品”请求新增，不改变已有项目开发顺序。

## 1. 结论

本轮建议先验证三个不同方向：

1. **东西放哪了**：解决低频物品找不到的问题，录入和查询闭环明确，适合最快试做。
2. **今晚吃什么·先排除**：从“随机给答案”改为“排掉不想吃的”，适合做低门槛传播实验。
3. **小屋摆放试验场**：输入尺寸、摆家具、比较两种布局，视觉演示最直观，但交互开发量更大。

如果只选一个先做，优先 **东西放哪了**。它与已有项目差异较大，不需要大量插画或内容生产，也容易判断用户是否真的用上。若目标明确偏向演示视频和视觉吸引力，改选 **小屋摆放试验场**。

这里的优先级是基于当前工程约束的产品判断，不是平台流量排名、销量预测或已验证需求结论。

## 2. 去重与选品边界

已检查 docs 索引、总路线、projects 目录及相关 README。已有方向包括：SBTI 山海兽格、物华录、大理寺字案录、汴京饮子铺、关系说明书、出门检查官、对话复盘、地球 Online、单细胞进化、鱼戏莲叶间、星风来信、番茄小院。

因此本轮不优先做另一套人格测试、另一种每日任务抽卡、换皮专注种植、随机治愈语录或普通出门清单。docs 的旧索引与实际工程数量存在时间差，本文仅记录本次检查范围，不重写旧项目状态。

所有候选遵循：

- 纯前端静态构建，无后端、账号、运行时 CDN 或必需外部 API。
- 内置业务文案、模板、规则参数放入本项目 `src/content/content.json`；运行时用户输入与状态另存本地结构化记录。
- 不保存用户图片、Base64、音视频或 Blob；视觉素材使用随包资源或代码绘制。
- 不依赖定位、摄像头、麦克风、系统分享、下载、通知或 Service Worker 完成核心体验。
- 截图卡直接在页面展示，用户手动截图即可；复制功能即使失败也可以手动选择文字。
- 首次使用尽量在 30–90 秒内得到可理解的结果。工具是否有用优先于收集、签到和装饰系统。

## 5. 首选 A：东西放哪了

### 定位与首屏

面向租房、小空间居住、经常收纳低频物品的人。首屏：“收得太好，下次又找不到？记住它在哪。”同时给“记一个位置”和“找东西”两个直接入口。

### 首发闭环

1. 填物品名，选择或新建房间、容器，可选填别名与备注。
2. 保存后立即显示位置卡。
3. 搜索物品名、别名或备注，定位到路径。
4. 东西挪位置时修改路径；旧路径不继续作为当前位置出现。

黄金样例：录入“备用钥匙”，别名“门钥匙”，位置“卧室 / 衣柜上层 / 蓝色收纳盒”。搜索“门钥匙”返回该卡，展示“最后确认日期”，而不是承诺实物仍在那里。

### MVP 范围

- 搜索页、物品编辑页、位置浏览页、数据管理入口。
- 名称必填，位置至少一级；允许同名物品，使用独立 ID。
- 20 条以内即可完整试用，首发硬上限建议 200 件；名称 40 字、别名最多 5 个、备注 120 字。
- 默认精确包含检索并做空格归一化；不承诺拼音搜索和模糊语义识别。
- 没找到时展示录入入口；本地存储不可用时允许本次会话继续使用并提示无法保留。
- 不录照片、条码，不做家庭共享、云同步或室内导航。

内容包包含位置建议、字段标签、提示语和演示记录；真实物品记录带 `schemaVersion`、`id`、`name`、`aliases`、`locationPath`、`note`、`updatedAt`。

### 传播素材与验证

15 秒演示：找备用钥匙 → 输入别名 → 跳出位置路径 → 点开容器看同箱物品。笔记标题可测：“东西不是丢了，是被我收得太好了。”

先找 5 位用户各录入 5 件低频物品，检查单件录入是否超过 30 秒；一周后回访是否真实查询过。若用户普遍拒绝录入，即使截图反馈好，也不加图鉴或收集系统掩盖问题。

最大风险是记录负担和位置过期。首发重点测试“复用上一个位置”和“快速搬位置”，不把精力花在大型房屋插画上。

## 6. 首选 B：今晚吃什么·先排除

### 定位与首屏

面向只想赶紧做出一餐选择的人。首屏：“先排掉你不想吃的，剩下的交给这张菜单。”

### 首发闭环

1. 选自己做或外面吃；外面吃仅提供菜品方向，不找餐厅。
2. 排除今天不想要的主食、口味、主要食材类别。
3. 自己做时再选愿意投入的时间档。
4. 展示最多 3 个候选、命中理由与“就吃这个”；可看其余符合条件的候选。
5. 保存最近 7 次选择，下次可主动开启避开最近吃过的功能。

黄金样例：自己做、不要面食、不辣、愿意用 15–30 分钟 → “番茄鸡蛋饭”等符合内置标签的方向。标签必须经过人工检查，时间仅为内容估计，不承诺实际完成时长。

### MVP 范围

- 先制作并人工核验 12 条黄金菜品，再扩至约 60 条家常菜品方向。
- 每项具备 `id`、`name`、`mealMode`、`staple`、`flavorTags`、`ingredientTags`、`effortBand`、`reasonTemplate`。
- 用户排除项是硬约束，随机仅用于符合约束的候选排序。
- 无结果时指出哪些条件使候选过少，由用户选择放宽；绝不悄悄恢复已排除食材。
- 不做营养诊断、过敏安全保证、精确热量、实时价格或外卖接入。
- 页面显示结果，手动截图；历史记录只保存菜品 ID、日期和筛选条件。

### 传播素材与验证

15 秒演示：传统“都不想吃”的状态 → 连续点三次排除 → 剩下三个可接受选项。笔记标题可测：“别问我想吃什么，先问我不想吃什么。”

用同一组菜品做两个纸面或可点击原型：普通随机抽取、排除后选择。让 5–8 位用户尝试并交叉调整体验顺序，观察是否更快接受结果、反复换一批的次数是否减少。小样本只帮助找到交互问题，不作为统计显著结论。

最大风险是内置菜单不符合个人饮食习惯。先验证菜品集合和排除标签，再考虑自建菜单；不先做复杂烹饪养成动画。

## 7. 首选 C：小屋摆放试验场

### 定位与首屏

面向租房、宿舍和小卧室布置。首屏：“输入房间尺寸，先把家具摆进去试试。”

### 首发闭环

1. 输入矩形房间长宽，展示俯视图。
2. 添加矩形床、桌子、柜子，手动填实际长宽。
3. 拖动或用按钮微调，旋转 90°。
4. 提示越界、矩形重叠，查看两件平行家具间的间隔。
5. 保存布局 A、复制成 B，切换比较并展示尺寸卡。

黄金样例：300 × 400 cm 房间，150 × 200 cm 床，120 × 60 cm 桌子；用户移动桌子时看到位置和几何间距随之改变。

### MVP 范围

- 仅矩形房间，最多 8 件矩形家具，固定 90° 旋转，最多保存 3 个布局。
- 房间和家具尺寸必须是有限正数，设置合理输入上下限；不接受空值、负数和非数值。
- 支持点击选中后方向按钮移动，避免拖拽成为唯一操作方式。
- 使用 SVG 或 Canvas 与二维几何；不需要三维引擎、图片上传或自动户型识别。
- 只提示所画几何形状的越界和重叠；不评估结构安全、真实通行合规、窗台和插座影响。
- 首发不模拟门扇开启与柜门抽屉，因此页面须明确“门窗与开合空间请另行核对”。
- 不把“没有重叠”写成“肯定能放下”；实际尺寸由用户测量核对。

内容包保存家具模板、建议初始尺寸、单位文案和提示；用户布局保存房间尺寸及家具 `id/type/x/y/width/depth/rotation`，坐标单位统一为 cm，屏幕缩放不改实物尺寸。

### 传播素材与验证

15 秒演示：桌子和床冲突 → 旋转移动桌子 → 冲突消失 → A/B 对比。笔记标题可测：“小卧室换个摆法，先试一遍再搬家具。”

先用 3 个真实矩形房间的手工测量值验证，重点观察手机输入尺寸、选中小物件和微调是否顺畅。若 390 px 下频繁误触，先改交互与缩放，再增加家具种类。

最大风险是用户把简化示意图当作精确装修方案，以及小屏编辑难度。适合愿意投入交互打磨的第二个原型。

## 9. 当前不推荐的方向

- **普通转盘、随机语录、泛人格测试**：已有项目或现成工具覆盖较多，只有主题换皮很难形成明确差异。
- **AI 穿搭识图、AI 文案改写、AI 心理对话**：任意输入理解依赖当前约束之外的能力，预设规则不能假称大模型生成。
- **实时天气穿搭、附近店铺、机酒比价、联网双人关系测试**：核心路径依赖外部数据、定位或后端。
- **锁屏白噪音、必达喝水提醒、后台专注提醒**：不能以未经确认的后台和设备能力为成立前提。
- **照片手帐、用户图片拼贴、视频模板**：当前不保存用户媒体的限制会使常见产品形态缺失核心能力，本轮不优先。
- **新的大体量经营养成游戏**：已有汴京饮子铺、单细胞进化和番茄小院等方向，新增内容、美术与平衡成本高于先验证工具需求。

## 10. 验证和立项方式

先验证前三名，不立即同时开三个完整工程。

1. 每个方向准备一张首屏、一张真实结果样例、一个 15 秒演示脚本。
2. 招募实际有对应问题的人，询问最近一次问题发生的情景与当时解决方式；不只问“你会不会用”。
3. 观察能否无讲解完成核心操作，记录耗时、卡点和是否得到可执行结果。
4. 优先选择发生过真实使用、愿意再次打开的方向。截图好看但不用，仅支持做传播素材，不能证明工具价值。
5. 若发布小红书笔记验证，分别记录曝光、有效需求评论、入口点击和实际完成；没有平台数据或手工记录就标记未知，不补造转化数字。发布行为另按明确任务执行。

建议的原型验收门槛属于内部决策标准：5 人中至少 4 人能无讲解完成；至少 3 人可以说出最近一次真实使用场景；如主要定位为复访工具，在一周回访中获得至少 2 次真实再次使用反馈。样本很小，仅用于决定下一步，不能推断总体市场。

立项前补齐：确认的用户场景、5–10 条黄金样例、页面与状态清单、数据字段与上限、计算规则、素材清单、空结果与存储失败处理。不要先批量生成几十张美术图。
