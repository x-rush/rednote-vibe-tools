# SBTI UI 与闻山陪行体验重设计

状态：已在对话中逐段批准
日期：2026-08-25
范围：`projects/01-sbti`

## 1. 背景

当前运行时已经具备夜读首页、四章二十四问、四选项题库、结果兽志、闻山首次三句引导和本地恢复能力，但答题主体仍接近普通单栏表单。已有设计文档描述的章节过场、行动落印、节点反馈、结果召回帮助和异常恢复尚未形成统一运行时系统。闻山目前主要出现在首次引导，未真正承担守卷人角色。

本次重设计将应用定义为“闻山陪行的山海夜读卷”：通过四卷旅程、行动签、卷印和关键节点陪伴建立独特体验，同时保持人格倾向测试的可读性、中立性与可恢复性。

## 2. 目标

- 让答题体验第一眼区别于普通问卷和通用 MBTI 换皮。
- 将 24 题组织成四卷，每卷 6 题，并为进入、完成和显形建立清楚节奏。
- 让闻山参与首次引导、续卷、章节交接、显形、结果帮助和异常恢复。
- 让 NPC 只负责陪伴、交接和解释规则，不评价答案，不暗示人格方向。
- 继续使用现有闻山正式图、头像和占位图，不生成新资源。
- 保持纯前端、本机计算、离线首次启动与现有 16 型结果体系。
- 在 375、390、430 CSS px 下维持完整可达、无横向溢出的移动体验。

## 3. 非目标

- 不把闻山做成自由输入聊天机器人。
- 不增加地图探索、战斗、抽卡、养成或积分系统。
- 不改变 48 题题库、每局 24 题、四维计分或 16 种异兽结果映射。
- 不新增依赖、后端、运行时 CDN、外部 API、Service Worker 或设备权限。
- 不生成新的异兽、NPC、背景或装饰位图。
- 不让动效成为完成答题或理解状态的必要条件。

## 4. 核心体验原则

### 4.1 闻山是守卷人，不是结果主角

闻山负责递卷、收卷、说明规则和恢复状态。异兽在结果页仍是唯一强视觉中心。闻山不得把本次结果解释为终身人格，不得评价单题选择，不得使用吉凶、命定、治疗或能力高下语言。

### 4.2 仪式只出现在关键节点

动效集中在递卷、行动落印、卷印完成、四维显形和兽志展开。常规导航、返回修改和帮助开关保持快速直接。

### 4.3 状态必须先于装饰

选中、已确认、章节完成、正在显形、图片失败和保存失败都必须由 DOM 文本、图形或控件状态表达。动画、纹理和图片只增强，不承担唯一信息。

### 4.4 不通过反馈污染答案

闻山不在每题后出现，也不对任何选项给出赞许、惊讶或解释。章节结束台词只说明卷册进度，不描述用户倾向。

## 5. 信息架构与旅程

### 5.1 首页：入司

首页改为山海司夜间案房。现有闻山主图位于卷案一侧，成为品牌锚点；页面仍保持单一主操作。

闻山台词由现有状态决定：

- 首次进入：`卷已备好，只等你落笔。`
- 有进行中进度：`旧卷停在第 {chapter} 章第 {current} 问。`
- 有最近结果：`你的兽志仍收在案上。`

若本地同时存在进行中进度和最近结果，首页优先呈现续卷状态；只有没有进行中进度时才呈现最近结果。首次引导覆盖以上首页台词，完成或跳过引导后再回到对应状态。

历史、设置和清空继续位于次级入口，不与主操作竞争。

### 5.2 测前：立约

首次引导继续使用三句可跳过对话：本次选择边界、本机保存边界、无高下优劣。完成后主动作改为接卷语义，再进入第一章。

重复进入时不强制重播三句引导；用户可通过闻山入口主动召回说明。

### 5.3 四章答题

每章 6 题，沿用现有章节：

1. 入境：第 1–6 题
2. 寻迹：第 7–12 题
3. 异变：第 13–18 题
4. 归来：第 19–24 题

第 1、7、13、19 题前显示可跳过的递卷过场。第 6、12、18 题完成后显示简短收卷反馈，再进入下一章。第 24 题完成后直接进入收卷显形流程，不重复普通章节结束页。

### 5.4 单题交互

题干表现为卷中批注，四个答案表现为纵向行动签。行动签保持完整文本与 72px 最小高度。

点击行动签后：

- 当前签条轻微抬起；
- 边缘墨迹显现；
- 左侧显示朱砂选择印；
- 底部动作从未选态变为 `落印，下一问`；
- 用户仍可选择其他签条覆盖本题答案。

不得选中后自动跳题，不显示权重、维度、正确性或人格暗示。

### 5.5 显形与结果

完成第 24 题后，闻山先收卷，随后四枚维度印依次显现，最后展开暖纸兽志。流程可跳过；减少动态时直接呈现最终结果并保留状态文本。

结果页闻山退居次级入口。用户点击头像后打开结果帮助卷页，查看：

- 如何理解四维倾向；
- 为什么会显示邻近兽格；
- 古籍事实与 SBTI 产品演绎的边界。

## 6. 视觉系统

### 6.1 夜案工作台

答题阶段使用深墨绿夜色、克制等高线、纸页边缘和案卷刻度。不得以大面积圆角卡片、彩色圆形图标、霓虹渐变或通用 SaaS 布局组织页面。

题目区域像铺开的窄幅卷页，行动签以纸墨层级、细边和签位标记区分。页面保持单栏，不采用横滑答题或 2×2 紧凑选项网格。

### 6.2 四卷进度

通用进度条替换为四枚卷印和当前题号：

- 未开始：灰墨轮廓；
- 当前章：石青或松绿高亮；
- 已完成：朱砂落印；
- 文本同时提供 `第 2 章 · 9 / 24`，不能只靠颜色表达。

### 6.3 夜读到兽志

首页与答题保持夜墨表面；计算阶段从墨色向暖纸过渡；结果页使用暖纸兽志。异兽主图是结果页唯一强视觉锚点，闻山不得与异兽并列成双主角。

## 7. 闻山使用矩阵

| 时刻 | 触发条件 | 形式 | 行为边界 |
|---|---|---|---|
| 首次引导 | `guideVersion` 未完成 | 主图底部卷页 | 三句，可跳过 |
| 首页新卷 | 无进度、无最近结果 | 主图与一句台词 | 只邀请开始 |
| 首页续卷 | 有进行中进度 | 头像与续卷台词 | 只报告章节和题号 |
| 章节开始 | 题号 1/7/13/19 | 头像递卷过场 | 可跳过，不点评倾向 |
| 章节结束 | 完成题号 6/12/18 | 头像收卷提示 | 只报告卷册完成 |
| 显形 | 第 24 题提交 | 边缘主图与状态文案 | 可跳过，不伪造百分比 |
| 答题召回 | 用户点击头像 | 当前上下文帮助卷页 | 规则、隐私、返回当前题 |
| 结果召回 | 用户点击头像 | 结果帮助卷页 | 四维、邻近型、文化边界 |
| 异常恢复 | 内容或存储失败 | 恢复卷页 | 说明原因、保留状态和下一步 |

答题页头像位于标题区，最小点击区域 44×44px，不固定悬浮，不遮挡题干、选项或底部操作。

## 8. 内容模型

所有新增闻山业务台词继续放在 `src/content/content.json`。建议将现有 `experience.guide` 扩展为：

```ts
type GuideCopy = {
  name: string
  role: string
  intro: string[]
  landing: {
    fresh: string
    resume: string
    recent: string
  }
  chapterStart: Record<ChapterCode, string>
  chapterEnd: Partial<Record<ChapterCode, string>>
  reveal: {
    collecting: string
    reading: string
    complete: string
  }
  quizHelp: string[]
  resultHelp: {
    dimensions: string
    neighbor: string
    culturalBoundary: string
  }
  recovery: {
    content: string
    storage: string
  }
}
```

`resume` 台词使用结构化占位值生成，组件不得在 JSX 中硬编码业务叙事。校验器需要保证所有数组非空、所有章节开始台词齐全、恢复文案分支齐全。

## 9. 状态与组件架构

### 9.1 纯状态派生

新增纯函数 `deriveGuideMoment()`，输入当前页面、题号、章节、是否续卷、结果和错误种类，输出可选的守卷人时刻：

```ts
type GuideMoment =
  | { kind: 'intro'; step: number }
  | { kind: 'landing-fresh' }
  | { kind: 'landing-resume'; chapter: ChapterCode; current: number }
  | { kind: 'landing-recent' }
  | { kind: 'chapter-start'; chapter: ChapterCode }
  | { kind: 'chapter-end'; chapter: ChapterCode }
  | { kind: 'reveal'; step: 'collecting' | 'reading' | 'complete' }
  | { kind: 'quiz-help' }
  | { kind: 'result-help' }
  | { kind: 'recovery'; reason: 'content' | 'storage' }
```

派生优先级固定为：不可继续的恢复状态、首次引导、显形流程、用户主动召回、章节交接、首页续卷、首页最近结果、首页新卷。页面组件只消费派生结果，不各自复制题号边界、首页竞争状态或 NPC 出现规则。

### 9.2 组件边界

- `GuidePresence`：渲染头像、身份和一句当前台词；不拥有流程状态。
- `GuideSheet`：承载首次引导、召回帮助和恢复内容；负责焦点管理、Escape 和关闭后焦点归还。
- `ChapterInterlude`：递卷与收卷过场；只接收章节、模式和完成回调。
- `VolumeProgress`：四卷状态与可访问文本。
- `ChoiceSlip`：单个行动签的选中、禁用和输入语义。
- `RevealSequence`：显形步骤、跳过与减少动态分支。

现有 `GuideIntro` 可收敛到通用 `GuideSheet`，现有 `GuideAvatarButton` 可作为 `GuidePresence` 的基础。不得把所有交互堆入 `App.tsx`。

### 9.3 运行状态

章节过场使用当前测评运行的结构化章节 ID。持久化仍以现有测评进度和当前题号为准，不新增动画帧、过场步骤或“已看过场”记录。刷新后恢复当前题；如果当前题正好是章节首题，允许再次显示可跳过的递卷提示。

收卷提示属于一次前进行为产生的瞬时 UI 状态：只在用户从第 6/12/18 题确认进入下一章时创建，过场完成或跳过后立即清除。它不写入本地存储。返回上一题不得再次触发已完成章节的收卷提示，单纯根据当前题号渲染也不得触发。

## 10. 错误与降级

- 闻山主图失败：使用现有 placeholder；placeholder 失败：使用 CSS 墨影。
- NPC 资源失败：所有按钮、台词和流程继续可用。
- 动画异常或减少动态：立即进入同一语义终态。
- 本地存储失败：说明本次是否仍可继续、哪些状态仍在内存、可执行的重试或清空动作。
- 内容包失败：不伪装成普通存储错误，提供重新加载和安全返回。
- 章节状态异常：回到当前有效题，不丢弃已有答案。

## 11. 动效与可访问性

| 动效 | 标准时长 | 减少动态 |
|---|---:|---|
| 行动签选中 | 160–200ms | 即时边框与朱印 |
| 递卷/收卷 | 400–650ms | 即时切换并保留标题 |
| 卷印完成 | 220–320ms | 即时颜色与图形变化 |
| 四维显形 | 总计不超过 1.8s | 直接显示全部维度 |
| 兽志展开 | 300–500ms | 直接显示结果页 |

- 所有主要按钮最小高度 48px；闻山召回按钮最小 44×44px。
- `ChoiceSlip` 继续使用原生单选输入语义，整个签条可点击。
- `GuideSheet` 打开时焦点进入标题，关闭后回到触发按钮。
- 章节过场可由键盘跳过，不形成键盘陷阱。
- 当前章、完成章和选中项均使用文字或图形辅助，不只依赖颜色。
- 长题与四个行动签自然纵向滚动，任何固定元素不得遮挡最后选项或下一步按钮。

## 12. 响应式约束

- 375、390、430 CSS px 均使用单栏布局。
- 页面内容最大宽度继续为 430px。
- 行动签不得变成横向轮播或双列网格。
- 闻山主图只在首页、首次引导和显形出现；答题中使用头像，避免挤压题目。
- 375px 下允许纵向滚动，但必须保持 0 横向溢出。
- 安全区 padding 同时支持 `100vh` 与 `100svh`。

## 13. 测试与验收

### 13.1 自动化测试

- `deriveGuideMoment()` 覆盖所有守卷人时刻与无 NPC 分支。
- 第 1/7/13/19 题触发递卷；第 6/12/18 题只在确认前进时触发一次收卷。
- 返回修改、刷新恢复和续卷不重复触发错误节点。
- 内容校验覆盖新增闻山台词、四章键、结果帮助和恢复分支。
- NPC 台词禁止包含吉凶、命定、治疗、能力高下或单题人格暗示。
- `GuideSheet` 焦点进入、Escape、关闭焦点归还和图片失败降级。
- 减少动态直接到达每个流程的语义终态。
- 现有题库、计分、存储和 16 型可达性测试继续通过。

### 13.2 浏览器验收

在 375、390、430 CSS px 验证：

- 首次引导可完成或跳过；
- 24 题全流程、四次递卷、三次收卷和最终显形可达；
- 四个行动签无横向溢出，最小高度 72px；
- 闻山头像与卷页不遮挡题干、选项或主操作；
- 结果帮助可打开、切换和关闭；
- 主图、头像、placeholder 分别失败时仍可完成流程；
- 减少动态下无依赖动画的死路；
- 控制台无 warning/error。

## 14. 实施边界

本设计只修改 `projects/01-sbti`。不修改根 `package.json`、`pnpm-workspace.yaml`、`pnpm-lock.yaml`、其他项目、根 `docs/` 或 `prep/`。不新增依赖，不提交用户图片、Base64、音视频或 Blob。

实施时必须保留当前未提交题库四选项改版以及用户已有的 `PROMPTS.md`、`VISUAL-QA.md` 修改，不做无关格式化。
