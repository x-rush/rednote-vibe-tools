# Conversation Replay V4 · 首页 Hero 与开始前确认页重设计

状态：`IMPLEMENTED · VERIFIED`

日期：2026-08-26

实施说明：390px 首轮截图发现左下批注与修订纸条相交，最终移动端改为 300px 独立人物画面区加舞台下缘署名批注。Hero 总高度约 416px，但人物、纸条和批注互不遮挡；390×844 无安全区时主按钮顶部为 765px，375×812 加 32px 安全区时为 797px，均可在首屏看到。

## 1. 目标

把首页从“标题下放一条较大的陪伴卡”升级为真正由迟言立绘主导的编辑手账封面；把开始前确认页从说明列表升级为迟言打开工作台、与用户确认保存方式的第二个连续场景。

成功标准：

- 用户打开首页时，一眼先感知迟言、修订纸条和编辑陪伴，而不是普通表单。
- 首页人物正脸、双手和分栏笔记本完整，视觉重心位于画面中右侧。
- 主要操作仍清楚、克制，不用聊天气泡、在线状态、输入状态或亲密关系暗示。
- 第二页延续首页的场景感，同时让无痕与本机保存的差异更容易选择。
- 关系、目标、情境页保留当前中型陪伴立绘；进入五层复盘后恢复紧凑陪伴条。
- 界面身份只显示“迟言 / 温和编辑搭档”。

## 2. 视觉方向

采用“编辑手账封面 + 陪伴工作台”，不采用全屏背景图，也不继续放大横向提示卡。

视觉层级：

1. 页面标题说明工具价值。
2. 迟言的大幅立绘建立陪伴与识别度。
3. 修订纸条表现产品核心动作。
4. 迟言批注降低开始压力并归还决定权。
5. 主按钮承接下一步。

人物与文字不互相覆盖。立绘使用 `object-fit: contain`，不通过放大裁切制造视觉冲击；舞台本身提供足够面积。画面不得裁掉头顶、正脸、双手或笔记本。

## 3. 首页 Hero

### 3.1 信息顺序

首页按以下顺序进入文档流：

1. 顶部安全栏。
2. eyebrow、主标题和简化 lead。
3. `LandingHero` 编辑舞台。
4. 隐私保证。
5. “从一个情境开始”主按钮和“查看本机复盘”次按钮。

现有业务文案与操作保持不变，不新增上传、自由输入或自动保存。

### 3.2 移动端构图

在 375–430 CSS px：

- 舞台宽度占满页面内容区；人物画面区固定为 300px，署名批注进入舞台下缘独立行，总高度约 416px。
- `chiyan-guide-master.webp` 位于人物画面区右下，宽度 240px，高度由 3:4 原图自然决定。
- 人物容器靠右，正脸位于页面水平中心右侧约 58%–66%；不得贴左边框。
- “原表达 / 更可核对的表达”成为两张左上叠放纸条，最大宽度为舞台的 52%，不覆盖脸和持笔手。
- 迟言邀请与自主权位于左下或舞台底部的署名批注，最大宽度为舞台的 62%；若与人物手部相交，批注进入舞台下缘独立行，不遮图。
- 主按钮顶部应在 812px 高视口内可见；次按钮允许位于首屏下缘，但不得推动主按钮完全离屏。

### 3.3 桌面构图

在 431px 以上：

- 舞台采用 46% 文案 / 54% 人物的两区构图，最小高度 410px。
- 人物宽度为 320–360px，靠右下放置。
- 修订纸条和迟言批注位于左区，保持纸张层级，不覆盖人物。
- 页面最大宽度继续沿用 760px，不扩展成横向营销站。

## 4. 开始前确认页

### 4.1 场景作用

第二页不是另一个首页，也不是长篇隐私政策。它承接迟言的陪伴，解释保存边界，并让用户直接选择一种模式。

### 4.2 页面结构

按以下顺序展示：

1. eyebrow、标题和 lead。
2. `PrivacyStage` 工作台场景。
3. 无痕与本机保存两张模式卡。

`PrivacyStage` 包含：

- 右侧迟言欢迎立绘，使用 `chiyan-guide-master.webp`；移动端可根据空间使用同图中型裁切，但必须保留正脸和笔记本道具。
- 左侧使用 `privacy` moment 的 invitation、reassurance 和 autonomy。
- 下缘排列“不上传 / 不判断对错 / 本机最多三份”三枚纸签，内容来自现有 `screen.sections`。

模式卡：

- 无痕模式为主卡，显示“退出后消失”的结果，点击行为仍派发 `CHOOSE_MODE: ephemeral`。
- 本机保存为次卡，显示“最多三份结构化复盘”，点击行为仍派发 `CHOOSE_MODE: local`。
- 两卡均为真实按钮，最小高度 64px；不增加预选、倒计时或默认保存。

### 4.3 响应式

在 375–430 CSS px：

- 场景最小高度 230px，人物视觉宽度 155–180px，靠右下。
- 陪伴文案位于左侧，宽度不超过 58%；三枚纸签可换行为 2+1，但不得横向滚动。
- 两张模式卡垂直排列。

在 431px 以上：

- 场景为左右构图，人物宽度 220–250px。
- 三枚纸签同排；模式卡可保持垂直，避免把隐私选择做成价格对比表。

## 5. 后续页面衔接

- 三步引导继续使用现有全幅 `ChiyanGuide`。
- 关系、目标、情境页保留当前 `is-featured` 中型陪伴条，移动端立绘宽 132px。
- 事实、感受、推测、需要、请求、草稿、演练、对照、结果、保存、退出、安全和恢复页继续使用紧凑 `CompanionNote`。
- 首页与开始前确认页不再渲染通用 `CompanionNote`，避免同一屏重复出现人物。

## 6. 组件与数据流

新增两个专用展示组件：

```text
LandingHero
  input: companion, beforeText, afterText
  output: 纯展示 Hero 舞台

PrivacyStage
  input: companion, privacy sections, primary/secondary labels and descriptions, callbacks
  output: 工作台场景与两张模式按钮
```

`App.tsx` 继续决定页面和派发 reducer action；新组件不访问状态、不读取 localStorage、不拼接业务结果。入口标题、lead、按钮、修订示例、隐私保证和模式说明全部来自 `content.json` 的 `content.intro`，并由运行时校验器保护；`buildScreenViewModelV2()` 继续提供标题、lead、按钮标签与 companion。现有首页修订示例沿用原文，不新增事实。

`CompanionViewModel.featured` 只服务关系、目标、情境等通用陪伴条。首页与开始前确认页由专用组件决定舞台构图，不再依赖 `is-featured` 调整横卡。

## 7. 图片与失败降级

- 不生成新美术资源，复用已经验收的本地主图和占位图。
- 首页与开始前确认页均使用 `chiyan-guide-master.webp`，通过不同舞台尺寸形成连续场景。
- 主图失败时切换 `chiyan-placeholder.webp`；占位图也失败时，人物区域保留纸面底色和固定尺寸，文案与按钮不移动、不消失。
- 图片为装饰性，不进入 Tab 顺序；页面语义由标题、修订文本和迟言批注承担。

## 8. 安全、隐私与情感边界

- 不改变默认无痕、本机最多三份、退出消失和不上传聊天记录的规则。
- 不把迟言写成真人朋友、咨询师或紧急支持；这些内部边界通过行为与文案体现，不在界面身份后追加角色性质标签。
- 陪伴文案只承诺当前整理过程，不做永久陪伴、排他理解或结果保证。
- 首页不增加“立即修复关系”“让对方理解”等营销承诺。

## 9. 测试策略

自动测试：

- `LandingHero` SSR 包含人物、修订前后文本、邀请和自主权，不包含聊天输入语义。
- `PrivacyStage` SSR 包含三条隐私保证和两个真实按钮，回调分别对应无痕与本机模式。
- 首页和 privacy 页不再渲染通用 `.companion-note`；关系、目标、情境页仍使用 featured companion。
- 图片 fallback、内容身份和现有 19 页 ViewModel 回归保持通过。

浏览器验收：

- 375×812、390×844、430×932 检查首页与开始前确认页。
- 首页人物正脸、头顶、双手和笔记本完整；人物处于中右侧，修订纸条不遮脸。
- 主要 CTA 在 812px 高视口内至少部分可见，所有按钮高度不低于 48px。
- `document.documentElement.scrollWidth === innerWidth`，0 断图，控制台 0 error / warning。
- `--safe-area-inset-top:32px` 下顶栏和页面标题均无遮挡。
- `prefers-reduced-motion: reduce` 下舞台无人物位移、缩放或持续动画。

## 10. 明确不做

- 不生成新的迟言立绘或背景插画。
- 不添加自由聊天、消息气泡、在线状态、好感度或角色记忆。
- 不改变 reducer 页面顺序、保存 schema、情境匹配和安全分流。
- 不修改根依赖、工作区配置或其他项目。
