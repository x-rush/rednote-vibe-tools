# 大理寺字案录 · 证物视觉与互动系统规格

状态：已实施并通过生产复检

日期：2026-08-26

范围：`projects/03-dalisizian`

## 1. 背景与目标

当前 32 条证物记录均含 `assetId`，但项目没有证物资源文件、证物资源解析器或互动渲染器。证物检查页因此无条件显示“人工核验资源位”，图片没有进入调查、复核或推理流程。

本次改造的目标不是用装饰插画替换占位符，而是把证物变成可观察、可复核、可参与判断的玩法对象：

- 32 件证物全部拥有独立视觉内容与缩略图；
- 四种证物类型使用稳定、易学而有差异的互动模板；
- 证物在取得、检查、推理和归档四个阶段均可见；
- 涉及古文字、字书和学术判断的图形必须有来源与审核状态；
- 维持纯前端、完全离线、单页运行和移动端安全区约束。

## 2. 设计原则

1. 图片承担证据功能。玩家应能从视觉中的形体、标注、关系或边界获得判断依据。
2. 一致操作，独立内容。四种互动模板保持学习成本稳定，每件证物仍有自己的构图、重点与文本。
3. 事实与叙事分层。史实材料、复原装帧和虚构案卷叙事必须在界面中明确区分；工程术语不直接暴露给玩家。
4. 宁可显示可信结构图，也不展示未经核验的古文字图形。
5. 不以观察点完成度卡住主线。观察能强化理解和评价，但玩家始终可以返回调查。
6. 业务内容只进入 `src/content/content.json`；组件、样式和资源清单不复制案情文案。

## 3. 证物类型与互动模板

### 3.1 字形时间轴 `glyph-timeline`

用于早期形体、构件组合、异体和字形演变。

- 横向或分段时间轴展示 2–4 个经核验阶段；
- 点击阶段切换主图、年代标签、材料性质和释义；
- 可点观察区域显示构件差异与证据边界；
- 每个阶段单独标记“公版字形摹本／旧拓摹本／人工摹写”等玩家可理解的材料性质；
- 无合格图形时采用结构框和文字关系图，不用现代字体伪装古文字。

### 3.2 字书展开卷 `lexicon-scroll`

用于《说文》、传统训释、分字条目和制度记录。

- 卷页由折叠状态展开；
- 条目正文、关键词和产品释文分层显示；
- 点击朱框定位关键词，展示现代说明和来源；
- 原文与现代解释不得混排成一段，避免玩家误认产品解释为原文。

### 3.3 语义关系图 `semantic-map`

用于构件功能、字族关系、义项变化和简化时序。

- 以 3–6 个节点和有向关系线呈现；
- 点击节点显示定义，点击关系线显示“材料支持到哪一步”；
- 颜色区分已证关系、可能关系和禁止跨越的推断；
- 当前推理题涉及的节点可被强调，但不直接泄露正确答案。

### 3.4 辨伪对照卷 `myth-verdict`

用于民间故事、价值倒推、单线起源说和争议边界。

- 初始展示传闻卡；
- 玩家点击或滑动揭开材料卡；
- 最终分为“材料能证”“材料不能证”“仍有争议”三栏；
- 越界步骤使用朱批断线表现，让错误发生在哪一步清楚可见。

## 4. 数据模型

`Evidence` 新增必填 `visualSpec`，采用按 `template` 区分的联合类型。所有用户可见文字、观察点和来源关联均存入 `content.json`。

公共字段：

- `template`：四种模板之一；
- `thumbnailLabel`：证据簿缩略图的短标签；
- `observationPoints`：可操作观察点，含稳定 ID、标题、说明、锚点与 `sourceIds`；
- 每个可触发核验的阶段、条目、语义节点／关系或辨伪揭示层必须以 `observationId` 显式关联观察点；禁止按数组位置猜测关联。只有关联材料真正展开时才记录观察完成；
- `completionPrompt`：完成主要观察后的归档提示；
- `palette`：从有限的产品色板枚举中选择，不允许任意颜色值；
- `fallbackSummary`：资源不可用时仍可完成推理的文字摘要。

类型专属字段：

- `glyph-timeline.stages`：阶段标签、年代、图形资源、材料性质、可信度和来源；
- `lexicon-scroll.entries`：条目标识、原文、产品释文、关键词区间和来源；
- `semantic-map.nodes/edges`：节点、关系、证据强度和来源；
- `myth-verdict.claim/supports/limits/disputes`：传闻、可证范围、不可证范围和争议说明。

内容校验必须保证：

- 32 件证物均有 `visualSpec`；
- 模板与证物类型匹配；
- 观察点 ID 在单件证物内唯一；
- 所有事实性观察点至少关联一个非虚构来源；
- 所有资源 ID 可解析为包内文件；
- 所有坐标、节点和边均指向有效目标；
- 不允许外部 URL、Base64 或 Blob 被写入内容包。

## 5. 组件边界

### 5.1 `EvidenceArtifact`

证物视觉总入口。输入一条 `Evidence` 和当前交互状态，选择对应模板；统一处理标题、来源入口、已观察数量、回退内容和减少动画模式。

### 5.2 四个模板组件

- `GlyphTimelineArtifact`
- `LexiconScrollArtifact`
- `SemanticMapArtifact`
- `MythVerdictArtifact`

模板只解释自己的数据结构，不读取全局案卷状态，不修改主线进度。

### 5.3 `EvidenceThumbnail`

用于取得动画、证据簿、推理关联案签和图鉴缩略图。缩略图从同一 `visualSpec` 派生，不维护第二套业务内容。

### 5.4 `EvidenceInspector`

负责详情页外壳、标题区、观察进度、来源说明和返回行为；证物图本身交给 `EvidenceArtifact`。

### 5.5 资源解析

新增独立证物资源清单，以稳定 `assetId` 解析本地 SVG/WebP。资源缺失时显示该证物自己的结构化回退内容并报告可测试的缺失状态，不再显示通用“人工核验资源位”。

## 6. 游戏流程

### 6.1 取得证物

节点授予证物后，在对话区上方展开缩略证物，依次执行“抽卷展开、关键点亮起、朱印归档”。玩家可选择“立即核验”或继续调查。

### 6.2 证物检查

详情页展示完整互动证物、当前观察点、来源与证据边界。关闭后必须返回进入前的准确对话节点，不能重置调查路线或推理反馈。

### 6.3 推理复核

推理题关联的证物以案签形式排列。点击后打开同一检查器；返回时保持当前题目与已选状态。证物视觉提供判断材料，但不以颜色或动画直接标出正确选项。

### 6.4 证据簿与归档

证据簿展示缩略图、类型、标题和“已核观察点／总观察点”。完成主要观察点后加盖“已核”印；未完成观察不阻断案件结局。

### 6.5 本地状态

只保存结构化的已观察点 ID：`evidenceObservationIdsByEvidenceId`。不保存图片、Base64、音视频或 Blob。旧存档没有该字段时按空记录迁移，不影响既有案件进度。

## 8. 美术与事实门禁

### 8.1 统一视觉语言

- 墨绿案台、米色纸张、朱砂批注、乌墨关系线；
- 四类模板使用不同的纸张轮廓和交互反馈；
- 图形区优先清晰度，不叠加影响辨认的颗粒和光效；
- 动画采用纸张展开、墨线生长和落印，不使用无关粒子特效。

### 8.2 古文字与字书

- 不使用图像生成模型绘制甲骨文、金文、小篆或古籍原文；
- 精确字形只接受授权明确的权威来源图、数据库渲染或双人审校的人工 SVG；
- 每项记录来源、著录号或条目定位、资源性质、描摹者、审核者和审核日期；
- 来源等级不足时使用不冒充原字形的结构图；
- 产品重排必须在详情中说明复原或摹写性质，不能暗示馆藏原件。

### 8.3 其他视觉

语义关系图和辨伪卡使用 HTML/CSS/SVG 原生绘制。生成模型只可用于无文字、无史实断言的纸张纹理或证物装帧；`evidence-home-early-form` 已采用一张 1080×720 WebP 复原案头底图，并将三份公版古文字 SVG 作为独立本地层准确叠加。其余证物继续使用轻量原生图形，避免无意义增加包体。

## 9. 动画、可访问性与移动端

- 所有交互目标最小 44 CSS px，主要操作最小 48 CSS px；
- 弹层与顶部固定控件叠加 `var(--safe-area-inset-top, env(safe-area-inset-top, 0px))`；
- 证物内容区独立滚动，并保留底部安全区；
- 不依赖 hover、双指缩放或横屏；
- 观察点可通过按钮顺序访问，状态不只依赖颜色；
- `prefers-reduced-motion: reduce` 下取消卷轴位移、墨线生长和落印弹性，只保留即时状态切换；
- 资源缺失、内容错误或旧存档迁移失败时仍提供文字回退和返回路径。

## 10. 测试策略

### 10.1 内容与单元测试

- 32/32 证物 `visualSpec` 完整性；
- 四种联合类型的必填字段、引用和来源校验；
- 证物资源清单全量解析；
- 观察状态新增、去重、迁移和异常字段清理；
- 证物详情返回原对话上下文；
- 推理复核不改变答案和主线状态。

### 10.2 组件与流程测试

- 每种模板至少覆盖首次打开、观察点操作、完成状态和回退状态；
- 八案分别走通取得证物、立即核验、返回调查、推理复核和证据簿归档；
- 验证未观察证物不会卡住结案；
- 验证减少动画模式下交互结果一致。

### 10.3 视觉与真机尺寸

- 375×667、390×844、430×932 CSS px；
- 顶部安全区分别模拟 0、24、47 CSS px；
- 检查标题栏、证物关键区域、返回按钮和弹层关闭按钮不被导航遮挡；
- 检查无横向溢出、短屏可滚到底、所有操作单手可达；
- 检查浏览器控制台无错误和资源 404。

### 10.4 发布验证

在项目目录执行：

```bash
pnpm lint && pnpm test && pnpm build
```

随后覆盖 `release-assets/大理寺字案录-小工具包-20260826.zip`，验证 `index.html` 位于 ZIP 根目录、资源均为包内相对引用、压缩包内容与当前 `dist` 逐字节一致，且包体不超过 10MB。

## 11. 完成标准

- 32 件证物均有正式互动视觉和缩略图；
- 游戏中取得、检查、推理和归档四处均展示证物；
- 通用“人工核验资源位”从正常流程中消失；
- 所有古文字和字书图形满足来源与人工审核门禁；
- 旧存档安全迁移，主线和评分逻辑无回归；
- 三档手机宽度和非零安全区验证通过；
- lint、完整测试、生产构建和离线包校验通过。

## 12. 非目标

- 不加入联网查询、在线图片、运行时 CDN 或外部 API；
- 不加入自由缩放画布、复杂拖拽拼字或需要设备能力的玩法；
- 不保存用户图片、Base64、音视频或 Blob；
- 不在本期扩展新的案件、角色或评分维度；
- 不使用未经核验的古文字图形换取表面上的“资源齐全”。
