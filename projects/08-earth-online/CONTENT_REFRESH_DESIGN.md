# 地球 Online 任务库升级设计

日期：2026-08-29
状态：已由产品确认并完成实现

## 目标

在不改变产品安全边界的前提下，将首发任务库从“有趣文案包装的轻量待办”升级为具有明确过程、选择和成果反馈的现实支线任务。

升级后仍保持 100 个可匹配的活跃任务，同时让已上线用户的历史记录和正在进行的旧任务完整保留。

## 范围

本轮完成：

- 退役 20 个低趣味或高度重复的任务。
- 新增 20 个使用新 ID 的任务。
- 深度改写约 25 个现有任务。
- 为全部 100 个活跃任务重新编写具体描述与步骤，移除现有五套通用结尾和第二步骤模板。
- 补足 20 分钟、E3、standard 和 brave 内容。
- 引入退役任务目录、历史快照和本地存储迁移。
- 更新匹配、展示、校验与测试。

本轮不完成：

- 最终 UI 或新页面结构。
- 新插画、徽章美术或正式任务图标。
- 定位、上传证明、运行时 AI、后端或在线账户。
- 付费任务、危险挑战或强迫陌生人配合的任务。

## 内容原则

挑战性来自以下机制：

- 多阶段：观察、判断、行动、确认结果。
- 约束：限定时间、材料、数量或表达形式。
- 选择：三选一、路线选择或有限策略取舍。
- 结果：产生一张小地图、一段文字、一套规则或一项真实改善。
- 不确定性：安全范围内的寻宝、宾果、记忆核对或推理。
- 自愿勇气：仅在用户允许社交时出现，且可随时退出、不依赖陌生人回应。

挑战性不得来自危险行为、身体硬撑、高额消费、隐私暴露、进入私人空间、骚扰陌生人、医疗或心理治疗暗示。

运动任务继续要求在舒适范围内进行，并明确允许随时停止。

## 活跃任务分布目标

活跃任务严格保持 100 项，类别仍维持 10 类各 10 项，避免破坏既有目标匹配覆盖。

目标分布：

- 时间：5 分钟约 30%，10 分钟约 35%，15 分钟约 25%，20 分钟约 10%。
- 精力：E1 约 45%，E2 约 40%，E3 约 15%。
- 难度：tiny 约 35%，light 约 40%，standard 约 20%，brave 约 5%。
- XP：按任务定义使用 20、35、55、80 四个主要档位；等级公式保持不变。
- 冷却：依据重复疲劳度采用 3、7、14 天，特色任务使用更长冷却。

最终数字允许小幅调整，但必须满足：

- 20 分钟、E3、standard、brave 均有真实任务。
- 20 分钟与 E3 用户条件存在精确匹配候选。
- 低精力、短时间、室内、独处条件仍有充分候选。
- 每个正常黄金条件至少存在一个安全候选。

## 退役任务模型

`content.json` 增加 `content.retiredTasks` 和 `content.legacyTasks`。前者保存本轮退役任务，后者保存仍沿用同一 ID 的 v1 完整定义，以保证所有旧进行中任务按接取版本继续执行。

- `content.tasks`：恰好 100 个活跃任务，是匹配器唯一使用的内容池。
- `content.retiredTasks`：仅用于解析旧的当前任务和旧历史，不参与匹配、随机选择、推荐去重或活跃任务统计。
- `content.legacyTasks`：保存 80 个保留 ID 的 v1 定义；只按 `questId + contentVersion` 解析，不参与匹配。
- 活跃与退役任务 ID 必须全局唯一。
- 活跃与 legacy 可以复用 ID，但同一 `questId + contentVersion` 必须唯一。
- 新任务必须使用新 ID，不复用退役任务 ID。
- 内容版本随本轮升级递增。

旧任务保留完整定义而不是只有标题，因为升级时可能仍有玩家正在执行，需要继续展示步骤、完成文案、XP 和安全退出方式。

## 历史快照

历史记录增加接取或结算时的不可变内容快照：

- `questTitle`
- `questContentVersion`
- `questCategory`
- `questDifficulty`
- `xpAwarded`

历史页优先展示快照，不使用当前任务标题覆盖旧记录。

`ActiveQuest` 增加接取时的内容版本。加载当前任务时按以下顺序解析：

1. 使用 `questId + questContentVersion` 查找版本化任务定义。
2. v2 当前任务命中活跃目录；v1 任务命中 legacy 或退役目录。
3. 对应版本不存在则进入已有的内容恢复状态，不猜测任务内容。

从 legacy 或退役目录解析出的旧版本当前任务显示“经典任务”状态，但仍允许正常完成或放弃。完成时按旧任务定义结算原 XP，并将旧任务标题写入历史快照。

## 本地存储迁移

存储 schemaVersion 递增，并提供从当前版本到新版本的显式迁移。

迁移流程：

1. 读取并验证旧 payload。
2. 对没有快照的历史记录，先查旧任务目录，再查活跃任务目录，补齐标题、内容版本、类别和难度。
3. 保留旧 `xpAwarded`，不重新计算过去奖励。
4. 保留指向退役任务的 `activeQuest`，并补齐接取内容版本。
5. 写入新 schema 的规范化 payload。
6. 如果任务 ID 无法解析，保留既有安全恢复语义，不伪造标题。

损坏 JSON、字段非法、未来 schemaVersion 和持久化失败继续使用现有恢复路径。不保存图片、定位、证明或敏感信息。

## 匹配规则

匹配器只接收 `content.tasks`。

已有不可放宽条件保持不变：

- 安全标签。
- 明确不可用地点。
- 用户选择不花钱。
- 用户选择不社交时的社交任务。
- 用户选择室内时的仅户外任务。

内容升级不修改既有逐级放宽顺序。新增的 20 分钟和 E3 任务应使对应条件在正常情况下命中精确阶段，而不是总进入 energy-relaxed。

退役任务不得出现在任何匹配、推荐、换一个或近期推荐结果中。

## 页面适配

保留现有语义页面与基础样式，仅做必要适配：

- 任务卡显示新增的时间、精力、难度和 XP 档位。
- 旧进行中任务显示文字型“经典任务”标记，不新增最终美术。
- 历史页优先显示不可变标题快照。
- 无法解析的旧任务继续使用现有错误或恢复页面。

不增加新页面、正式徽章图、任务图标或公会插画。

## 首轮替换方向

优先退役以下类型的低反馈任务：

- 仅要求短暂停顿、重命名或设置提醒的恢复/运动任务。
- 与数字生活重复的文件整理任务。
- 只观察单一对象、没有确认结果的观察任务。
- 只读一页或看一个标签、没有复述或推理结果的学习任务。
- 多个仅对陌生人说一句话的同质社交任务。
- 过于模糊的公共空间善意任务。
- 数门、坐着扮演 NPC 等缺少过程的微型冒险。

新增任务重点采用：现实宾果、记忆核对、组合动作、双答案调查、有限决策冲刺、安全小环线、数字逃生演练和低压力熟人互动。

## 校验

生产内容校验增加：

- 活跃任务恰好 100 项。
- 活跃 ID 唯一，且不与退役 ID 冲突。
- 退役任务定义合法，但不计入活跃类别分布。
- 20 分钟、E3、standard、brave 均非空。
- 新 XP 与冷却值合法。
- 全部活跃任务描述和步骤为具体作者文案，不使用已知通用模板。
- 每个新任务具有完整安全标签、环境、时间、精力和不适用条件。
- 所有正常用户条件仍可匹配。

## 测试与验收

自动化测试至少覆盖：

- 100 个活跃任务、唯一 ID、合法标签和全局 ID 不冲突。
- 退役任务永不进入匹配结果。
- 20 分钟/E3/standard-brave 的精确匹配。
- 新内容不再使用五套旧描述结尾和五套旧第二步骤。
- 20 个新任务的安全性、完整性和可匹配性。
- 旧存储历史迁移后保留原始标题。
- 旧进行中任务升级后可展示、完成、放弃并按原 XP 结算。
- 新历史写入不可变任务快照。
- 损坏及未来版本存储仍安全恢复。
- 既有 12 组黄金条件，以及新增的高精力、长时间和退役兼容样例。

最终在项目目录运行：

```text
pnpm lint
pnpm test
pnpm build
```

同时使用真实浏览器验证 375、390、430 CSS px，以及非零 `--safe-area-inset-top` 下的顶部控件和锚点目标。
