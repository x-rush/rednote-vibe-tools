# 原生一滴水的战争 玩法与视觉完成度审查

审查日期：2026-10-18。代码基线：`main / 1c2d8c40`。本次只新增审查文档、截图和复现脚本，没有修改产品源码或内容，也没有提交、推送或发布。

## 核心判断

目前已有不少内容：24 种器官、12 种协同、26 种生物、6 个环境、3 个结局。最值得投入的是把已有内容串成玩家能感受到的成长过程。

当前的主要缺口是：通关对主动游玩的要求不足；六段倒计时迁徙与三层尺度进化没有统一；形态、预览和结算分别绘制，成长缺少一致的视觉证据；真实目标和背景纹理的辨识层级不清；手机上的选择信息和宿主按钮避让仍有问题。

建议保留单指移动、自动器官、暂停三选一、完整包裹吞噬、离线静态运行这些已确认方向。第一轮围绕一段好玩的生态圈补齐，再推广到后续生态。

## 需要优先解决的问题

### P1 主动捕食没有成为通关的必要条件

固定种子 727 下，不做移动，只接受第一项变异就能进入结局。水流和自动器官仍会使角色位移、获得收益；因此这里的“不移动”指没有方向输入，不代表角色世界坐标不变。

代码原因很明确：[engine.ts](../src/game/engine.ts) 的 `createRunDirector` 仍传入旧 `content.journey`；`stepJourney` 在旅程结束时主要根据存活体数量和稳定度判断结局。`enterEnvironment` 又按阶段序号除以二切换尺度，并非“进化压达标且完成生态考验”才跃迁。

最新的 [尺度进化设计](2026-09-02-scale-evolution-redesign.md) 已明确要求后者。`markLifecycleEncounterResolved`、`mutationMilestones`、`advanceForm` 等能力已经存在，但生产调用链没有完成连接。

建议统一为三层生态，每层都有进化压、两次构筑选择、一次生态考验和明确出口。倒计时用于加剧环境压力、提醒目标，不直接赠送尺度跃迁或通关。考验允许捕食、诱导、隐匿等多种移动解法，避免强迫所有构筑使用同一种打法。

验收：无方向输入加默认选项不能自动进入胜利结局；未达进化压或未完成考验不能跃迁；选定的多种解法均能用正常角色状态完成。多个固定种子需要分别验证，不能只覆盖 727。

### P1 三种生命形态没有完整落实到画面

[morphology.ts](../src/rendering/morphology.ts) 已计算 `primal / colony / ciliate` 骨架，但 [cell.ts](../src/rendering/cell.ts) 没有读取 `.skeleton`，轮廓主要仍由旧体态与路线决定。聚合体可增加内部核心，但尚不足以形成多细胞共享外膜的清楚轮廓。

进化卡使用 CSS 图形，战斗使用 Canvas，结果又使用另一套 CSS 图形。玩家容易看到名字变了、颜色变了，却认不出自己长出了什么。

建议让 `formId + build` 驱动统一的生物绘制：原始体单核心与柔软膜；聚合体多个相连胞体和共享外膜；复合体明确长轴、纤毛带和定向口沟。器官在真实安装位置生长，并沿用到选择预览、局内、结算和收藏展示。预览可用同一绘制模块生成，不必保持完整游戏循环。

验收：隐藏名称、改为灰度后也能区分三种形态；同一构筑在所有页面一致；选择后新增结构能被肉眼指出；在既有低画质模式仍保持主要轮廓与危险提示。

### P1 375px 下的进化代价被裁切

[375px 进化截图](review-2026-10-18/375-mutation.png) 中，三张卡片的代价行被下边界裁切。`.evolution-choice` 的固定最小高度、网格分配与 `overflow: hidden` 组合，使文字存在于 DOM 中也不可完整阅读。

建议优先保证“能力、触发条件、代价”全部可见；预览在短屏适当缩小。卡片按内容撑开，选择区域滚动，确认按钮保留独立区域。不能靠缩小正文到难以阅读解决。

验收：375 / 390 / 430、44px 系统安全区下，三项代价可完整读到，确认键可操作；增加文字长度或文字缩放后仍可滚动访问。现有 `responsive-layout.test.ts` 只断言 CSS 字符串，应补充真实包围盒或截图验证。

### P1 系统安全区没有解决宿主按钮遮挡

生产构建的暂停键在三个竖屏宽度下均为 `y=54, height=44`，正好位于模拟宿主操作区。左侧分数同样会被模拟宿主返回区盖住。

原因在 [App.css](../src/App.css) 的 `.game-hud` 和 `.game-hud .game-hud__pause`：只计算了系统安全区，未给宿主左右占位与触摸余量留空间。

建议将暂停操作移到顶部安全中区或 HUD 下方，重排分数和目标；建立可配置的宿主占位参数。背景可以延伸到顶部，不要用整页大块空白避让。

验收：所有实际页面状态在左右宿主覆盖层下可读、可点；真实横屏与未来若有的 CSS 旋转模式分别检查；最后使用同一产物做宿主真机校准。

### P2 雷达存在外观，但没有接入真实世界数据

[App.tsx](../src/App.tsx) 渲染 `Hud` 时没有传入 `radar`；[Hud.tsx](../src/ui/Hud.tsx) 使用 `1×1` 世界和空威胁数组作为默认输入。因此当前雷达不能承担寻找考验、出口或预警的功能。

建议接入实际玩家位置、已公开的威胁与当前目标，只显示符合发现规则的信息；距离较近时优先在画面边缘给方向提示。没有可提供的信息时隐藏雷达，让出视野。

验收：移动后标记位置正确变化；发现目标后出现指示，目标完成后消失；未知敌人不会被无条件泄露。

### P2 背景的生物纹理与可交互对象争夺注意力

开场与实际游玩截图中，背景自带大细胞、亮色内核和纤维，而真实猎物可能只有少量小亮点。玩家需要先判断哪个东西能吃，再判断自己能否吃得下。

[renderer.ts](../src/rendering/renderer.ts) 叠加环境大图、焦散、环境 SVG 与部分场景纤维；[effects.ts](../src/rendering/effects.ts) 的基础液体场也固定使用一组蓝色。层数较多，但不同生态的视觉辨识主要仍依赖背景。

建议保留显微水域风格，拉开三个层级：远景大形低对比、低清晰度；地形危险提供明确边界与流向；可交互生物拥有最清楚的轮廓和材质。背景中的大细胞不能与可吃对象拥有相同的亮边语言。

验收：静态截图中能快速指出自己、猎物、威胁、目标；关闭背景纹理仍能辨认玩法；灰度下通过尺寸、形状、线型区分关系。

### P2 自动器官的决策价值需要更直接展示

三选一目前有能力与代价文案，这是值得保留的基础。但 `data-part` 没有对应器官预览绘制，电囊和包裹口等同路线器官的预览非常接近。

建议每张卡呈现真实器官变化和一个短行为示意，例如“敌人靠近→电弧反击”“追逐后→喷流加速”；附带与当前构筑相关的一条信息，如已有协同、即将成型或当前环境的适配原因。确认后首次触发给局部可读反馈，再把提示淡出。

沿用已有三选一池，不增加多套复杂管理系统。路线名是辅助信息，玩家首先要理解“这次选了之后，我该如何移动”。

### P2 局外界面和重复游玩动机弱于内容体量

[Lab.tsx](../src/ui/Lab.tsx) 首次游玩隐藏了正常设置入口；回流后又把出生形态、四个工具、每日种子、培养皿码和八个词缀放在同一长页。首页的细胞是 CSS 与资源叠加的独立展示，不是玩家刚养出的生物。

当前基因节点只有三个，主要解锁另外两个起源。存储保留最多 30 次档案，界面却通过 `lastArchive` 主要展示最近一份，历史生命缺少可浏览的收藏呈现。图鉴的主要内容仍是名称与记录状态，对“这个生物怎么追、怎么躲”的帮助有限。

建议首页突出“继续孵化、上次生命、一个可达成的发现目标”；挑战和培养皿码收进次级入口，设置从第一局前就可访问。收藏优先展示已有档案和生物，不先扩建永久数值树。图鉴补生态行为与应对方式，帮助下一次选择。

### P2 设置存在接线遗漏

`reducedShake` 有 UI 和存储字段，但 `GameCanvas` 没有把它传给渲染器，震动计算只读取 `reducedMotion`。用户单独打开“减少震动”不能改变这条震动路径。

建议逐项核对声音、动态、闪烁、粒子、震动和画质的实际作用，使用行为断言验证。全局减少动态 CSS 的 `0.01ms` 动画处理也应改成有意保留必要状态变化的方案。

## 推荐的玩法体验

以下时间是待试玩校准的目标，不是当前测试结果。

| 时间 | 玩家体验 | 设计动作 |
| --- | --- | --- |
| 0–5 秒 | 看懂自己和能吃的目标 | 一小群真实营养粒出现在安全可见范围，短示意提示单指拖动，首次操作后退场 |
| 5–15 秒 | 完成首次追逐与包裹 | 有明确收益、短暂膜形变、吸收轨迹与声音；避免大量粒子遮住下一个目标 |
| 20–40 秒 | 做出第一个构筑选择 | 三项改变移动策略的能力；选择后很快有合适的触发场景 |
| 40–90 秒 | 利用新能力完成一次有风险的机会 | 抢食群、借流追猎、诱敌进入环境危险等，资源与风险在场景中可判断 |
| 约 2–3 分钟 | 完成生态考验并第一次跃迁 | 有明确对手或目标、公开解法、完成反馈，然后身体和生态尺度一起变化 |

中后期复用这一结构，但改变猎物、地形、运动和对手。上一层的威胁在下一层成为可猎目标，让力量增长通过关系反转被感受到。避免只增加敌人数量与碰撞伤害。

吞噬应继续以现有完整包裹规则为准。对接近成功的包裹、受伤和自动反击提供不同的局部反馈，让失败原因可理解。

## 推荐的美术方向

整体保留深水显微生态与清楚的街机轮廓，向“有材质、有生命、有层次”推进。

| 部位 | 改进重点 | 应保留的限制 |
| --- | --- | --- |
| 主角 | 半透明外膜、局部高光、内部颗粒、朝向形变、受力回弹，三形态骨架真正不同 | 碰撞边界明确；不因柔体效果让玩家误判包裹 |
| 猎物与威胁 | 轮廓、游姿和关键结构区别；危险提示统一线型 | 可识别性不依赖色相；低画质保留提示 |
| 水域 | 景深、低对比大形、少量焦散和环境特色 | 装饰不能看起来像真实可吃对象 |
| 自动器官 | 长在身体上的结构与对应触发特效 | 不变成新增技能按钮，不扩大操作负担 |
| 进化 | 同一真实生物的前后变化，器官生长、膜重组 | 选择文字完整；减少动态模式能直接理解结果 |
| HUD | 主目标、成长进度、膜状态和安全暂停；正文大小适合手机 | 当前约 8.64px 的小标签需要提升；避免两个无说明进度条 |
| 结算与收藏 | 真实终态、独特名称或已有物种信息、关键进化和发现成果 | 先展示已经发生的事实；导出或分享能力另按宿主规范确认 |

优先用 Canvas 几何、共享绘制配方和缓存的小型材质完善现有实现。新增内置图像需要确实改善材质或生态辨识，再考虑包体。当前 `microscope-fibers-v2.webp` 约 819 kB，可结合可见收益重新评估；不应只为提升精美度继续叠加大纹理与全屏模糊。

现有 Web Audio 合成音效可以继续完善吞噬连段、受伤、器官触发和跃迁的节奏。无需为了基础反馈改成外部音频请求。未来采用采样音频时，必须沿用仓库已确认的构建期静态 JS 字节资源与 Web Audio 解码方案。

## 实施顺序与停止条件

| 顺序 | 本轮交付 | 完成条件 |
| --- | --- | --- |
| 1 | 单一尺度进化状态机、考验门槛、首局目标、有效雷达、宿主避让、完整三选一文字 | 正常角色状态下完成首层；不能等待自动胜利；移动、选择与结果的关系明确 |
| 2 | 第一生态圈的统一生物渲染、背景层级、吞噬/受伤/器官反馈、真实进化预览 | 同一构筑跨页面一致；三形态轮廓可区分；背景与目标不混淆；手机预算通过 |
| 3 | 将验证过的节奏扩展到后两层，补收藏浏览、图鉴行为、回流首页和设置接线 | 一局有连续成长，下一局有明确的新选择或发现；旧存档可读 |

第一轮停止条件是把首层做成可独立判断好玩与精美程度的完整体验。后续新增内容以试玩问题为依据，不先扩大器官、环境、词缀和永久成长的数量。

## 应调整的验证方式

现有测试在数值有限性、状态机、内容和静态构建上有价值，应继续保留。`playthrough.ts` 的 `keepAuditPlayerAlive` 会清除部分附近敌人，把玩家膜与能量至少补到 10,000，将半径调整为 50，必要时移到安全角落。这种流程审计不能作为普通难度、首局节奏或可操作性的证明。

新增验证应覆盖：

- 正常初始数值下，多个固定种子的首次可见目标、首次吞噬、首次选择和首次考验时间。
- 无方向输入、简单追食、只逃跑、正常多路线构筑之间的结果差异。
- 进化压不足、考验未解决、两者完成等条件组合，以及终局成功门槛。
- 三形态的实际 Canvas 轮廓和所有预览、结算、存档的对应关系。
- 375 / 390 / 430、非零安全区、左右宿主覆盖、横屏下的真实文字和按钮包围盒。
- 合成触摸与中断手势、各设置实际生效、后期密集场景的帧耗时。
- 构建与最终 ZIP 白名单审计；创服平台与 Android / iOS 对同一产物的验收单独记录。

机械设计扫描仅返回三项提示：警告条的单侧边线、进度条的 `width` 动画、字体栈里的 Inter。前者有明确警告语义，中文主要使用系统字体；它们不是当前完成度低的根因。进度条动画可以在后续性能整理中处理，不应挤占玩法和形态改版优先级。
