# 八项目引导 NPC 系统设计与交互契约

状态：`NPC ROSTER FROZEN / UI AND ASSET INTEGRATION PENDING`

日期：2026-08-24

## 1. 为什么需要 NPC

NPC 不负责增加新玩法，而负责把已有说明、反馈和恢复动作放进产品世界观。每个项目只有一位常驻引导者，承担三类职责：

1. **首次引导**：用不超过 3 个短对话气泡解释目标、隐私和第一步；
2. **节点反馈**：只在完成一章、获得关键物、经营结算或生成结果时出现一句有信息量的反馈；
3. **异常恢复**：存储失败、数据损坏、无可用任务等状态中说明“发生了什么、数据是否还在、下一步做什么”。

NPC 不是装饰性吉祥物，也不是强制教程弹窗。用户可以跳过首次对话；设置与帮助页可再次召回；跳过后所有关键规则仍须由界面本身表达。

## 3. 分项目台词与行为冻结

### 3.1 闻山｜SBTI 山海兽格

- 自称：`守卷人闻山`；称用户：`来访者`，结果后可称 `持卷人`。
- 首次开场：`山海旧卷只记异兽，不替人定命。你只需按此刻最自然的选择作答。`
- 隐私提示：`本次选择只在你的设备上计算；记录最多留三次。`
- 结果揭晓：`卷上落的是本次倾向，不是终身判词。先看它照见了什么。`
- 接近型：`两兽只差一线，不必急着舍去其中一个。`
- 禁止：预言、运势、吉凶保证、临床心理术语、把 MBTI/SBTI 写成科学诊断。

### 3.2 许照｜物华录

- 自称：`物华馆图录助理许照，叫我阿照就好。`
- 首次开场：`先看轮廓、用途与痕迹，再猜名字。猜错也会留下线索。`
- 错答：指出一条可观察事实，不直接公布答案。
- 收录：`名称只是入口；年代、用途和证据链才让它真正进入图录。`
- 禁止：伪造馆藏编号、把创意复原图冒充文物照片、用价格衡量文物价值。

### 3.3 沈砚｜大理寺字案录

- 身份口径：大理寺虚构录事，不使用真实历史官员姓名。
- 首次开场：`字形、证词、物证各有偏差。先记下事实，再决定相信谁。`
- 对话选择前：只说明目标与可问方向，不提示正确选项。
- 证据冲突：`这两条不能同时为真。要先查时间，还是查字形？`
- 结案：复述用户使用的关键证据，不把结论伪装成唯一历史答案。
- 禁止：替用户选问句、剧透真凶、现代警察制服、法医或刑侦术语乱入。

### 3.4 阿沅｜汴京饮子铺

- 首次开场：`铺面借来了，钱却不是风刮来的。先定今日饮子，再看客从哪条街来。`
- 晨间：概括天气、库存和现金，只提醒最突出的一个风险。
- 事件：提供两种做法的现实后果方向，不泄露随机结果。
- 濒临倒闭：`还能救，但要先保现金还是保口碑，只能选一个重点。`
- 第 100 日：按玩家经历回顾一件最关键的经营选择。
- 禁止：无限送资源、替玩家决定、使用现代连锁店话术、把亏损讽刺成玩家失败。

### 3.5 小满｜我希望被这样对待

- 首次开场：`这张卡不是要求别人服从，而是让你的需要更容易被理解。`
- 选择冲突：`两个都重要也没关系，我们先写更常用的一条。`
- 改写建议：优先“当……时，我希望……”而不是“你总是……”句式。
- 分享前：提醒卡片可能包含私人边界，确认是否隐藏敏感条目。
- 禁止：诊断依恋类型、建议分手／和好、裁判谁对谁错、强迫分享。

### 3.6 路岚｜出门检查官

- 首次开场：`告诉我去哪里、做什么、和谁一起；我只补容易忘的，不把清单越写越长。`
- 生成后：解释最多三项“为什么出现”，其余保持安静。
- 临出门：只读未完成的高优先项，不重复已完成事项。
- 无网络／天气不可用：明确使用用户手动选择，不假装知道实时天气。
- 禁止：恐吓式风险文案、无限增加“以防万一”、把非必要项标成必须。

### 3.7 迟言｜当时这样说就好了

- 首次开场：`不用上传聊天记录。选一个最接近的场景，我们只整理你想表达的部分。`
- 复盘顺序：事实 → 当时感受 → 真正需要 → 可说出口的句子。
- 生成后：`更好的表达不保证对方同意，但能让你的意思更清楚。`
- 高冲突场景：提供暂停表达和离开现场选项，不鼓励继续对抗。
- 禁止：读取聊天记录、揣测对方人格、承诺修复关系、使用心理治疗身份。

### 3.8 弥拉｜地球 Online

- 公会称呼：`地球 Online 冒险者公会委托官弥拉。`
- 首次开场：`主线不用着急，先来领一个小任务。`
- 发任务：说明耗时、地点、安全边界和完成条件，不制造必须连续打卡的压力。
- 放弃任务：`撤回不是失败，公会会把它放回任务池。`
- 结算：奖励只用于收藏、称号和回顾，不与金钱或概率付费挂钩。
- 禁止：照搬“赛利亚”的外貌、服装、称呼和台词；不得把危险、违法、骚扰陌生人或高消费行为包装成冒险。

## 4. 统一交互契约

### 4.1 出场层级

| 层级 | 形式 | 最大内容 | 是否自动出现 |
|---|---|---:|---|
| 首次引导 | 半身像 + 对话卡 + `下一句／跳过` | 3 句，每句 ≤ 38 汉字 | 仅首次 |
| 节点反馈 | 头像圆片 + 单句气泡 | 1 句 ≤ 46 汉字 | 关键节点一次 |
| 可召回帮助 | 右上角 NPC 头像按钮 | 当前页 1–3 条说明 | 用户主动 |
| 异常恢复 | 小头像 + 状态说明 + 恢复操作 | 标题、原因、数据状态、操作 | 异常时 |

### 4.2 状态机

`unseen → intro-1 → intro-2 → intro-3 → dismissed/completed`

- `跳过`：直接进入 `dismissed`，不能阻止使用核心功能；
- `再次召回`：打开当前页帮助，不重置首次引导；
- `减少动画`：角色和气泡直接出现，无位移、弹跳或逐字打印；
- `本地存储失败`：本次会话仍可继续，NPC 不反复弹出首次引导；
- 版本新增关键规则时使用独立 `guideVersion`，只展示新增的一条说明，不重播全部教程。

### 4.3 无障碍与触控

- NPC 图片必须有角色名与身份 alt；纯表情变体使用空 alt；
- 对话文本必须是 DOM 文字，不能烧在图片里；
- `跳过引导` 与 `下一句` 触控高度至少 44px；
- 焦点顺序：角色身份 → 对话 → 次操作 → 主操作；
- 屏幕阅读器播报时不包含装饰性动作、服饰和背景描述；
- NPC 不覆盖主操作、结果数字、证据图或安全区。

## 5. 资源冻结策略

每个 NPC 首发只生成一张透明背景或可安全抠图的 3:4 半身母版，不为三种表情重复生成完整人物：

- `guide-master.webp`：900×1200，建议 ≤ 180 KB；
- `guide-avatar.webp`：由母版裁切 160×160，建议 ≤ 12 KB；
- `guide-placeholder.webp`：72×96，建议 ≤ 4 KB；
- `guide-silhouette.svg`：确定性失败降级，由前端／SVG 制作；
- 情绪变化首发用气泡色、眉眼轻量 SVG 叠层或 CSS，不生成互相不一致的多套人物。

古风四项目的服饰、发式、案牍、器物必须先建历史参考证据包；现代四项目也需以真实职业／日常服装参考约束剪裁和功能细节。不得凭空拼出“朝代混搭汉服”或不可使用的现代工具。

## 6. 页面增量要求

每个项目至少新增或改造四类状态：

1. 首次进入的 3 句引导；
2. 一个核心节点反馈；
3. 可召回帮助面板；
4. 一个异常恢复状态。

这些状态可在同一预览卡中展示多步，不强制为每句增加一部手机屏，但必须在 UX-SPEC 和 UI-HANDOFF 中列出完整状态、触发条件和跳过路径。
