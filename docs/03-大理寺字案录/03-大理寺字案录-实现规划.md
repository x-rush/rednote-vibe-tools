# 大理寺字案录：实现规划

## 产品定义

正式名：**《大理寺字案录》**。

副标题：**查的不是人，是汉字的前世今生。**

“大理寺字案录”借用古代断案意象构建虚构的文字案件世界，并非真实历史上存在的机构或职司。产品首次说明或来源页必须明确这一点。

一句话：领取一份文字疑案，通过字形、古义和历史语境，查清流传很广的汉字故事是真是假。

参赛标签：`#国风vibecoding #小红书vibecoding大赛 #vibeknow`。

## MVP 范围

- 第一季 8 个案件。
- 每案包含：传言、第一判断、3 个调查步骤、最终判定、争议说明、来源。
- 判定等级：基本可信、部分可信、证据不足、常见误解。
- 案件档案、已结案状态、侦探类型结果、本地存储。

候选案件：安、美、北、取、武、鲜、好、囧。正式采用前必须逐案完成权威资料复核。

不做：自由输入回答、自由输入查字、OCR、手写识别、AI 实时解释、全量字典。

## 核心流程

```text
大理寺接案 → 坊间传言 → 初步判断 → 验看字形证据
→ 查看历史语境 → 区分事实与演绎 → 修改/坚持判断
→ 落下判词 → 来源 → 收入已结字案
```

## 玩法

- 整体采用选项式 Galgame 结构：角色对话、追问、查证、判断和最终判词全部使用预设选项。
- 用户不需要输入自由文本，系统也不进行语义分析；所有分支均由本地数据、案件 flags 和有限状态机驱动。
- 用户开始时先表态，结案前可以修改判断。
- 每个证据步骤不是“下一页”，至少包含一次找构件、排序或真假辨识。
- 系统记录用户偏好：字形证据、语境证据、直觉或怀疑。
- 8 案完成后生成断案风格：形证派、语境派、审慎派、直觉派等。
- 不用正确率羞辱用户；重点是“看到证据后是否更新判断”。

## UI 与美术

- 风格：古代官署案卷 + 现代信息可视化；使用卷宗、签条、朱批和印章意象，但避免昏暗到难读。
- 汉字演变用 SVG 时间轴；字形不得由 AI 凭空生成。
- 结案使用“大理寺判定”盖章动画，但动画短于 800ms。
- 证据分为“资料”“解释”“产品提示”，视觉层级清晰。

## 事实规范

- 至少一条权威字书、学术出版物或可信机构来源支撑关键结论。
- 有争议的内容明确写“存在不同观点”。
- 不把构形趣说包装为唯一字源。
- 每案保留研究笔记和引用页码/章节；产品页可显示简化引用。

## 测试

- 8 案均能完成、恢复和重置。
- 所有选择路径都能到达唯一结案页面。
- 断案风格在不同答题策略下可达。
- SVG 在常见手机尺寸不裁切。
- 来源抽屉可从每案打开。
