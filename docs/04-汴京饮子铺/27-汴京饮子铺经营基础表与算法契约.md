## 3. 天气与季节

天气：晴和、暑热、阴天、骤雨、寒风、风尘。天气由内置 seed 生成，不调用真实天气 API。

| 天气 | 客流 | 偏好 | 经营影响 |
|---|---:|---|---|
| weather-clear | +0 | 通用 | 无 |
| weather-hot | +15% | 青梅、薄荷 | 易坏库存风险+ |
| weather-cloudy | -5% | 温和饮子 | 无 |
| weather-rain | -20%街客/+夜归客 | 姜蜜、枣香 | 排水事件权重+ |
| weather-cold | -10% | 姜蜜、桂香、枣香 | 燃料成本+ |
| weather-dust | -15% | 带盖/热饮 | 清洁精力成本+ |

100 天划分为四个游戏季段，而非严格历法：初春 1–25、长夏 26–55、初秋 56–80、入冬 81–100。季段只控制题材和权重。

## 4. 每日经营输入

玩家晨间设置：

- 今日上架 3–5 种饮子。
- 每种备货量 0–12。
- 售价在基准价的 80%–140% 内取整数。
- 是否提前打烊保护精力。

MVP 不做复杂原料逐项采购；每杯成本在备货时扣除，未售出部分按饮子保存率返还 0%–40%，避免库存表过重。

## 5. 客流与销量公式

```text
baseVisitors = stageBase + reputationBonus + eventDelta
weatherVisitors = baseVisitors × weatherMultiplier
customerMix = seasonWeights + eventOverrides

purchaseScore =
  priceFit × 35%
  + drinkPreference × 30%
  + reputation × 20%
  + serviceCapacity × 15%
```

- 不展示伪精确百分比给玩家。
- 实际销量受备货上限约束。
- 同一 seed、状态和经营输入必须得到同一结果。
- 声望不会无限放大客流，达到 70 后边际收益下降。

## 6. 日终计算

```text
income = Σ sold × price
stockCost = Σ prepared × unitCost
wasteReturn = Σ unsold × unitCost × keepRate
dailyProfit = income - stockCost + wasteReturn + eventMoneyDelta

energyCost = baseOpenCost
  + Σ sold × complexityEnergy
  + eventEnergyDelta
  - restProtection
```

结算顺序固定：销量 → 库存 → 事件延期效果 → 账款/工资 → 状态 clamp → 倒闭/结局检查 → 写安全存档。

## 7. 难度保护

- 第 1–10 天不会同时触发两项大额强制支出。
- 钱低于 15 时提高低成本翻盘事件权重，不直接送钱。
- 精力低于 15 时强制出现休息建议，拒绝后也不允许跌到负数。
- 连续三天负利润后显示原因摘要，但不自动替玩家选择。
- 第 90 天后不新开三段连锁。
- 任何坏结果都可追溯到状态和选择，不能因隐藏随机数直接倒闭。


每日安全快照最多保留当前日与上一日；事件历史可保留整局，但只存事件 ID、选择 ID 和数值变化。
