# 器华录 · 许照五幕主线与终章规格

状态：`READY FOR USER REVIEW`

## 1. 目标

在不改写现有 20 件文物内容、不改变“观察—线索—辨认—五札—记忆问答—归档”流程的前提下，增加一条随收藏进度展开的许照主线，使玩家获得明确的开场缘由、关系推进、章节转折和全收集情绪回收。

本次增强应让玩家感到：自己不是在完成二十道彼此独立的题，而是在闭馆后的几次整理中，与许照共同写完一本仍然留有空白的《器华录》。

## 2. 方案选择

采用“轻量线性主线叠加层”。主线由序章、五幕关键节点与全收集终章构成，根据已归档的不同文物数量依次解锁。

未采用的方案：

- 不继续扩写单件文物长文；现有 100 节史料叙事已经完整，继续加长会拖慢手机阅读。
- 不制作多分支恋爱或好感度系统；它会让知识游戏的主题偏移，并显著增加状态和文案成本。
- 不把章节绑定到某个专题柜完成；当前每日与练习模式会随机抽取文物，绑定专题柜会导致章节顺序不可控。

## 3. 叙事边界

- 许照、闭馆整理工作、交接册和玩家协作均为虚构馆内叙事。
- 每个主线页面固定显示“馆内叙事 · 虚构角色线”，不得与文物史实或来源等级混排。
- 文物名称、年代、来源、制作和用途等事实只沿用现有 `content.json` 已核验内容。
- 主线可以谈“如何观看、如何记录、为何记住”，不得为文物虚构持有者、对白、传奇或确定性历史现场。
- 所有运行时剧情正文只存放在 `src/content/content.json`；组件、SVG 和图片内不得硬编码业务文案。

## 4. 核心命题

主线围绕一句话推进：

> 档案不是替旧物把话说完，而是给下一次观看留下入口。

许照的变化不是“从陌生到恋爱”，而是从谨慎地照章整理，走到愿意把判断过程、犹疑和未完成的一页交给玩家共同记录。玩家的变化则从“猜中名字”走向“能够用证据观看，也愿意为未知保留空白”。

## 5. 章节结构

### 序章 · 未完成的交接册

- 触发：新玩家第一次进入引导；老玩家升级后第一次回到任务板。
- 场景：闭馆后的整理室，许照从一叠待归档材料中抽出一本只写了标题、没有结语的交接册。
- 作用：交代玩家为何参与整理；明确“先看证据，再叫名字”的共同规则。
- 呈现：沿用现有首页／引导大立绘，不额外打断第一次操作教学。

### 第一幕 · 物先说话

- 触发：归档第 1 件不同文物后。
- 关系阶段：许照仍然专业、克制，但第一次认可玩家的观察方式。
- 剧情动作：她没有在交接册里先写文物名，而是先记下玩家找到的一个结构证据。
- 回收：对应教学中的“先看，不急着认”。

### 第二幕 · 名字之外

- 触发：归档第 4 件不同文物后。
- 关系阶段：许照主动谈起自己曾经只背标签、却忽略器物结构的失误。
- 剧情动作：交接册第一页盖下第一枚不完整的朱印，印边故意留有缺口。
- 回收：玩家已经完成足够多次观察，能够理解“答对名称不等于看懂”。

### 第三幕 · 没有消失的声音

- 触发：归档第 8 件不同文物后。
- 关系阶段：许照开始把问题抛给玩家，而不是只给提示。
- 剧情动作：她请玩家从已归档文物中选出自己最记得的一处证据；不做分支存档，只根据当前最近归档的文物生成一句确定性回应。
- 回收：骨笛、编钟、说唱俑等“不可直接听见却留下声音证据”的主题，也允许玩家尚未收集这些文物时使用更一般的表达。

### 第四幕 · 档案里的人间

- 触发：归档第 12 件不同文物后。
- 关系阶段：许照不再只以整理员身份说话，承认自己小时候第一次进博物馆时，记住的不是年代，而是一件器物如何被人使用。
- 剧情动作：她把一张旧参观票夹进交接册。该票只属于虚构角色经历，不与任何真实馆藏建立确定联系。
- 回收：灯、香具、酒器、乐舞与葬具共同说明档案保存的也是人的生活方式。

### 第五幕 · 谁在写器华录

- 触发：归档第 16 件不同文物后。
- 关系阶段：许照明确把玩家视为共同整理者。
- 剧情动作：她把交接册推到玩家这一侧；前四枚印已经相接，最后一格仍为空。
- 回收：揭示书一直没有预写结语，因为最后一页必须由真正完成观看的人留下。

### 终章 · 天亮前最后一页

- 触发：归档第 20 件不同文物后；第五幕已经看过才可进入。
- 场景：整理室窗外天色转亮，许照合上已经完成主体、仍保留少量空白的交接册。
- 关系收束：她感谢玩家的不是“猜对二十件”，而是愿意逐一看过证据，并在未知处停笔。
- 主题回收：显示核心命题；五枚印完整并列，但末页保留一条未写的横线。
- 完成奖励：解锁图鉴页的“共同整理完成”章和终章回看入口，不增加货币或数值养成。
- 终章结束后直接进入 20/20 图鉴，不返回一轮答题总结，避免情绪被分数截断；总结仍可从正常轮次流程查看。

## 6. 触发与顺序

主线里程碑按不同文物的收藏数量判定：`1 / 4 / 8 / 12 / 16 / 20`。

- 每一幕只完整播放一次，并写入 `seenNarrativeIds`。
- 若老存档升级时已越过多个里程碑，每次回到任务板最多补播一幕；玩家可以选择“稍后再看”，其余章节保留在任务板入口，不连续轰炸。
- 新解锁章节在当前文物的“归档移交”页面完成后触发，不插进观察、答题、五札或记忆问答中间。
- 第 20 件归档时，按“第五幕（若未读）→终章→图鉴”顺序处理。
- 章节是否解锁只依赖 `collection.length` 与已读 ID，不依赖答题星级，避免知识掌握程度被误写成角色亲密度。
- 已解锁章节可在任务板的“闭馆手记”入口重看；重看不修改进度。

## 7. 台词轮换

现有每件文物、每个阶段均有三条许照台词，但运行时多数固定取第一条。本次增加纯函数选择器：

`pickGuideLine(lines, roundSeed, artifactId, phase): string`

- 使用稳定字符串散列选择索引，不调用随机数。
- 同一轮、同一文物、同一阶段保持一致，避免重渲染时台词跳动。
- 不同轮次可看到另两条已有台词。
- 错误复盘、揭晓、归档、全局帮助入口和专题封签统一使用选择器；普通观察签说明保持现有文物专属内容。
- 台词轮换不影响答题、星级或状态持久化。

## 8. 内容模型

在 `content.json` 的 `content` 下新增 `narrative`：

```ts
type NarrativeBeat = {
  id: string
  speaker: '许照' | '旁白'
  body: string
}

type NarrativeChapter = {
  id: 'act-1' | 'act-2' | 'act-3' | 'act-4' | 'act-5' | 'finale'
  unlockCount: 1 | 4 | 8 | 12 | 16 | 20
  eyebrow: string
  title: string
  summary: string
  imageAssetId: string
  beats: NarrativeBeat[]
  actionLabel: string
}

type NarrativeContent = {
  fictionLabel: string
  journalTitle: string
  journalIntro: string
  recentArtifactResponseTemplate: string
  prologue: NarrativeBeat[]
  chapters: NarrativeChapter[]
  completionSeal: string
  completionLine: string
}
```

校验规则：

- 六章 ID 与阈值必须完整、唯一并严格递增。
- 每章 3–5 个短对话节拍；单节适合 375 px 屏幕一次读完。
- 章节图片必须能在资源清单中找到。
- 第三幕使用 `recentArtifactResponseTemplate` 插入最近归档文物的名称与现有观察证据；模板本身仍位于内容数据中。
- 业务文案不得散落到 TypeScript、CSS 或 SVG。

## 9. 状态与持久化

`StoragePayload` 新增：

```ts
seenNarrativeIds: string[]
deferredNarrativeIds: string[]
```

- 字段按可选旧数据迁移；缺失时补为空数组，不清空收藏、星级或学习进度。
- 保持当前存储 schema 主版本，提升 `contentVersion`；内容版本变化仍遵循现有会话恢复规则。
- 只保存稳定 ID，不保存剧情正文、图片、Base64、Blob 或远程 URL。
- 非法、重复或已不存在的章节 ID 在读取时清理。

应用状态新增 `narrativeInterlude` 屏幕，并保存足以恢复原流程的轻量续接目标：下一题、专题封签、轮次总结或图鉴。重新加载时若正处于关键节点，可从该幕第一节重新进入，但不得重复写入已读状态。

## 10. 界面与交互

新增 `NarrativeInterlude`，采用手机 GALGAME 式关键节点版式：

- 上半区为许照 3:4 大立绘，保留头顶、肩部和手部安全区；不再使用小头像卡片。
- 下半区为深色半透明对话纸层，显示虚构标签、幕名、说话人和 1 个对话节拍。
- 轻触对话区或“继续”按钮推进；最后一步使用章节专属动作文案。
- 提供“稍后再看”，但终章首次触发时只允许完成或返回任务板，避免误触永久跳过。
- 对话节拍切换使用 180–240ms 淡入与轻微上移；立绘只做低幅度景深推近，不做人物肢体伪动画。
- `prefers-reduced-motion` 或应用减少动态设置开启时，全部转换为无位移淡入。
- 章节回看入口放在任务板，不挤入单件文物图鉴详情。

全收集后，图鉴标题区增加小型朱印“共同整理完成”，并出现“重读最后一页”入口。锁定文物卡、五札长页和编辑型文物详情布局保持不变。

## 13. 验收标准

- 现有 20 件文物的观察、线索、选项、五札、记忆问答和图鉴详情数据不被改写。
- 六个里程碑按 `1 / 4 / 8 / 12 / 16 / 20` 严格依次解锁且只首播一次。
- 旧存档收藏与星级完整保留；异常剧情 ID 可恢复。
- 300 条现有许照阶段台词能按稳定规则轮换，无重渲染跳变。
- 终章结束进入 20/20 图鉴，完成章和回看入口可用。
- 375 / 390 / 430 CSS px 无横向溢出，许照头部、双手和对话操作不被裁切。
- 所有图片本地加载，无运行时 CDN、外部 API、音视频或设备能力。
- `pnpm lint && pnpm test && pnpm build` 全部通过。

## 14. 明确不做

- 不加入恋爱数值、分支结局、付费资源、抽卡或每日签到。
- 不加入配音、音乐、视频或自动播放。
- 不生成真实文物的剧情场景复原图。
- 不允许跳过观察直接看答案，也不改变现有星级规则。
- 不重排二十件文物或替换用户已经确认满意的交互流程。
