# 花少有狼：全流程审查与整改

审查日期：2026-09-15。范围限于项目 16。未新增依赖，未修改其他项目，未发布到外网。

## 结论

已修复本次确认的内容归属、移动端操作路径和部分 NPC 行为问题。基础流程与按钮分支通过自动化检查，可以继续试玩。

这不是“真人感与高可玩性已经被证明”的结论。电脑仍是有限规则驱动，不是自由对话模型，也没有真人用户测试来证明复玩意愿。

## 按严重程度排列的发现

| 优先级 | 问题 | 状态与处理 |
| --- | --- | --- |
| P1 | 原创风味台词容易被理解成嘉宾真实金句，无法满足真实资料要求 | 已修复：图鉴仅展示 7 条有来源的本人公开博文摘录；对局明确标注模拟。原 168 条原创文案保留在开发内容档案，不再进入构建后的公开内容，也不再显示 |
| P2 | 手机端需要滚动穿过整段讨论和线索才能发言 | 已修复：增加阅读/行动快捷入口，支持上下安全区，保留原有纸感与绿色视觉体系 |
| P2 | 预言家查验完成缺少明显提示 | 已修复：行动区显示私密结果入口；不把查验自动放进公开讨论 |
| P2 | 被指认者面对证据只作笼统回应 | 已改善：变票、前后查验矛盾、争预言家身份分别回应；被报好人不会直接接受对方身份；被质疑的真预言家只公开自己实际持有的查验，不凭空生成 |
| P2 | 限定候选人时电脑仍可能投已查明好人或已知狼队友 | 已修复：投票策略允许在这种情况下弃票，不改变普通发言的选人逻辑 |
| P2 | 嘉宾图鉴曾导致用户感觉离开了正在进行的游戏 | 已有修复并再次回归：对局内以弹窗展示，关闭后仍停留本局，目标选择和存档不变 |
| P3 | 移动端正文偏小、部分操作按钮点击区域偏小 | 已改善：讨论正文 14px，主要选项/紧凑/关闭按钮至少 44px；底部按钮 48px |

## 随机身份与可信行为

- 嘉宾卡、身份牌分别洗牌，玩家座位随机，不把某张嘉宾卡固定为狼人。
- 相同随机种子可以重现同局，用于存档与测试；正式新局用浏览器随机数生成种子，不是预写固定剧情。
- 身份比例固定为 2 狼、1 预言家、1 女巫、3 平民；“比例固定”不等于“人物身份固定”。
- 电脑策略只读取允许的信息视图。普通好人没有其他人的身份与查验；狼人知道队友；女巫在规则允许时知道刀口。
- 初轮电脑发言使用各自开场视图，避免后说者全部机械跟随最先说话的人。
- 支持、质疑、公开证据、报查验会改变后续判断，但有限规则无法模拟完整的人类心理。

## 剩余风险和下一步优先级

1. 复玩时仍可能感觉电脑的普通试探发言重复。应增加基于本局实际事件的不同推理表达，而不是重新塞入无来源的明星金句。
2. 目前只有 7 条已核对公开博文摘录，资料规模较小。后续如果增加“节目金句”，需要官方正片/片段及准确时间位置，不能用本文的博文核验代替视频核验。
3. 未在实体 iPhone、微信内置浏览器或 Android 真机执行测试；桌面 Edge 模拟宽度和安全区不能替代真机。
4. 没有进行真人试玩访谈或长期平衡性研究；不能承诺“人人觉得有趣”、公平胜率或接近真人水平。
5. 纯前端单机没有反作弊保障。开发者工具可查看本地状态，隐私锁只防误触曝光，不是加密安全系统。
6. 本轮测试使用独立浏览器上下文和临时端口，没有读取、覆盖用户在 4316 端口的对局存档。

本报告取代早期验证文档中对“168 条原创金句”的产品展示描述；历史原创数据只是开发档案。
