# E03 解法与教学示例

## Q07 上下文与会话

假设客服会话80轮，模型可用上下文预算16000token；订单号必须准确，摘要有可能把o123误写为o132。

### 最低合格

原文/事实/摘要来源分离；关键ID回查；预算与输出余量

### 完整参考解法

我会先区分对话原文、结构化事实和模型摘要。身份、订单号与已授权动作由可信业务记录提供，不能把自由文本摘要当唯一来源。摘要保存来源消息ID或订单查询记录，关键字段可以回查；如果摘要写成o132但工具记录是o123，应以核验记录纠正并记录冲突，而不是不断压缩错误使它显得更可信。当前任务只装入必要事实、最近相关消息和必要工具结果，给系统指令、输出与工具参数留预算。
预算接近上限时采用选择性压缩或检索历史，而非机械保留全部80轮。摘要说明哪些是用户自报、哪些是查询确认、哪些已过期；费用和窗口不只由输入决定，还需为模型输出保留空间。会话键绑定用户与租户，不能通过猜thread_id访问他人聊天；敏感信息按目的限制存储与留存，用户要求删除时需处理摘要、索引及缓存，不仅删除可见消息。对于支付授权，长期记忆不能自动延长授权期限，当前动作仍检查对象和版本。测试长对话丢关键订单、错误摘要、切换用户、过期政策以及删除后召回。也可以暂不做长期记忆，只保存当前会话必要状态，这对实习项目往往更易可靠交付。回答要解释保留什么、谁是事实权威、怎样纠错，不是笼统说“用滑动窗口或RAG”。

### 关键点

- 原文/事实/摘要来源分离
- 关键ID回查
- 预算与输出余量
- 租户隔离和过期删除

### 可接受替代

- 仅当前会话状态适合短任务，复杂度低
- 历史检索代替长摘要可保留来源，但仍需权限和相关性控制

### 常见错误

- 把所有聊天塞窗口
  - 原因：把所有聊天塞窗口：成本增加且不能保证注意到关键事实；摘要也可能传播错误。


## Q08 记忆策略

假设用户明确说“我偏好中文”，模型从一次英文资料误推其偏好英文；长期记忆存储可被用户查看、更正和删除。

### 最低合格

显式自报与推断区分；checkpoint与跨会话store；更正删除传播

### 完整参考解法

我会把显式偏好和模型推断分开。用户说偏好中文是有来源的自报事实，可在说明用途后保存；上传一次英文文档并不支持偏好英文，不能覆盖显式信息。记忆字段含类型、值、来源消息、写入时间、有效范围及可选置信，冲突时优先询问或保留旧显式偏好，而不是按最后一次摘要随意更新。长期记忆只保存任务有用的最小信息，不把全部聊天永久入库。
短期任务状态例如当前订单和已执行工具属于会话checkpoint，长期跨会话偏好属于store，两者寿命与权限不同；采用某框架时要检查实现，内存字典不能保证进程重启保存。读取记忆绑定用户和租户，不能让模型自选owner；使用时显示或可解释来源，过期政策和一次性授权不应成为永久事实。删除要覆盖主存储、索引、缓存及未来摘要引用，已经输出的数据无法保证追回，备份处理按实际留存规则说明。错误记忆更正后要使旧版本失效，避免旧索引晚到重新覆盖。测试包括误推偏好、两用户同名、纠正后检索、删除后召回以及旧事件重放。对于没有长期需求的应用，关闭长期记忆是合理选择，短期状态足够。面试中关键是写入依据、冲突、更正和隔离，而不是说“加向量库做memory”；向量召回只是一种读取方法，不构成可信事实或授权。

### 关键点

- 显式自报与推断区分
- checkpoint与跨会话store
- 更正删除传播
- 记忆不延长动作授权

### 可接受替代

- 不做长期记忆适合一次性工具
- 结构化偏好表比全量向量记忆更易校验；历史语义检索仅按需补充

### 常见错误

- 所有聊天向量化就是可靠记忆
  - 原因：所有聊天向量化就是可靠记忆：会把推断当事实、过期授权长期化，并增加隐私与删除困难。

## Q09 长任务与上下文交接

资料研究助手要处理30份政策文件；每次模型上下文有限，任务跨三个会话运行。上一会话声称已完成10份，但只保存了报告草稿，没有来源清单或处理状态。禁止把整套原文件无限塞进上下文。

### 最低合格

用结构化任务清单、来源及工件记录进度；摘要只辅助定位；恢复时检查实际工件与完成条件，按需载入资料，未证实的完成项重新核对。

### 完整参考解法

把任务状态与对话文本分开：记录每份文件的ID、版本、处理状态、产物路径、引用定位、验证结果和待办项。模型摘要可以描述进展，却不能证明文件真的处理完成。恢复时先读取任务清单和工件索引，对上一轮声称完成的10份检查是否有可定位来源和有效结果。只有满足完成条件才标done；缺证据的项目标待验证，不直接丢弃全部历史，也不照抄摘要结论。

上下文选择围绕当前子任务，只载入必要文件段落、相关规则和进度，不反复附上30份全文。压缩时保留原始证据定位和关键约束；文件内容属于不可信数据，不能成为新的系统指令。每个阶段生成结构化检查点，验证报告的引用是否真的支持结论，再推进任务。子Agent可用于隔离独立研究，但必须规定输入输出、访问范围、总预算和审核方式；数量本身不是质量保证。

Deep Agents和Claude Agent SDK的harness能力提供了文件、子任务或执行环境的实现方向，但不替代开发者定义完成标准。面试不要求背某版API。验证应在中断、坏工件、来源更新、重复恢复和上下文压缩后重跑，检查没有遗漏或重复处理，并对未完成内容诚实汇报。真正跨进程恢复需要持久化和运行环境，此题为架构设计，不声称纯前端教学模拟已经实现真实Agent执行。

### 关键点

- 任务状态与对话分离
- 工件及来源作为证据
- 按需组装上下文
- 中断恢复与预算

### 可接受替代

- 满足题面授权、证据、预算与恢复要求的框架无关实现同样可接受；需解释取舍。

### 常见错误

- 把上一会话摘要当系统消息，直接从第11份开始
  - 原因：摘要可能遗漏或误报完成，且提高消息优先级不能修复证据缺失。
