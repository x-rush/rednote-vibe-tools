# 我希望被这样对待｜首发内容与数据契约

状态：CONTENT READY / 待转 JSON 与最终语气盲审。

## 1. 首发结构

- 7 个章节。
- 16 道问题。
- 每题 3 个可选回答，部分允许“取决于情境”。
- 42 条基础输出句：偏好、边界、共同承诺各 14 条。
- 只生成一份说明书；允许编辑、隐藏、排序。
- 不评分、不分型、不诊断关系。

## 2. 七个章节

| ID | 名称 | 说明 |
|---|---|---|
| section-contact | 联系节奏 | 多久联系、忙碌时怎样告知 |
| section-listening | 倾听与回应 | 倾听、建议和确认 |
| section-conflict | 发生分歧 | 当下讨论、暂停和恢复 |
| section-space | 独处空间 | 怎样给空间而不制造失联 |
| section-care | 关心表达 | 语言、行动和细节 |
| section-boundary | 边界与禁区 | 隐私、公开、玩笑和拒绝 |
| section-repair | 修复与承诺 | 道歉、改变和重新约定 |

## 3. 十六道首发题

每个选项映射 1–2 个输出句 ID。选项没有优劣，不形成总分。

### 联系节奏

1. `question-busy-contact`：彼此都很忙时，我更舒服的方式是：简短报平安 / 有空再完整交流 / 不设固定频率但重要变化及时说。
2. `question-message-delay`：消息暂时没有回复时，我更希望：提前说大概多久后回复 / 不必解释但不要长期失联 / 重要事情换一种明确渠道联系。
3. `question-plan-change`：已经约好的计划需要改变时，我更希望：尽早告诉我 / 说明原因并一起改时间 / 紧急时先通知、之后再解释。

### 倾听与回应

4. `question-when-venting`：我诉说烦恼时，希望对方：先听完 / 帮我理清 / 先问我需要倾听还是建议。
5. `question-hard-feeling`：我表达难受时，希望对方：先确认听见了 / 给一点安静陪伴 / 用具体问题帮助我说清。
6. `question-disagree-story`：对同一件事理解不同时，希望：先复述对方的理解 / 分开事实与解释 / 暂不统一结论但尊重体验。

### 发生分歧

7. `question-conflict-timing`：发生分歧时，我更适合：当下谈清 / 冷静后约时间 / 先处理最急部分再谈关系影响。
8. `question-pause-signal`：需要暂停时，我希望：说明暂停原因 / 给大概恢复时间 / 可以延后但不要无声消失。
9. `question-conflict-tone`：讨论冲突时，我不能接受：人身定性 / 威胁离开来逼迫答应 / 把私密内容带到公开场合。

### 独处空间

10. `question-alone-space`：我需要独处时，希望：得到完整空间 / 偶尔轻轻确认 / 让我主动回来但保留紧急联系方式。
11. `question-space-not-rejection`：为了不让空间被误解，我愿意：说明不是惩罚 / 给出大概时间 / 回来后主动恢复联系。

### 关心表达

12. `question-care-language`：我更容易感受到关心的方式是：具体行动 / 直接说出来 / 记得对我重要的小事。
13. `question-help-without-asking`：对方想帮忙时，我更希望：先问再做 / 小事可以直接帮 / 给几个选项让我决定。

### 边界与禁区

14. `question-private-sharing`：涉及我的私事时，我希望：分享前先问 / 只在约定范围内说 / 即使不点名也先考虑我是否可被认出。
15. `question-saying-no`：我说“不”时，希望对方：先接受答案 / 可以问原因但不反复施压 / 以后需要再谈时重新询问。

### 修复与承诺

16. `question-repair`：关系需要修复时，我最需要：承认具体影响 / 解释但不抵消责任 / 一起约定下一次怎么做。

## 4. 四十二条首发输出句

### 偏好 14 条

| ID | 句子 |
|---|---|
| pref-contact-brief | 忙碌时，一句简短的“我看到了，晚些回复”会让我更安心。 |
| pref-contact-flexible | 我不需要固定频率的联系，但重要变化希望能及时知道。 |
| pref-reply-expectation | 如果暂时无法回复，能让我大概知道什么时候再联系会更舒服。 |
| pref-plan-change | 已经约好的计划要改变时，我希望我们尽早说，并一起确定下一步。 |
| pref-listen-first | 我诉说烦恼时，通常希望先被听完，再考虑解决办法。 |
| pref-ask-mode | 你可以先问我：“现在更需要我听，还是一起想办法？” |
| pref-confirm-feeling | 当我表达难受时，一句具体的确认比立刻说服我更有帮助。 |
| pref-separate-fact | 出现分歧时，我希望我们把事实、各自的解释和感受分开来说。 |
| pref-conflict-timing | 我更适合在情绪稍微平稳后，约一个明确时间继续谈。 |
| pref-space | 我需要独处时，希望这段空间可以被尊重，而不是被理解成惩罚或拒绝。 |
| pref-care-action | 对我来说，具体行动常常比泛泛的安慰更容易被感受到。 |

| pref-care-details | 你记得那些对我重要的小事时，我会感到自己被放在心上。 |
| pref-help-choice | 想帮助我时，给我几个可选择的方式，会让我既被支持又保有自主。 |

### 边界 14 条

| ID | 句子 |
|---|---|
| boundary-no-disappear | 冲突可以暂停，但我不能接受用突然失联来惩罚或迫使我让步。 |
| boundary-no-label | 我愿意谈具体行为，但不接受用“你就是……”给整个人下结论。 |
| boundary-no-threat | 我不能接受用分手、离开或伤害自己来逼迫我立刻答应。 |
| boundary-private | 涉及我的私事时，请在分享给别人之前先问我。 |
| boundary-identifiable | 即使不说名字，只要别人可能认出我，也希望你先征得同意。 |
| boundary-no-pressure | 当我说“不”时，可以询问一次原因，但请不要反复施压。 |
| boundary-public-conflict | 我不希望私下的冲突未经同意被带到公开场合讨论。 |
| boundary-jokes | 如果我明确说某个玩笑让我不舒服，希望它可以停止，而不是要求我证明自己为什么介意。 |
| boundary-device | 未经同意查看我的设备、账号或私人记录，会越过我的边界。 |
| boundary-time | 紧急以外的事情，我不保证随时能够回应；延迟回复不等于不在乎。 |
| boundary-space | 我提出需要空间时，不代表对方可以无限期消失；我们仍需要基本约定。 |
| boundary-advice | 如果我明确只想被听见，请不要持续给建议或评价我的选择。 |
| boundary-promise | 我不希望在情绪最激烈的时候被要求作出长期承诺。 |
| boundary-safety | 如果出现威胁、控制或伤害，安全会优先于把一场对话“说完整”。 |

### 共同承诺 14 条

| ID | 句子 |
|---|---|
| commit-say-change | 如果我的需要发生变化，我愿意重新说出来，而不是要求你一直猜中。 |
| commit-clarify | 我会尽量说具体发生了什么，而不是只用评价描述你。 |
| commit-listen | 当你表达不同需要时，我也愿意先确认自己是否听懂。 |
| commit-pause | 如果我要暂停争论，我会尽量说明原因和大概何时回来。 |
| commit-return | 暂停之后，我愿意主动回来完成尚未说完的重要部分。 |
| commit-no-mindread | 我会提醒自己：对方没有立刻做到，不一定等于故意忽视。 |
| commit-own-impact | 即使我的出发点没有恶意，我也愿意听见行为造成的实际影响。 |
| commit-no-overpromise | 我不会为了尽快结束冲突而答应自己无法持续做到的事。 |
| commit-boundary | 我会尽量在边界被反复越过之前说明，而不是积累到突然爆发。 |
| commit-respect-no | 我也愿意尊重对方的拒绝，不把亲密当作必须答应的理由。 |
| commit-private | 我会同样保护对方的隐私，不把分享当作解决冲突的手段。 |
| commit-repair-action | 道歉之后，我愿意和你一起确认下一次可以怎样做得不同。 |
| commit-check-assumption | 当我发现自己在猜测你的动机时，我会尽量把猜测当作问题来确认。 |
| commit-not-contract | 这份说明书是一次沟通的起点；我愿意让它在真实相处中被修改。 |

## 5. 映射规则

- 每个回答最多加入 2 个偏好句。
- 边界句由相关问题直接加入，不因其他答案自动删除。
- 最终至少加入 2 个共同承诺，优先选择与用户边界章节对应者。
- 相同句子 ID 去重；同一章节输出最多 4 句，超出时按用户明确选择优先。
- 用户编辑后保存 `sentenceId + editedText`；内容版本更新不覆盖编辑稿。

## 6. 精确数据契约

```ts
type RelationshipContent = {
  sections: Section[];
  questions: PreferenceQuestion[];
  sentences: ManualSentence[];
  sensitivityRules: SensitivityRule[];
};

type PreferenceQuestion = {
  id: string;
  sectionId: string;
  prompt: string;
  mode: "single";
  options: {
    id: string;
    text: string;
    outputIds: string[];
  }[];
};

type ManualSentence = {
  id: string;
  sectionId: string;
  kind: "preference" | "boundary" | "commitment";
  text: string;
  sensitive: boolean;
  compactDefault: boolean;
};
```

## 7. 内容验收

- 每个问题至少 3 个差异明确且无优劣的选项。
- 输出不会命令对方“必须随时”“永远”“无条件”。
- 边界句不被温柔语气稀释。
- 共同承诺不把伤害责任推回用户。
- 不出现依恋类型、人格障碍和伴侣合格评分。
