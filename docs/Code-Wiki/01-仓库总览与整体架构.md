# 01 · 仓库总览与整体架构

## 1. 仓库定位

这是一个面向**小红书 vibecoding 平台**的纯前端小工具合集（GitHub: x-rush/rednote-vibe-tools）。每个项目是一个独立的小游戏 / 小工具，以离线 H5 形式交付：

```text
项目源码（src/）
  → 构建为纯静态产物（dist/：index.html + 经典 JS + CSS + 本地资源）
  → 打包为离线 ZIP（release/）
  → 上传小红书创服平台，由容器（PC 模拟器 / Android / iOS WebView）加载运行
```

容器的关键限制（来自 [.codex/SKILL.md](../../.codex/SKILL.md) 与根 [AGENTS.md](../../AGENTS.md)）：

- 纯本地运行，不联网；所有资源必须打包在 ZIP 内。
- 上传端文件类型白名单：`jpg / css / gif / svg / png / js / jpeg / json / html / woff2 / webp / woff`（**没有 mp3**，音频必须走 Base64+WebAudio 链路，见 03 分册 §8）。
- JS 最低基线：Android 8.1 出场 Chrome / WebView 61，直接交付的 JS 使用 ES2017，更新语法由构建链转译。
- ZIP 建议 ≤ 2 MiB（上限 10 MiB），单段解码音频 ≤ 1 MiB。

## 3. 工作区机制

根 [package.json](../../package.json) 只声明包管理器 `pnpm@11.19.0` 与四个聚合脚本：

```json
{ "build": "pnpm -r --if-present build", "test": "pnpm -r --if-present test",
  "lint": "pnpm -r --if-present lint", "check": "pnpm lint && pnpm test && pnpm build" }
```

[pnpm-workspace.yaml](../../pnpm-workspace.yaml) 的关键设置：

- `packages: ["projects/*"]` — 25 个项目都是 workspace 成员。
- `linkWorkspacePackages: false` + `strictPeerDependencies: true` — **项目之间不允许互相 import**，每个项目必须独立可构建、独立可上传。
- `minimumReleaseAge: 1440` — 依赖发布满 24 小时才允许安装（react/vite/vitest/typescript 等白名单除外）。
- `sharedWorkspaceLockfile: true` — 全仓库单一 `pnpm-lock.yaml`，由总控统一维护（普通 Agent 不得改锁文件）。

**"共享代码"的实现方式是复制而非引用**：早期规划（[19 号文档](../00-总控与共用/19-八项目技术架构测试与提交开工包.md)）中的 `tool-core` 包从未作为 workspace package 落地，而是把 content 校验、存储信封、PRNG 等模式以"同构文件"的方式复制进每个项目（如每个 React 项目都有自己的 `src/content/validate.ts`、`src/storage/storage.ts`）。

## 4. 三代技术栈演进

| 批次 | 项目 | 技术栈 | 测试 | 背景 |
|---|---|---|---|---|
| 第一代"八项目" | 01-08 | React 19 + TypeScript 6 + Vite 8（`tsc -b && vite build`） | Vitest | 按 19 号工程契约开发，DOM/UI 密集型工具（测试、探案、经营、清单） |
| 过渡代 | 09-11 | 同上，但核心玩法走向 Canvas / 粒子 / 模拟 | Vitest | 互动视觉类（进化模拟、鱼群、星风粒子） |
| 第二代"轻原生" | 12-17 | **零 npm 依赖**原生 JS（ES Module 源码）+ Node 构建脚本（`scripts/*.mjs` 或 `tools.mjs`） | Node `--test` | 放弃 React 换取极小包体；14/17 引入音频 Base64 打包链路 |
| 第三代"治愈收集/国风" | 18-25 | TypeScript strict + Canvas2D/WebGL1 + `tools.mjs`（调用工作区 .pnpm 里的 rolldown@1.2.5 / typescript，`transform.target: 'chrome61'` 输出 IIFE） | Node `--test` + qa/ 浏览器检查 | 固定时间步 + seed 复现 + WebGL 降级 Canvas2D；18-22 自然系收集，23-25 国风 |

版本数字以 `pnpm-lock.yaml` 为准：react@19.2.8、vite@8.2.2、typescript@6.1.0（React 批次）；rolldown@1.2.5 与 typescript@6.0.3 由工作区依赖图传递提供，被 18-25 的 tools.mjs 以绝对路径调用。

**48 号新一轮开发明确沿用第三代模式**（见 [09 分册](./09-面向48号清单的开发复用指引.md)）。

## 5. 单项目通用分层架构

尽管技术栈不同，25 个项目共享同一个概念分层（这是仓库最强的架构约定）：

```text
┌─────────────────────────────────────────────────────┐
│ src/content/content.json   唯一业务内容源（文案/数值/配置）│
│   ↓ 构建期校验（validate/schema）或编译为 content.js    │
│ 纯逻辑层（engine / domain / model）                    │
│   · 状态机 + 可注入 PRNG（seed 复现）                   │
│   · 纯函数：state + content + seed → selection         │
│   ↓                                                  │
│ 渲染/表现层（React 组件 或 Canvas/WebGL 渲染器）          │
│   · 表现不回写逻辑；粒子/动效只读状态                     │
│   ↓                                                  │
│ 存储层（storage.ts）                                   │
│   · localStorage/IndexedDB 信封：schemaVersion+迁移     │
│   · 只存结构化状态，不存用户媒体                          │
└─────────────────────────────────────────────────────┘
```

三种内容注入方式并存：

1. **React 批次**：`import content from './content/content.json'`（构建期内联进 bundle）。
2. **12-17 原生批次**：构建脚本把 content.json 编译为 `dist/content.js`，挂全局变量（如 `window.GARDEN_CONTENT`、`window.STORY_CONTENT`、`window.TONGFU_AUDIO`）。
3. **18-25**：rolldown 直接打包 `src/app.ts` 时内联，或同样输出 `dist/content.js`。

## 6. 文档体系与工程的关系

- `docs/00-总控与共用/`：编号文档从 00（路线）到 49（数据快照），记录了选品、规格冻结、Schema、视觉标准、验收与上线决策的完整历史。**对开发最有用的是**：19（技术架构契约）、31（内容封装 Schema）、34/36/37（UI 验收）、38（响应式回归）、47（视觉与动效标准）、48（新一轮选品清单）。
- 每个项目的 `PROJECT.md` / `README.md` / `DELIVERY.md`（18-25 尤其完整）是该项目现状的第一手资料。
- 根 [AGENTS.md](../../AGENTS.md) 的两段"全项目共享记忆"（宿主按钮避让、音频打包）对**所有**项目生效，属于硬约束。
