# 大理寺字案录 · UI/UX 重设计 V2

状态：`IMPLEMENTED / PRODUCTION QA PASSED`  
方向：`A / 活案牍 · 手作推理台`  
黄金切片：`case-home-roof-pig / 家字失踪案`  
基准视口：`390 × 844 CSS px`，同时覆盖 375 / 430 px

## 1. 设计结论

《大理寺字案录》不再表现成“古风文字视觉小说”，而是一张可以操作的字案桌。玩家的核心身份是录事：接卷、封存初判、验看证物、翻面查细节、比对字形、标记矛盾、连接证据、组合判词并落印归档。

人物对话仍使用 Galgame 层级，但只承担案情推进和证词取得。视觉重心随流程从人物转向证物，再转向玩家亲手构成的证据链。事实不因选择改变；选择改变证词展开顺序、可见补充信息和断案风格标签。

体验关键词：`明亮案房`、`可触摸纸面`、`克制朱批`、`证据吸附`、`有依据的成就感`。

明确避免：阴森刑堂、血迹滤镜、泛仙侠金光、廉价仿古纹理、伪古字、装饰性乱连线、用红色表示善恶、用高压倒计时逼迫判断。

## 2. 玩家循环

```text
领取案卷
→ 听取传言并封存初判
→ 在三条调查路径间自由选择
→ 取得证词／字形／语境证据
→ 翻面或聚焦检查已定义细节
→ 在案牍板上标出矛盾与关系
→ 选择证据组成可验证证据链
→ 选择判词并解释证据边界
→ 落印；错判则退回判前安全卷页
→ 查看初判／终判变化与来源
```

### 不变规则

- 全程只有 2–4 个预设选项，不出现自由文本判题。
- 关键证据不会因一次不理想的选项永久丢失。
- 初判锁定，只用于终局比较，不影响证据取得。
- 调查顺序自由；节点完成后仍可回看。
- 古文字只使用可追溯数据库材料和人工核验 SVG。
- 错判不死亡、不清档、不羞辱；返回最近的判前安全页继续核验。
- 沈砚只解释程序和证据方法，不透露参考判词。

## 3. 信息架构

### 第一层：案库

- `CaseShelf`：8 宗案卷、当前进度、已结状态与推荐案。
- `CaseCover`：传闻、争议字、预计时长、方法提示与来源状态。
- `CaseArchive`：最近一次初判／终判、引用证据、结案日期、重审入口。

### 第二层：查案

- `DialogueStage`：场景、人物、身份、证词、预设追问。
- `InitialVerdict`：初判选择、封存确认、保存反馈。
- `InvestigationDesk`：三条调查路径、证据数、结案门槛和当前目标。
- `EvidenceInspector`：证物正面、反面、放大热点、核验说明。
- `GlyphTimeline`：同一字的不同时代材料对照。
- `ContradictionCompare`：证词与材料并置，玩家选择不合之处。
- `ClueLedger`：事实、解释、待确认三组记录。

### 第三层：推理与归档

- `RelationBoard`：将已定义证据卡连接到有限关系槽。
- `DeductionChain`：选择 2–4 条证据组成“材料 → 解释 → 边界”。
- `FinalVerdict`：选择判词、选择矛盾解释、确认引用链。
- `VerdictSeal`：短落印反馈。
- `WrongVerdictRewind`：展示链条中不成立的一环并回到安全卷页。
- `ClosingDocument`：初终判比较、参考判词、争议说明、来源抽屉。

## 4. 视觉系统

### 4.1 色彩

| Token | 色值 | 用途 |
|---|---|---|
| `--night-ink` | `#101916` | 案房外框、沉浸场景 |
| `--official-green` | `#23463F` | 官署结构、人物名牌、已验证关系 |
| `--paper` | `#F3E7CB` | 主纸面 |
| `--paper-light` | `#FFF8E8` | 可操作卡、正文底 |
| `--paper-deep` | `#D8C39C` | 次级层、卷边 |
| `--cinnabar` | `#B54132` | 当前选择、朱批、落印 |
| `--mineral-blue` | `#477873` | 事实证据、来源标签 |
| `--amber` | `#B98543` | 待确认、提示 |
| `--ink` | `#182521` | 正文 |
| `--muted` | `#68736D` | 元信息 |

红色不表示“坏”或“错误”；它表示玩家当前正在批注或准备提交。错误使用文字、结构和琥珀色边界说明。

### 4.2 材质

- 大背景为深墨绿案房，不使用纯黑。
- 主操作层是平整暖纸；只在边缘使用轻微纤维和压痕，正文区域保持干净。
- 卡片阴影短、偏硬，模拟纸张叠放，不使用悬浮玻璃拟态。
- 木、卷轴和服饰只出现在美术层；交互控件不伪装成难辨认的历史器物。

### 4.3 字体与字形

- 标题：系统宋体栈，强调案卷感。
- 正文与控件：系统黑体栈，保证窄屏清晰。
- 案号与来源编号：等宽字体栈。
- 现代争议字可使用系统宋体大字；甲骨、金文、小篆禁止用现代字体冒充。
- 权威字形未就绪时统一显示“线框占位＋时代＋著录＋状态”，不出现仿写图形。

### 4.4 图标

图标使用 1.5–2px 单色线框 SVG/CSS：翻面、放大、连线、来源、回卷、收卷、已验证。普通功能图标不调用图像模型。

## 5. 页面骨架

### 案库页

顶部保留当前案卷进度卡；下方是纵向卷宗脊。每宗只突出争议字、案名、状态和 3–5 分钟，不把它做成手游关卡链。已结案件出现小型朱印，不使用金色星级。

### 案件封面

封面像一份刚从卷柜抽出的档案：现代字“家”由 HTML 渲染，右侧叠一张无可读文字的证物签和场景裁片。传闻放在引号框内，来源状态与虚构声明常驻页脚。

### 对话页

场景与人物占上方约 52–57%；对话纸层从底部压住人物下缘。2–4 个选择表现为批签，而不是等宽灰色按钮。选择后先出现 160ms 的朱批短线，再进入下一节点，防止快速双击重复提交。

### 调查台

三条路径不是地图坐标，而是三列或三张可移动案签：`坊间证词`、`字形旧档`、`语境案卷`。线只在玩家确认关系后出现；默认状态不预画装饰线。上方固定显示“关键证据 1/4”和结案缺口。

### 证物检查

证物遵循三层：

1. 原始资料或核验重构；
2. 玩家主动翻面／放大后看到的已定义细节；
3. 解释和产品提示。

热点由内容数据给出，不进行自由图像识别。图片失败时保留同尺寸文字卡，玩家仍可完成节点。

### 字形时间线

横向滑动只在字形数量超过两项时启用。每项常驻：时代、材料类别、著录、资源性质、能证明什么、不能证明什么。未完成的人工 SVG 明确显示“待核”，不参与强结论。

### 关系板

关系板不是无限画布。每案定义 2–4 个关系槽，例如：

```text
早期字形材料 ──支持──> 可观察构件
《说文》字条 ──补充──> 声符传统解释
坊间传言 ──越界──> 人人屋中养猪的社会史结论
```

玩家点选两张卡，再选择有限关系词。合法关系吸附成线；不成立的关系保留为虚线并给出证据边界反馈。

### 定案

定案分三步，始终可返回：

1. 选择 2–4 条证据；
2. 选择它们如何解释传言中的矛盾或越界；
3. 选择四类判词并确认。

提交前展示完整证据链。提交后先给结构反馈，再显示参考判词；不只弹出“正确/错误”。

## 7. 沈砚的四种介入

| 状态 | 作用 | 禁止 |
|---|---|---|
| 首次引导 | 说明“先记事实，再做判断” | 说出参考判词 |
| 冲突提示 | 指出两份材料不合 | 把矛盾等同于定罪 |
| 召回帮助 | 汇总当前目标、事实与操作 | 推进节点或改变选择 |
| 异常恢复 | 说明保留和失去的状态 | 把坏节点标为完成 |

头像按钮固定在非关键区；任何状态下不得覆盖证物、选项、判词或来源。

## 8. 响应式

### 375 px

- 页面左右安全边距 12px。
- 证据卡单列；关系板使用纵向三段结构。
- 对话区最高 48vh，长文内部滚动。
- 双操作按钮在文字过长时改为纵向。

### 390 px

- 作为设计基准；主画布宽 366px。
- 证物热点、选择签和底部操作区均至少 48px 高。

### 430 px

- 主画布最大 390px，居中；增加场景露出，不拉长正文行宽。
- 关系板可使用轻微错位叠卡，但关系词仍居中可读。

### 桌面

- 体验画布最大 480px；外围可显示案号、帮助和设计说明，不把移动布局强行扩为宽屏后台。

## 9. 无障碍

- 主操作触控高度不小于 48px。
- 所有选择用真实 `button`；翻面卡仍提供可见按钮与 `aria-expanded`。
- 连线玩法同时提供“选择证据 A / 选择关系 / 选择证据 B”的列表模式。
- 字形图提供等价文字描述和来源性质。
- 不只靠红绿区分状态；使用图标、边框样式和文字标签。
- 页面标题、说话人、正文、选项按阅读顺序排列。
- 焦点在抽屉、弹层、回卷后返回触发点。

## 10. 降级与恢复

- 角色图失败：保留场景、姓名签、身份与对话。
- 场景图失败：回退官署青渐变和文字场景牌。
- 非关键证物图失败：显示核验文字卡，可继续取得事实。
- 古文字 SVG 失败：显示著录、来源与人工描述，不把节点判为失败。
- 内容节点缺页：返回最近完整调查节点，缺页不写入完成状态。
- IndexedDB 失败：允许重试或临时审案；明确关闭后的数据损失。

## 11. 数据与组件边界

- 业务文案、选项、关系槽、证据热点和参考判词只来自 `src/content/content.json`。
- UI 只消费类型化 view model，不在 HTML/JSX 写死正式案件答案。
- 位图只通过稳定 asset ID 绑定；失败由统一 fallback 处理。
- UI 不引入自由文本、OCR、NLP、运行时 API 或设备图片能力。
- 用户存档只记录稳定 ID、状态、数值与时间，不保存图片或 Blob。

## 12. 验收

- 5 秒内能看出“汉字证据推理游戏”，不是普通 Galgame。
- 玩家每 20–40 秒至少完成一次有意义操作：选、翻、看、连、组合或盖印。
- 关系板上的每条线都代表内容数据允许的关系。
- 证据链能解释最终判词，而不是仅凑齐数量。
- 375 / 390 / 430 px 无横向溢出，底部安全区无遮挡。
- `prefers-reduced-motion` 下不依赖位移、翻转或震动传达结果。
- 所有古文字位均通过资源性质和来源门禁。

## 13. 生产实现记录 / 2026-08-26

- V2 已从 19 状态静态预览接入真实 React 案件引擎；八案卷宗架、接案、对话、初判、调查、证据、推理、落印与归档均沿用 `content.json` 图谱。
- 问案堂、字案房、坊间街角和三类人物使用稳定 asset ID；未知人物与图片失败统一使用语义 fallback，不出现浏览器破图图标。
- 沈砚身份统一为“大理寺录事”，只解释程序、当前目标和证据方法，不代替玩家作答。
- 帮助层实现首焦点、Tab／Shift+Tab 环绕、Escape 关闭和触发按钮焦点归还。
- 选择提交期间锁定控件，快速双击只推进一个节点；落印 720ms 后归档，减少动态模式直接呈现等价结果。
- 375／390／430 CSS px 浏览器实测 0 横向溢出、0 可见破图，主操作高度不小于 48px；完整首案结案与错误推理保留证据均通过。

## 14. 断案图鉴与分享卡

- 案卷柜与首页均可进入固定八格图鉴；已结案使用场景裁片、争议字和朱印形成藏品，未结案只显示封条及解锁状态。
- 图鉴只消费结构化最高分与 `caseVerdicts` 记录；不完整旧存档回退正式结论，并明确提示详细初判已恢复。
- 落印完成后自动进入图鉴并打开 3:4 战绩卡，不需要玩家再次寻找入口。
- 战绩卡展示案号、争议字、初判／终判、评价、分数、线索／证物数量和北京时间结案日期；不展示长判词或剧透式证据正文。
- 纯净模式隐藏所有应用控件，保留完整卡片安全区供系统截图；打印模式只输出卡片。运行时不创建或持久化图片、Base64、音视频或 Blob。
