# 视觉表现力提升与动效制作标准

日期：2026-09-06。目标：轻松可玩的小工具必须在构图、材质、动作反馈与镜头节奏上形成吸引力。本轮仅做诊断与制作方法，不修改工程或新增依赖。

## 1. 诊断证据与边界

本轮检查番茄小院的 `src/art.js`、`src/style.css` 与存档 `artifacts/mobile-390.png`；星风来信的 `src/scene/WindowLayer.tsx`、动效规范、存档 `release-assets/390-result.png` 和 `references/03-stars-entering.jpg`；鱼戏莲叶间的 `src/canvas/draw.ts`。

这是源码与已有图片审阅，未重跑当前页面、未完成动态录屏或真机性能测试。存档图片可能落后于源码，不能把两者当作同一版本的完整验收；也未逐个实玩排行榜竞品，不能推断它们采用什么技术。

| 证据 | 可以确认的现象 | 具体改进方向 |
|---|---|---|
| 番茄小院手机存档与 CSS | 导航、标题、计时器、输入和统计在上，植物场景排在下面；手机样式将双列顺序改为纵列 | 将植物与环境作为首屏主要画面，计时信息与当前操作嵌入场景边缘；统计移入次级入口，保持计时可读性 |
| 番茄小院 art.js | 植物由程序化 SVG 色块、路径和少量明暗组成 | 若继续走平面插画，应完善轮廓、笔触与风格一致性；若目标是绘本质感，制作同视角、同光源的分层原创植物素材 |
| 星风来信存档 | 窗框、月亮、帘线均存在，但光束的硬直边较明显；帘线细且相似 | 将体积光与地面投影分开调，建立宽窄亮暗不同的纤维簇，增加明确的受力与弯曲关系 |
| 星风来信源码与规范 | 已有多层渐变、柔光、星场深度、投影和分阶段时间线 | 不应声称没有做特效；需要把已有实现对照参考逐帧调到位，不能用函数和特效数量代替画面质量 |
| 鱼戏莲叶间 draw.ts | 已有 Canvas 鱼体曲线、摆尾、荷叶高光、水面线条及涟漪 | 若延续平面水墨风，先统一鱼、叶、背景的笔触；若要水下空间感，再验证局部折射与遮挡，不能无目的增加粒子 |

## 2. 制作顺序

改用：**明确画面目标 → 手机关键帧 → 分层素材 → 核心动作样板 → 接业务闭环 → 真机视觉验收**。

每个阶段以可查看产物推进，不以“高级、唯美、治愈、炫酷”之类描述作为完成证明。

1. 为单项目挑 3–5 个针对性参考：构图、材质、动作各有参考目的。只学习视觉原则与操作规律，不复制角色、标志或未授权素材。
2. 确认 390 × 844 的首帧、动作峰值帧、成品帧。至少同屏对照两种构图；不要先扩展所有页面。
3. 制作同光源、同视角的可动画素材；静态背景可以烘焙，主体、阴影、前景遮挡须按需要拆层。
4. 用真实渲染路线实现最困难的 3–5 秒互动。效果图只能证明美术方向，不能证明运行时效果。
5. 样板的画面、操作和帧率成立后，扩内容、收藏与导航。

已有星风来信已经有视觉参考和时间线，因此其重点是执行对照验收，不能再靠追加一份长规范代替打磨。

## 3. 场景的画面标准

- 首屏最醒目的是用户要把玩的物体；以场景占主要可用区域为目标，具体比例按项目验证。
- 标题、导航、表单和统计避免同时争抢主视觉；保留当前动作与必要状态。
- 明确一个主要光源，包括方向、颜色和软硬；高光、阴影与反射遵循同一空间关系。
- 建立背景、主体、前景的遮挡与明暗关系；不要把所有东西排在同一平面。
- 接触阴影解释物体“落在哪里”，投影解释光从哪里来。悬空时阴影位置、软硬与距离对应变化。
- 不同材质使用不同线索：玻璃依赖边缘反射与透射，果冻依赖厚度感与局部形变，毛绒依赖纤维方向与轮廓，纸依赖纤维和折边。
- 停止动画时画面也要完整；运动不能掩盖比例、轮廓和层次的问题。
- 强烈特效只围绕关键动作出现，普通状态留出安静时间。

## 4. 动画应描述物体如何受力

以果冻为例，不能把整个对象统一缩放当作完整软体反馈。建议先做以下可调动作原型，时间是设计起点，需试玩后调整。

| 阶段 | 建议起始时间 | 应有的变化 |
|---|---|---|
| 触碰 | 0–80ms | 触点附近先凹下，周围略鼓起；不能等长动画结束后才响应 |
| 持续施力 | 随手指持续 | 凹陷跟随位置，幅度设上限；主体底部受盘子约束 |
| 松手回弹 | 松手后约 0–450ms | 第一轮回弹最明显，后续振幅衰减；高光随曲面变化 |
| 余振 | 约 450–900ms | 顶部和底部错相轻晃，小装饰有滞后，逐渐稳定 |
| 再次触碰 | 任意时刻 | 从当前姿态继续响应，不突然跳回初始帧 |

脱模另设完整过程：拉开模边 → 局部脱离 → 整体滑落 → 接触盘子 → 压扁回弹 → 稳定。落盘时阴影收紧，声音落在接触时刻，镜头如需推进仅作小幅变化。

每个动效规格必须写清：触发、作用对象、受力方向、延迟、持续时间、结束状态、连续触发、取消和减少动态模式。星风来信等持续场景还要检查后台暂停与重播连续性。

## 5. 技术按目标选择

纯前端静态部署允许本地打包渲染和动画库；“无后端、无运行时 CDN”不等于只能使用简单 DOM 和 CSS。新增依赖仍按根规则先报告、由总控统一处理锁文件。

| 视觉需求 | 候选路线 | 注意事项 |
|---|---|---|
| 控件、抽屉、轻转场 | CSS / Web Animations；复杂编排再考虑时间线库 | 不为单个按钮引入整套动画依赖；动效与可读性一致 |
| 绘本场景、角色、局部形变和擦除 | Canvas 或 PixiJS，配合本地纹理、遮罩与局部滤镜 | PixiJS 的位移滤镜能偏移像素，可用于水波等效果；滤镜不能自动创造正确材质 |
| 果冻、玻璃球、旋转陶器等空间材质 | Three.js / WebGL，简单模型、环境光、受控材质 | Three.js 物理材质支持透射和清漆等特征，增加每像素成本；必须先测目标移动端 |
| 固定构图、精致插画 | 分层图片 + SVG/Canvas/CSS 的 2.5D 组合 | 适合避免全场景三维；背景、主体和接触阴影要拆开 |

技术事实参考：[Three.js 物理材质](https://threejs.org/docs/pages/MeshPhysicalMaterial.html)、[PixiJS 场景与滤镜](https://pixijs.com/8.x/guides/components/scene-objects)、[web.dev 动画性能指南](https://web.dev/articles/animations-guide)。

建议果冻先对比一个二维形变样板和一个简单三维透射样板的实际手机效果再定路线；毛绒优先纹理与遮罩；雪景球依据固定视角还是需要真实旋转决定 2.5D 或三维。不要三个项目套同一种技术。

## 6. 素材生产必须服务互动

美术生成输入至少包含：目标尺寸、视角、主光方向、风格、对象比例、背景是否透明、拆层清单与可动关节/区域。

交付不止一张封面，应包括：

- 干净背景；
- 可操作主体或模型；
- 前景遮挡；
- 接触阴影与高光的处理方式；
- 所需纹理及重复方式；
- 动作关键状态或骨骼/网格约束；
- 同一风格的小型配件；
- 来源、许可与生成记录。

AI 图片可以作为方向稿、纹理和原始素材候选。拆层后需要处理透明边缘、重绘遮挡区域、透视与缩放一致性；不能承诺一张生成图直接变成同等质量的可交互场景。

## 7. 视觉验收与性能验收分开

| 维度 | 验证方式 |
|---|---|
| 构图 | 首帧无讲解时主体和操作入口清楚，必要 UI 不盖住它 |
| 材质 | 暂停看，玻璃、毛绒、纸、果冻是否有区分，不只是不同颜色 |
| 动作 | 逐帧检查蓄力、接触、形变、回弹、余振；连续操作不跳帧 |
| 输入反馈 | 静音也可理解动作；触控取消、滑出和重复触碰可恢复 |
| 视觉一致性 | 背景、主体、配件和 UI 的视角、线条与光源不冲突 |
| 流畅度 | 在目标手机测渲染耗时、拖动延迟与长运行；60fps 约 16.7ms/帧是预算目标，不能当未测的成绩 |
| 性能降级 | 先减少背景粒子、滤镜分辨率与设备像素比，再减少次要动态，保留核心操作反馈 |
| 兼容性 | 测小红书内实际运行环境；WebGL 不可用或上下文丢失时有可用反馈与恢复/降级路径 |
| 减少动态 | 缩短大位移、旋转和镜头变化，保留状态变化；不强制频闪、抖屏 |

项目既有 `pnpm lint && pnpm test && pnpm build` 仍需通过，但它们不证明美观。另验 375 / 390 / 430 CSS px、非零模拟安全区；顶部 sticky/fixed 控件和锚点偏移叠加 `var(--safe-area-inset-top, env(safe-area-inset-top, 0px))`。

## 8. 下一步建议

暂停扩大候选数量，先做一个可对照的视觉样板。

- 若验证新玩法：优先果冻，只做一只模具、一只果冻、一张盘子，覆盖静态材质和触碰/脱模。
- 若先改善已有成果：优先番茄小院的首屏构图，把植物放回视觉中心；再处理生长动画和风格素材。
- 星风来信按已有参考重做关键帧对照，分别验构图、帘线材质、光束和投影，避免笼统说“增加氛围”。

在视觉样板上直接比较改前改后截图和短录屏，通过后再推广到其他页面。不要仅增加文档数量或动效代码数量。
