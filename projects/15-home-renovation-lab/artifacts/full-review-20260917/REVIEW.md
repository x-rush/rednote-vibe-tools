# ROOMISH 整体交互审查

日期：2026-09-17。对象：http://127.0.0.1:4311/ 当前预览。

结论：不建议直接作为稳定交付版本。共确认 4 类问题，其中草稿处理包含两种用户可见故障。此次仅审查，未修改业务源码、构建产物或发布包。

## 1. P1：门的可编辑状态与高亮提示脱节

复现：默认方案轻点可见门洞，确认选中高亮；打开灵感，应用一种风格；关闭操作台。

两次独立浏览器上下文均出现：操作前 selected.openingId 存在且 scene.doorPreview.visible=true；操作后同一 openingId 仍保留，但 scene.doorPreview 不再可见。用户看不到门仍处于可拖动状态。结合已有按下处理条件，这会保留门拖动入口，违背“有明确选中提示才能移动”的规则。

涉及：src/app.js 的 refresh、choose、门 pointerdown；src/scene.js 的 rebuild、select。

证据：door-highlight-after-style-1.png、door-highlight-after-style-2.png。使用实际触摸点选和实际射线命中，只注入只读状态观察，不替换命中函数。

## 2. P1：关闭的草稿仍劫持全局操作，且会隐式保存

复现 A：自建户型，打开房间设置，清空宽度，点 X 收起，再打开菜单（桌面打开清单）。面板重新出现并显示尺寸错误，目标菜单没有打开。

复现 B：房间宽度初始为 5，输入 6，不点完成或应用，点 X 收起，再打开菜单。localStorage 中宽度在收起后仍为 5，打开菜单后变为 6。并非只是显示输入，而是实际保存了修改。

竖屏、模拟横屏、真实横屏布局和桌面均独立复现两次。源于全局操作前的 saveRoomDraft，与“收起保留草稿、完成负责保存”的承诺不一致。

涉及：src/app.js 的全局 click 分发、saveRoomDraft、关闭面板的提前返回分支。

证据：final-flows.json；final-portrait-draft-invalid-other-tools-2.png；final-portrait-draft-not-implicitly-saved-2.png；其余方向对应截图。

## 3. P1（宿主适配风险）：右上角菜单仍占用宿主按钮区域

非零模拟系统安全区 28px 下，375 / 390 / 430 宽竖屏的 mobile-menu 均与右上方宿主覆盖矩形相交。例如 390 宽时，菜单位置为 x=338、y=35、44×44 CSS px；模拟宿主区域为 x=342..378、y=48..84。844×390 真实横屏布局也相交。

这表明共享规则尚未完整落实到页面布局。宿主矩形取保守模拟值，未声称是真机 SDK 测量。用户此前提供的实际宿主截图也显示同一区域重叠。模拟横屏在本次首页矩形条件下未检出相交，不代表其他页面状态全部安全。

涉及：src/style.css 的 topbar/top-actions/mobile-menu-button 与横竖屏规则。

证据：results.json 的 host-overlap 记录；375-portrait-host-overlap.png、390-portrait-host-overlap.png、430-portrait-host-overlap.png、844-natural-host-overlap.png。

## 4. P2：Escape 的退出行为不统一

普通清单弹窗可用 Escape 关闭，modal-open 也正确移除；但房间属性面板在 Escape 后仍显示。390 竖屏布局和 1280 桌面分别复现两次。此项主要影响桌面预览、电脑录制及外接键盘，不等同于手机系统返回键问题。

涉及：src/app.js 的 keydown Escape 分支，未复用面板关闭状态。

证据：flows.json；flow-1280-desktop-escape-closes-settings-2.png。

## 测试误报与覆盖缺口

- results.json / flows.json / native.json 为原始探索日志，不是缺陷清单。早期脚本误用了手机隐藏的应用按钮、跳过横屏装修抽屉或房间设置菜单、在桌面弹窗打开时选择了后方同名按钮。这些超时已排除，不作为产品故障。
- 最终 final-flows.mjs 使用可见抽屉入口，并优先点击当前对话框中的按钮；相关保存与清单流程通过。
- 原生触摸探索中有混用鼠标与触摸后的导航超时。单独使用纯触摸打开装修操作台并切换户型，两次通过，因此暂不认定为点击失效产品缺陷。
- 旧 interaction.mjs 仍要求门可拖到相邻墙、添加后保留旧取消入口，与已确认的新需求相反。旧报告不能作为当前版本的新验收证据。
- 未完成小红书真机返回按钮、软键盘、相册权限与导出桥接、WebGL 降级、长时间帧率及内存、所有家具实际拖动边界与持久化故障的全量验收。
- 未重新构建或打包。本报告针对当前预览，不代表旧交付 ZIP 已包含所有近期修改。

## 优先级结论

发布前首先处理门的选中可视状态、草稿与全局导航的耦合、宿主按钮区域；随后统一关闭与 Escape。此次没有把单元测试通过等同于整体体验通过，也没有宣称全部真机场景已验收。
