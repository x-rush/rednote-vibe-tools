目标是实现一个手机竖屏、纯前端静态运行的互动动画：

1. 初始是深蓝色房间、关闭的窗户、窗外月亮和星空，以及覆盖窗口的发光线帘。
2. 内置中文短句快速纵向轮播，中间一句清晰，上下句虚化。
3. 用户只点击一次；点击后轮播立即产生反馈并逐渐减速，在 1.0–1.4 秒内随机停下一句。
4. 停下后保留 0.6–0.8 秒阅读时间。
5. 随后不要求任何操作，风自动吹动并掀开帘子。
6. 第二阵风使窗框轻颤，并把窗扇向室内自动吹开。
7. 月光随着窗户开启进入房间。
8. 窗外的星尘、拖尾光粒和主角星穿过窗口，被风吹进室内，再围绕选中的句子稳定成结果画面。
9. 结果只提供“再听一次星空”，点击后完整重置并重新轮播。

构图不能做成普通正面窗户。参考图最重要的视觉特征是侧面斜视：镜头位于窗户左前下方，窗户处于画面上半部偏右，窗框和横梁带明显纵深透视；风从窗外向室内压入，窗帘形成从顶部固定点向左下和前景甩出的长弧面，窗扇向观看者方向旋开。星星沿着倾斜的月光和风道，从窗框后方穿过开口，飞向画面左下方的室内空间。请在写复杂动画前先用静态构图验证这个侧视透视。

以下是不可变的硬性要求：

- 不允许用户输入文字。
- 不允许用户手动滑动、拖动或控制窗帘和窗户。
- 点击选句后，帘子和窗户必须全自动演出。
- 星星必须明确来自窗外。每颗主角星的起点位于窗框后方，窗户打开达到阈值后才能穿过窗口裁切区域进入室内。
- 不得在室内突然淡入粒子来冒充“星星被吹进来”。
- 不得把主体动画做成星星从室内飞向窗外。
- 选中的句子保持清晰稳定；文字不变成星星，也不被风吹走。叙事是星星来到这句话身边。
- 不添加输入框、账号、积分、签到、排行榜、抓星星小游戏、分享弹窗、多页导航或额外产品功能。
- 无后端、无运行时 CDN、无必需外部 API；不调用麦克风、陀螺仪、摄像头、振动或未经确认的设备 API。
- 所有业务句子必须放在 `src/content/content.json`，至少纳入 `CONTENT_SPEC.md` 的 60 条内容并提供稳定 ID、类别和必要元数据。

工程实现要求：

- 使用仓库现有且无需新增依赖的技术方案。
- 建立清晰的有限状态机：`loading → spinning → slowing → selected → wind → window-opening → stars-entering → result → resetting`。
- 同一阶段只允许启动一次；处理快速连点、动画中点击、重播连点、页面失焦/恢复和刷新。
- 最近 8 次结果不重复；不让用户误以为能精准点中点击瞬间的句子。
- 帘子应表现为约 50–90 根独立发光细线，顶端固定、底端摆幅更大、风动具有横向传播和不同延迟，不能整片同步平移。
- 星粒子分为星尘、拖尾粒子和主角星三层；性能回退优先减少粒子数，不牺牲进入方向。
- 实现 `prefers-reduced-motion`，但简化版仍必须表达“自动开窗、星星从窗外进入”。
- 音效只能作为增强，并在用户点击后尝试启用；音频失败或静音不得阻塞体验。
- 所有顶部固定控件叠加 `var(--safe-area-inset-top, env(safe-area-inset-top, 0px))`，并用非零安全区测试。
- 移动端优先，必须验证 375、390、430 CSS px；不出现横向滚动、文字裁切或关键主体出屏。
- 不使用外部图片来代替核心动画。窗户、帘线、月亮、星星、光束与环境应由本地 HTML/CSS/SVG/Canvas 等实现。

请按 `IMPLEMENTATION_PLAN.md` 分阶段工作。先完成可验证的静态构图和状态机，再实现复杂动效；不要一开始就堆粒子。为内容规则、随机去重、状态转换、连续点击锁定、重置清理、reduced-motion 和“窗户打开前主角星不能进入室内”编写测试。不得删除或削弱测试来通过检查。
