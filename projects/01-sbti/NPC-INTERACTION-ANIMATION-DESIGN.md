# SHBTI 闻山陪行、中文维度与交互动画设计

状态：对话方向已确认，等待书面设计复核

日期：2026-08-25

范围：`projects/01-sbti`

## 1. 目标

在不改变题库、计分、题序和十六种结果映射的前提下，让闻山真正承担“山海司守卷人”的陪行职责，并用卷册、落印、收卷和显形动画增强测评的仪式感。

本轮同时解决两项表达问题：

- 用户不应看到缺少解释的内部维度代码或结果代码。
- `SHBTI` 必须明确指向本产品，而不是依赖用户猜测或与其他同名缩写混用。

## 2. 正式品牌定义

- 正式名：`SHBTI｜山海兽格测试`
- 英文释义：`Shan Hai Beast Temperament Indicator`
- 中文解释：`山海异兽性格倾向指标`
- 产品边界：娱乐性自我探索工具，不是专业心理测评。

`SHBTI` 是唯一允许在主界面保留的英文缩写。英文释义只出现在“关于测试”或完整说明区域，不进入答题、显形、结果和分享的主要阅读路径。

首页、测前说明和结果页底部需要能找到正式名、中文解释与产品边界。首次出现时使用完整正式名，不以单独的 `SHBTI` 替代产品名称。

## 3. 全中文用户表达

内部维度代码与四字母结果代码继续用于程序计分、存储、测试和资源映射，但不得出现在用户可见界面、无障碍名称、分享文案或动画文字中。

四个维度统一显示为：

1. 与世界相遇：应世 / 隐世
2. 理解线索：察微 / 观象
3. 衡量选择：衡理 / 感应
4. 面对变化：守形 / 化生

结果身份只显示“异兽名 · 中文兽格名”，例如“陆吾 · 山司型”。历史记录、相邻兽格、分享卡和图片替代文字遵循同一规则。

显形阶段依次展示四枚中文卷印。每枚卷印包含维度标题和两侧中文倾向，不显示任何内部代码；本次真实偏向在展开兽志后呈现，显形动画不改变结果计算时机。

## 4. 闻山陪行原则

### 4.1 有存在感，但不干扰作答

闻山可以持续出现在流程中，但不对单题选择表示赞同、惊讶、正确、危险或人格判断。他只说明卷册状态、操作方式、隐私边界和阅读方法。

强制停顿只保留在首次引导、章节交接和最终显形。普通答题中的闻山反馈必须在原位置更新，不额外弹窗，不阻止继续作答。

### 4.2 异兽仍是结果主角

闻山在首页是品牌锚点，在答题中是陪行角色，在结果页退居解释入口。结果页不得把闻山与结果异兽做成等权双主角。

### 4.3 不模拟自由聊天

“问闻山”使用三项预设问题与对应回答，不提供自由输入，不调用后端或外部接口，也不保存用户询问记录。

## 5. 闻山触点

### 5.1 首页

闻山主图继续位于夜间案房一侧。台词按状态派生：首次入山、已有进度、已有最近结果。点击闻山打开三句首次说明或“关于本测试”，但不与主按钮竞争。

### 5.2 测前说明

测前说明新增紧凑品牌定义区，明确正式名、中文解释和娱乐性边界。英文释义只放在该说明的展开内容中。

### 5.3 答题常驻守卷席

每题标题区下方保留紧凑闻山席位。台词由当前章节位置和选择状态派生：

- 本卷前段：提示按更自然的行动落笔。
- 本卷中段：只报告行程，不评价已选内容。
- 本卷末页：提示即将收卷。
- 尚未选择：提醒四种行动没有高下。
- 已经选择：说明朱印已经落下，仍可换签修改。
- 返回旧题：说明旧印仍可更换，最终只记录确认后的行动。

选择行动后，闻山台词在原位置更新；不自动打开卷页，也不朗读与选项倾向有关的反馈。

### 5.4 问闻山

点击答题页闻山打开统一卷页，提供三个可点选问题：

1. 这一题应该怎么选？
2. 落印以后还能修改吗？
3. 答案会保存到哪里？

卷页一次展示一个回答。切换问题不关闭卷页；关闭后焦点回到闻山入口。选择的问题只存在于组件内存，不写入测评状态或本机存储。

### 5.5 章节交接

第 1、7、13、19 题前由闻山递卷；第 6、12、18 题确认后由闻山收卷。过场可以跳过，返回上一题后不得重复已经完成的收卷。

### 5.6 最终显形

第 24 题完成后，闻山先合卷，再依次展开四枚中文维度卷印，最后交出兽志。用户可以直接跳到“兽志可展开”的语义终态。

### 5.7 结果页

结果异兽稳定显示后，闻山以次级入口出现。点击后提供“三问闻山”：

1. 四种倾向应该怎么读？
2. 为什么会有相邻兽格？
3. 古籍记录和产品创作如何区分？

回答仍从内容包读取。结果页和分享卡不显示内部结果代码。

### 5.8 异常恢复

内容损坏、存档已清除、存储不可用和本次写入失败继续使用不同闻山台词与动作。恢复页必须如实说明保留了什么以及刷新后的影响。

## 6. 交互动画

### 6.1 首页夜案

- 山雾缓慢横移，案灯使用低幅度明暗呼吸。
- 闻山主图保持稳定，只让外缘墨气轻微浮动，不制作循环眨眼或夸张身体动作。
- 台词变化采用卷签展开与墨迹显字。

### 6.2 行动签与朱印

- 点击行动签后，签条上移 2–3px，边缘墨线由左向右显现。
- 朱砂印以轻微缩放和 2–4 度偏转落下，不使用弹簧跳动。
- 更换选择时，旧印先淡退，新印再落下。
- 主按钮文字从“请先选择一种行动”切换为“落印，下一问”时使用短距离揭帘，不改变按钮尺寸。

### 6.3 闻山守卷席

- 台词更新使用 120–180ms 墨迹交替，不移动整个页面布局。
- 已选状态下，头像外缘出现一次克制的朱砂印环反馈。
- 点击闻山时卷页从底部展开，背景进入不可交互状态，焦点落在标题。

### 6.4 四卷进度

- 当前卷印轻微提亮。
- 完成一卷时执行一次压印动画，并保留“已完成”文字或图形。
- 递卷与收卷使用纸页横移、卷轴合拢和印记显现；总时长不超过 650ms。

### 6.5 中文维度显形

- 四枚维度卷印依次展开：维度标题先出现，两侧中文倾向随后显现；本次偏向留到兽志结果页说明。
- 整段标准动画不超过 1.4 秒，并始终提供跳过动作。
- 动画结束后出现明确的“展开兽志”按钮，不自动跳转。

### 6.6 结果显影

- 页面从夜墨过渡到暖纸，异兽图使用墨色遮罩淡出形成显影效果。
- 结果标题和异兽图稳定后，闻山解释入口才淡入，避免争夺首屏注意力。

### 6.7 减少动态

启用减少动态时：

- 取消位移、缩放、雾气循环和连续显影。
- 行动签、卷印、中文维度和结果页直接进入最终视觉状态。
- 所有状态文字、按钮和焦点顺序保持不变。

## 7. 内容与状态结构

所有品牌定义、闻山问题、回答和状态台词继续放在 `src/content/content.json`。

内容契约需要覆盖：

- 正式品牌名、英文释义、中文解释和产品边界。
- 答题前段、中段、末页、未选、已选与返回修改台词。
- 答题帮助的三个问题、标签和回答。
- 结果帮助的三个问题、标签和回答。
- 四个中文维度的用户显示名称与两侧中文倾向。

纯派生函数根据页面、章节内位置、是否已选择和是否返回旧题，决定当前闻山台词。帮助主题选择、动画步骤和卷页开关属于瞬时组件状态，不进入 localStorage。

计分、题库选择和结果映射继续使用现有内部代码，不改变存储 schema。显示层通过内容定义将内部结果映射为中文名称。

## 8. 组件边界

- `GuidePresence`：显示闻山头像、身份、当前状态台词和召回入口。
- `GuideTopicSheet`：复用现有卷页焦点与图片降级能力，增加预设问题切换。
- `deriveQuizGuideLine`：纯函数，决定答题中的陪行台词。
- `ChoiceSlip`：负责行动签、墨线和朱印状态。
- `VolumeProgress`：负责当前卷与完成压印动画。
- `RevealSequence`：消费中文维度显示模型，不直接渲染内部代码。
- `ResultPage`、`HistoryPage`、分享预览：只消费中文结果身份。

不得把以上状态统一堆入 `App.tsx`，也不得复制另一套模态焦点或图片降级逻辑。

## 9. 错误与降级

- 新交互不得依赖新增美术资源才能操作。
- 闻山正式图失败后继续使用 placeholder，再失败使用 CSS 墨影。
- 动画初始化异常时直接显示语义终态。
- 内容缺少任一品牌字段、中文维度字段或闻山帮助主题时，内容校验必须失败，不能静默显示内部代码。
- 结果映射缺失时进入内容恢复页，不能把内部结果代码当作替代标题展示。

## 10. 测试与验收

### 10.1 自动化

- 校验品牌正式名、英文释义、中文解释和产品边界均存在。
- 校验四个中文维度及八个中文倾向完整。
- 校验答题和结果的三项闻山帮助完整且 ID 唯一。
- 覆盖前段、中段、卷末、未选、已选和返回修改台词派生。
- 覆盖帮助主题切换、Escape、焦点循环和关闭后焦点归还。
- 覆盖标准动画可跳过与减少动态直接到达终态。
- 用户可见页面的渲染测试不得出现内部维度代码或四字母结果代码。
- 现有题库、计分、存储、章节回退和十六型可达性测试继续通过。

### 10.2 浏览器

在 375、390、430 CSS px 下验证：

- 首页、答题、章节交接、显形、结果和恢复均无横向溢出。
- 闻山常驻席位不挤压题干，不遮挡行动签和底部按钮。
- 三项答题帮助和三项结果帮助均可由键盘完成。
- 行动签落印、更换选择、卷印完成和中文维度显形均有明确终态。
- 减少动态后没有依赖动画的死路。
- 正常资源会话为零控制台错误和警告。

## 11. 美术资源交付

当前实现继续使用已有闻山主图、头像和 placeholder。新增姿态不是运行前置条件。

功能完成后，在项目根目录输出 `ART-REQUEST.md`，记录可选增强资源。用户后续授权 Codex 直接生成，因此递卷与阅卷两张姿态已经在角色一致性、手部结构、卷面无字和移动端裁切初检后接入；守案与异常安抚仍是可选项。文档至少包含：

- 守案、递卷、阅卷、异常安抚四种闻山姿态。
- 每项资源的文件名、用途、使用页面、画布尺寸、透明背景与安全区。
- 与现有闻山保持脸型、帽冠、交领、配色和工笔纸墨风格一致的约束。
- 完整生成提示词、负面提示词、验收清单和 WebP 体积预算。
- 资源缺失时继续使用现有主图或头像的明确 fallback 映射。

资源只有在实际生成、人工复核并接入 manifest 后，运行时代码才可引用；当前两个新路径均已落盘并登记。

## 12. 范围边界

- 只修改 `projects/01-sbti`。
- 不新增依赖、后端、外部 API、运行时 CDN、自由聊天、剧情分支或新计分维度。
- 不修改其他项目、根配置、锁文件、`docs/` 或 `prep/`。
- 美术资源只按用户后续明确授权生成；不自动格式化既有 CRLF 文档，不提交或推送。
