# 小红书小工具：八项目总实施路线

## 1. 目标与边界

本目录包含八个纯前端小红书小工具的实施规划。所有项目遵循以下硬约束：

- 构建后上传静态文件，不依赖自建后端、数据库、登录和云函数。
- 核心体验所需文字、JSON、图片、字体、音频全部随项目打包。
- 用户状态根据数据规模使用内存、`localStorage` 或 `IndexedDB`；禁止把用户图片和不可控的大体积文件写入本地数据库。
- 不在运行时调用大模型、图片生成或远程知识库。
- 不把摄像头、麦克风、定位、系统分享、文件下载等兼容性不稳定能力作为核心路径。
- 移动端竖屏、触屏优先；首屏必须在 3 秒内说明“这是什么、怎么玩”。
- 每个首发版必须自身完整；“持续迭代”只能扩展内容，不能代替首发的闭环。

## 3. 共用技术母版

推荐使用 React + TypeScript + Vite；如构建包限制或兼容性测试不理想，可降级为原生 TypeScript。不要引入路由、状态管理和 UI 框架，除非某项目确实需要。

```text
src/
  components/       通用按钮、进度条、卡片、弹窗、来源抽屉
  engines/          quiz、rule、collection、event、weightedRandom
  storage/          本地存储、版本迁移、清空数据
  content/          单一 content.json 内置内容包
  screens/          页面级组件
  theme/            每个项目独立设计令牌
  utils/            种子随机、资源预加载、格式化、校验
public/
  images/
  audio/
  fonts/
```

### 共用模块

- `AppShell`：安全区、最大宽度、错误边界、横屏提示。
- `StartScreen`：一句话价值、预计时长、开始按钮、资料/隐私入口。
- `ProgressBar`：题目、案件、天数等进度。
- `ChoiceCard`：支持键盘和触屏的选择卡。
- `ResultCard`：适配手机截图的结果区域；不依赖浏览器下载。
- `SourceDrawer`：史料名称、机构、链接文字、访问日期、许可。
- `LocalDataControls`：查看、重置、清空本地数据。
- `seededRandom`：每日内容、固定局面和可复现测试。
- `contentValidator`：构建时检查 ID、空字段、重复项、资源路径与来源。

## 4. 全局体验规范

- 点击目标最小 44×44 CSS 像素。
- 正文建议不小于 15px；关键按钮 16px 以上。
- 动画遵守 `prefers-reduced-motion`；低性能设备可关闭粒子和模糊。
- 音频必须由用户首次点击后启动，并提供静音按钮。
- 关键状态刷新后可恢复；数据结构带 `schemaVersion`。
- 所有随机结果可解释，避免“为了随机而随机”。
- 历史类内容区分“原始资料”“主流解释”“产品创意演绎”。
- AI 美术需统一风格、尺寸、视角和色板；不得冒充真实文物原图或古籍原图。

### 用户数据与图片边界

- 八个首发 MVP 不提供用户图片选择、上传、缓存或本地保存功能。
- 不把用户图片转成 Base64 写入 `localStorage`，也不把不可控的图片 `Blob` 写入 `IndexedDB`。
- `localStorage` 保存小体积、读写简单的状态：设置、当前进度、答案、任务 ID、收藏状态和有限长度文字。
- `IndexedDB` 可保存数量较多的结构化记录：经营事件历史、多份存档、图鉴明细、案件节点进度、冒险日志和版本迁移数据。
- 所有可保存字段设置长度、条数和版本上限，并提供删除、清空和损坏数据恢复入口。
- 本地数据可能因清理缓存、卸载应用、系统存储回收或运行环境变化而丢失，产品不承诺永久保存或跨设备同步。
- 项目所需文物、异兽、角色、背景和图标均由项目方审核后随静态包内置，不接收用户图片作为内容源。

### 本地存储选择规则

| 情况 | 推荐 |
|---|---|
| 单一设置、当前进度、少量答案 | `localStorage` |
| 多条记录、需要索引查询、独立对象更新 | `IndexedDB` |
| 用户图片、视频、音频或不可控 Blob | 禁止本地持久化 |
| 只在当前页面使用的临时状态 | 内存 |

首发默认优先 `localStorage`；只有数据条数、查询或迁移需求明确时才使用 `IndexedDB`，不为了技术完整而引入。

## 5. 资源与版权台账

每个项目的 `content.json` 内包含 `sources` 字段，资料项至少包括：

```json
{
  "id": "source-001",
  "title": "资料或素材名称",
  "creator": "作者/机构",
  "url": "来源地址",
  "license": "CC0/CC BY/自有/已授权/仅事实引用",
  "accessedAt": "2026-08-23",
  "usage": "使用位置",
  "notes": "是否裁剪、重绘、调色或合成"
}
```

赛事存在奖金和推广价值，音频优先自录、CC0 或明确商用授权；CC BY 必须署名；默认不使用 CC BY-NC。每个 AI 生成资源保存提示词、生成日期、工具和人工修改说明。

## 6. 内容生产流水线

1. 人工确定数据结构和 5-10 条黄金样例。
2. Codex 按样例扩写候选内容。
3. 自动检查字段、重复度、长度、禁用词和资源缺失。
4. 人工审核事实、语气、趣味性和安全性。
5. 将通过审核的内容标记为 `approved: true`，构建仅打包已审核内容。
6. 真机试玩，记录中途退出点、误触点和结果分布。

## 7. 完成定义

每个项目只有满足下列条件才算完成：

- 从首屏到结果/结局形成闭环。
- 无网络时核心流程仍可运行。
- 至少完成一轮真机竖屏测试。
- 刷新、返回、切后台后状态符合预期。
- 无资源 404、控制台错误和不可恢复白屏。
- 有空状态、数据损坏恢复、清空数据和静音状态（如有音频）。
- 历史/知识项目拥有可见来源说明。
- 有适合录制 15-30 秒参赛视频的“高光时刻”。

## 8. 推荐执行闸门

每个项目依次经过：`内容样例通过 → 可玩原型 → UI 定稿 → 批量内容/美术 → 真机 QA → 上传包 → 参赛笔记`。当前项目未过真机 QA，不进入下一项目的批量生产阶段。

### 单项目标准任务拆分

每份规划开始实施时，统一拆成以下可并行工作包；其中产品定义和数据契约先完成，后续工作才真正并行：

1. `产品/内容`：锁定 MVP、数据字段、黄金样例、事实与安全审核标准。
2. `UI/交互`：输出信息架构、关键页面、设计令牌、状态与动效说明。
3. `美术/声音`：建立风格基准图，再批量生成并完成资源台账和压缩。
4. `前端`：搭建数据驱动闭环、存储、错误恢复和性能降级。
5. `内容扩写`：根据黄金样例批量生成，经过自动校验与人工审核后入库。
6. `QA`：桌面浏览器初测、移动端尺寸测试、真机小工具测试、回归测试。
7. `发布`：构建 ZIP、上传检查、参赛标签、封面、15-30 秒演示脚本。

### 每个项目交给 Codex 前的输入清单

- 本规划文档路径。
- 已批准的 5-10 条内容黄金样例。
- 一张批准的视觉风格基准图或明确设计令牌。
- 可用资源及其许可台账。
- 明确的“本轮只做什么/不做什么”。
- 验收设备尺寸、构建命令和上传包要求。
