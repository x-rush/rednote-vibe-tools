# 07 · 依赖关系与复用地图

## 1. 包依赖图

```text
pnpm workspace（单一 pnpm-lock.yaml，由总控维护）
│
├─ projects/01..11（React 批次）
│    dependencies:  react, react-dom        （react@19.2.8）
│    devDependencies: vite(@8.2.2), typescript, vitest, oxlint, @vitejs/plugin-react, @types/*
│    │
│    └─ vite 8 基于 rolldown → 工作区 .pnpm 存储中出现 rolldown@1.2.5
│
├─ projects/12..17（原生 JS 批次）
│    dependencies:  （空）
│    devDependencies:（空）—— 纯 Node 内置模块（fs/path/http/child_process）
│
├─ projects/18..25（TS 批次）
│    dependencies:  （空）
│    devDependencies:（空）
│    └─ tools.mjs 以绝对路径调用工作区 .pnpm 中的 rolldown@1.2.5 与 typescript@6.0.3
│       （这两个包由 React 批次的依赖图传递安装；仓库对此的约定见下）
│
└─ 25-moonfall 例外：vendor/p5.min.js 本地内置（不走 npm、不走 CDN）
```

**关键结论**：

1. **项目之间零运行时依赖**（`linkWorkspacePackages: false`）——任何一个项目目录单独拷走都能构建上传。这是刻意的交付约束，不是技术债。
2. **"共享代码"靠复制同构文件**：`content/validate.ts`、`storage/storage.ts`、`random.ts`（PRNG）、`conditions.ts`（条件引擎）等模式文件在多个项目里各有一份演化副本。修 bug 时要意识到同类文件的存在，但**并行开发规则禁止跨项目修改**——由总控决定是否同步。
3. **18-25 依赖工作区存储的 rolldown/typescript**：意味着根目录必须先 `pnpm install`（React 批次装好后 .pnpm 里才有这两个包），单独 checkout 18-25 无法构建。新增依赖（如升级 rolldown）必须走总控改锁文件。

## 4. work/ 与 prep/ 的角色

- [work/](../../work/)：01-04 项目时代的浏览器 QA 产物（截图、`check-*.mjs`、渲染脚本）。新项目不再往这里放东西（18+ 自带 `qa/` 与 `.cache/`），但其中的检查脚本是"无头浏览器验证"的早期范例。
