# 一庭春慢 v5 设计提案：自由造景与抽屉操作

状态：2026-09-21 研究与设计提案，尚未修改运行代码、存档或交付包。

## 目标与参考

用户需要自由、美观、操作方便的园林；面板可收起，随时看全景。保留离线收益、高阶景物更高产出的玩法。独立作品，不与《兰香别枝》联动。

官方资料：
- Tiny Glade：https://store.steampowered.com/app/2198150/Tiny_Glade/ 。无网格建造，路径与建筑等相互作用并自动适配细节。借鉴宽容的编辑与景观衔接；不承诺复刻其三维程序化建筑。
- Townscaper：https://store.steampowered.com/app/1291340/Townscaper/ 。在不规则网格上放置色块，算法按组合生成房屋、拱门、桥等。借鉴少量操作产生连贯外观；它并非无网格。
- SUMMERHOUSE：https://store.steampowered.com/app/2533960/SUMMERHOUSE/ 。小规模自由建造，以环境氛围、生活细节和轻松创作为核心。借鉴素材统一和小景叙事。

以下交互是本项目设计推导，不声称上述游戏均使用相同抽屉或手势。

## 当前根因

1. 园林只是页面中的一个窗口，收益、选中详情、方案等在上下堆叠，编辑还会缩小窗口。
2. 四庭各自划分落位区；可见土地与实际可用范围不一致，内边界影响自由布置。
3. 植物视觉冠幅与落地占地不应同等限制；固定预览圈无法准确解释当前碰撞。
4. 固定底图加独立景物不足以构成完整园林；缺少路、水岸、围墙等连接元素。

## 画布与抽屉

- 园林占满应用可视区，页面本身不纵向滚动；目录和详情只在抽屉内部滚动。相机不随抽屉开合改变缩放或世界中心。
- 手机底部统一操作坞：添景、整理、园务、赏园。收益小标仅显示金额与速率，详情归入园务。收藏、故事、目标归入抽屉，不再常驻。
- 抽屉三档：收起仅保留约 56–64px 操作坞；半开约可用高度 35%；展开最高约 75%。尺寸为初始设计参数，需小屏实测调整。拖动把手、点击收起均可用，不能只靠手势。
- 选择素材后自动收至半开或操作坞；底部出现轻量放置条。材质、样式、尺寸等放入可展开详情。始终只开一个主抽屉。
- 赏园收起面板、收益、选中框与编辑辅助线；保留底部中央返回入口，仍可平移缩放。尚未确认的预览不能被赏园动作悄悄提交；返回恢复选择、目录位置与镜头。
- 桌面和真实横屏采用可收起侧栏，约 320–360px，受屏幕宽度限制。第一版不增加 CSS 模拟横屏功能。
- 所有操作避让系统安全区与小红书宿主左右按钮；上方不放关键交互，不以整条大留白解决。预留可配置宿主占位，横屏分别校验。

## 操作约定

- 浏览时单指拖动始终平移，不因为起点压着树就误搬树；点击景物选中，再拖动选中物移动。双指始终控制镜头，取消当前单指拖动预览，不能误提交。
- 新增：点素材、点地面预览、拖动微调、确认。有效预览显示实际落地范围；无效显示具体原因与阻挡对象。
- 移动、改变形态、镜像、尺寸、收纳均集中在选中工具条。小物件被遮挡时通过园中清单选中并定位。
- 连续放置保持同一种素材，适合竹丛、石灯。明确每件价格，逐件确认扣款，余额不足保留最后有效状态。复制优先取收纳库存，否则展示购买价；不能免费复制收益物。
- 增加撤销/重做，初期覆盖移动、外观与收纳等布局操作。购买、升级、收益领取不进入布局撤销，避免复制资金或回滚时间。每个已提交动作先结算收益再更新产出。
- 允许微调步进，屏幕边缘拖动自动缓慢平移。吸附默认轻量、可关闭，不强制排成行列。

## 连续土地与碰撞

- 四庭转为地点书签和风格提示，不再作为内部碰撞围栏。采用统一世界坐标，跨原四庭检测占地。
- 初始可见的基础园地开放摆放；用景物解锁与全园经营容量保留成长。扩建如继续使用，应增加外侧可见土地，不能解锁已经看起来可用的空白。数值需单独模拟，不直接沿用旧扩建表。
- 地表与铺路可重叠覆盖；花草丛允许交叠；树冠允许交叠，仅主干根部避免完全重合；建筑地基禁止穿插。石灯、盆景允许贴近建筑，不设过宽空隙。
- 水面限制以真实水域形状计算；桥与临水建筑用专属锚点校验。软提示与硬禁止分开：挡住窗景仅提示，越界或建筑地基相交才阻止。
- 不提供忽略一切碰撞的默认模式。自由的目标是自然组合，仍要维护基本空间可信度。

## 美术与连接景观

- 延续淡彩园林插画，统一视角、光源、地面锚点、线条与阴影。地面、路径、水岸、建筑、植被分层。
- 将固定主宅从底图拆为独立对象；首次可提供已经摆好的可编辑布局，不要求玩家从空白开始。
- 首批连接元素：曲线石径与汀步、草地边缘、可组合池岸、墙段与月洞门。路径拖画自动平滑；墙段先支持素材已有方向和端点吸附。水系先用可衔接模块，完整自由水面画笔后置。
- 建筑仅支持真实已有视向及镜像；不能用平面图片旋转假装三维转向。新增方向需另制素材。
- 保留植物三形态、三尺寸；调整体量不改变收益。竹林应能围合空间，兰草负责近景，不按价格决定画面大小。
- 将造景方案升级为可预览的布局组合：显示已有与缺件，只放已有或确认后购买；整体预览确认后逐件可编辑。先做一套竹下茶庭闭环，再推广其他组合。

## 放置收益与主题

- 循环为：布置满意的小景 → 离线收益 → 获得新素材 → 改造更大的园林。开局给予足以组成小景的入门素材，避免只能等钱。
- 高阶景物继续有更高产出；移动、尺寸和镜像免费。普通路径、地被等基础造景材料不计生产收益，设性能上限，避免装饰自由被收益容量挤占。
- 不用苛刻的审美评分迫使玩家摆成唯一答案。组合提示帮助发现关系，奖励保持温和且可预知。
- 《兰香如故》的关联继续使用已核实的项目主题资料；兰花、窗景、园居只是视觉表达，不凭这些就声称高度还原原剧。新增原剧人物或事件前另核实来源。原创园中便笺作为可选内容，不阻断编辑。

## 技术落地与迁移

第一阶段：固定画布、抽屉状态机、浏览/选择/放置手势、赏园、连续坐标及分类占地、原因提示、布局撤销。先解决现在的操作问题。

第二阶段：主宅拆层、路径与池岸模块、墙段连接、组合摆放与连续放置，完成一套竹下茶庭。先证明能摆出自然景观，再扩素材。

第三阶段：校准收益与素材解锁节奏，补可选故事与其他方案，做小屏与宿主验证。

- 沿用纯前端静态构建，无新增依赖。业务规则、素材映射和文案继续放 content.json。
- 新存档使用明确版本号，旧 area/x/y 转为统一坐标；保留 uid、购买物、等级、样式、收藏、收益与故事。迁移先在内存校验，失败保留原存档，不为碰撞新规则直接删除或收纳旧景物。
- 将 camera、drawer、selection、placement 分离；拖动仅更新预览，不每帧重建整页 DOM；收益刷新不重置镜头与抽屉。
- 地形与路径保存为有上限的结构化坐标数据，不保存媒体或 Base64。性能预算用低端设备测量后定，不能仅因电脑流畅无限增加对象。
- 文档、实施、测试、打包分别记录状态；本提案不代表现有版本已经支持这些能力。

## 验收场景

1. 手机打开直接看园；添景、落位、微调、赏园全程无需滚动页面。
2. 抽屉开关、选物、切换类别不使园林缩放或跳位；被抽屉遮住时仅显式定位调整镜头。
3. 竹丛可跨原庭界放置，树冠可重叠，建筑地基真实相交时给明确提示；预览占地与确认判定一致。
4. 十次连续添景、移动、撤销后存档与金币一致；刷新恢复，旧存档迁移无资产丢失。
5. 完成一处有入口、路径、主景、陪景和留白的竹下茶庭，并能拆开自由调整。
6. 375/390/430 CSS px、桌面、真实横屏，非零安全区及左右宿主覆盖层；抽屉三档、编辑、赏园均检查。真实小红书设备验收单独记录。
7. 按项目要求 lint/test/build 与包白名单审计；新增操作才新增对应有意义的验证，不以测试数量代表好玩程度。
