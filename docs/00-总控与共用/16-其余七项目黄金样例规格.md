# 其余七项目黄金样例规格

状态：GOLDEN SAMPLE SPEC COMPLETE（2026-08-23）。事实型内容仍需在批量扩写阶段逐条核验来源；本文件冻结玩法结构、字段需求和纵切片验收方式。

## 1. 物华录：文物寻踪

### 1.1 黄金一轮

一轮固定 3 件，顺序由“轮廓明显 → 局部混淆 → 功能推理”递进。每件最多显示 3 条线索，首次作答正确得 3 星，每看一条追加线索少 1 星，最低 1 星。

#### 文物 A：后母戊青铜方鼎

- ID：`artifact-houmuwu-ding`
- 类别：青铜礼器。
- 识别锚点：长方形深腹、两只立耳、四柱足、体量巨大。
- 线索 1：我有四只足，却不是用来行走的。
- 线索 2：我的腹内有三个字，其中两个与母亲的庙号有关。
- 线索 3：我重约 832.84 千克，是目前已知中国古代最重的青铜器。
- 正确项：后母戊青铜方鼎。
- 干扰项：四羊方尊、利簋、大盂鼎。
- 揭晓知识：器腹内壁铸“后母戊”铭文；曾称“司母戊鼎”。
- 权威事实源：[中国国家博物馆馆藏页](https://www.chnmuseum.cn/zp/zpml/kgfjp/202008/t20200824_247255.shtml)。
- 图片策略：自制黑色轮廓和局部纹样示意，不默认复制官网图片。

#### 文物 B：长信宫灯

- ID：`artifact-changxin-palace-lamp`
- 类别：汉代铜灯。
- 识别锚点：跪坐宫女执灯；身体内部与袖管构成烟气通道。
- 线索 1：我看起来像一位安静跪坐的人，但身体的一部分其实是器具结构。
- 线索 2：我的袖管不仅支撑灯体，也让烟气进入身体内部。
- 线索 3：我与西汉中山靖王刘胜之妻窦绾墓的出土背景有关。
- 正确项：长信宫灯。
- 干扰项：错银铜牛灯、雁鱼铜灯、铜奔马。
- 揭晓知识：结果页只写经权威来源确认的结构，不使用“世界上最早的环保灯”等绝对化网络说法。
- 来源状态：正式入库前必须补河北博物院或考古报告的 A 级来源 URL。
- 图片策略：AI 重构只表现整体剪影；结构说明使用自绘剖面示意。

#### 文物 C：越王勾践剑

- ID：`artifact-goujian-sword`
- 类别：春秋晚期青铜兵器。
- 识别锚点：剑身菱形暗格纹、近格处鸟虫书铭文。
- 线索 1：我不是铁器，身上却有细密而规整的深色纹理。
- 线索 2：我的主人名字没有用今天熟悉的楷书写下。
- 线索 3：剑身近格处的鸟虫书铭文包含“越王”和“自作用剑”等信息。
- 正确项：越王勾践剑。
- 干扰项：吴王夫差矛、越王州句剑、战国错金银铜剑。
- 揭晓知识：不使用“千年不锈完全因为某种神秘配方”的单因果说法。
- 来源状态：正式入库前必须补湖北省博物馆或正式考古资料的 A 级来源 URL。
- 图片策略：轮廓图和铭文位置示意均自绘；不描摹受限摄影作品的具体光影。

### 1.2 页面纵切片

```text
封面 → 本轮藏品匣 → 文物剪影 → 选择答案
  → 错误/继续观察 → 新线索 → 再选择
  → 揭晓与一眼记住 → 获得星级 → 下一件
  → 本轮总结 → 收入图鉴
```

### 1.3 验收

- 三件都能在不看图片版权原图的情况下完成猜谜。
- 干扰项与正确项属于可比较对象，不出现明显送分项。
- 星级扣减可解释，重复点击不重复扣星。
- 每件文物都有权威来源 ID、图片性质和争议说明。

## 2. 大理寺字案录

### 2.1 黄金字案：《家字失踪案》

- 案件 ID：`case-home-roof-pig`
- 核心问题：“家”是不是简单等于“屋里养猪”？
- 事实边界：不同历史阶段字形、构件解释和学界争议必须以文字学来源为准；游戏剧情不能把流行段子直接判成事实。
- 结构：开场传闻、初判、三段调查、证据簿、终判、结案文书。

### 2.2 角色

- 寺丞：引导流程，不提供最终答案。
- 说书人：主张“古人家里都养猪，所以有家”。
- 匠人：提供屋舍、构件和字形观察。
- 书吏：展示不同阶段字形和出处。

### 2.3 三段调查

#### 第一段：验字形

用户从三个选项中选择先看：早期字形、楷书拆字、民间故事。无论顺序如何，最终获得证据 `evidence-early-form`；选择民间故事只获得“传闻”标签，不作为定案证据。

#### 第二段：问构件

用户选择比较“宀”和“豕”在其他字中的表现，或询问构件是否总等于现代图画。获得证据 `evidence-component-meaning`。

#### 第三段：审流传

用户比较三个结论：确定事实、合理推测、后世通俗解释。获得证据 `evidence-certainty-level`。

### 2.4 初判与终判

所有判词都是选项：

- `credible`：传言基本可信。
- `partial`：抓住了部分构件信息，但把复杂历史说得过于确定。
- `uncertain`：证据不足，应保留争议。
- `myth`：与可靠资料明显冲突。

黄金案建议官方判词为 `partial`，但必须在文字学资料完成核验后才能正式锁定结案理由。

### 2.5 页面纵切片

```text
卷宗封面 → 角色对话 → 初判
  → 三段选项式调查 → 证据获得动画
  → 证据簿 → 终判 → 与初判比较
  → 结案文书 → 文字学来源
```

### 2.6 验收

- 全程只有预设选项，不出现用户自由输入。
- 任意调查顺序都能到结案，不存在死节点。
- 事实结论不因玩家选择改变，变化的是玩家取得证据的顺序和判案风格。
- 大理寺字案录明确标注为虚构叙事机构。

- 同事件遵守冷却，连锁事件按前置标记出现。
- 事件效果不会让精力、声望越过合法边界。

## 4. 我希望被这样对待｜关系说明书

### 4.1 六道黄金题

1. 忙碌时的联系：简短报平安 / 有空再完整交流 / 不需要固定联系。
2. 我诉说烦恼时：先听完 / 先帮我理清 / 先问我需要倾听还是建议。
3. 发生分歧时：当下谈清 / 各自冷静后约时间 / 先暂停但不要消失。
4. 我需要独处时：给我明确空间 / 偶尔轻轻确认 / 让我主动回来。
5. 表达关心时：具体行动 / 直接说出来 / 记得小事。
6. 修复关系时：承认具体影响 / 解释当时处境 / 一起约定下一次怎么做。

每题允许单选或“这取决于情境”；不计算人格类型，只映射到候选说明句。

### 4.2 黄金输出卡

必须至少生成四类句子：

- 偏好：“我分享烦恼时，希望你先问我现在更需要倾听还是建议。”
- 边界：“如果我们需要暂停争论，我希望能约定大概什么时候再继续，而不是突然失去联系。”
- 愿望：“我会很珍惜你记得那些对我重要的小事，但这不是要求你永远不忘。”
- 共同承诺：“如果我的需要发生变化，我也愿意重新告诉你，而不是让你猜。”

### 4.3 编辑能力

用户可以编辑、隐藏、拖动排序；敏感句默认不进入简洁分享版。所有修改本地自动保存，只保留一份说明书 MVP。

### 4.4 页面纵切片

```text
用途说明 → 选择关系情境 → 六题
  → 生成说明书 → 编辑/隐藏/排序
  → 完整版/简洁版预览 → 本机保留或清空
```

### 4.5 验收

- 不把说明书写成对他人的服从清单。
- 每张卡同时包含用户愿意承担的沟通责任。
- 刷新后编辑内容仍在；清空后不可恢复并提前确认。
- 不提供心理诊断、依恋类型判定或伴侣评分。

## 5. 出门检查官

### 5.1 黄金场景 A：日常通勤

基础项目：手机、钥匙、支付方式、工作/学习所需物、饮水。条件项目：下雨加伞；需要门禁加门禁卡；电量低加充电设备；服药条件由用户主动勾选后加药物提醒。

空间动线：桌面 → 充电处 → 玄关 → 冰箱/水杯处。

### 5.2 黄金场景 B：周末短途

基础项目：手机、钥匙、支付方式、证件、饮水、行程信息。条件项目：过夜加换洗与洗漱；户外加防晒/防雨；乘车加车票与充电；有预订加预订凭证。

空间动线：卧室 → 卫生间 → 充电处 → 玄关。

### 5.3 三种查看方式

- 重要程度：关键、重要、可替代。
- 类别：证件、电子、衣物、健康、行程、其他。
- 空间动线：按用户在家中可能经过的位置分组。

### 5.4 规则样例

```text
scenario=commute AND rain=true → umbrella
scenario=short-trip AND overnight=true → toiletries, change-of-clothes
battery=low → charger
item 已由多条规则加入 → 只保留一条，优先级取最高
规则结果为空 → 回退到该场景基础清单
```

### 5.5 页面纵切片

```text
选择场景 → 回答2–5个条件 → 生成清单
  → 切换三种视图 → 勾选 → 添加短文本项目
  → 全部完成提示 → 最近三份 / 清空
```

### 5.6 验收

- 同一物品不重复。
- 自定义项目不超过 30 字，不允许图片。
- 三种视图切换不丢失勾选状态。
- 药物、证件等只作为提醒，不宣称清单完整。

## 6. 当时这样说就好了

### 6.1 三个黄金虚构场景

#### 场景 A：朋友迟到

- 事实：约定 15:00 见面，对方 15:35 到达，中间没有发消息。
- 感受候选：着急、失落、烦躁、担心。
- 解释提醒：“你根本不尊重我”是解释，不是可直接观察事实。
- 需要候选：可靠、知情、时间被尊重、可预期。
- 请求示例：“如果下次会晚到十分钟以上，你愿意在知道时发一句消息告诉我吗？”

#### 场景 B：伴侣临时改计划

- 事实：原定周六一起吃饭，对方周五晚上提出改到下周。
- 感受候选：失望、困惑、不安、疲惫。
- 需要候选：被考虑、共同安排、稳定、解释。
- 请求示例：“你愿意告诉我这次改变的原因，并和我一起定一个新的具体时间吗？”

#### 场景 C：同事遗漏交接

- 事实：约定写入交接表的三项信息中有两项未填写，用户在截止前一小时才发现。
- 感受候选：紧张、挫败、恼火、无措。
- 需要候选：协作、清晰、可靠、准备时间。
- 请求示例：“下一次交接前，你愿意在提交时按这三项检查一遍，并在缺信息时标出来吗？”

### 6.2 五步结构

```text
发生了什么（事实）
→ 我有什么感受
→ 我脑中怎样解释它
→ 我在意什么需要
→ 我能提出什么具体且可拒绝的请求
```

最终表达不自动发送，也不承诺一定改善关系。

### 6.3 页面纵切片

```text
无痕说明 → 选择空白整理/虚构示例
  → 事实 → 感受 → 解释 → 需要 → 请求
  → 组合草稿 → 用户编辑
  → 不保存退出 / 明确保存到本机（最多3份）
```

### 6.4 验收

- 默认无痕，刷新即丢失未保存内容时必须提前说明。
- 每字段限制 300 字。
- “被忽视”“被背叛”归入解释或体验描述，不冒充纯感受词。
- 暴力、威胁和控制情境优先显示安全提示，不鼓励单独对质。
