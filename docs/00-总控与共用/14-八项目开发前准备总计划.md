# 八项目开发前准备总计划

状态：MASTER PRE-DEVELOPMENT PLAN（2026-08-23）。

目标：在任何一个项目正式进入 UI 成品设计、AI 美术批量生成和业务代码开发前，把八个项目共同需要的规则，以及每个项目自己的内容和数据输入准备到可以并行执行、可以验收、不会依赖临时口头决定的状态。

## 1. 什么叫“开发前准备完成”

一个项目只有同时满足以下八个条件，才标记为 `DEV READY`：

1. **玩法冻结**：入口、核心循环、结果/结局、复玩方式和明确不做的功能已经确定。
2. **内容就绪**：黄金样例通过，首发内容达到最低数量，事实、安全和重复度审校完成。
3. **数据契约冻结**：`content.json` 字段、稳定 ID、引用关系、用户状态与迁移规则确定。
4. **页面流程冻结**：页面清单、页面之间的跳转、返回/刷新/中断恢复和空状态确定。
5. **交互状态冻结**：每个关键组件的默认、选中、完成、错误、禁用、加载和恢复状态确定。
6. **美术资产有清单**：每张图的用途、尺寸、格式、透明背景要求、复用方式和生成提示词方向确定。
7. **技术方案冻结**：框架、目录、路由、状态管理、本地存储、内容校验、测试和构建方式确定。
8. **验收标准可执行**：核心流程、内容、性能、隐私、无障碍和小红书 WebView 适配都有明确检查项。

“有想法”“有文案草稿”或“画了首页”都不等于 `DEV READY`。

## 2. 开发前必须准备的九类交付物

### A. 产品规格包

每项目一份，回答：

- 用户为什么打开它。
- 30 秒内做什么。
- 一轮要多久。
- 核心操作是什么。
- 怎样产生结果、奖励或结局。
- 为什么愿意再次打开。
- 哪些功能明确不在 MVP 中。
- 如何向用户说明后续会持续更新，同时不拿“以后更新”掩盖首发内容不足。

现状：八项目玩法和 MVP 已冻结，主体在 `docs/09`、`docs/10` 及八份项目规划中。

### B. 内容生产包

每项目需要：

- 首发实体数量表。
- 黄金样例。
- 内容模板与字段说明。
- 批量扩写规则。
- 重复度标准。
- 事实核验表或安全审校表。
- 来源和许可记录。
- 最终 `content.json` 内容草案。

现状：总体配额已冻结；SBTI 黄金样例已通过，其余七项目待制作黄金样例。

### C. 数据契约包

每项目需要：

- `content.json` 的运行时 schema。
- 所有内置实体的稳定 ID 规则。
- 实体之间的外键关系。
- localStorage envelope。
- 必要项目的 IndexedDB 数据库和表定义。
- 内容版本与存档版本迁移规则。
- 构建前 JSON 校验规则。
- 一份最小有效 JSON 和一份故意无效的测试 JSON。

现状：顶层规则已经冻结；项目级字段仍需随黄金样例补齐到可直接实现的精度。

### D. 信息架构与页面流程包

每项目至少输出：

- 页面/弹层清单。
- 从封面到完成的一条主流程。
- 返回上一步、退出、刷新和继续的处理。
- 第一次使用与再次使用的差异。
- 空状态、内容耗尽、没有匹配结果、存档损坏等异常流程。
- 分享卡展示内容，但不依赖自动保存用户图片。

交付形式采用文本流程图和页面状态表；此阶段不决定精确颜色和插画。

### E. 交互规格包

每个关键操作必须写清：

- 点击后立即发生什么。
- 是否允许撤销。
- 是否自动保存。
- 连续点击如何处理。
- 选项改变后分数/状态何时提交。
- 动画能否跳过。
- 关闭工具再打开时从哪里恢复。
- 用户如何清空全部本地数据。

尤其需要提前冻结：测评回退是否改分、经营事件能否撤销、案件证据何时入簿、任务更换如何进入冷却。

### F. 视觉与美术准备包

开发前只做设计输入，不批量生成最终资产。每项目需要：

- 视觉关键词和明确禁用风格。
- 颜色功能表，不只是气氛色板。
- 字体策略及商用/打包许可。
- 核心页面线框说明。
- 组件视觉层级。
- 美术资产清单和优先级。
- 每类资产的母提示词、负面约束和一致性要求。
- 文件名、尺寸、格式、压缩目标和裁切安全区。
- 哪些资源使用 CSS/SVG，哪些确实需要 AI 位图。

正式美术生成必须等待资产清单冻结，避免先生成大量无法放入页面的图。

### G. 技术架构包

八项目共同确定：

- 推荐统一使用 React + TypeScript + Vite，减少八套工程差异。
- 静态构建、无服务器、无远程运行时依赖。
- 每项目独立构建包，内容与用户存储完全隔离。
- 统一的内容读取器、运行时 schema 校验器、本地存储 envelope、错误边界和设置组件。
- localStorage/IndexedDB 封装接口。
- 音效加载与静音策略。
- 图片预加载、懒加载和 WebP/AVIF 回退策略。
- 不依赖 URL History 的返回策略，避免平台 WebView 行为差异。
- 构建产物资源路径必须相对化。

项目级确定：

- 状态机或 reducer 的状态定义。
- 随机种子和可复现规则。
- 存档时机。
- 内容索引方式。
- 核心算法伪代码和边界情况。

### H. 测试与验收包

每项目在开发前先写验收用例，而不是开发后再凭感觉测试：

- 1 条黄金主路径。
- 1 条中断恢复路径。
- 1 条边界或失败路径。
- 内容引用完整性测试。
- localStorage/IndexedDB 写满、损坏和版本变化测试。
- 小屏、长屏、刘海/底部安全区测试。
- 断网首次打开后的静态资源完整性测试。
- 重复点击、快速切换、刷新和返回测试。
- 清空数据测试。
- 无音频权限或资源加载失败时的降级测试。

### I. 比赛提交与合规包

每项目提前准备：

- 作品名称、副标题、一句话介绍和玩法说明。
- 所属赛道与标签组合。
- 国风项目同时参加两个比赛时的标签检查。
- 首屏免责声明和隐私说明。
- 来源页、AI 美术说明、图片/字体/音效许可清单。
- 演示脚本、录屏路线、封面图和小红书发布文案提纲。
- 静态包上传前检查表。

提交材料可在开发后填入最终截图和数据，但结构必须现在确定。

## 3. 八项目共用准备工作

这些工作只做一次，八个项目复用：

### 3.1 统一工程模板规格

```text
project/
  public/
  src/
    app/
    components/
    content/content.json
    content/schema.ts
    content/validate.ts
    features/
    storage/
    styles/
    assets/
    tests/
  scripts/validate-content.ts
  index.html
  package.json
  vite.config.ts
```

这里只冻结目录和接口；等八项目准备完毕后再建立真实工程模板。

### 3.2 共用数据外壳

所有 `content.json` 使用：

```ts
type ProjectContentPackage<TContent> = {
  meta: {
    projectId: string;
    schemaVersion: number;
    contentVersion: string;
    generatedAt: string;
    locale: "zh-CN";
  };
  content: TContent;
  sources: SourceRecord[];
};
```

### 3.3 共用本地存储能力

- `load / save / remove / clearProjectData`。
- schema 迁移和损坏恢复。
- localStorage 容量失败提示。
- IndexedDB 打开、升级和事务失败降级。
- 不保存用户媒体文件。
- 设置页统一提供“清空本工具数据”。

### 3.4 共用移动端交互约束

- 以单手竖屏为主。
- 主要触控目标不小于约 44×44 CSS 像素。
- 重要按钮避开底部安全区。
- 不依赖 hover。
- 正文避免超长单屏。
- 动画支持跳过或减少动态效果。
- 音频默认遵守浏览器首次交互限制，加载失败不阻塞玩法。

### 3.5 共用内容与资源门禁

- 内容 JSON 校验。
- 稳定 ID 和引用校验。
- 文本长度、禁用词和重复度检查。
- 资源路径、格式、尺寸和体积检查。
- 来源 ID 与许可字段检查。
- 构建产物不得包含研究草稿、开发机路径、远程热链或秘密信息。

## 5. 推荐制作顺序与阶段门

### 阶段 P0：总规则冻结——已完成

- 八项目名称、顺序、比赛方向。
- 纯前端、无后端。
- 单一 `content.json`。
- localStorage/IndexedDB 分工。
- 不存用户图片。
- MVP 玩法和首发数量。

### 阶段 P1：八项目黄金样例

按顺序完成：

1. SBTI：已通过 4 型、16 题结构样例。
2. 物华录：3 件文物完整一轮。
3. 大理寺字案录：1 个完整字案。
4. 汴京饮子铺：可跑通的 10 天经营。
5. 关系说明书：6 题生成并编辑一张卡。
6. 出门检查官：2 场景与三种查看方式。
7. 对话复盘：3 个虚构场景完整五步。
8. 地球 Online：12 个任务与筛选回退。

阶段门：八份黄金样例均通过，才能把内容模板视为稳定。

### 阶段 P2：首发内容生产与审校

- Codex 按黄金样例批量产出初稿。
- 逐项目做事实、安全、重复度和移动端字数审核。
- 合并为项目级 `content.json` 草案。
- 运行静态校验和逻辑覆盖检查。

阶段门：首发内容达到配额，并且无未解决的 A 级事实/安全问题。

### 阶段 P3：流程、交互与算法规格

- 八项目页面地图。
- 页面状态表。
- 核心算法伪代码。
- 存档时机、恢复和重置流程。
- 边界情况与验收用例。

阶段门：任何 UI 设计师或编码任务只读文档就能还原完整流程，不需要猜产品决定。

### 阶段 P4：视觉方向与资产计划

- 建立八项目各自视觉方向，同时共享基础移动端组件规范。
- 输出线框、组件层级、色彩功能和字体策略。
- 输出逐资产 manifest 和 AI 生成提示词计划。
- 完成许可策略，尤其是文物图、字体和音效。

阶段门：每个资产都知道放在哪个页面、以什么尺寸展示、失败时如何降级。

### 阶段 P5：技术与测试开工包

- 工程模板规格。
- 类型与 schema。
- localStorage/IndexedDB 接口。
- 测试矩阵。
- 静态构建和平台上传检查表。
- 将工作拆成 UI、内容、美术、逻辑、集成和 QA 六类任务，并写清文件边界与依赖。

阶段门：八项目全部标记 `DEV READY`，再开始正式实现。

## 6. 并行开发前必须冻结的接口

用户计划让 Codex 并行处理 UI、逻辑、美术与代码。真正并行前，以下接口不能再含糊：

| 并行工作 | 必须先拿到 | 输出不能擅自改变 |
|---|---|---|
| UI | 页面地图、组件状态、真实文案长度 | 玩法流程、内容字段、存储策略 |
| 游戏逻辑 | 状态机、算法、事件/题目 schema | UI 风格和美术文件本体 |
| 美术生成 | 资产 manifest、尺寸、风格母提示词 | 文件名、主体构图安全区、透明要求 |
| 内容生产 | 黄金样例、字段模板、来源规则 | schema、维度定义、安全边界 |
| 数据层 | 存储模型、版本迁移、清空规则 | 业务玩法和内容语义 |
| QA | 验收用例、测试数据和成功标准 | 不在测试时临时发明产品行为 |

每个任务都要写明：输入文件、允许编辑目录、预期输出、验收命令和不能改动的冻结项。
