# 汴京饮子铺：今日开张 · UI/UX 重设计 V2

状态：待书面规格确认
日期：2026-08-26

## 1. 设计目标

把现有表单式经营骨架重构成“市井铺面主舞台＋纸面经营台”的移动端经营体验。玩家应清楚感受到一日由晨入夜的五段节奏，同时保留经济公式、事件、连锁、结局与固定 seed 的确定性。

体验关键词：市井、克制、可解释、有人情味、可复盘。

## 2. 冻结边界

- 不改变 100 日经营公式、商品成本/基准价、80 个事件、5 条连锁、8 个结局及 RNG。
- 不新增依赖，不修改工作区或锁文件。
- 纯前端静态构建，不使用后端、运行时 CDN、外部 API、Service Worker 或设备 API。
- 业务文案只存放于 `src/content/content.json`；React 只消费类型化 view model。
- 存档仍只保存稳定 ID、数值、时间和有限文本，不保存图片、Base64、音视频或 Blob。
- 美术缺失或加载失败时，所有经营数字、选择和结算仍可完成。

## 3. 视觉系统

### 3.1 构图

- 顶部：日期、时段、天气与四项状态，关键经营数字不压在图片上。
- 中部：店铺场景，复用于封面、晨间、营业、事件、里程碑与结局。
- 底部：纸面经营台，承载按钮、商品、选择、账簿和恢复操作。
- 桌面宽度下使用“场景／经营台”左右双栏；移动端保持单列流程。

### 3.2 色彩与材质

- 墨黑 `#1f2927`：夜色、标题和高对比信息。
- 宣纸 `#f2e5c7`：经营台、账簿与卡片底色。
- 赭木 `#704a32`：铺面结构、次级按钮。
- 紫苏红 `#983f38`：主动作、风险和印记。
- 茶青 `#697b55`：成功、提示和自然信息。
- 金褐 `#b58a4b`：金额与里程碑点缀，不使用现代金币爆炸效果。

正文使用系统无衬线中文字体；标题使用系统宋体栈。数字启用等宽数字特性。位图中不生成文字，店名、招幌和账目全部由 HTML/CSS 渲染。

## 4. 页面与主流程

### 4.1 封面与继续经营

- 场景上方显示“一铺饮子，一百日烟火”的经营承诺。
- 有存档时主动作是“继续第 N 日”，新开存档为次动作。
- 显示最近存档的日数、资金、口碑和阶段；结局册为弱入口。
- 读取失败进入恢复页，不出现白屏。

### 4.2 首次引导

- 阿沅用三步说明：本金有限、先定饮子、再判断今日客流。
- 可逐句继续或跳过；跳过不修改经营状态。
- 角色立绘不得覆盖现金、日数和主动作。

### 4.3 晨间情报

- 顶部同时显示资金、口碑、体力、人情及昨日趋势。
- 中部为今日店铺场景；天气、季段和库存风险在纸面情报条显示。
- 只提供需求方向，不泄露事件或精确销量。
- 主动作进入备货与定价。

### 4.4 备货与定价

- 顶部预算条实时显示预计备货成本、剩余资金和当前体力。
- 商品行包含饮子图、名称、库存、成本、售价、备货步进器。
- 商品选择维持引擎的 3–5 种约束；备货量 0–12，售价为基准价 80%–140%。
- 控件达到上限、下限或预算不足时禁用并显示原因。
- 草稿仅保存在当前 React 状态；开门前可返回修改。

### 4.5 经营策略与开门确认

- 本轮不新增经济策略效果；保留既有 `strategyId` 数据接口和“提前打烊”选择。
- 开门确认汇总商品、数量、售价、备货成本和提前打烊状态。
- “开门营业”提交后锁定当日决策并写安全存档。

### 4.6 营业

- `openDay` 仍一次性确定天气、客流、销量和事件；UI 只分段演示已确定结果。
- 场景依次显示辰时／午后／黄昏反馈，商品售出与库存简讯来自 `pendingOpening.sales`。
- 玩家可等待短暂演示或使用“快速结算营业过程”，无需连续点击。
- 有事件时进入事件场景；无事件时进入普通日结确认。

### 4.7 事件与连锁

- 场景复用三类顾客、阿沅和八类事件符号，不为 80 个事件分别绘图。
- 玩家先选中选项，再按“确认选择”提交；提交前可更换。
- 选中态只展示 `impactTags` 的定性后果，不展示精确数值。
- 提交按钮带重复点击保护；提交后保存安全快照并进入日结。
- 连锁事件增加案头“线索”标记，但不展示内部 flag 或未来节点。

### 4.8 日结与账簿

- 首屏显示净变化、客流和阿沅的一句复盘。
- 账目按销售收入、备货成本、余货折返、固定成本、事件与延期影响排序。
- 所有 `labelId` 通过 view model 转换为用户可懂标签。
- 商品表现使用移动端卡片列表，不使用需要横向滚动的宽表格。
- 下一日、里程碑、破产和百日结局沿用引擎状态。

### 4.9 里程碑、破产和结局

- 里程碑使用大日数字、经营路线摘要和已发生的人物回响。
- 破产说明资金链、体力和关键转折，提供重开与查看账簿，不使用羞辱文案。
- 第 100 日结局复用店铺与角色合成，显示最终资产、四状态、评价和分享短句。
- 结局册只显示已解锁 ID 的用户文案，不清除旧收藏。

### 4.10 异常恢复

- 当前快照损坏且上一日有效时，明确列出保留内容和唯一会失去的晨间草稿。
- IndexedDB 不可用时可重试或返回封面；不伪装为已保存。
- 阿沅恢复提示只解释本地状态，不修改经济数据。

## 5. 组件边界

- `App`：持有浏览器存储、游戏对象、页面与 UI 草稿状态。
- `GameHeader`：日期、时段、天气和四项状态。
- `ShopScene`：背景、时段/天气层、人物槽位和场景标题。
- `GuideCard`：阿沅首次引导、日结反馈、召回和恢复。
- `PreparationPanel`：商品选择、数量、售价和预算验证。
- `OpeningSummary`：提交前只读清单。
- `BusinessTicker`：营业阶段与已确定销量反馈。
- `EventDecision`：选择态与二次确认。
- `LedgerPanel`：账目与商品表现。
- `OutcomePanel`：里程碑、破产和最终结局。

这些组件可先作为 `App.tsx` 内的局部组件实现；若文件超过可维护范围，再拆入 `src/ui/`，不做无关重构。

## 6. View model 与数据流

`buildGameViewModel` 增加：

- 天气名称、季段、已解锁商品的图片路径和库存；
- 备货预算摘要；
- 营业简讯；
- 用户可读账目标签；
- 事件类别、选项后果标签与连锁标记；
- 结局和恢复页面所需的只读摘要。

UI 状态只包含引导步骤、当前营业阶段、选中的事件选项、备货草稿和面板展开状态。所有经营结果继续来自 `openDay` / `resolveDay`，UI 不复制经济计算。

## 7. 响应式与无障碍

- 375px：四状态 2×2；商品行保持图、信息、步进器可读；底部安全区不遮最后一项。
- 390px：单屏场景基准；事件和账簿使用整页纸面层。
- 430px：扩大场景和卡片留白，数字列仍保持稳定宽度。
- 主触控目标最小 46px；步进器带可读 `aria-label`。
- 选中、增减和盈亏同时使用文字/符号/边框，不能只靠颜色。
- 图片具备描述性 `alt`；装饰性天气层使用空 `alt`。
- `prefers-reduced-motion` 下关闭蒸汽、雨线位移、翻页和时段过渡。
