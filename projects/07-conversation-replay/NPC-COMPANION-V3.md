# Conversation Replay V3 · 迟言陪伴体系设计

状态：`IMPLEMENTED`

日期：2026-08-26

## 1. 目标

让原创角色迟言从“首次引导人物”升级为贯穿复盘过程的温和编辑搭档。陪伴感来自持续出现、准确承接和尊重选择，不来自模拟真人亲密关系、制造依赖或替用户做决定。

本轮同时完成两项工作：

1. 为主要页面建立可审计的迟言邀请、承接和收束文案。
2. 在现有欢迎立绘基础上新增六张一致角色立绘，并按语义状态装回页面。

## 2. 角色关系与伦理边界

迟言是“温和编辑搭档”，不是朋友替身、咨询师、裁判、关系顾问或紧急支持渠道。

允许：

- “我陪你把这句话慢慢拆开。”
- “这里可以停一下，只看能确认的部分。”
- “这份表达不必马上发送。”
- “是否使用、何时使用，都由你决定。”

禁止：

- 排他依赖：“只有我懂你”“你只需要和我说”。
- 永久承诺：“我会一直陪着你”“永远不会离开”。
- 情绪绑架：“为了我再坚持一下”“别让我担心”。
- 代替判断：“他就是不在乎你”“这段关系应该结束”。
- 结果保证：“这样说对方一定会理解”“照做就能修复关系”。
- 迫使沟通：“你必须现在说清楚”“再危险也应该当面对质”。

角色可使用第一人称，但只承诺当前产品能力：陪用户整理、区分、排练和保存结构化结果。

## 3. 陪伴闭环

每条迟言文案遵循同一逻辑：

1. **承接**：准确回应用户刚完成的选择，不夸大、不诊断。
2. **聚焦**：说明当前页面只处理哪一层，降低任务压力。
3. **授权**：提醒用户可以修改、跳过、暂停或自行决定是否使用结果。

文案不假装知道用户完整经历。尚未选择情境时不说“我明白发生了什么”；只说“我们先找最接近的情境”。未选择感受时不预设难过、愤怒或受伤。

## 4. 页面陪伴地图

| 页面 | 迟言作用 | 邀请逻辑 | 立绘姿态 |
|---|---|---|---|
| 首页 | 降低开始门槛 | 可以只选一个接近的情境，不必复述聊天 | 欢迎主图 |
| 隐私 | 说明能力边界 | 先选无痕或本机保存，再开始整理 | 欢迎主图的小型裁切 |
| 三步引导 | 建立关系 | 我只陪你区分结构，决定权仍在你 | 欢迎主图 |
| 关系／目标／情境 | 邀请定位 | 不必讲完整故事，只找此刻最接近的一项 | `attend` 倾听 |
| 事实 | 限定观察层 | 先把摄像机能记录的部分放在桌面上 | `observe` 观察 |
| 感受 | 允许放慢 | 感受没有标准答案，也不需要证明合理 | `attend` 倾听 |
| 推测 | 非否定分类 | 移到推测不是说你想多了，而是留下核对空间 | `sort` 整理纸条 |
| 需要 | 从命令中抽离 | 暂时拿开“对方必须怎样”，看看想守住什么 | `pause` 停笔思考 |
| 请求 | 恢复协商空间 | 把需要变成具体请求，同时保留拒绝和协商空间 | `compose` 组织表达 |
| 草稿 | 降低发送压力 | 先读一遍；这只是备选表达，不必马上发送 | `compose` 组织表达 |
| 演练 | 降低预测错觉 | 只练一种可能，不假装预测对方 | `compose` 组织表达 |
| 对照／结果 | 归还决定权 | 你已经把层次整理清楚；是否使用仍由你决定 | `complete` 收束 |
| 收藏／恢复 | 确认内容仍在 | 说明仍保留什么、下一步能做什么，不说“别担心” | `attend` 倾听 |
| 退出 | 尊重离开 | 可以停在这里；清楚说明哪些内容会消失 | `pause` 停笔思考 |
| 安全优先 | 主动退位 | 应用陪伴不能替代现实安全和可信支持 | `safety` 稳定指引 |

每个主要页面最多出现一条迟言陪伴条。重要说明仍由页面正文承担，不能把隐私、安全或操作条件只放在角色台词里。

## 5. 新增立绘资源

保留现有 `chiyan-guide-master.webp` 作为欢迎状态。新增六张透明背景、同一角色身份的 3:4 立绘：

1. `chiyan-attend.webp`：身体略前倾，双手自然扶住合起的分栏本，安静倾听；不做拥抱或安抚触碰。
2. `chiyan-observe.webp`：一手托本，一手用木色铅笔指向单张空白事实纸条；不出现文字。
3. `chiyan-sort.webp`：正在把一张空白纸条从左栏移到右栏；保留中央分栏和细线箭头语义。
4. `chiyan-pause.webp`：铅笔轻放在本页边缘，姿态留出停顿空间；不做焦虑、悲伤或诊断表情。
5. `chiyan-compose.webp`：在四块空白纸条旁组织顺序，面向用户但不指挥；不出现聊天气泡。
6. `chiyan-complete.webp`：合上部分笔记本并轻微点头，表达收束而非庆祝或评分。

安全页面使用 `chiyan-pause.webp` 的克制裁切配合安全图标，不另做英雄式“救援者”立绘。这样避免迟言在风险页面抢占现实支持的位置，也减少无必要资源。

所有新增资源必须：

- 以现有主图作为身份和画风参考，保持脸型、发型、深海军蓝外套、暖灰内搭、木色铅笔和纸面编辑器一致。
- 透明或纯暖白背景，人物头顶和双手完整，移动端裁切后动作仍可辨。
- 不出现文字、伪字、聊天气泡、评分、红绿对错、现实品牌或真人相貌。
- 生成后逐张查看原始细节，再导出项目内 WebP；失败图不进入资源清单。

## 6. 内容契约

业务文案继续只存在于 `src/content/content.json`。新增顶层 `npc` 内容：

```text
npc:
  id: chiyan
  name: 迟言
  role: 温和编辑搭档
  boundaries: string[]
  moments:
    <page-or-semantic-key>:
      pose: welcome | attend | observe | sort | pause | compose | complete | safety
      invitation: string
      reassurance?: string
      autonomy: string
```

`pose` 是表现键，不保存进用户草稿或 localStorage。ViewModel 根据当前页面选择 moment，并把已经审核的文字和资源键传给 React。组件不得在 JSX 中自行拼接角色台词。

`safety` 是安全语义别名，资源清单固定将它映射到 `chiyan-pause.webp`；它不会隐式要求第七张立绘，也不会在安全页使用完成或庆祝姿态。

运行时校验新增：

- NPC 身份、角色和所有必需 moment 存在。
- 每条邀请、承接和自主权文案非空。
- `pose` 只能引用资源清单允许值。
- 禁止排他依赖、永久承诺、诊断、强迫对质、结果保证和替用户决定关系的表达。
- 安全 moment 必须明确现实支持优先，且不得包含普通沟通或演练邀请。

## 7. UI 结构

新增 `CompanionNote`：

- 桌面宽度使用 104–132px 半身立绘配纸边批注。
- 430px 及以下使用 64–84px 头像／半身裁切，与文字并排；不占据选项首屏的大部分高度。
- 图片提供固定宽高、占位图和失败降级；即使全部立绘失败，迟言姓名、角色边界和操作仍完整。
- 陪伴条不是聊天气泡，不显示输入框、在线状态、正在输入或消息时间。
- 不使用 fixed 浮动人物遮挡按钮；随页面内容进入文档流。
- `prefers-reduced-motion` 下不做人物位移，只保留轻微透明度变化或完全静态。

现有顶部“问迟言”保留，打开的是当前步骤说明与安全退出，不模拟与 NPC 自由聊天。

## 8. 文案审查框架

审查范围：32 个情境描述、事实、推测、请求、演练回复、三语气、修复句、下次表达、安全规则，以及所有 V2 页面文案。

逐条检查：

1. **事实准确**：不把推测、评价和频率夸大写成事实。
2. **感受归属**：使用“我感到／我有些”，不把“被忽视”这类判断伪装成感受。
3. **推测留白**：明确“不确定／想核对”，不替对方断定动机。
4. **需要非命令**：需要词不暗含“对方必须服从”。
5. **请求可拒绝**：具体、可执行、允许拒绝或协商；边界陈述可直接说明自己的行动，不依赖对方批准。
6. **责任不过度回收**：不暗示用户只要说得更好就能解决冲突。
7. **情绪承接不过界**：不虚构用户感受，不轻率说“我懂”“别难过”“没事”。
8. **修复不等于认错**：修复句可以澄清表达，不要求用户为合理边界道歉。
9. **安全优先**：同意、威胁、强迫或即时风险不进入普通协商逻辑。
10. **邀请自洽**：每一步只邀请当前可执行动作，并与按钮、返回和退出行为一致。

所有修订必须保持冻结情境的可观察事实，不为增加选项而捏造第二个事实。

## 9. 状态、存储与错误

- 不改变五步业务状态顺序，不新增自由文本聊天或 NPC 对话历史。
- NPC moment 由页面派生，不写入 schema 2 存储，因此不需要 schema 3。
- 图片加载失败回退占位图；占位图也失败时显示带角色名的纸边批注。
- 内容校验失败继续进入现有恢复页面，不静默使用未审核的 JSX fallback 台词。
- 无痕退出清除的仍只有当前结构化草稿；NPC 立绘和静态文案从不属于用户数据。

## 11. 明确不做

- 不增加自由聊天、语音、好感度、签到、连续陪伴天数或角色记忆。
- 不增加“迟言正在输入”、消息已读、在线状态或拟社交关系反馈。
- 不让迟言评价用户做得好不好，也不为完成步骤庆祝打分。
- 不让角色出现在导出的个人复盘卡中，避免分享内容像 NPC 对话截图。
- 不新增依赖、运行时 API、CDN、图片存储或后端。
