诚实记录原则（沿用 45/48 号）：

- 排期以**门禁与交付物驱动**，不给日历承诺；每个阶段的出口条件写明，满足即进、不满足即停。

## 1. 目标与范围

**目标**：按 48 号清单交付 8 个"视觉玩法"小工具（手势 → 物理/粒子反馈 → 状态变化动画的核心循环），复用 18-25 号验证过的第三代工程模式，控制单项目风险并维持每周运营节奏。

**范围内**：48 号 §1 的 10 个选题——A 梯队（捏捏工坊、敲晶洞、糖画转盘）、B 梯队（流心切切乐、打铁花、高压水枪洗刷刷、放河灯）、C 梯队（摇签筒、捏捏货架上新、节日换皮）。

**范围外**：

- 44 号候选池中的生活实用工具线（48 号明确不在本文范围）。
- 48 号 §7 废案（查手机推理、馄饨摊、成语每日猜、部首合成、阿Sue/Judy/韦特塔罗复刻等）——不再重复提议。
- 既有 01-25 项目的修改（除非发现共享约束需同步，走总控决策）。

## 2. 总体策略

1. **门禁驱动排期**：六个阶段门禁（G0-G5，见 §4），每阶段出口条件明确；数据观察（G2）决定 B 梯队节奏，不硬性铺开。
2. **模板先行**：Phase 0 产出可复制的工程骨架模板（复制 21 号 tools.mjs 模式）与宿主避让参数系统，之后每个项目零新增 npm 依赖、零根锁文件改动，并行开发互不干扰（遵守 AGENTS.md 目录所有权）。
3. **样板先行于量产**（47 号 §8）：手感类玩法（捏捏、切切、糖画）先做"一只可玩样板"通过视觉对照验收，再扩内容与图鉴。
4. **主力项目分批放量**：捏捏工坊五材质族首发 2-3 族，其余按周补齐（与 C9 货架运营位天然衔接），降低单次交付体量与风险。
5. **收集与截图产物内建**：每款从第一天就设计图鉴/结果卡/对比卡（48 号 §4"魔法时刻与可截图产物"），不做"先玩法后补收集"。

## 6. 项目开发卡片（26-33）

每张卡片：定位 / 核心循环 / 技术方案 / 复用清单 / content.json 草案 / 魔法时刻与截图产物 / 专项验收 / 主要风险。通用部分（工程规范、全量验收）见 §8/§9，不重复。

### 6.1 26-流心切切乐（B4 · 试水首发）

- **定位**：滑动下刀切开糕点，截面揭示是核心（月饼流心淌出、蛋糕露夹层、汤圆爆浆），切完摆盘收图鉴。
- **核心循环**：选糕点 → 下刀（可多刀）→ 截面揭示动画 → 摆盘 → 图鉴点亮 → 下一件。
- **技术方案**：糕点为离屏 Canvas 分层绘制（皮/夹层/流心层）；切割 = 切割线两侧 clip 分离 + 微位移 + 微颤；流心 = 粒子液滴从切面发射（粘度/速率参数化）；摆盘为 DOM/CSS 层。固定时间步 + seed 复现（同 seed 同糕点同切序同结果）。
- **复用**：19 号分层渲染纪律；13 号 [contour.js](../../projects/13-jelly-atelier/src/) 裁切几何；10/11 号粒子；13 号 `cleanCollection` 图鉴上限清洗。
- **content.json 草案**：`pastries[]`（id/name/family=月饼|汤圆|青团|蛋糕/layers[]/flow 粒子参数/skin）、`cutting`（gestureTuning/separation 位移与微颤）、`plating`（盘子/摆位）、`collection`、`copy`、`quality`。
- **魔法时刻**：月饼流心淌出特写；截图产物 = 整套餐点图鉴 + 切面特写卡。
- **专项验收**：切割手势跟手（≤1 帧延迟）；截面层数与 content 定义一致；流心粒子总量在 quality 档位内；图鉴去重与上限；连续快切不丢刀、不跳变。
- **主要风险**：多刀切割的 clip 状态管理复杂度——首发限定**一刀/两刀**，多刀后续版本再加。

### 6.2 27-敲晶洞（A2 · 试水首发）

- **定位**：敲开原石揭示晶簇，矿物标本图鉴（紫晶/萤石/月光石…），收藏向。
- **核心循环**：选原石 → 逐下敲击（裂纹按敲击点蔓延）→ 最后一击爆开 → 晶簇折射光斑 → 摆上标本架。
- **技术方案**：裂纹系统 = 敲击点为种子的分支生长（每击新增裂纹段，密度累积到阈值触发爆开，阈值随石种）；石屑粒子 + 爆开冲击波；晶簇 = Canvas 2D 伪 3D 多面体（晶面参数化：面数/朝向/高光）；稀有晶开出时光柱 + 满屏光尘（11 号 hero 粒子模式）；不同石头敲击震动参数不同（手感调参全入 content.json）。
- **复用**：18 号整体架构（model/render/storage 分层、固定时间步、seed、图鉴）；10/11 号粒子；22 号 catchRecords 式稀有度记录。
- **content.json 草案**：`rocks[]`（id/name/shell 纹理参数/crackParams 分支与阈值/hitFeel 震动）、`crystals[]`（id/name/family/rarity/facets/glow/hidden 隐藏矿种）、`bench`（标本架）、`collection`、`gestureTuning`、`copy`、`quality`。
- **魔法时刻**：石头裂开晶体露出的反光瞬间；截图产物 = 满架发光标本柜。
- **专项验收**：裂纹生长确定性（同 seed 同击点序列同裂纹）；爆开阈值可达（内容测试：任一原石在合理击数内可开）；稀有度分布符合配置权重；标本架状态持久化与恢复。
- **主要风险**：伪 3D 晶簇观感不达"精致感"——G0 样板阶段先做一颗晶簇的视觉验证（47 号：暂停看材质是否成立）。

### 6.3 28-捏捏工坊（A1 · 主力，工作量最大）

- **定位**：制作 + 收集 + 盘捏解压；天花板最高，与 13 果冻严格分界（果冻=凝固的透明：倒/静置/嵌物；捏捏=会变形的软体：揉/包芯/合模，卖点=裂/弹/爆/破/瘪，48 号 §6）。
- **核心循环**：选材质族 → 制作小游戏 → 脱模/成型 → 上架收藏 → 盘捏解压 → 图鉴点亮 → 货架每周新款。
- **五材质族**（48 号 §6 完整表，制作差异与手感签名不得混淆）：
  1. **脆皮脆脆**：模具反复蘸壳（每蘸一层壳变厚可见）→ 凝壳 → 注软芯。盘捏：按出裂纹蔓延；捏三下整壳碎裂露芯，碎屑迸落。
  2. **糯糯慢回弹**：双色粉团揉出大理石纹 → 模压 → 蒸发泡鼓起。盘捏：深指印数秒缓缓弹回；捏久留永久浅痕。
  3. **爆浆流心**：做皮 → 针管注芯（充盈度可见）→ 封口捏褶。盘捏：挤到皮绷薄发白，"啵"地喷出流心粒子。
  4. **起泡软胶**：双色胶混合 → 打发充气（体积膨大气泡密布）。盘捏：戳破小泡有顿挫（+可选音效）；拉伸出丝回缩颤动。
  5. **充气啵啵**：打气塑形，表面绷紧时颜色变浅。盘捏：越捏越大，过临界"噗——"泄气瘪掉打转。
- **技术方案**：形变系统 = 波场叠加（pokeWave 扩展：多触点、裂纹状态机、碎屑发射、泄气缩径+旋转）；五族手感签名各自独立参数组；制作小游戏 = 步骤状态机（蘸壳次数/揉团轨迹/注芯量/打发时长/打气量均参数化）；图鉴三维（族×造型×限定色），按手感分五页。
- **复用**：13 号 `pokeWave/sampleUnmold/pourAmount`（动效数学）；13 号 mold-editor/contour（模具轮廓）；11 号粒子（碎屑/流心/气泡）；47 号 §4 受力动效阶段表（触碰 0-80ms/回弹 450ms/余振 900ms）。
- **content.json 草案**：`families[]`（id/name/craft 步骤配置/squish 手感签名参数组/sounds 可选）、`molds[]`、`shapes[]`、`colors[]`（含限定色）、`shelf`（weeklySlots/rotation，C9）、`collection`（dimensions/pages:5/limits）、`copy`、`quality`。
- **分批放量**：首发脆皮脆脆 + 糯糯慢回弹（一个"裂"一个"弹"，签名差异最大、验证最充分）；第二批爆浆流心 + 起泡软胶；第三批充气啵啵 + 限定色/造型扩充。
- **魔法时刻**：脱模撕开瞬间 + 脆壳碎裂露芯；截图产物 = 收藏架（材质×造型×色）。
- **专项验收**：五族手感签名盲测可区分（内部试玩对照）；连续触发从当前姿态响应不跳回初始帧（47 号）；裂纹/泄气/爆浆状态可恢复或明确终结；制作小游戏每步反馈三连（形变+粒子+状态变化）；图鉴三维组合完整性测试。
- **主要风险**：全仓库最高——手感不达"解压"标准。对策：Phase 1 期间并行做样板（G0 条件③），样板不过则调整技术方案（波场 → 网格形变）再进编码；分批放量控制单次损失。

### 6.4 29-糖画转盘（A3 · 国风）

- **定位**：非遗题材国风原创，无直接对标（供给稀少是机会）。
- **核心循环**：转盘定图样 → 按住屏幕糖浆随笔迹流出 → 松手渐渐凝固出琥珀光泽 → 铲刀贴板铲起 → 收入糖画册。
- **技术方案**：笔迹 = pointer events 记录；糖浆流 = 延迟跟随（跟随滞后 + 速率随手速，慢了滴落堆积，13 号 pourAmount 速率积分逻辑）；凝固 = 分阶段高光扫过（时间线驱动，sampleUnmold 式多通道）；铲起 = 整片微颤 + "叮"（可选音效）；透光展示 = 对光高光模式。图样完成度 = 笔迹与引导轮廓（pathGuide 关键点）的覆盖率判定，宽容度参数化。
- **复用**：23/24/25 号国风视觉基调（48 号明确要求）；11 号 letterFlight 路径跟随；13 号时间线与速率积分。
- **content.json 草案**：`patterns[]`（id/name/season 节气生肖限定/difficulty/pathGuide 关键点/completionRule）、`sugar`（flowRate/followLag/dripRule/settleTime/gloss/lift）、`wheel`、`album`、`copy`、`quality`。
- **魔法时刻**：铲起整片糖画对光一照；截图产物 = 透光糖画图。
- **专项验收**：手速→流速映射跟手；滴落堆积不穿模；完成度判定对新手宽容（≥80% 覆盖即成）；凝固/铲起动画按 47 号阶段表逐帧可查；节气限定图样切换只改 content.json。
- **主要风险**：笔迹美感依赖引导轮廓设计——图样库先做 8-12 个基础款打样，节气款走周更。

### 6.5 30-打铁花（B5 · 奇观向）

- **定位**：节日爆发型粒子烟花，验证"奇观+氛围"赛道。
- **核心循环**：拖拽蓄力抛铁水 → 击打时机判定 → 花树绽放（越准越大越密）→ 连续命中点亮夜空 → 花型图鉴。
- **技术方案**：蓄力 = 拖拽向量 + 轨迹预览；抛物线 = 21 号 createFlight/stepFlight 固定时间步；击打时机窗 = timingWindow 判定（perfect/good 档位）；绽放 = 1600℃ 橙金渐变粒子树（分支数/密度参数化）+ 落地溅射余烬；夜空点亮状态 = 连续命中累积。
- **复用**：21 号抛物线物理；11 号粒子（发射/生命周期/衰减）；20 号粒子预算纪律（沙粒 ≤350 的同款上限思维）。
- **content.json 草案**：`bloomPatterns[]`（id/name/density/branches/rarity）、`iron`（charge/trajectory/timingWindow/splatter）、`sky`（scenes/festivalThemes，C10）、`collection`、`copy`、`quality`。
- **魔法时刻**：第一朵完整花树绽开；截图产物 = 绽放瞬间（自带氛围）+ 花型图鉴。
- **专项验收**：蓄力-抛出-击打链路 ≤3 次操作内可完成首轮绽放；粒子总量在 quality 档位内（低端机降密度不降玩法）；时机判定公平（固定 seed 可复现）；春节/中秋限定只改 content.json。
- **主要风险**：粒子观感同质化——花型差异化靠分支结构参数，G0 粒子样板阶段验证 2-3 种花型结构。

### 6.6 31-高压水枪洗刷刷（B6 · 实现路径最短）

- **定位**：before/after 揭示，对比图天然是爆款笔记格式。
- **核心循环**：选场景 → 按住喷射冲开泥垢 → 底色渐露 → 整幅洗净 → 自动出对比卡 → 图鉴。
- **技术方案**：泥垢层 = 离屏 Canvas 噪声纹理（块密度/色相参数化）；擦除 = `destination-out` 按水柱命中半径；泡沫/水雾/脏水痕 = 粒子与贴花；洗净判定 = 覆盖网格（20 号 96×96 模式）统计擦除比例，只在判定时刻采样，不逐帧读像素；对比卡 = 前后帧截图合成（01 号分享卡渲染模式）。
- **复用**：19 号分层；20 号网格更新预算（≤20Hz）；01 号 [shareCardRenderer](../../projects/01-sbti/src/share/shareCardRenderer.ts)。
- **content.json 草案**：`scenes[]`（id/name/underPaint 底画/dirt 噪声参数/dirtTint/difficulty）、`water`（jet 半径与压强/foam/mist/drain）、`progress`（grid 分辨率/cleanThreshold/compareCard）、`collection`、`copy`、`quality`。
- **魔法时刻**：洗净瞬间 before/after；截图产物 = 对比卡。
- **专项验收**：水柱跟手；擦除边缘自然（水花粒子修饰）；洗净阈值不卡死（内容测试：任一场景合理操作内可洗净）；对比卡生成成功且不含用户数据。
- **主要风险**：最低——适合作为 26 之外的"第二试水"或并行项。

### 6.7 32-放河灯（B7 · 治愈氛围）

- **定位**：全场唯一允许一行文字的入口（可不填）。
- **核心循环**：可选写一行愿望 → 划火柴点亮灯芯 → 推灯入水随波漂远 → 镜头拉远，满河千百盏灯渐次亮起。
- **技术方案**：水面 = WebGL1 波纹（Canvas2D 降级，21/22 模式）；涟漪推开 = 10 号涟漪粒子；灯光倒影摇曳 = 灯形贴图 + 水面扰动采样；划火柴 = 摩擦手感（力度阈值 + 火苗生长）；漂流 = 缓慢流场 + 灯间避让；镜头拉远 = filmTime/ease 驱动（25 号 sketch.js 模式）；满河灯 = 分批渐次点亮脚本（ceremony 配置）。**愿望文本只存当次会话，不持久化**（隐私稳妥默认，待确认项 §12）。
- **复用**：21/22 号水面；10 号涟漪；25 号镜头脚本；23/24/25 号视觉基调。
- **content.json 草案**：`lanterns[]`（id/name/festival 七夕中秋限定/shape/glow）、`river`（flow/ripple/reflection）、`match`（friction/ignite）、`ceremony`（launch/drift/finale 渐次亮起脚本）、`wish`（maxChars:12/persist:false）、`collection`、`copy`、`quality`。
- **魔法时刻**：镜头拉远满河灯渐次亮起；截图产物 = 满河灯远景。
- **专项验收**：灯数上限与内存（满河灯为贴图池复用，不无限建对象）；漂流不穿模；镜头脚本后台暂停/恢复连续性（47 号）；七夕/中秋限定只改 content.json。
- **主要风险**：氛围类玩法"没得收集"——对策：灯形图鉴 + 里程碑（第 N 盏灯解锁新灯形）维持复访。

### 6.8 33-摇签筒（C8 · 占卜位）

- **定位**：占卜需求验证（塔罗 67.9w），避开韦特版权；仪式全动画，文字压到一行。
- **核心循环**：拖拽摇晃签筒 → 签枝跳动碰撞（有声，可选）→ 一支跳出倒下 → 展开**只有一行**签文 → 签文卡。
- **技术方案**：签枝 = 有限弹簧/碰撞简化刚体（22 号约束思维，不引入物理引擎）；摇晃 = 拖拽加速度驱动筒体，签枝响应；跳出 = 弹道 + 落地弹跳；抽取结果 = rng 状态内嵌（16 号模式，可回放防"重摇换签"作弊感知）；签文卡 = 01 号分享卡模式。
- **复用**：22 号弹簧约束 + 状态机；16 号 rng 内嵌；23 号国风视觉与签文 content.json 集中配置；17 号音频链路（碰撞声，可选）。
- **content.json 草案**：`signs[]`（id/text ≤16 字/category/season 限定）、`tube`（shake 参数/sticks 数量与物理/collision 可选音效）、`ceremony`（jumpOut/reveal）、`collection`、`copy`、`quality`。
- **魔法时刻**：签跳出倒下、展开一行签文；截图产物 = 签文卡。
- **专项验收**：摇晃物理稳定（长时间摇不崩溃不穿透）；同一次会话重摇规则明确（首签有效或允许重摇，写死在 model 并测试）；签文一行显示不折行（375 宽度下）；节气/节日限定签只改 content.json。
- **主要风险**：签文库质量——文案需单独评审（一行字但要"准"，参考 48 号 §3.3 爆款共性第 5 条）。

### 8.1 技术栈（全部 8 个项目）

### 8.3 内容、存储与随机

- **content.json**：业务内容唯一来源；顶层统一 `title/storageKey/version/copy/quality` + 业务段（§6 草案）；构建期内联，运行时不 fetch。
- **存储**：localStorage 信封（schemaVersion + 迁移函数）；只存结构化状态（图鉴、进度、设置）；**禁止**持久化用户媒体/Base64/Blob；32 号愿望文本默认不持久化。
- **随机**：mulberry32 + 状态内嵌 rng（16 号模式）；seed + contentVersion + simulationVersion 三要素复现；QA 可指定 seed。

### 8.4 音频（可选）

按项目决策；若做，复制 17 号链路（构建期 Base64 白名单校验 ≤1MiB/段 → 运行时 decodeAudioData → BufferSource+GainNode → generation 防幽灵清理），测试覆盖 17 号 audio-bank.test.mjs 场景清单。**无音效项目必须保证纯视觉反馈完整**（形变+粒子不可缺）。

### 8.5 宿主避让（所有项目硬门槛）

- 避让参数配置化（G0 系统），覆盖层模拟进 qa 脚本。
- 交互热区不进左右上角宿主按钮区及触摸余量；横竖屏切换与关闭入口始终可见。
- 三态验证：竖屏 / 真实横屏 / **模拟横屏（CSS 旋转，宿主占位区需坐标映射）**。
- 普通浏览器预览不算数；真机验收未完成时在 DELIVERY.md 明确记录。

## 10. 任务包拆分与协作

每项目开工时拆为 8 个任务包（沿用 19 号 §13，按本批技术栈调整），顺序执行、不得跳包：

| # | 任务包 | 职责 | 不可修改项 |
|---|---|---|---|
| 1 | content | content.json 草案→终稿（数值、手感参数、文案、限定项） | 不改代码 |
| 2 | schema-storage | 类型、校验、存储信封与迁移 | 不改内容语义 |
| 3 | game-logic | model.ts 纯函数 + seed + 固定时间步 + 单测 | 不碰渲染 |
| 4 | render-ui | 分层渲染、粒子、手感参数接入、宿主避让 | 不改逻辑语义 |

| 6 | integration | 真实内容与资源接入 | 冲突统一在此处理 |
| 7 | qa | §9 矩阵全量 + 专项验收 + 修复复测 | 不得删测试过检 |
| 8 | release | 构建、ZIP 审计、上架素材（全新制作）、平台三步验证提醒 | 记录真机验证状态 |

协作规则：一个 Agent 一个项目目录（AGENTS.md）；本轮**零新增依赖**（模板复制 21 号模式），不触发根锁文件改动；跨项目共性发现（如宿主避让参数需校准）报总控统一决策。
