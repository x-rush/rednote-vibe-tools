## 1. content.json 内容封装

**规则**：业务内容（文案、数值、图鉴、关卡、播放选项）只放 `src/content/content.json`，代码不硬编码业务数据。31 号文档定义了 Schema 约定。

**通用顶层结构**（01-08 批次）：

```json
{ "schemaVersion": 1, "contentVersion": "...", "projectId": "...", "meta": {...}, "<业务根字段>": {...} }
```

- 18-25 批次常见顶层：`title`、`storageKey`、`version` + 业务字段（如 19 的 `habitats/spawnSlots/species/clusterRules/occluders/gestureTuning/atlasFrames/copy/audio/layout/quality`；22 的 `spots/baits/fishSpecies/biteProfiles/fightProfiles/physicsTuning/inputTuning/catchRecords`）。

**校验流水线**（19 号文档 §4，各 React 项目同构实现）：

```text
应用启动 → import content.json → 校验顶层 meta → 校验项目 schema
→ 建 ID 索引（Map<id, entity>）→ 读取并迁移用户状态
→ 校验用户引用的内容 ID → 渲染继续/开始页面
```

代表实现：

| 项目 | 文件 | 关键导出 |
|---|---|---|
| 01 | [src/content/validate.ts](../../projects/01-sbti/src/content/validate.ts) | `ContentValidationError`、`isRecord` |
| 08 | [src/content/schema.ts](../../projects/08-earth-online/src/content/schema.ts)、[validate.ts](../../projects/08-earth-online/src/content/validate.ts) | schema + 校验 |
| 17/23/24 | [tools.mjs](../../projects/17-call-stories/tools.mjs) | 构建期解析校验并产出 `dist/content.js` |

## 2. 存储信封与版本迁移

**规则**：所有持久化走带 `schemaVersion` 的信封（envelope），版本不匹配走迁移或重置；只存结构化状态。

代表实现：

| 项目 | 文件 | 存储 key / 方案 |
|---|---|---|
| 01 | [src/storage/storage.ts](../../projects/01-sbti/src/storage/storage.ts) | `xhs-tool:shbti:state:v1`；`loadStorage/saveStorage/clearStorage` 校验 schemaVersion+quizVersion |
| 02 | [src/storage/storage.ts](../../projects/02-wuhualu/src/storage/storage.ts) | `xhs-tool:wuhualu:state:v1`；默认 payload 含收集进度/最近尝试/设置 |
| 04 | [src/storage/](../../projects/04-bianjing-drink-shop/src/storage/) | IndexedDB + `migrate-v1..v4` 逐版迁移 + `repository` + `save-codec`，仓库内最完整的迁移样例 |
| 07 | [src/storage/storageV2.ts](../../projects/07-conversation-replay/src/storage/storageV2.ts) | `schemaVersion: 2` 信封：`saveMode`、`draft`、`savedResults`（上限 3 份，隐私模式不落盘） |
| 12 | [src/engine.js](../../projects/12-tomato-garden/src/engine.js) | `STORAGE_KEY = 'tomato-garden-v1'`，`freshState()` 定义信封默认值 |
| 13 | [src/engine.js](../../projects/13-jelly-atelier/src/engine.js) | `cleanCollection`/`cleanRecipe` 读入即清洗（id 白名单、条数上限、数值边界），坏数据静默丢弃 |

**清洗函数模式**（13 号最典型）：`cleanX(raw, content)` 接受任意 localStorage 读出的脏数据，逐字段验证（id 存在于 content、数值有限且在界内、数组去重截断），不合法返回 null/空数组。**任何从存储读出的数据都先过清洗再进状态机。**

## 3. seed 复现与 PRNG

**规则**（19 号文档 §6）：随机不散落 `Math.random()`，统一用可注入 seed 的 PRNG；seed 随一轮开始保存，刷新后输出一致；QA 可指定 seed 复现。

代表实现：

| 项目 | 文件 | 关键函数 |
|---|---|---|
| 02 | [src/game/random.ts](../../projects/02-wuhualu/src/game/random.ts) | `hashSeed`、`createSeededRandom`、`seededShuffle` |
| 08 | [src/domain/random.ts](../../projects/08-earth-online/src/domain/random.ts) | 任务/事件加权抽取 |
| 13 | [src/engine.js](../../projects/13-jelly-atelier/src/engine.js) L30 | `mulberry32(seed)` |
| 16 | [src/engine.mjs](../../projects/16-flower-werewolf/src/engine.mjs) L4-10 | mulberry32 变体作为**状态内嵌 rng**：`s.rng` 存进游戏状态，事件序列可完整回放 |
| 18-25 | `src/core/model.ts` 等 | 固定时间步 + seed + `simulationVersion` 三要素复现 |

mulberry32 标准写法（13/16 共用）：

```js
function mulberry32(seed) { return () => { seed |= 0; seed = seed + 0x6D2B79F5 | 0;
  let t = Math.imul(seed ^ seed >>> 15, 1 | seed);
  t = t + Math.imul(t ^ t >>> 7, 61 | t) ^ t;
  return ((t ^ t >>> 14) >>> 0) / 4294967296; }; }
```

## 4. 状态机引擎

**规则**：玩法逻辑是显式状态机 + 纯函数 reducer/命令处理器，UI 只渲染状态；表现层永不回写逻辑。

三种风格并存：

1. **React reducer**（08）：[src/app/state.ts](../../projects/08-earth-online/src/app/state.ts) 处理 `RESTORE / OPEN_PREFERENCES / QUEST_ACCEPTED / GUILD_UPDATED...` 等 action；`shouldPersistAppState` 控制持久化边界。
2. **剧情条件引擎**（03）：[src/game/conditions.ts](../../projects/03-dalisizian/src/game/conditions.ts) 的 `evaluateCondition` 支持 `all/any/not/field` 组合条件，`getAvailableOptions` 按状态过滤分支；[engine.ts](../../projects/03-dalisizian/src/game/engine.ts) 维护 `CaseRuntimeState`（visited/evidence/tags/verdicts）。04 号的 `engine/conditions.ts`、`operating-mode.ts` 是同一模式的经营版。
3. **命令式状态机**（16）：[src/engine.mjs](../../projects/16-flower-werewolf/src/engine.mjs) `PHASES = ['deal','night','day','vote','roundEnd','over']`；`createGame(seed, characters, roles)` 初始化、`emit()` 追加事件流（`events/audit/evidence` 三个日志数组）、`winnerOf()` 判定胜负。非法动作 `ensure()` 抛错，天然可测。

## 5. Canvas / WebGL 渲染架构

**分层原则**（19 号项目最完整）：Canvas 2D 多层绘制，从后到前——背景缓存 → 静态土壤/根 → 菌体 → 移动遮挡叶 → 水珠土粒 → 前景光影。静态背景烘焙缓存，只重绘变动区。

| 项目 | 方案 | 要点 |
|---|---|---|
| 19 | Canvas 2D 分层 + CPU 空间网格 | 网格同时服务命中检测与遮挡查询 |
| 18 | WebGL1 + Canvas2D 混合，高低画质两套 render | 高档开 WebGL 特效，低档保逻辑只降视觉 |
| 20 | WebGL1 2.5D + CPU 96×96 高度网格 | 地形局部更新/上传遮罩；沙粒 ≤350、网格更新 ≤20Hz、输入/模拟 60Hz |
| 21 | WebGL1 水面 + Canvas2D 石头/粒子 | WebGL 失败降级简化水面；固定时间步物理 |
| 22 | WebGL1 水面 + 2.5D 鱼/竿线 + DOM/CSS | 纯状态机 + 有限弹簧约束，**不用**大型刚体/绳索引擎 |
| 25 | p5.js（本地 vendor）+ Canvas2D | [src/flow.js](../../projects/25-moonfall/src/flow.js) `MoonFlow.create/route/sections/pools/ledges/rockProfile`；[src/terrain.js](../../projects/25-moonfall/src/terrain.js) 山脉/月亮/薄雾 |

**固定时间步**：模拟以 1/60s 步进，与渲染帧率解耦；配合 seed 保证同版本完全复现（18 的 DELIVERY.md 明确：`seed / contentVersion / simulationVersion` 三要素）。

**性能纪律**：粒子池 + typed arrays 复用；禁止逐帧 `readPixels`/`toDataURL`；降级顺序——先减背景粒子、滤镜分辨率、DPR，再减次要动态，**核心操作反馈永远保留**。

**弹簧物理**：

## 7. tools.mjs 构建脚本模式

12-25 全部不依赖项目级 devDeps，构建统一走根目录 Node 脚本。以 21 号 [tools.mjs](../../projects/21-lakeside-stone-skipping/tools.mjs) 为标准范例（~17 行核心）：

```text
lint   → spawn tsc --project tsconfig.json（strict）
         + JSON.parse(content.json) + node --check 工具脚本
test   → rolldown 打包 src/model.ts 为 .cache/model.mjs（ES 格式）
         + node --test tests/*.test.mjs
build  → rolldown({ input: src/app.ts, transform: { target: 'chrome61' } })
         → dist/app.js（IIFE，name 全局）
         + 复制 index.html / style.css / assets
         + audit() 产物审计
dev    → build 后起 node:http 静态服务（路径穿越防护，端口默认 4321）
preview→ 只起静态服务
```

关键工程细节：

- rolldown / typescript 通过**硬编码工作区路径**调用：`../../node_modules/.pnpm/rolldown@1.2.5/...`、`.../typescript@6.0.3/bin/tsc`（由工作区依赖图传递安装，主要是 React 批次的 vite 8/typescript 引入）。
- `audit(dir)` 递归校验扩展名白名单 + 扫描 `dist/app.js` 禁止 `fetch( / new Worker( / new Function( / eval( / WebAssembly. / import(`。
- 更早的 12-17 用 `scripts/serve.mjs` + `scripts/build.mjs` + `scripts/lint.mjs` 分文件版本，逻辑等价。
- 专用变体：14 号 [scripts/build-minitool.mjs](../../projects/14-tongfu-rhythm/scripts/build-minitool.mjs)（含 ffmpeg 音频转码与运行时代码替换）；17/23/24 的 `tools.mjs`（rolldown 虚拟模块注入音频/内容，多 qa 子命令，ZIP 打包）。

## 8. 音频 Base64 + WebAudio 链路

**构建期**（两条参考路线）：

- 14 号 `build-minitool.mjs`：读 `src/content/content.json` 里的音轨配置 → `ffmpeg` 编码为 80k MP3 → Base64 写入 `release/package/audio-data.js`（`window.TONGFU_AUDIO = {...}`）→ 把源码中 `loadAudio` 的 `fetch(asset(...))` 替换为 `atob → Uint8Array → ctx.decodeAudioData` → 校验产物无 `fetch/import/import.meta`、单段 ≤ 1 MiB。
- 17 号 [tools.mjs](../../projects/17-call-stories/tools.mjs)：扫描 `assets/audio/*.mp3` → 文件名白名单校验 → 每段 ≤ 1 MiB → Base64 编码为 rolldown **虚拟模块** `embedded-audio` 注入 `src/app.mjs` → 输出 `dist/app.js`。

**运行期**（17 号 [src/audio-bank.mjs](../../projects/17-call-stories/src/audio-bank.mjs)，标准参考）：

```text
createAudioBank(embeddedAudio)
  decode(file): data[file] 取 Base64 → atob → Uint8Array → context.decodeAudioData
  create(file): 返回音频对象 { play/pause/volume/muted/currentTime }
    播放：新建 AudioBufferSourceNode + GainNode（音量/静音/loop）
    结束：onended 中停止节点、断开连接、释放 buffer
```

**会话防幽灵**（17 号 [src/call-player.mjs](../../projects/17-call-stories/src/call-player.mjs)）：`generation` token + 定时器；`stop()` 时递增 generation，异步解码完成回调检查 token 不匹配则丢弃，杜绝"已取消却又响铃"。

**测试覆盖要求**（17 号 [tests/audio-bank.test.mjs](../../projects/17-call-stories/tests/audio-bank.test.mjs)）：停止播放、清除 buffer、WebAudio 不可用降级、loop/volume/mute/stop/自然结束。替换播放链路后必须重验剧情节奏逻辑。
