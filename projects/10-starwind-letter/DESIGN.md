# 星风来信高保真动画设计

## 1. 设计目标

“星风来信”要保留参考图最重要的视觉叙事：安静关闭的夜窗被一阵突如其来的风吹开，银蓝线帘向室内前景甩出，月光和星星随后从窗外穿过窗口洒进房间。内置星语是这段动画的落点，不是覆盖在动画之上的产品卡片。

第一版仍采用既定的一次点击交互：句子先快速轮播，用户点击让它减速并停下一句；随后风、窗帘、窗户和星星全自动完成约 7.5 秒的演出。用户不输入文字，也不拖动窗帘或窗户。

## 2. 视觉原则

### 2.1 原动画是主角

- 窗户位于画面上半部偏右，镜头从左前下方斜看窗口。
- 窗框上沿、横梁和帘杆具有一致的透视收束，不能退化为正面矩形窗。
- 初始窗户明确关闭，月亮和窗框从半透明帘线后若隐若现。
- 风从右上方窗外穿过窗口，向左下方室内前景推进。
- 窗扇以铰链边为固定轴向观看者旋开，而不是淡出、缩放或二维平移。
- 所有可辨认主星都必须从窗外出生，穿过窗口后才能进入室内。

### 2.2 星语采用“光尘显字”

- 不使用卡片、厚重信纸、书本、输入框或结果弹窗承载星语。
- 星语位于画面下方约 25% 的安静区域，最多两行，避开窗框、帘线密集区和主风道。
- 字体使用纤细的中文宋体风格回退栈，颜色为克制的银白，只有轻微冷蓝辉光。
- 轮播时中心句清晰，上下候选句像远处光影一样淡化和虚化。
- 风压峰值时选中句降低亮度但保持可读，让视觉焦点交给帘子和开窗动作。
- 星星进入后从文字后方和周围经过；主星最终停在句尾附近，文字随之重新点亮。
- “再听一次星空”只在结果态出现，以轻盈文字按钮呈现，不破坏截图构图。

## 3. 技术架构

项目使用工作区现有的 React、TypeScript、Vite 和 Vitest，不增加依赖。场景采用 390×844 的设计坐标系，再根据实际视口等比缩放并居中；375、390、430 CSS px 下使用同一套空间关系。

### 3.1 模块边界

- `ExperienceMachine`：管理合法状态、点击锁、重播、暂停和恢复。
- `SceneTimeline`：维护统一的动画时间、阶段进度和页面失焦暂停。
- `WindowLayer`：绘制斜视窗框、窗扇、月亮、窗外空间和月光。
- `CurtainLayer`：生成并更新独立帘线的贝塞尔路径。
- `ParticleSystem`：管理窗外和室内粒子、穿窗检测、生命周期及性能档位。
- `PhraseCarousel`：负责轮播减速、随机落句、近期去重和最终文字表现。
- `AudioController`：在首次用户点击后解锁并播放短促的风、窗框和星铃反馈；失败时安全静音。

React 只负责状态和语义 UI。连续动画由同一个 `requestAnimationFrame` 时钟驱动，避免 CSS、SVG 和 Canvas 各自计时造成失步。

### 3.2 渲染分层

从后到前的图层顺序为：

1. 深蓝室内背景和环境渐变。
2. 窗外 Canvas 粒子层，只能在窗口多边形裁切区内显示。
3. SVG 月亮、窗外空间、窗框和关闭/开启中的窗扇。
4. SVG 月光束与风流线。
5. SVG 线帘。
6. 室内 Canvas 粒子层。
7. DOM 星语与结果操作。
8. 顶部音效控件。

粒子在窗外阶段由窗外层绘制。只有位置连续穿过窗口平面、且窗扇开启达到阈值后，粒子才转移到室内层。这样可以直接证明星星来自窗外，而不是在室内淡入。

### 3.3 窗户与帘线

窗户由一组设计坐标中的四边形描述。窗扇的铰链边保持固定，另外两个角根据开启进度和透视投影计算新位置，形成约 65° 的向室内旋转。月光宽度、亮度和落点使用同一开启进度。

首版使用约 64 根线帘。每根帘线拥有独立长度、亮度、相位、延迟和风响应系数；顶端固定，越靠近底端位移越大。线条使用二次或三次贝塞尔曲线，风压由迎风侧向另一侧传播。峰值时大部分线条形成从右上固定点到左下前景的扇形长弧，但仍保留少量落后线束和回弹余波。

## 4. 状态与数据流

稳定状态依次为：

`loading → spinning → slowing → selected → wind → window-opening → stars-entering → result → resetting → spinning`

- `spinning` 只接受第一次主场景点击，音效控件点击不触发选句。
- 进入 `slowing` 时立即锁定目标句和后续主动画，连续点击不能改变结果。
- `selected` 结束后由统一时间线自动推进，不再需要用户输入。
- `result` 只接受一次重播请求；`resetting` 期间锁定操作。
- 页面失焦时暂停统一时钟和音效，恢复后从一致进度继续。
- 刷新不恢复半开的窗户，始终从稳定首屏开始。

内容从 `src/content/content.json` 加载并校验。最近八次结果在浏览器会话内去重。内容文件异常时使用打包在代码中的最小非业务回退提示，不阻塞场景进入。

## 5. 点击后演出时间线

| 相对时间 | 阶段 | 画面与声音 |
|---|---|---|
| 0.00–1.20s | 减速 | 轮播滚过 3–6 句，带惯性停下；首次点击在 100ms 内产生压缩或光圈反馈。 |
| 1.20–1.90s | 静默停顿 | 星语微亮，月亮或窗外一颗星闪一下，帘线底端首次轻动。 |
| 1.90–3.40s | 风压爆发 | 风声快速增强；帘线受力传播并向左下前景拉成长弧面。 |
| 3.40–4.30s | 开窗 | 窗框轻颤约 120ms，窗扇带重量感向室内旋开，月光同步扩大。 |
| 4.30–5.20s | 星尘进入 | 微小星尘从窗外聚向开口，穿窗后沿月光扩散。 |
| 4.70–6.20s | 拖尾进入 | 细长光粒沿弧线穿窗洒入，形成演出的视觉峰值。 |
| 5.20–6.50s | 主星进入 | 约八颗主星依次进入，至少一颗具有可连续追踪的完整路径。 |
| 6.50–7.50s | 星语形成 | 风势减弱，帘线保留余韵；主星落在句尾附近，星语重新点亮，结果操作淡入。 |

声音不使用循环背景音乐。首次点击后可播放轻微选句反馈，随后用短风声、窗框声和少量星铃增强节奏。音频失败、被浏览器拒绝或用户静音时，视觉演出完整继续。

## 6. 粒子系统

粒子分为三层语义：

- 星尘：高性能档约 70 个，用于表现风的体积和方向。
- 拖尾：高性能档约 22 个，用于形成穿窗速度和弧线。
- 主星：约 8 颗，位置可辨认，负责完整空间路径和最终构图。

每颗主星记录 `outside`、`crossing`、`inside`、`settling` 四个空间阶段。窗扇未达到开启阈值时不得进入 `crossing`；粒子从窗口多边形之外穿墙时判定为错误。主星进入后沿左下方向继续一段距离，再使用缓动曲线靠近星语，不能在窗口处突然跳到结果位置。

## 7. 性能、降低动态与安全区

- Canvas 有效设备像素比上限为 2。
- 连续帧耗时过高时，先将星尘降至约 35 个、拖尾降至约 10 个、主星降至约 5 个。
- 性能回退不能删除窗扇旋转、帘线长弧面或主星穿窗方向。
- 避免大面积实时模糊；优先使用局部渐变、有限阴影和低分辨率光晕。
- `prefers-reduced-motion: reduce` 时降低轮播速度、帘线摆幅、粒子数量和高速拖尾，但保留自动开窗以及“窗外 → 窗口 → 室内 → 星语”的叙事。
- 顶部音效控件的点击区域至少 44×44 CSS px，并叠加 `var(--safe-area-inset-top, env(safe-area-inset-top, 0px))`。
- 横屏显示居中的竖版舞台，不让场景结构崩坏。

## 8. 内容一致性

星语保持诗意、安慰和微小启示的语气，不作具体未来承诺。候选内容中带有确定性未来结果的句子在进入 `content.json` 前柔化为可能性或祝愿，例如：

- “明天会有一个小小的惊喜”改为“也许明天，会有小小惊喜”。
- “一件好事正在慢慢靠近”改为“愿一件好事慢慢靠近”。

其余内容按 `CONTENT_SPEC.md` 校验 ID、类别、长度、两行上限和语义边界。

## 9. 测试与视觉验收

自动测试至少覆盖：

- 状态转换顺序、非法状态点击和快速连点锁定。
- 轮播减速、目标句固定和最近八次去重。
- 时间线暂停、恢复和重置时的句柄清理。
- 窗扇开启阈值与主星穿窗约束。
- 窗外/室内粒子层转移连续且不能穿墙。
- 降低动态模式仍保留正确方向叙事。
- 内容 JSON 可解析、ID 唯一、类别和句长合法。

视觉实现采用静态构图先行：复杂动画开始前先输出关闭态、风压峰值和完全开窗态三张程序化画面。只有以下关系全部成立才进入粒子细化：

- 窗户位于上半屏偏右，透视方向与参考图一致。
- 关闭态可透过帘线看见月亮和窗框。
- 风压态的帘线从右上固定点甩向左下前景。
- 开窗态能辨认窗扇向观看者旋开。
- 星语处于安静留白，不与主风道竞争。

最终在 375、390、430 CSS px 和非零顶部安全区下分别检查首屏轮播、选中、风压、开窗穿星和结果五个状态。连续重播十次不得出现重复时间线、残余粒子、半开窗或明显掉帧。提交前执行 `pnpm lint && pnpm test && pnpm build`。

## 10. 非目标

- 不逐像素复制参考作品，也不把参考截图作为运行时素材。
- 不实现平台状态栏、作者信息、点赞评论或视频进度条。
- 不增加输入、拖动、抓星星、分享面板、账号、积分或多页面导航。
- 不依赖后端、运行时 CDN、外部 API、Service Worker 或未经确认的设备 API。
