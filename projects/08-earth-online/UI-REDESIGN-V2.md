# 地球 Online：冒险者公会大厅｜UI/UX 重设计 V2

日期：2026-08-26
状态：已完成会话设计确认，待书面规格复核

## 1. 设计目标

把现有“表单加结果卡”升级为一条完整、可恢复的现实支线仪式：用户进入温暖的冒险者公会，登记今天真实可用的状态，从公告板揭下一张安全任务纸，完成后把它收入个人冒险日志。

首要成功标准：

- 5 秒内理解产品是“根据当前状态匹配一件现实小事”，不是随机鸡汤或打卡应用。
- 20 秒内完成状态登记；30–60 秒内看懂推荐任务、匹配理由和退出条件。
- 任务领取、换取、接取、完成、放弃、恢复和异常降级均有明确反馈。
- 游戏化只记录探索投入，不制造战斗力、稀有度、断签或失败羞耻。
- 首次离线启动可用；不定位、不上传证明、不保存图片或个人资料。

## 2. 设计原则

### 2.1 一个核心隐喻

公告板、任务纸、压印和日志是同一套连续的实体隐喻。视觉装饰必须说明当前状态：纸在板上表示“待选择”，揭下表示“已匹配”，黄铜压印表示“已接取”，收入册页表示“已完成或已放回”。

### 2.2 现实先于幻想

世界观是温暖的西方异世界冒险者公会，但任务仍发生在真实日常。允许木板、羊皮纸、车票、路线签、背包牌和黄铜扣件；禁止武器、盔甲、法杖、龙、宝箱、酒馆战斗氛围、金币充值和抽卡语义。

### 2.3 解释先于惊喜

任务揭晓必须同时显示时间、精力、环境、社交、预算、推荐理由和退出条件。任何放宽都明确列出；安全、时间上限、地点、预算和用户明确选择的社交边界不得静默放宽。

### 2.4 低压力游戏化

XP、等级、类别熟练度和徽章只反映已经做过的方向。放弃和换任务不扣分；连续记录不在首屏施压，不展示断签、补签或倒计时催促。

## 3. 视觉系统

### 3.1 气质

方向名为“会呼吸的现实冒险者公会”。整体是编辑设计与手作纸张质感的结合：大厅沉静、任务纸清楚、反馈温暖，避免廉价游戏皮肤感。

### 3.2 色彩

- 大厅夜蓝 `#182824`：主背景和沉浸区。
- 墨绿 `#29433A`：公告板、确认和安全信息。
- 羊皮纸 `#F2E6C8`：主要阅读表面。
- 暖白 `#FFF9E9`：高对比正文底。
- 黄铜 `#B8874E`：压印、边线和关键装饰。
- 酒红 `#8F3F38`：完成印章和强调，不用于失败惩罚。
- 灰蓝 `#58758A`：次操作、帮助和临时模式。

所有正文与背景组合至少满足 WCAG AA。状态不得仅通过颜色区分。

### 3.3 字体与排版

不引入远程字体。标题使用 `Georgia, "Songti SC", "STSong", serif`，界面正文使用系统无衬线。数字、任务编号和短标签使用系统等宽字体栈。

- 首屏标题：32–42px，最多三行。
- 页面标题：26–34px。
- 任务标题：25–31px，允许最长 27 个汉字自然换行。
- 正文：15–17px，行高 1.65–1.8。
- 标签：12–13px；不承载唯一关键信息。

### 3.4 表面与层级

木板和纸张采用 CSS 渐变、噪点感 SVG pattern、内外阴影和轻微旋转，不使用大型背景位图。纸张边缘始终保持足够对比，文字区域不叠加高对比纹理。

## 4. 响应式框架

### 4.1 手机优先

- 375 / 390px：单列，页面内边距 16px，任务纸有效宽度不小于 343px。
- 430px：单列，任务纸最大宽度 398px，不无意义拉大字号。
- 768px 以上：内容最大宽度 920px；大厅可形成公告板与柜台双区，任务纸仍保持 430px 左右阅读宽度。

### 4.2 顶部与底部控件

顶部栏使用：

```css
padding-top: calc(var(--safe-area-inset-top, env(safe-area-inset-top, 0px)) + 8px);
```

若使用 `sticky`，其 `top` 也必须叠加同一安全区变量。底部导航叠加 `env(safe-area-inset-bottom)`。所有锚点目标使用 `scroll-margin-top` 加顶部控件高度与安全区值。

顶部只保留当前场景名、弥拉帮助入口和等级摘要。底部导航为大厅、日志、图鉴、档案四项；领取和结算流程中可临时隐藏底部导航，避免与主动作竞争。

### 4.3 触控与滚动

主按钮至少 52px，普通按钮至少 44px；相邻危险性不同的动作不紧贴。页面允许自然纵向滚动，不锁定 viewport 高度。底部动作区若固定，必须预留等高内容 padding，且不能遮挡长任务文案。

## 5. 信息架构与状态

### S00 首次引导

弥拉半身像、身份和三句引导。第一句固定为“主线不用着急，先来领一个小任务。”第二句说明耗时、地点和安全边界，第三句说明可随时换取或放回。支持跳过；跳过后进入状态登记。引导完成标记只保存布尔值。

### S01 公会大厅｜首次或无进行中任务

首屏展示品牌句、四张真实任务纸缩略样例和“登记今日状态”。次级信息说明 100 条本地审核任务、约 20 秒、无需账号。弥拉在柜台边缘出现，不覆盖主标题或按钮。

### S02 公会大厅｜有进行中任务

当前任务成为第一视觉。展示任务名、等级、预计时间、接取时间和“继续当前任务”；重新登记状态只能作为次级入口，并明确不会覆盖已接任务。

### S03 今日状态登记

采用单页分组卡而非逐题路由，减少等待：

1. 时间：5 / 10 / 15 / 20 分钟。
2. 精力：很低 / 一般 / 不错，对应 1 / 2 / 3。
3. 环境：室内 / 白天可在熟悉公开区域外出。
4. 社交：想独处 / 熟人互动也可以。
5. 目标：放松、探索、整理、运动、连接、观察、创造、学习。
6. 时间段：白天 / 夜间。

预算固定为首发全部 0 元，以不可编辑安全说明呈现。允许载入上次选择，但必须由用户确认今天仍适用。

### S04 匹配中

持续约 700–1100ms，展示系统正在核对的真实条件标签，不显示百分比。用户可跳过动画。算法同步完成后，先尝试持久化 offer，再进入揭晓；持久化失败进入临时模式说明。

### S05 任务揭晓

任务纸展示：类别图标、E/D 等级、任务名、描述、时间、精力、环境、社交、0 元、推荐理由、已放宽项、未放宽安全项、步骤与退出规则。

主动作“接取这项支线”；次动作“换一张”；三级动作“这类任务今天不适合”。弥拉只用头像和两行解释参与，不占据任务纸主体。

### S06 换任务与公告板重排

第一次直接换取；新任务不得与近期展示重复。连续换取时显示已应用的近期排除和“调整今日状态”入口，不责备、不扣 XP、不制造随机冷却倒计时。当前 Foundation 没有真实时间冷却字段，因此 V2 不伪造 30 秒冷却。

### S07 条件回退

当匹配阶段不是 `exact`，揭晓页顶部先展示“放宽了什么”和“始终保留什么”。文案直接消费 matcher 的 `stage`、`reasons` 与 `relaxed`。若为 `no-match`，不伪造通用任务，转到 S17。

### S08 任务进行中

聚焦任务目标、步骤、预计时间和退出条件。显示“不定位、不计时、不上传证明”。主动作“我完成了”；次动作“放回任务板”；三级动作“这类任务今天不适合”。

### S09 完成确认

底部确认 sheet 防止误触，复述任务名并说明只需自我确认，不要求证明。确认后才调用幂等完成结算。

### S10 完成结算

完成印章、任务专属 `completionText`、本次 XP、等级进度变化和本次新徽章。主动作“收入冒险日志”；次动作“再领一项”。没有金币雨、稀有度或连续签到提示。

### S11 放弃确认与完成态

先显示无惩罚说明，再提供可选结构化原因：比预想更累、环境不合适、临时没有时间、改变主意。原因不写入自由文本。确认后记录 `abandoned`，展示任务专属 `abandonText` 并可返回大厅或重新登记。

### S12 不适合反馈

只记录结构化软反馈，允许撤销，不永久删除类别。可选原因与安全硬条件分开；选择“环境不安全”时立即建议停止，而不是仅降低权重。

### S13 冒险日志

按全部、完成、放回、更换、类别筛选。记录日期、标题、类别、状态和 XP；损坏单项隔离显示“已下线任务”，不清空全部日志。空态使用内容包文案。

### S14 类别图鉴与徽章

十类图鉴显示已完成次数和方向说明；五枚成就显示解锁条件。锁定项仍展示明确条件，不采用“?”制造抽卡悬念。E/D/C 说明投入量而非能力，C 只作未来图例。

### S15 冒险者档案

等级、总 XP、当前级进度、累计完成、最佳记录和数据说明。连续记录放在次级区域，并说明间隔不会扣除已有成果。

### S16 弥拉帮助抽屉

任何任务页点击头像打开，不改变当前 offer、active quest、筛选或 RNG。提供任务条件、安全边界、等级含义、本地存储和放回规则五项折叠说明。

### S17 无匹配、存储错误和临时模式

- 无匹配：列出不能同时满足的条件和永不放宽项，返回修改状态。
- localStorage 写入失败：不得显示已保存；允许当前会话临时任务，明确关闭会丢失且不结算永久 XP/徽章。
- IndexedDB 不可用：当前任务与有限 localStorage 历史仍可运行，日志区域显示降级提示。
- 内容损坏或未来 schema：保留原始 key，用户确认重置前不覆盖。

## 7. 数据与文案流

- 任务标题、描述、步骤、完成/放弃文案、类别、目标、徽章和所有业务说明只来自 `src/content/content.json`。
- `content.json` 新增类型化 `ui` 区域承载大厅、引导、恢复、帮助和空态文案；不得把新的业务文案散落在 JSX。
- matcher 的完整结果在 offer 生命周期内保留为 UI 可消费的匹配说明；刷新后可由稳定偏好和任务字段重建基础说明，不能伪造原始分数。
- localStorage 保存稳定 ID、数值、时间、布尔设置和有限结构化原因；不保存图片、Base64、Blob、位置、证明或自由备注。
- IndexedDB 保存长期结构化日志与反馈；不可用时回退到有限 localStorage 摘要。

## 8. 错误处理

所有错误页必须提供用户能理解的原因和下一步。错误分为内容、安全无匹配、当前任务引用失效、localStorage 写入失败、IndexedDB 降级和未知错误。安全无匹配属于正常业务状态，不使用红色警报式视觉。

执行持久化相关动作时遵循：计算下一状态 → 尝试保存 → 保存成功后宣布成功。任何保存失败都不能以成功 UI 掩盖。

## 9. 无障碍

- 使用真实 `button`、`form`、`fieldset`、`legend`、`dialog` 或等价可访问结构。
- 所有图标有可读名称或正确的 `aria-hidden`；弥拉装饰性头像不重复朗读。
- 焦点样式对所有背景可见；弹层打开后焦点进入，关闭后回到触发按钮。
- 动画期间不抢焦点；匹配状态使用礼貌的 live region。
- XP 进度同时显示数字；任务等级和状态不只靠颜色。
- `prefers-reduced-motion: reduce` 下移除位移、旋转、粒子和连续循环。

## 10. 验收策略

自动测试覆盖：

- UI 瞬时状态和领域状态分离；确认、取消和恢复路径。
- 匹配理由、放宽项、任务文案均来自真实 ViewModel/content。
- 首次引导设置、结构化不适合原因和临时模式不含禁存字段。
- localStorage 成功/失败与 IndexedDB 降级呈现一致。
- 任务完成幂等、刷新恢复、日志筛选和锁定/解锁徽章。

真实浏览器覆盖：

- 大厅 → 登记 → 匹配 → 揭晓 → 接取 → 刷新 → 完成 → 结算 → 日志。
- 换任务、非 exact 回退、no-match、放弃、不适合、帮助抽屉和存储失败。
- 375×812、390×844、430×932；另以非零 `--safe-area-inset-top: 32px` 验证顶部控件和锚点。
- `document.documentElement.scrollWidth <= innerWidth`，无断图，所有主要触控目标至少 44px。
- reduced-motion、键盘导航、最长任务标题/描述/退出规则和浏览器 200% 缩放。

## 11. 明确不做

账号、后端、在线排行、支付、运行时 API、定位、上传证明、计时器强制、通知权限、Service Worker、真实地图、逐任务插画、100 个独立图标、分享图片生成和未经确认的设备能力。
