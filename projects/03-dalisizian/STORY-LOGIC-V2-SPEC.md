# 《大理寺字案录》追线索剧情逻辑 V2 规格

状态：`IMPLEMENTED / PRODUCTION QA PASSED`

日期：2026-08-26

## 1. 改造目标

把现有“按固定顺序阅读三段材料”的流程改造成一套可判断、可回查、可复盘的证据推理体验，同时保持纯前端、纯选项、3–5 分钟单案时长与关键事实不可永久错过。

完成后，玩家应当能够：

1. 封存初判后，自由选择三个调查方向，完成任一路线后返回调查板。
2. 先阅读原始材料，再主动执行核验或归档动作，之后才取得对应线索和证物。
3. 在推理失误时得到与本案证据直接相关的反馈，并可一键回到对应调查路线复核。
4. 依靠证据关系完成判断，而不是依靠固定选项位置或通用正确话术。
5. 在结案时看到初判、首次推理、复核过程、终判与评分依据之间的联系。

## 2. 不做事项

- 不增加自由文本输入、后端、运行时外部 API、新依赖或设备权限。
- 不以初判是否符合参考结论作为扣分项。
- 不设置一次选择后永久丢失关键证据的分支。
- 不生成或伪造古文字图形；相关资源继续使用人工核验 SVG、拓片或文字替代。
- 不推倒现有内容索引、存档与结案图鉴体系。
- 不把事实性业务文案硬编码进 JSX；所有案件内容继续只放在 `src/content/content.json`。

## 3. 核心流程

```text
案卷封面
→ 开场问案
→ 初判封存
→ 调查板（三路自由选择）
   ├─ 路线 A：观察原始材料 → 选择核验动作 → 主动收录证据 → 返回调查板
   ├─ 路线 B：追问或对照资料 → 选择证据边界 → 主动收录证据 → 返回调查板
   └─ 路线 C：对质传言陈述者 → 揭示动机/省略 → 主动收录证据 → 返回调查板
→ 三条关键线索齐全
→ 证据关系推理
   ├─ 首次成立：继续下一问
   └─ 首次不成立：指出断裂关系 → 回查对应路线或留在题面复核
→ 终判
→ 初判与终判对照、复核轨迹、评分明细
→ 落印、图鉴、战绩卡
```

调查板不是地理地图，而是案牍式关系板。三个入口始终可见；已完成路线显示所得线索并允许回看。满足全部必要线索后才显示主动作“整理证据，申请终判”。

## 4. 运行时状态与内容模型

### 4.1 新增运行时状态

`CaseRuntimeState` 增加：

- `deductionAttempts: Record<string, number>`：每道推理提交次数。
- `firstDeductionAnswers: Record<string, string>`：只记录第一次提交，用于评分与复盘。
- `reviewedRouteIds: string[]`：因推理反馈主动回查过的调查路线。

保留现有字段：

- `deductionAnswers` 保存最近一次答案，兼容当前 UI 与存档恢复。
- `styleTags` 继续记录调查风格，但不再作为无后果装饰字段。
- `flags` 只保留会被条件、文案变化或评分读取的标记；删除全部未消费的 `rumor-noted` 标记。

旧存档缺少新字段时安全恢复为空集合，不清空已取得线索、证物或已完成案件。

### 4.2 内容模型扩展

为支持内容驱动而非 JSX 特判，增加：

- `NodeKind` 新增 `investigation-hub`，由内容节点声明调查板。
- `CaseNode.routeId?: string`，标识节点所属调查路线。
- `HanziCase.investigationRoutes`，每项包含 `id`、`title`、`summary`、`entryNodeId`、`requiredClueIds` 与 `accent`。
- `DeductionOption.reviewNodeId?: string`，错误答案可指向对应复核节点。
- `DeductionQuestion.focusEvidenceIds`，题面展示本问需要比较的证物。
- `ScoringRule.condition` 支持首次答案、尝试次数、路线回查和风格标签判断。

调查板入口使用现有条件表达式控制状态，不为八案在组件中建立 switch/case。

## 5. 主动取证规则

1. 路线内的资料展示节点只负责呈现材料，不在进入节点时发放线索。
2. 玩家点击明确动作，如“核对年代并收入证据簿”“记录字书原文与适用边界”后，通过 choice effect 获得线索和证物。
3. 同一证据重复归档必须幂等，不重复计数。
4. 关键事实不会因前一轮选错而消失；错误选择应揭示一段反馈，再提供重新观察、追问或对照的入口。
5. 路线完成后返回调查板。回看路线不重复获得评分，也不覆盖首次推理记录。

## 6. 推理与回查规则

每案保留三层推理，但三层必须使用本案的具体材料：

1. **材料关系**：哪些证物能直接证明什么。
2. **边界判断**：从材料到解释的哪一步发生了越界。
3. **终判**：综合证据确定可信范围。

约束：

- 正确选项位置在全案中均衡分布，不能固定为 B。
- 错误项必须对应真实的推理错误，如时代倒置、把声符当图画、从个例推全体、把传统解释当唯一历史事实。
- 第一次错误后展示“断裂链”：`所选结论 → 缺失/冲突证据 → 建议复核路线`。
- 玩家可以直接重答，也可以回查；回查后返回原推理题。
- 错误不会清空证据、阻断结案或把玩家送回案件开头。

## 7. 评分设计

满分 100，四个维度：

| 维度 | 分值 | 规则 |
| --- | ---: | --- |
| 证据完整度 | 30 | 三条必要线索各 10 分，正常结案可全部取得 |
| 首次推理 | 30 | 三道题首次成立各 10 分；重答后仍可继续但不补首次分 |
| 知识边界 | 25 | 终判成立 15 分；完成至少一次由反馈触发的有效回查 10 分。若全程首次成立，则自动获得“证据链完整”10 分 |
| 调查方法 | 15 | 选择至少两次有证据意识的操作 10 分；明确标注不确定性或材料范围 5 分 |

评价区间维持：

- 90–100：明镜高悬
- 75–89：慎思明辨
- 60–74：案牍清通
- 0–59：重审有得

初判只用于结案比较与“观点修正”叙事，不计入正负分。最低完成分不应固定，正常玩家首次有误时应主要落在 70–90 分区间，使图鉴最高分与战绩卡具有实际区分度。

## 8. 八案差异化机制

### 第一案《家字失踪案》：构件功能与社会史跨越

- 核心操作：字形分期、传统构形说核对、社会史推断越界识别。
- 证人动机：为了让听众记住“家”，把可能承担声符功能的构件讲成普遍生活制度。
- 冲突点：字里出现“豕”相关构件，不等于足以证明“古人人人屋内养猪”。

### 第二案《休字树下案》：有效个例与万能规则

- 核心操作：确认“人依木”的传统解释，再检验能否推广到所有汉字。
- 证人动机：以一个直观成功案例兜售“见形猜义”的万能口诀。
- 冲突点：个例成立不推出方法普遍成立。

### 第三案《取字夺取案》：语义变化时间链

- 核心操作：排列不同时期义项，找出把现代常用义倒投古代的节点。
- 证人动机：只截取现代语感最强的一义制造戏剧性。
- 冲突点：后起常用义不能单独定义早期构形。

### 第四案《采字混色案》：近形字身份辨认

- 核心操作：整理 `采 / 釆 / 彩` 的材料身份与关系，不以现代字形近似代替历史证明。
- 证人动机：把三个近形字合成一则好记的颜色故事。
- 冲突点：相关、相近与同一来源是三个不同命题。

### 第五案《监字照盆案》：关系图谱

- 核心操作：连接 `监 / 鉴` 的构件、器物与后续字义关系。
- 证人动机：把多阶段关系压缩成“一个动作直接造出两个字”。
- 冲突点：关系存在不表示演变过程只有一步。

### 第六案《武字止戈案》：传统训释与早期材料辩论

- 核心操作：分别给传统价值阐释和早期字形材料标注其可证范围。
- 证人动机：借一句著名训释推出唯一、原初且无争议的字源结论。
- 冲突点：有文化影响力的传统解释，不自动等同于唯一的早期构形事实。

### 第七案《法字神兽案》：残缺古形重建

- 核心操作：比较 `法 / 灋` 的材料层级，识别省变后的现代字形不能完整保留旧构件故事。
- 证人动机：用神兽叙事替代法律概念与字形材料的复杂历史。
- 冲突点：旧字形材料真实存在，不等于神兽传说的每个细节都是历史事实。

### 第八案《秋字虫火案》：双假说权衡

- 核心操作：把两套解释放入同一证据表，分别标注支持、冲突与尚缺材料。
- 证人动机：把仍有争议的解释包装成确定答案。
- 冲突点：材料不足时，专业结论应允许“证据不足”，而非强行二选一。

## 9. 人物与文本要求

- 每名案件证人至少有三段专属内容：原始断言、被追问后的依据、面对矛盾后的澄清或改口。
- 沈砚只提示调查方法，不提前泄露正确终判。
- 书吏负责材料出处、年代和记录边界，不代替玩家完成推理。
- 每条调查路线至少包含一段案件专属故事信息，使文本卡片既提供知识，也推进人物冲突。
- 删除八案复用的见证人套话和通用推理题；界面通用提示可以复用。
- 文案必须区分“材料显示”“传统解释认为”“现代研究常讨论”“本作虚构情境”四类语气。

## 10. 来源分层

- `A`：古籍、权威字书、可核验的原始或基础资料。
- `B`：现代学术研究、权威工具书或博物馆/高校资料，用于支撑语义变化和学术争议。
- `F`：本作人物、对白与案件包装，只挂在场景或结案叙事，不挂在事实证物上。
- 每件证物只列直接支撑其正文的来源，不再给同案所有证物机械复用同一来源组。
- 每案至少配置一条适用于现代解释或争议边界的 B 类来源；无法核验时明确写入不确定性，不伪造来源。

## 11. UI 与动效

### 调查板

- 三张路线卡通过红线连接中央案签；完成路线后红线由灰转朱红，并出现所得线索标题。
- 进入路线采用 180–240ms 的案纸推入过渡；返回调查板采用反向归档过渡。
- 最后一条关键线索归档后，中央“申请终判”印章出现一次轻微落印反馈。

### 主动取证

- 玩家选择归档动作后，证据卡从当前材料区域缩入右上角证据簿计数。
- 动效只改变视觉，不延迟状态持久化；`prefers-reduced-motion` 下退化为 1ms 状态切换和静态高亮。

### 推理反馈

- 正确关系以朱线闭合；错误关系以墨线中断，并显示缺失的证据类别。
- 不使用抖动、红屏或惩罚性音画反馈。
- 所有动画不遮挡按钮焦点，键盘与触屏均能完成相同流程。

## 12. 兼容与恢复

- 内容版本升级后，旧案中仍有效的稳定 ID、已结案记录和图鉴最高分继续保留。
- 旧的进行中案件若当前节点不再存在，只重开该案件，不清理其他案件和图鉴。
- 新状态字段一律提供安全默认值并限制数量，继续禁止存储图片、Base64、音视频或 Blob。
- 内容节点缺失、路线配置错误或无可用选择时显示可恢复错误页，并允许返回案卷柜。

## 13. 验收标准

### 自动验证

- 8 案每案至少存在三条调查路线，三条路线可按六种顺序完成。
- 所有节点可达、无悬空引用、无无法退出的条件循环。
- 任何关键事实都可在一次错误选择后重新取得。
- 进入材料节点不会自动获得证据；执行归档选项后才获得。
- 错误推理增加尝试次数、保留首次答案，并能回到指定复核节点。
- 完成案件的分数至少覆盖三个评价区间，不再固定为 100。
- 旧格式进行中存档能恢复，新字段使用安全默认值。
- `pnpm lint && pnpm test && pnpm build` 全通过。

### 浏览器验证

- 375、390、430 CSS px 下，调查板三路线、证据归档、推理反馈、结案评分均无横向溢出。
- 触屏按钮最小点击区域不低于 44 CSS px。
- 关闭动画偏好下无必须等待的过渡。
- 断网首次启动仍能完整游玩；资源缺失时使用现有可恢复占位。

### 内容验收

- 八案证人不存在整句重复对白。
- 八案三层推理不存在整组重复选项，正确答案位置不形成固定规律。
- 每案终判可以从该案已展示证据逐步推出，不依赖界面外知识。
- 事实证物不引用 `F` 类来源；现代解释有对应 B 类来源或明确不确定性说明。

## 14. 实施顺序

1. 先扩展类型、条件、引擎与存档恢复，并以测试锁定新行为。
2. 完成调查板、主动取证、回查与评分 UI 的通用实现。
3. 将第一案重写为黄金样板，完成 375/390/430 浏览器验收。
4. 按八种独立机制迁移其余七案，逐案执行图结构和正确/错误路径测试。
5. 最后统一复核来源、文本重复、评分分布、离线资源与全量质量门。
