# 葵花点穴手 · 同福音律局

《武林外传》二十周年主题的纯前端四键节奏游戏。玩家是白展堂，对手仅为李大嘴、吕秀才、郭芙蓉、佟湘玉。

## 启动

在本目录执行 `pnpm dev`，访问 http://127.0.0.1:4313 。执行 `pnpm build` 得到可静态托管的 `dist/`，`pnpm preview` 预览构建产物。

需要 Node 20 或更新版本。此电脑 PATH 中微信开发者工具附带的旧 Node 不支持 `node --test`，验收使用桌面运行环境自带的 Node 24。在共享仓库执行 pnpm 前设置 PowerShell `$env:pnpm_config_verify_deps_before_run='false'`，防止 pnpm 11 自动安装/更新根锁文件；项目本身没有依赖需要安装。

无第三方新增依赖。构建/检查脚本使用 Node 内置模块；网页运行时不使用 Node、后端、运行时 CDN 或外部 API。所有文案、曲目配置、谱面、人物信息均在 `src/content/content.json`。

## 玩法

- 电脑 D / F / J / K；手机双拇指。四键依次对应左腰、左肩、右肩、右腰。
- 短音符到判定线时点击；长音符头到线时按住至尾部通过；中间两键可同时长按。
- 完整片头版本，来源页面 01:39，解码 98.104 秒，未截取。设置中支持音量、速度和 ±250ms 判定偏移。
- 20 秒基础练习不计入本机最高分。完整挑战不中途淘汰。
- 练习使用正式谱面的 16–36 秒人声段，可直接体验呼喊、Rap 开头、单点和双指长按。
- 每乐句安排一位对手；完成率达到 75% 定身。暂停、切后台、失焦会暂停音乐。暂停中的长按在继续后需要重新按住；有 350ms 恢复容错，未重新按住不继续加分。
- 不持久化用户图片、音视频、Base64 或 Blob；仅保存设置和最高分。音频解码仅存在当前页面内存。

## 项目文件

- `src/engine.mjs`：独立判定/持续计分引擎。
- `src/app.mjs`、`src/style.css`：网页、Canvas 轨道、Pointer Events 多指、Web Audio 实际输出时间同步。
- `src/content/content.json`：全部业务内容和最终谱面。
- `public/audio/`、`public/art/`：本地音频与生成美术。
- `design/REQUIREMENTS.md`：需求和验收约定。
- `design/ASSETS.md`：音频/剧照来源、生成美术说明。
- `scripts/analyze_audio.py`：离线频谱起音检测，需要开发环境 NumPy；不参与网页运行。
- `scripts/make-content.mjs`：按实际强起音编排谱面，保留少量头尾落在重音的跨拍长按；不会在无起音的位置填入模板音符。

## 验证

`pnpm lint && pnpm test && pnpm build`

测试覆盖真实谱面合法性、重复点击、早晚判定、长按随时间计分、提前松手、双指独立性、暂停续按与完整曲目满分模拟。浏览器验收另见 `design/QA.md`。

## 音频与发布

音乐是公开视频的完整片头音轨，来源与哈希见 `design/ASSETS.md`。下载成功不代表取得站点公开传播授权；当前交付为本地开发版本，未发布。正式公开使用前应由项目方确认音频与角色相关授权。


## 第三版节奏优化

发布谱现为 206 个音符，完整音频保留 98.104 秒。前奏/收尾跟伴奏，呼喊与 Rap 段跟人声。字音区间来自混音与分离人声的 Whisper 对齐；选点由 content.json 中的分段计划明确指定，再用独立人声波形定位起音。13 个长按音符对应九个持续字音（其中四组双指），不再连接两个无关重音。分析与人声段证据见 design/vocal-chart-report.json。当前仍标记为未经人工听感终审，不能把自动满分当作音乐验收。

首页的“听谱与调校”进入 `?studio=1`：原曲/人声/伴奏切换、分句循环、0.5/0.75/1× 试听、谱面点击声、节拍器、波形、音符增删及 5ms 微调、长按编辑、键盘录入、撤销、本地 JSON 草稿、JSON/.osu 导入导出与 `?draft=1` 试玩。慢放会降低音高。草稿仅保存结构化数据；草稿试玩不更新正式成绩。分轨文件仅供制谱试听，游戏仍播放原曲。

运行时优先使用 getOutputTimestamp 对齐音频输出位置，回退到报告的输出延迟；键盘/触控判定使用事件时间戳。按键校准与画面偏移独立，旧版混合校准会迁移归零。可启用谱面提示音，所有提示按音频时钟预排。成绩按谱面版本保存，旧成绩不会被删除，也不会与新版直接比较。

离线工具只安装在被忽略的 test-results/audio-tools；模型缓存也只用于开发，不加入 dist 或前端依赖。UVR ONNX 分离脚本先校验官方模型元数据，并做 STFT 往返与混合重建检查。`scripts/build-vocal-chart.py` 默认只写候选文件，只有显式 --apply 才覆盖内容。`scripts/make-content.mjs` 不再生成模板：无参数校验发布谱，有参数时导入明确提供的 JSON/.osu。

新增验证：audio-clock.test.mjs、chart-io.test.mjs、qa-optimization.mjs、qa-rhythm-sync.mjs。后者模拟 120ms 输出队列完成全曲，验证输出时钟路径；不是物理扬声器回录测试。

## 第四版 Rap 局部修订（2026-09-09）

当前正式谱为 194 个音符。32.7–64.7 秒 Rap 从 83 点改为 71 点，按 content.json 中 17 组显式短句选择组织。其余段落音符保持原样，13 条长按/4 组双指保留。成绩按 chartRevision=4 隔离，旧版成绩仍保存在本机。

旧算法在目标后最多 180ms 搜索最强上升，可能选中字音内部更晚的能量起伏。新版在每个目标 -55/+90ms 邻域内找有足够强度、距离目标较近的上升，再回溯其前沿；低信号不强行改动。69 个落点由邻域波形重新定位，2 个缺少合适候选的点保留。没有按统一偏移或强制网格移动整段；没有把波形方法称为人工听感验收。

新增首页「专练 Rap 32 秒」，直接从 32.7 秒开始，暂停重开仍在同一区间，不计正式纪录。重新选择 Rap 内人物交接处的空隙，避免音符落在结算间隙。

复核了伴奏不同段落相对现有 120 BPM 网格的局部位置，前奏约 +10ms，Rap 四段及后段约 +15ms，未见持续累积的漂移。该结果用于排查 BPM 漂移，不是直接决定人声落点的量化规则。详见 design/rap-beat-check.json 和 design/rap-revision-report.json。
