# 02 · 工程规范与质量门禁

本册汇总改代码前必须知道的全部硬约束。来源：根 [AGENTS.md](../../AGENTS.md)、[.codex/SKILL.md](../../.codex/SKILL.md)、总控文档 19/34/38/47 号。

## 1. 协作边界（AGENTS.md）

- **目录所有权**：每个 Agent 只允许修改分配的 `projects/<project>` 目录。不得动其他项目、根 `package.json`、`pnpm-workspace.yaml`、`pnpm-lock.yaml`、`docs/`、`prep/`。
- **新增依赖必须先报告**，由总控统一修改锁文件。
- **不得删除测试来通过检查。**

## 2. 运行约束（对所有项目生效）

| 约束 | 内容 |
|---|---|
| 架构 | 纯前端静态构建；**无后端、无运行时 CDN、无必需外部 API** |
| 内容 | 业务内容只放本项目 `src/content/content.json`（台词、数值、文件映射、播放选项） |
| 存储 | 可用 localStorage / IndexedDB 保存**结构化状态** |
| 禁止持久化 | 用户图片、Base64、音视频、Blob 不得进入草稿存储 |
| 禁用能力 | Service Worker、Node API、未经确认的设备 API |
| 资源路径 | 静态资源相对路径，构建后非根路径可打开；不用 History 路由（单页状态切换或 hash） |

## 3. 提交前命令门禁

在项目目录执行（等价于根目录 `pnpm check` 对全部项目执行）：

```bash
pnpm lint && pnpm test && pnpm build
```

各批次实际命令（详见 [08 分册](./08-运行构建与打包指南.md)）：

- 01-11：`oxlint` / `vitest run` / `tsc -b && vite build`
- 12-17：`node scripts/lint.mjs` 或 `node tools.mjs lint` / `node --test` / `node scripts/build.mjs` 或 `node tools.mjs build`
- 18-25：`node tools.mjs lint|test|build`（lint = tsc strict + JSON 解析 + node --check；build 末尾自动跑产物审计）

**浏览器直跑不可信**：普通浏览器预览没有宿主按钮和容器限制，不能作为交付验收依据（.codex/SKILL.md 明文规定）。

## 4. 响应式与安全区验证

- 至少验证 **375 / 390 / 430 CSS px** 三档宽度（38 号文档为回归记录范例）。
- 所有 `sticky` / `fixed` 顶部控件及锚点跳转必须叠加：

```css
var(--safe-area-inset-top, env(safe-area-inset-top, 0px))
```

并以**非零模拟安全区**验证控件与目标内容均不被状态栏遮挡。

## 5. 宿主按钮避让（共享记忆一，2026-09-17）

小红书宿主在屏幕**左上方显示返回按钮、右上方显示操作按钮**，浮在工具页面之上。规则：

1. **区分两层**：系统状态栏安全区（`env(safe-area-inset-top)`）≠ 宿主按钮占位区；只加安全区解决不了宿主遮挡，也不能靠提高 `z-index` 解决。
2. 宿主按钮可见区域及触摸余量内**不得放置**任何交互热区（按钮、菜单、关闭、撤销、确认、横竖屏切换等）；Logo、标题等重要信息也应避让。
3. **以局部排布为主**：操作移到中间、下方或浮动操作区；不要在整页顶部堆大块空白；背景和非交互内容可以延伸到该区域。
4. **模拟横屏**（竖拿手机 + CSS 旋转）时宿主按钮仍在物理屏幕原位，必须把宿主占位区**映射到旋转后的布局**，不能照搬竖屏顶部留白。横竖屏切换与抽屉关闭入口必须始终可见、可点且远离宿主返回按钮。
5. 宿主按钮几何不能写死为固定 CSS 像素；用**可配置的避让参数** + 保守布局 + 真机校准。
6. 验收时须**模拟左右宿主按钮覆盖层**，覆盖首页、编辑、看效果、弹窗、抽屉等所有页面状态，并检查真实横屏与模拟横屏。未完成真机验收时必须明确记录。

## 6. 音频门禁（共享记忆二，2026-09-18）

平台上传白名单只有 `jpg/css/gif/svg/png/js/jpeg/json/html/woff2/webp/woff`，**MP3 直接进 ZIP 会被拒**（项目 17 实测）。因此：

- 原始 MP3 保留在开发素材目录，**不得**进入上传 ZIP，也不得改后缀伪装。
- 构建期把音频字节编码为 Base64 写入经典 JS（`audio-data.js` 或合并进 `app.js`）；运行时 `atob → Uint8Array → AudioContext.decodeAudioData → BufferSource + GainNode` 播放。**不做** `<audio src="data:...">`、不做 Blob URL 媒体源。
- 单段解码后 ≤ 1 MiB；> 100 KiB 记录风险并考虑裁剪/降码率。ZIP ≤ 10 MiB（建议 ≤ 2 MiB）。
- 运行时：用户手势时创建/恢复 AudioContext；能力缺失给可理解提示并保留无声路径；每次播放新建 BufferSource，停止/拒接/挂断/取消时停节点、断连接、取消计时器；用会话标记（generation token）防止"已取消却又响铃"。
- 打包前递归检查产物目录与 ZIP 内每个文件的扩展名白名单，遇不支持类型直接失败。

参考实现：[projects/14-tongfu-rhythm/scripts/build-minitool.mjs](../../projects/14-tongfu-rhythm/scripts/build-minitool.mjs)、[projects/17-call-stories/src/audio-bank.mjs](../../projects/17-call-stories/src/audio-bank.mjs)、[projects/17-call-stories/tools.mjs](../../projects/17-call-stories/tools.mjs)。完整链路说明见 [03 分册 §8](./03-共享架构模式与技术方案.md)。

## 7. 小工具 ZIP 规范（.codex/SKILL.md）

打包产物必须同时满足 zip-artifact-spec / device-capabilities / js-compatibility / css-compatibility / performance-budget 五份 reference 与在线文档：

- `index.html` 位于 ZIP 根目录；资源全部相对路径引用且都在包内。
- JS 兼容基线 Chrome 61：直接交付 JS 用 ES2017，新语法靠构建链转译（18-25 的 rolldown `target:'chrome61'`）；Web API 做能力检测。
- CSS："Chrome 61 基线层 + 能力检测增强层"，只为实际使用的新能力做局部回退。
- 产物审计禁止：`fetch(`、`new Worker(`、`new Function(`、`eval(`、`WebAssembly.`、动态 `import(`（18-25 的 tools.mjs `audit()` 内置该检查）。
- 性能预算：首屏关键 JS+CSS gzip ≤ 250 KB 目标；首屏立即请求 ≤ 1.5 MB；WebGL 必须有运行时降级。
- 交付时必须提醒：创服平台模拟器 → Android 真机 → iOS 真机三步验证，均标记为待用户完成。

## 8. 视觉与动效标准（47 号文档摘要）

新一轮"视觉玩法"项目的验收基线，48 号清单直接引用：

- **制作顺序**：明确画面目标 → 手机关键帧（390×844 首帧/峰值帧/成品帧）→ 分层素材 → 核心动作样板 → 接业务闭环 → 真机视觉验收。
- **画面标准**：首屏最醒目的是用户把玩的物体；一个主光源；背景/主体/前景分层次；不同材质有不同线索（玻璃=边缘反射、果冻=厚度+局部形变、毛绒=纤维方向）；停止动画时画面也完整。
- **动效必须描述受力**（以果冻为例）：触碰 0-80ms 触点先凹 → 持续施力跟随且有上限 → 松手 0-450ms 主回弹 → 450-900ms 余振错相轻晃 → 再触碰从当前姿态继续。每个动效规格写清：触发、对象、受力方向、延迟、持续、结束态、连续触发、取消、减少动态模式。
- **反馈三连**（48 号归纳的爆款共性）：形变 + 粒子 + 音效，缺一不可；一切围绕"揭示瞬间"设计。
- **验收**：视觉验收（构图/材质/动作/输入反馈）与性能验收（60fps≈16.7ms/帧预算、降级顺序：先减背景粒子/滤镜分辨率/DPR，再减次要动态）分开；`lint/test/build` 通过不证明美观。
