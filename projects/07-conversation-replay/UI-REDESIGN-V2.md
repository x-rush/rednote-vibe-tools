# 当时这样说就好了 · UI/UX Redesign V2

状态：`APPROVED DESIGN`

日期：2026-08-26

## 1. 设计目标

把现有“关系／目标／冲突／情绪／原表达”选项向导升级为完整的句子编辑台。用户从冻结情境出发，将一次卡住的沟通整理为事实、感受、推测、需要和请求，再得到三种同权语气、一次低压力演练和一张可带走的复盘卡。

体验不模拟聊天 App，不判断谁对谁错，不读取或上传聊天记录，也不把沟通结果的责任只放在表达者身上。

成功标准：

- 5 秒内理解“不上传聊天记录、默认无痕、不判断对错”。
- 30 秒内体验“事实与推测分开”的核心认知高光。
- 3–8 分钟完成一份结构化复盘。
- 32 个情境均能走完普通或安全优先路径。
- 375／390／430 CSS px、键盘、触屏和 reduced-motion 均可完成流程。

## 2. 信息架构

正式主流程：

```text
封面
→ 隐私方式
→ 迟言简短引导（可跳过）
→ 关系
→ 当时目标
→ 3–6 个匹配情境／不确定入口
→ 事实
→ 感受
→ 推测
→ 需要
→ 请求
→ 三语气草稿
→ 无压力演练
→ 复盘卡
→ 主动保存／重新复盘
```

辅助状态：本机收藏、无痕退出确认、保存第四份覆盖确认、保存失败、坏存档、内容错误、迟言召回帮助和安全优先分支。

关系与目标用于渐进筛选，不再在首屏铺出 32 张情境卡。用户选择具体情境后不暗中改换情境；只有“不确定”入口使用可解释匹配和固定 fallback。

## 3. 五步编辑台

### 3.1 事实

用户从情境专属选项中选择 1–2 个“摄像机可以记录”的行为。选项可展开分类理由；混有动机判断的句子会提示稍后放入推测，但不使用“错误”标签。

### 3.2 感受

用户选择 1–2 个感受词，并可选轻微、明显或很强烈。强度只帮助选词，不评价反应是否合理。48 个感受词按当前情境筛选，不一次全部铺开。

### 3.3 推测

事实栏中的动机判断可移动到推测栏。移动不否定感受，而是说明这部分不能被直接观察，需要在沟通中留出核对空间。拖动是增强能力，点击按钮、键盘移动和撤回始终可用。

### 3.4 需要

用户选择 1–2 个真正想守住的需要或价值。界面明确区分“我需要可预期”与“你必须随时向我报备”这类命令。

### 3.5 请求

请求由时间、具体行为和边界／协商方式组成，必须可执行、可回应，并允许拒绝或协商。宽泛承诺、人格证明和操控性要求不进入推荐稿。

## 4. 草稿、语气与演练

草稿标题固定为“如果再说一次，我想这样表达”。柔和、直接、坚定三种语气视觉同权，不使用推荐色、警告色或从弱到强的评分顺序。

核心流程由结构化选项完成。最终草稿允许有限手工修改，但页面不分析自由文本；无痕模式退出后清除，本机模式才保存有限文字。

演练不使用对方头像、消息气泡或逐字聊天。`PracticeBoard` 展示一个可观察回应和 2–3 个下一句选项，帮助用户练习澄清、暂停、修复或坚持边界。演练结果不是对对方反应的预测。

## 5. 安全优先

安全等级拥有最高优先级。威胁、暴力、强迫、跟踪、严重控制、监控、经济控制、隔离、自伤／他伤或即时危险会在普通编辑前进入安全页面。

安全页面暂停普通草稿和演练，提供离开可能升级的现场、联系可信任的人，以及按所在地实际情况寻求紧急或专业支持的说明。不提供诊断、风险评分、过期电话号码或独自对质建议。

## 6. 视觉系统

视觉命题为“安静的纸面编辑台”。暖灰工作台承托暖白编辑纸；蓝灰负责主操作，鼠尾草绿表示整理完成，赭石用于编辑痕迹，灰玫瑰用于待核对推测，安全页面使用克制的砖红棕。

事实、感受、推测、需要和请求共享纸条结构，通过文字、图标、边线和批注位置区分，不依赖颜色。减少胶囊和大圆角，使用索引签、铅笔下划线、页边批注和轻微纸张层次。

标题使用系统宋体栈，正文使用系统黑体栈；不依赖运行时字体 CDN。

## 7. 组件边界

- `QuietShell`：全局纸面、宽度、安全区和页面背景。
- `TopRail`：返回、当前步骤、保存模式和帮助入口。
- `PrivacyStamp`：无痕／本机模式，图标始终配文字。
- `ScenarioNavigator`：关系、目标、情境三级筛选。
- `StepRail`：五步图标、文字和当前位置。
- `SentenceDesk`：事实与推测的双区编辑台。
- `SemanticSlip`：可选择、移动、撤回和键盘操作的语义纸条。
- `MarginNote`：迟言的结构提示和分类理由。
- `ToneSwitcher`：三种同权语气。
- `PracticeBoard`：可观察回应和下一句演练。
- `ReplayCard`：可截图的 DOM/CSS 结果卡。
- `SafetyNotice`：安全优先说明与退出路径。
- `ExitSheet`：无痕退出和将消失内容确认。
- `RecoveryPanel`：保存失败、坏档和内容错误恢复。

组件只消费页面 ViewModel，不直接解释复杂内容引用或匹配规则。

## 8. 迟言

迟言是虚构的对话复盘陪练兼句子编辑，不是咨询师、裁判或关系顾问。他只在首次引导、事实转推测的关键节点、帮助召回和异常恢复出现。

首次引导三页，可跳过：不用上传聊天记录；先选择最接近的情境；只整理用户想表达的部分。普通步骤使用小头像或署名批注，不让人物遮挡前后句对照、请求或安全退出。

## 9. 响应式与无障碍

- 375／390px：严格单列，一屏一个认知任务。
- 430px：编辑区保持单列，短批注可形成窄侧栏。
- 宽屏：事实／推测和前后对照可以双栏，但不使用手机外框。
- 主要触控目标至少 48px。
- 底部主操作随内容滚动，避免软键盘遮挡。
- sticky 顶栏叠加 `var(--safe-area-inset-top, env(safe-area-inset-top, 0px))`。
- 锚点使用同一非零安全区偏移，保证目标标题不被顶栏遮挡。
- 状态、分类和完成度都有文字；不只靠颜色、运动或图标表达。
- 焦点顺序与视觉顺序一致，纸条移动后通过 `aria-live` 宣告结果。

## 10. 内容与状态架构

数据流保持：

```text
content.json
→ 运行时校验
→ 领域纯函数与页面 ViewModel
→ reducer
→ React 组件
→ localStorage／IndexedDB 适配器
```

每个情境在 `src/content/content.json` 中补齐可观察事实、推测及分类原因、请求结构和演练内容。感受、需要、三语气、安全规则与下一步继续使用稳定 ID 和现有审核内容。业务文案不进入 JSX。

草稿状态包含：情境、目标、事实、感受及强度、推测、需要、请求、语气、演练回应、下一句、有限编辑和当前步骤。

安全选择覆盖具体情境。普通具体情境不再被匹配器替换；不确定入口沿用确定性评分、稳定决胜和固定 fallback。

## 11. 存储与隐私

存储升级为 schema v2。读取 v1 时执行受控迁移；不兼容或损坏数据不被静默覆盖，页面提供恢复说明。

localStorage／IndexedDB 只保存稳定 ID、数值、时间和有限文本。本机最多保留最近三份；第四份保存前明确显示将被覆盖的最旧记录。无痕模式不持久化当前选择。

结果图片只在用户主动点击时于浏览器内临时生成并下载，不写入浏览器存储，不保留 Base64、图片、音视频或 Blob。所有资源随静态构建打包；无后端、运行时 CDN、外部 API 或 Service Worker。

## 12. 错误处理

- 修改早期选择时只清理已失效的后续字段。
- 内容缺项使用明确通用回退，不拼接半句或空卡。
- 无痕退出列出将消失的情境、五步、草稿、编辑和隐藏状态。
- IndexedDB 失败保留当前内存，提供重试、复制和临时截图下载。
- 坏存档保留原数据，允许用户确认后清除此工具的数据。
- 图片失败时仍保留迟言身份、文字引导、跳过和继续操作。

## 13. 页面与状态覆盖

正式验收至少覆盖：封面、隐私方式、迟言引导、关系、目标、情境结果、情境确认、事实、感受、推测、需要、请求、三语气草稿、演练、表达对比、复盘卡、收藏、无痕退出、第四份覆盖、安全优先、保存失败、坏存档、内容错误和迟言召回。

## 14. 测试与验收

- 内容契约：32 个情境五步引用、唯一 ID、三语气、安全规则与 fallback。
- 领域：筛选、匹配、具体情境锁定、结果构建和安全覆盖。
- 状态：前进、返回、修改清理、恢复、退出和重开。
- 存储：v1→v2、坏 JSON、未来 schema、失效引用和第四份覆盖。
- 浏览器：普通完整路径、安全完整路径、保存失败、坏档和收藏路径。
- 视口：375×812、390×844、430×932。
- 安全区：模拟 32px 顶部 inset，检查 sticky 控件和锚点目标。
- 无障碍：键盘、焦点、屏幕阅读器文案、reduced-motion 和 200% 缩放。
- 内容压力：长中文、连续英文、emoji、换行和特殊字符。
- 提交前执行 `pnpm lint && pnpm test && pnpm build`。

## 15. 明确不做

- 上传、粘贴或分析聊天记录和截图。
- 账号、后端、云同步、在线排行或运行时模型生成。
- 情绪评分、人格诊断、关系责任判定或结果保证。
- 聊天气泡、对方头像、冲突人物插画和 32 情境配图。
- 未确认的设备 API、Service Worker 或媒体持久化。
