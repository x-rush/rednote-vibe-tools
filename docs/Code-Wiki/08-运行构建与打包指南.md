# 08 · 运行构建与打包指南

## 1. 环境准备

- Node.js（满足 Vite 8 / rolldown 要求：`^20.19.0 || >=22.12.0`）+ pnpm。
- 根 [package.json](../../package.json) 声明 `packageManager: pnpm@11.19.0`。

```bash
git clone https://github.com/x-rush/rednote-vibe-tools.git
cd rednote-vibe-tools
pnpm install        # 必须在根目录执行一次（18-25 的构建工具也来自这里）
```

## 2. 本地开发

```bash
cd projects/<project>
pnpm dev
```

| 批次 | dev 实现 | 说明 |
|---|---|---|
| 01-11 | `vite` | Vite dev server，终端输出地址 |
| 12-15 | `node scripts/serve.mjs` | Node 静态服务 |
| 16-17 | `node tools.mjs dev` | 先 build 再 serve（产物即所见） |
| 18-25 | `node tools.mjs dev` | 同上；可用 `PORT` 环境变量改端口（默认 4321） |

## 3. 检查与构建

单项目（在项目目录）：

```bash
pnpm lint && pnpm test && pnpm build
```

全仓库（在根目录）：

```bash
pnpm check    # = pnpm lint && pnpm test && pnpm build（-r 递归所有项目）
```

各批次命令明细：

| 批次 | lint | test | build |
|---|---|---|---|
| 01-11 | `oxlint` | `vitest run`（09/11 加 `--maxWorkers=1`） | `tsc -b && vite build` → `dist/` |
| 12-15 | `node scripts/lint.mjs` | `node --test tests/*.test.mjs` | `node scripts/build.mjs` → `dist/` |
| 16-17 | `node tools.mjs lint` | `node --test ...` | `node tools.mjs build` → `dist/` |
| 18-25 | `node tools.mjs lint`（tsc strict + JSON + node --check） | `node tools.mjs test`（先打包 model 再 node --test） | `node tools.mjs build` → `dist/` + 自动产物审计 |

产物预览：`pnpm preview`（静态服务 dist/）。

## 4. 小工具 ZIP 打包（平台交付）

不同批次有不同的 minitool 打包路径：

| 项目 | 命令 | 产物 |
|---|---|---|
| 04 | `pnpm build:minitool` | `vite --mode minitool` + `scripts/prepare-minitool.mjs` |
| 05 | `pnpm check`（含 `verify:minitool`） | dist 校验 |
| 06 | `pnpm validate:mini` | `scripts/validate-mini-package.mjs dist` |
| 08 | `pnpm package:minitool` | build:minitool → validate:minitool → package-minitool.mjs 三步 |
| 14 | `node scripts/build-minitool.mjs` | `release/package/`（含 audio-data.js） |
| 17/23/24 | `node tools.mjs build`（17/24 内置打包与 ZIP） | `dist/` + `release/` ZIP |
| 18-25 | `node tools.mjs build` | `dist/`；release ZIP 视项目而定（21 有 `.cache` 审计记录） |
| 25 | `scripts/package.ps1`（PowerShell） | `exports/` ZIP |

**打包自检清单**（来自 .codex/SKILL.md，必须逐条核对）：

1. ZIP 根目录有 `index.html`；所有资源相对路径且都在包内。
2. 逐文件扩展名白名单：`jpg/css/gif/svg/png/js/jpeg/json/html/woff2/webp/woff`——**没有 mp3**；用 [audit_artifact.mjs](../../.codex/scripts/audit_artifact.mjs) 或 tools.mjs 内置 audit 递归校验（含 ZIP 内部）。
3. 产物 JS 无 `fetch( / new Worker( / new Function( / eval( / WebAssembly. / import(`。
4. 无 source map（如提交政策要求关闭）、无绝对路径、无远程热链、无草稿与用户数据样本。
5. 体积：ZIP ≤ 10 MiB（建议 ≤ 2 MiB）；单段解码音频 ≤ 1 MiB。
6. 音频走 Base64+WebAudio（见 [03 分册 §8](./03-共享架构模式与技术方案.md)）。

## 5. 交付验收（界面部分）

按 [02 分册](./02-工程规范与质量门禁.md)执行：

1. `pnpm lint && pnpm test && pnpm build` 通过。
2. **375 / 390 / 430 CSS px** 三档宽度回归。
3. 非零模拟安全区：顶部 sticky/fixed 控件叠加 `var(--safe-area-inset-top, env(safe-area-inset-top, 0px))`。
4. **宿主按钮覆盖层模拟**：左右上角模拟宿主返回/操作按钮，覆盖所有页面状态（首页、编辑、看效果、弹窗、抽屉），检查真实横屏与 CSS 模拟横屏下的遮挡映射。
5. 视觉/动效按 47 号标准验收（构图、材质、受力动效、降级路径）。
6. 平台三步验证：创服平台模拟器 → Android 真机扫码 → iOS 真机扫码（浏览器直跑结果不可作为依据）。

## 6. 常见问题

| 问题 | 处理 |
|---|---|
| 18-25 构建报找不到 rolldown/tsc | 先在仓库根 `pnpm install`（构建工具来自工作区 .pnpm 存储） |
| 想给项目加依赖 | 停：报告总控统一改 `pnpm-lock.yaml`（AGENTS.md 规则） |
| MP3 打进 ZIP 被平台拒 | 走 14/17 音频链路；MP3 只留在开发素材目录 |
| 修改被 lint 拒绝 | 先看是否动了分配目录之外的文件；不得删测试过检 |
| 端口冲突 | 18-25 用 `PORT` 环境变量；01-11 看 vite.config |
