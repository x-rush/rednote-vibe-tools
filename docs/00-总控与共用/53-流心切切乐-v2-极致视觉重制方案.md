日期：2026-09-29。状态：**P0 视觉原型已完成（2026-09-29），待用户过目**：WebGL raymarching 3D 糕点 + 完整切割时刻（hit-stop/慢动作/俯视运镜/metaball 流心）+ 三段合成音效；门禁全绿（单测 18/18、QA 36 项、包体 ~210KB）。用户点头后进入 P1；截图与边界记录见项目 DELIVERY.md。取代 [52 号](./52-流心切切乐-立项与开发计划.md) 的呈现层设计（52 号的玩法定义、任务包纪律、验收矩阵、宿主避让约束继续有效）。触发：v1 内置浏览器实测后被用户否决——"页面设计、动画交互质量太低，要求完全重新开发"；用户进一步定向：**3D 写实材质效果**。

## 1. 诚实归因：v1 为什么丑

| 症状 | 根因 | 教训 |
|---|---|---|
| 糕点是"棕色圆片"，不是食物 | Canvas2D 径向渐变画不出材质：没有皮层酥松感、没有光泽、没有次表面散射 | 食物质感必须有真实体积、光照与散射——2D 平面渐变只能做线框稿 |
| 切开没有"爽感" | 分离=两块平移；无 hit-stop、无慢动作、无镜头、无挤压弹性 | 解压游戏的生命在 juice（打击感），不在状态机 |
| 流心是"小圆点" | 质点粒子无融合，像沙子不像液体 | 液体必须有体积、光泽与融合拉丝 |
| 没有声音 | 首发默认无音效是错误决策 | 解压品类 ASMR 占体验一半，静音解压不成立 |
| 配色没食欲、UI 像后台 | 奶油底+棕字，系统字体，无美术指导 | 需要明确的 art direction 与展示字体，糕点要是画面唯一主角 |

根本教训：**v1 用工程门禁（测试绿、白名单过）替代了视觉验收，而视觉验收的对象只有自己**。视觉"成立"必须外部对标（美食摄影、榜单头部竞品），不由开发者自评。

## 2. 重新定义：这个小工具的意义

切糕解压的本质是**情绪价值产品**：用户为"切开那一刻的多巴胺"而来（48 号数据：解压玩具供给 653、命中 15.3/千，性价比最高赛道；复访靠图鉴收集）。推论：

- **视觉与声音就是产品本身**，逻辑（切割/图鉴）只是骨架。投入比呈现 80% / 逻辑 20%。
- 魔法时刻只有一个：**下刀瞬间 + 流心淌出的 2 秒**。全部资源压在这 2 秒上。
- 图鉴与结果卡是传播物料，必须精致到"想截图"。

## 3. 3D 写实：为什么对这款游戏是正确方向

切割游戏的中心画面是**截面**。3D 化带来三个 2D 做不到的东西：

1. **任意切线 → 完美三维截面**：用户随便什么角度下刀，露出的都是真实体积的层（酥皮厚度、馅心弧度、流心透光），而不是贴图画层；
2. **写实材质的三板斧**：折射（流心透亮）、次表面散射（糯米/青团边缘透光）、真实高光（油润镜面随视角流动）——这些只有带体积与法线才能成立；
3. **镜头语言**：微俯视机位 + 切割瞬间推近 + 可拖拽小角度环视，"这是个 3D 东西"的实感本身就是传播点。

## 4. 技术栈选型（主路线：Raymarching 分层 SDF，全程序化、零素材）

**渲染：WebGL1 片段着色器 raymarching**（21 号已证明容器支持 WebGL；Canvas2D 简化降级保底）。糕点不再用网格，而是**分层 SDF 体积场**：皮/馅/流心是同心体积层（旋转体+噪声扰动边缘），摄像机微俯视 15-25°。

- **写实材质**：简化 PBR（GGX 高光+菲涅尔）；流心带折射（透射采样）、糯米/青团带次表面散射近似（边缘透光）、酥皮噪声法线起层+油光；蛋糕海绵气孔体积噪声。
- **切割 = SDF 布尔分割**：任意切线下刀直接对体积场做平面分割，截面即"真实的 3D 切面"——这是相对网格方案的决定性优势，也是本玩法的核心画面。
- **流心液体 = 同场景 SDF metaball**：液滴光滑融合成股、拉丝垂落、盘面聚泊，带光泽与折射，真实体积感。
- **软体颤动 = SDF 域扭曲**：切割冲击沿切线方向的衰减正弦弯曲，整糕弹动（47 号受力阶段表）。
- **光照**：单主光 + 半球环境 + SDF soft shadow 接触阴影；揭示时刻高光扫过 = 光源方向动画；后期暗角聚光+白闪+加法发光同 pass 完成。
- **性能**：糕点包围盒内定步长 raymarch（高档 ≤64 步 / 低档 ≤40 步）、内部渲染 0.75×/0.5× 分辨率再上采样、低端降 DPR；粒子/液滴数沿用 quality 双档。目标中端机 60fps。
- **兜底**：WebGL 不可用 → Canvas2D 简化渲染（可玩保底，画质明示降级，不冒充实测结论）。

**备选路线（P0 性能不达标时切换）**：旋转体网格 + 程序生成截面 cap + Blinn-PBR/matcap——性能可预期，但任意切线截面生成复杂，写实上限略低。

**物理：自研弹簧质点软体**（JS 固定时间步，v1 的 1/60 步进与 seed 纪律沿用；上传白名单无 wasm）。**声音：17 号 Base64→WebAudio 链路**，Node 离线合成 ASMR 四件套（下刀噗/酥皮碎裂/流心咕叽/滴落），5-8 段 × ≤60KB。**字体：开源中文字体子集 woff2 ≤80KB**（SIL OFL）。**不引入** npm 依赖、wasm、运行时 CDN、外部图片——全部程序化，包体预计 ≤1.5MB。

## 5. 视觉基准（逐元素验收线，对标外部）

| 元素 | v2 标准 |
|---|---|
| 糕点材质 | 四族一眼可辨（酥皮起层油光/糯米半透/艾草绒面/海绵奶油）；**静帧能骗过"渲染还是照片"的第一眼** |
| 切割瞬间 | hit-stop 80ms → 刀光 → 慢动作 0.35×（500ms）两半弹开颤动 → 镜头推近 15% → 碎屑迸溅，全链路 ≤2.5s |
| 流心 | metaball 体积液体：涌出、聚珠、拉丝、盘面聚泊；高光与折射随液面流动 |
| 立体感 | 微俯视透视成立；可拖拽 ±12° 环视不穿帮；接触阴影随分离移动 |
| 声音 | ASMR 四件套可开关；静音时纯视觉反馈仍完整 |
| UI/传播物 | 展示字体+纸纹+聚光构图；图鉴全家福带标题与累计数据，精致到想截图 |

## 6. 实现到什么程度（DoD）

- 材质：四族静帧并排与头部竞品对照不输；内部 3 人盲猜族类 100% 正确；"照片感"主观通过。
- 切割时刻：逐帧录屏对照 47 号受力阶段表；"想再看一次"为通过线（内部 3 人）。
- 性能：中端机 60fps 实测（非模拟器）；低端档降档后玩法与质感骨架不变。
- 包体：≤2MiB、音频单段 ≤1MiB、白名单逐文件审计。
- 工程：v1 的 model/存储/图鉴/QA 矩阵/宿主避让保留并继续绿；新增 raymarch 参数单测与音效链路测试（17 号场景清单）。

## 7. 重制范围

| 层 | 处置 |
|---|---|
| model.ts（切割几何/seed/图鉴/存储） | **保留**，新增软体/慢动作时间标度参数 |
| content.json | **保留扩充**：每款增加 3D 材质参数组（层厚、噪声频率、光泽、折射率、流心 metaball 参数） |
| render.ts（Canvas2D） | **废弃重写** → render/gl/（raymarch 管线）+ render/softbody + render/juice |
| 无音效 | **推翻** → audio/（17 号链路+离线合成音源） |
| UI/CSS | **重做**：展示字体、纸纹背景、聚光构图、图鉴光影卡 |
| tools.mjs/QA 骨架 | **保留**，qa 增加逐帧录屏、shader 降档断言、中端机帧率实测 |

版本 0.2.0-v2，同目录原地重制（git 留 v1 历史）。

## 8. 里程碑：视觉原型先行，不过门禁不铺开

- **P0 视觉原型（硬门禁）**：只做一只「流心奶黄」——3D 写实材质（静帧对照美食摄影）+ 一次完整切割时刻（hit-stop/慢动作/metaball 流心/碎屑）+ 一条合成音效 + 中端机帧率实测。产出 3 秒录屏与静帧，**用户看过点头才准进入 P1**；不达标只在这一只糕上迭代。
- **P1 全材质管线**：四族参数化、摆盘、图鉴光影卡、UI 新皮。
- **P2 软体与声音**：软体颤动、全音效链、慢动作导演调参。
- **P3 验收与发布**：47 号矩阵+性能分档+ZIP 审计+真机三步，52 号 §9 全量验收不跳项。

## 9. 风险

| 风险 | 对策 |
|---|---|
| raymarch 低端机帧率不达标 | 定步长+糕点局部渲染+分辨率/DPR 降档；仍不达标切换备选网格路线（P0 阶段即实测） |
| shader 复杂度推高工时 | P0 只做一只糕，材质参数全部 content.json 化后批量复制 |
| 写实感不足 | 光照三件套（soft shadow/SSS/折射）逐项对照美食摄影，缺哪补哪 |
| 合成音效不像食物声 | 先验证"噗"一声；不像则 ffmpeg 处理真实录音素材转 base64 |
| 容器 WebGL 兼容 | 21 号已验证 WebGL 可用；Canvas2D 兜底保可玩 |
| 包体超 2MiB | 音频单段门禁+着色器压缩；图片为零 |
