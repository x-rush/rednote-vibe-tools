# 八项目技术架构、测试与提交开工包

状态：ENGINEERING CONTRACT FROZEN（2026-08-23）。正式编码前仍需用小红书平台提供的最新脚手架/上传工具验证构建细节；若平台约束变化，只调整适配层，不改变业务数据契约。

## 1. 工程策略

八项目采用同一技术基线、八个独立应用：

- React + TypeScript + Vite。
- 静态前端，无服务端、无运行时 API 依赖。
- 每项目独立 `package.json`、构建目录、`content.json`、存储前缀和 IndexedDB。
- 共用代码在开发仓库中以内部 workspace package 或复制后固定版本的模板提供；上传包内不依赖其他项目。
- 不使用需要服务器回退的 History 路由；MVP 优先单页状态切换或 hash 路由。
- 所有静态资源使用相对路径，构建后在非根路径也能打开。

## 3. 共用模块边界

### `tool-core/content`

- 读取静态 JSON。
- 运行时 schema 校验。
- 构建前内容校验接口。
- 建立 `Map<id, entity>` 索引。
- 返回可读错误，不自动修正文案。

### `tool-core/storage`

- 带 `schemaVersion` 的 localStorage envelope。
- IndexedDB 打开、升级、事务封装。
- 迁移函数注册。
- 项目级清空，不跨项删除。
- 容量不足、隐私模式、数据库被阻止时的错误类型。

### `tool-core/ui`

- 安全区容器、页面壳、按钮、选项卡、确认弹层、错误恢复页、静音与减少动态设置。
- 只包含行为和无品牌基础样式；各项目视觉令牌独立。

### `tool-core/testing`

- 固定随机种子。
- localStorage/IndexedDB 测试替身。
- 内容引用检查助手。
- 页面主路径通用断言。

## 4. 内容加载规则

```text
应用启动
→ import content.json
→ 校验顶层 meta
→ 校验项目 schema
→ 建 ID 索引
→ 读取并迁移用户状态
→ 校验用户引用的内容 ID
→ 渲染继续/开始页面
```

生产构建不允许跳过内容校验。开发环境可以显示完整错误路径；生产环境显示“内容包未能读取”及重新打开/清空状态选项，不暴露堆栈。

## 5. 项目级状态机

### SBTI

`idle → briefing → answering → chapterTransition → revealing → completed`。

关键数据：seed、24 个 questionIds、currentIndex、answers、scores、resultCode、contentVersion。

### 物华录

`idle → roundReady → guessing → revealed → roundCompleted`。

关键数据：artifactIds、index、revealedClueIds、availableStars、answer、collection。

### 大理寺

`caseClosed → opening → initialVerdict → investigating → finalVerdict → report`。

关键数据：caseId、nodeId、visited、evidence、tags、initialVerdict、finalVerdict。

### 饮子铺

`noSave → morning → configured → event → resolving → daySummary → ending`。

关键数据：seed、day、四项状态、库存、价格、flags、chainProgress、pendingEffects、history。

### 关系说明书

`intro → answering → generated → editing → preview`。

关键数据：answers、generated sentenceIds、editedText、visible、order、sensitive flags。

### 出门检查官

`scenario → conditions → checklist → completed`。

关键数据：scenarioId、conditions、itemIds、customItems、checked、viewMode。

### 对话复盘

`privacyIntro → fact → feelings → interpretation → needs → request → draft`。

关键数据默认只在内存；显式保存后生成 debrief ID。

### 地球 Online

`statusInput → offering → active → resolved`。

关键数据：adventurerStatus、offeredQuestId、activeQuestId、feedback、logs、cooldowns。

## 6. 随机与可复现

- 题目、事件、文物和任务随机均使用可注入 seed 的 PRNG，不直接把 `Math.random()` 散落在组件中。
- seed 在一轮开始时保存；刷新后输出一致。
- 内容权重函数为纯函数：`state + content + seed → selection`。
- QA 可以指定 seed 复现某个事件或任务。
- SBTI 只用随机选择满足配额的题，不让随机改变同一答案的结果。

## 7. 存储与隐私

| 项目 | localStorage | IndexedDB |
|---|---|---|
| SBTI | 本轮与最近结果 | 无 |
| 物华录 | 本轮、收藏、星级 | 无 |
| 大理寺 | 当前入口状态 | 案件进度、判词 |
| 饮子铺 | 当前存档 ID、设置 | 存档、事件历史、结局 |
| 关系说明书 | 单份说明书 | 无 |
| 出门检查官 | 当前及最近三份 | 无 |
| 对话复盘 | 模式设置；无痕草稿不写 | 用户主动保存的最近三份 |
| 地球 Online | 今日状态、当前任务、收藏 | 日志、反馈 |

全部禁止保存用户图片、视频、音频、Base64 和不可控 Blob。

## 8. 性能预算

开发开始前以保守目标约束：

- 首屏关键 JS + CSS gzip 后尽量控制在 250 KB 内，不含字体与图片。
- 首屏立即请求资源不超过 1.5 MB。
- 非首屏插画懒加载。
- 单一 JSON 内容包按项目控制；饮子铺和地球 Online 如超过约 500 KB，优先精简字段与重复文案，不拆成运行时远程请求。
- 长列表使用分段渲染或窗口化的必要性由真机数据决定；20 件图鉴和 100 条任务通常可先分页/筛选。
- 低端设备减少粒子、模糊滤镜和大面积固定背景。

这些是内部预算，不是假装平台硬限制；最终以平台实测为准。

## 9. 内容校验命令规格

每应用提供：

```text
npm run validate:content
npm run test
npm run build
npm run verify:dist
```

`verify:dist` 检查：

- 无绝对文件路径。
- 无远程热链。
- 无 source map（若提交政策要求关闭）。
- 无研究草稿和未使用大图。
- 入口 HTML 存在。
- 静态资源引用可解析。
- 包内没有秘密、token 和用户数据样本。

## 10. 测试矩阵

### 单元测试

- 计分、抽题、事件权重、条件规则、任务过滤。
- schema、迁移、ID 索引和损坏恢复。
- 文本长度与记录上限。

### 内容测试

- ID 唯一和外键存在。
- 节点可达和结局可达。
- 随机池在所有合法条件下非空。
- 来源与资源路径存在。
- 内容重复度报告。

### 组件测试

- 选项提交只执行一次。
- 返回修改、弹层确认、清空数据。
- 图片/音效失败降级。

### 端到端测试

- 每项目黄金主路径。
- 刷新恢复路径。
- 失败/边界路径。
- 第一次与再次打开。

### 真机与平台测试

- 常见窄屏和长屏。
- Android/iOS 平台 WebView。
- 键盘弹起后的页面布局。
- 底部安全区。
- 切后台、系统返回、弱性能和离线。
- 小红书小工具预览环境的上传包和实际入口。

## 11. 八项目专项测试

- SBTI：16 型可达、24 题配额、平分、改答、题序复现。
- 物华录：线索扣星一次、错误重试、收藏最高星更新。
- 大理寺：节点无死路、证据齐全才终判、任意调查顺序。
- 饮子铺：固定种子 10/30/100 天、不会普遍必死或必胜、连锁前置和冷却。
- 关系说明书：重算不覆盖手工编辑、敏感项默认隐藏。
- 出门检查官：规则去重、三视图状态一致、空池回退。
- 对话复盘：默认不落盘、明确保存、第四份覆盖提示、安全提示。
- 地球 Online：硬过滤永不突破、冷却、20 次领取、空结果回退。

## 13. 并行开发任务包

每项目正式开工时拆为：

1. `content`：只编辑内容草稿和最终 JSON。
2. `schema-storage`：类型、校验、迁移和存储。
3. `game-logic`：纯函数、状态机和单测。
4. `ui`：页面与组件，不修改内容语义。
5. `art-audio`：按 manifest 输出资源与台账。
6. `integration`：接入真实内容和资源。
7. `qa`：执行测试、修复、复测。
8. `release`：构建、包检查、录屏和参赛材料。

任务描述必须写：允许编辑目录、输入契约、输出文件、验收命令和不可修改项。并行工作合并前由集成任务统一处理冲突。
