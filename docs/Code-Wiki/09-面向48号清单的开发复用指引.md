# 09 · 面向 48 号清单的开发复用指引

本册把 [48 号选品清单](../00-总控与共用/48-排行榜视觉玩法选品与开发清单.md)（10 个视觉玩法选题）映射到仓库现有代码资产，作为立项后的技术起点。建议立项顺序（48 号结论）：**敲晶洞或流心切切乐先行**，捏捏工坊同步设计，糖画转盘随后。

## 1. 新项目工程骨架（所有选题通用）

按 48 号 §8 与第三代模式（18-25）搭：

```text
projects/NN-<slug>/
├── src/
│   ├── app.ts                 # 入口：读 content → 初始化 renderer/storage/audio
│   ├── model.ts               # 纯逻辑：状态机 + 固定时间步 + seed
│   ├── render/                # Canvas2D/WebGL 渲染（分层）
│   ├── storage.ts             # localStorage 信封（storageKey 来自 content.json）
│   ├── style.css
│   └── content/content.json   # 唯一业务内容源
├── tests/                     # node --test（先打包 model 再测）
├── qa/                        # browser-check.mjs（宿主按钮覆盖层模拟）
├── tools.mjs                  # 复制 21 号范本：lint/test/build/dev/preview + audit
├── index.html
├── tsconfig.json              # strict
└── package.json               # 零依赖，scripts 全走 node tools.mjs
```

直接复制 [projects/21-lakeside-stone-skipping/tools.mjs](../../projects/21-lakeside-stone-skipping/tools.mjs)（本仓库最清晰的范本：rolldown chrome61 + IIFE + 白名单审计 + 禁 fetch/eval 检查 + 自带静态服务）。

**通用验收**：48 号 §8 要求——`pnpm lint && pnpm test && pnpm build`、375/390/430 三档、非零安全区、左右宿主按钮覆盖层模拟（含模拟横屏映射）、按 47 号动效标准自检、不复用旧条目历史素材。

## 3. 音频（可选项，统一决策）

48 号定调：音效可选，白噪音/摩擦/碎裂等短音效走 14/17 参考链路；**无音效也必须保证纯视觉反馈完整**（形变+粒子三连缺一不可的规则里，音效是第三连，缺失时用更强的视觉反馈补偿）。

若做：复制 [17 的 tools.mjs 音频段](../../projects/17-call-stories/tools.mjs)（扫描 → 白名单 → ≤1 MiB → Base64 虚拟模块）+ [audio-bank.mjs](../../projects/17-call-stories/src/audio-bank.mjs)（解码/播放/清理）+ [call-player.mjs](../../projects/17-call-stories/src/call-player.mjs) 的 generation 防幽灵模式。测试至少覆盖 17 号 audio-bank.test.mjs 的场景清单。

## 4. 设计红线（48 号 §4/§7，开发前重读）

1. 核心循环必须是"手势 → 物理/粒子反馈 → 状态变化动画"；文字只当标签（≤5 字）。
2. 每款必须设计"魔法时刻"（揭示瞬间）和可截图产物（结果卡/图鉴/对比图）。
3. 与自家项目错位（13 果冻、17 捡手机、18-22 治愈收集、01 测试引擎的分界见各选题"差异化"栏）。
4. 不碰阿Sue/Judy/韦特塔罗等版权素材；不做叙事/聊天/多结局文本向；不做套皮每日打卡（Wordle 式已否决，不再提议）。
5. 立项排期按 48 号 §1 梯队：敲晶洞 / 流心切切乐先行试水，捏捏工坊同步设计。
