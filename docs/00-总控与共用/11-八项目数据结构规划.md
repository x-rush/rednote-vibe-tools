# 八项目数据结构规划

状态：APPROVED / FROZEN（2026-08-23）。后续只有在冻结玩法无法实现、数据校验失败或平台限制变化时才修改；新增字段必须同步提升 `schemaVersion` 或 `contentVersion`。

## 1. 通用约定

### 1.1 数据分层

```text
静态内容层：每个项目随构建包发布一份 content.json，只读
运行状态层：当前会话和当前流程，内存/localStorage
长期记录层：多条历史、存档和索引查询，IndexedDB
资源层：项目方审核后的图片、SVG、字体和音频，随包内置
```

### 1.2 通用字段

```ts
type ContentMeta = {
  id: string;
  contentVersion: string;
  approved: boolean;
  sourceIds?: string[];
};

type StoredEnvelope<T> = {
  schemaVersion: number;
  updatedAt: string;
  data: T;
};
```

### 1.3 单一内置 JSON 内容包

每个项目只发布一份业务内容文件：

```text
src/content/content.json
```

统一顶层结构：

```ts
type ProjectContentPackage = {
  meta: {
    projectId: string;
    schemaVersion: number;
    contentVersion: string;
    generatedAt: string;
    locale: "zh-CN";
  };
  content: Record<string, unknown[]>;
  sources: {
    id: string;
    title: string;
    creator?: string;
    url?: string;
    license?: string;
    accessedAt?: string;
  }[];
};
```

- TypeScript 文件只定义类型、读取器和校验器，不承载业务内容。
- 运行时内容只从 `content.json` 读取，不从 localStorage/IndexedDB 复制题库、事件、文物或任务。
- 用户存档只保存稳定内容 ID；读取时再用 ID 关联 `content.json`。
- 内容更新只替换 `content.json` 并提升 `contentVersion`。
- 构建前校验 ID 唯一、引用存在、必填字段、来源和资源路径。
- 如果研究和编辑阶段使用多个临时文件，发布前必须合并为这一份 `content.json`；运行包中不保留分散内容文件。

### 1.4 本地数据规则

- 时间统一保存 ISO 8601 字符串。
- ID 使用稳定英文 slug，不使用数组序号。
- 用户自由文本必须限制长度，保存前去除多余空白。
- localStorage key 统一前缀：`xhs-tool:<project>:v<schema>`。
- IndexedDB 每项目独立数据库，表名使用复数名词。
- 所有数据支持清空；迁移失败时保留可恢复提示并允许重置。
- 不保存用户图片、视频、音频、Base64 图片或不可控 Blob。

### 1.5 稳定 ID 命名规则

所有 ID 使用小写 ASCII `kebab-case`，不使用中文、空格、数组序号或随机 UUID 表示内置内容。

```text
内置实体：<类型>-<语义名>
例：question-mist-gate、creature-bai-ze、artifact-lotus-bowl

用户记录：<类型>-<时间戳>-<短随机串>
例：save-1787472000000-a7k3
```

- 同一项目内全局唯一；删除后不得把旧 ID 分配给其他含义。
- 关系字段一律保存 ID，不保存数组位置。
- `choiceId` 只需在所属实体内唯一，但运行记录保存时同时带父实体 ID。
- 美术和音频资源使用相同语义名，例如 `creature-bai-ze.webp`。

### 1.6 文本与记录上限

| 数据 | 上限 | 超限处理 |
|---|---:|---|
| 内置标题 | 30 个汉字 | 构建失败 |
| 内置选项 | 42 个汉字 | 构建警告，超过 60 构建失败 |
| 内置正文/事件描述 | 220 个汉字 | 构建警告，超过 320 构建失败 |
| 用户自定义清单项 | 30 个汉字 | 输入时截断并提示 |
| 关系说明书单句编辑 | 120 个汉字 | 阻止继续输入并显示计数 |
| 对话复盘单字段 | 300 个汉字 | 阻止继续输入并显示计数 |
| 冒险日志备注 | 120 个汉字 | 阻止继续输入并显示计数 |
| 最近清单 | 3 份 | 新记录覆盖最旧记录 |
| 已保存对话复盘 | 3 份 | 保存前提示将覆盖最旧记录 |

内置正文需要更长时拆成多个节点，不放宽移动端单屏阅读上限。

### 1.7 版本兼容与迁移

- `schemaVersion`：字段形状或存储结构变化；代码必须提供显式迁移函数。
- `contentVersion`：题目、事件、文案、权重或资源更新；不必迁移用户存储，但需检查所引用 ID 是否仍存在。
- 内容实体需要下线时，先标记 `deprecated: true`，至少保留一个内容版本；读取旧存档时映射到 `replacementId` 或安全回退。
- 存档读取顺序：解析 envelope → 校验 schema → 逐版迁移 → 校验内容引用 → 丢弃失效的非关键引用 → 给关键失效存档显示“内容已更新，可重新开始”。
- 迁移失败不得静默覆盖原数据；先保留原 key，再允许用户导出文本摘要或清空重置。

### 1.8 构建前 JSON 校验门禁

每个项目提供同一套校验入口，例如 `npm run validate:content`，至少检查：

1. JSON 可解析且符合 TypeScript 对应的运行时 schema。
2. 所有 ID 唯一，所有外键、下一节点和资源路径存在。
3. 必填文本不为空，长度和枚举合法。
4. 随机池达到最低数量，不会因筛选条件出现空池。
5. 流程图没有无法抵达的必需节点、死循环或无结局路径。
6. 文物、古籍和历史性断言有 `sourceIds`；来源 ID 存在。
7. 图片、字体、音频只有项目内静态路径，不含开发机绝对路径和远程热链。
8. JSON 不包含函数、HTML 脚本、用户数据或秘密信息。

校验失败即阻止构建发布；警告必须在发布检查表中人工确认。

## 2. SBTI 山海兽格

### `content.json` 内容字段

```ts
type SbtiQuestion = ContentMeta & {
  chapter: "entry" | "trace" | "change" | "return";
  primaryDimension: "RH" | "TV" | "LE" | "SM";
  sceneTags: string[];
  reverseKeyed: boolean;
  scene: string;
  options: {
    id: string;
    text: string;
    scores: Partial<Record<"R" | "H" | "T" | "V" | "L" | "E" | "S" | "M", number>>;
  }[];
};

type SbtiProfile = ContentMeta & {
  code: string;
  name: string;
  creatureId: string;
  oneLiner: string;
  strengths: string[];
  blindSpots: string[];
  underStress: string;
  relationshipNeeds: string[];
  misunderstoodAs: string[];
  action: string;
  neighborCodes: string[];
};
```

同一文件中的其他字段：`dimensions`、`creaturesClassical`、`creatureArchetypes`、`sources`。

### localStorage

```ts
type SbtiLocalState = {
  currentQuestionIndex: number;
  answers: Record<string, string>;
  lastResult?: { code: string; completedAt: string; contentVersion: string };
  settings: { muted: boolean; reducedMotion: boolean };
};
```

首发不使用 IndexedDB。

### 首发题库与抽题规则

- `content.questions` 首发必须包含 48 道正式题，不区分“正式题”和“备用题”。
- 题库按 `chapter × primaryDimension` 形成 16 个格子，每格至少 3 题。
- 每次测试抽取 24 题：每章 6 题、每个主维度 6 题。
- 抽取器避免连续出现相同 `primaryDimension`，并平衡两个端点出现在左右选项的位置。
- `sceneTags` 用于避免一轮中同类生活场景过度重复，不参与人格计分。
- `reverseKeyed` 用于题目审校和位置平衡；计分必须读取选项的显式 `scores`，不能由左右位置推断。
- 一轮生成后保存本轮 `questionIds` 与顺序，刷新页面不得重新抽题。

## 10. 冻结结论

1. 每项目运行时只有一份 `src/content/content.json`，业务文案不散落在 TypeScript 中。
2. 内置数据只读；用户状态只保存答案、进度、稳定 ID 和少量自由文本。
3. 大理寺、饮子铺、对话复盘和地球 Online 使用 IndexedDB；其余 MVP 使用 localStorage。
4. 对话复盘默认无痕，只有用户主动保存才进入 IndexedDB，最多 3 份。
5. IndexedDB 可保存结构化数据，但八个项目均不保存用户图片、音视频、Base64 或不可控 Blob。
6. 所有项目必须在正式内容生产前先通过黄金样例验证，再批量扩充 JSON。
7. 下一份文档进入“必要资料清单与黄金样例”，不进入 UI、美术和代码实现。
