## 维度说明

12 个维度分别为：联系清晰度、倾听方式、感受确认、分歧表达、暂停与恢复、独处空间、行动关心、语言关心、细节关心、建议自主、隐私同意、修复行动。

- 每个选项显式保存维度影响、0–3 分强度、标签、适用场景、冲突引用、边界引用和结果文案键。
- 聚合采用归一化分值；优先偏好按稳定内容顺序输出，不使用随机数。
- 最高分并列时保留全部并列偏好，不强行选出一个“类型”。
- 空答卷使用安全 fallback；有答卷时至少加入两条共同承诺。
- 算法只描述偏好、请求和边界，不生成心理类型、关系评分或诊断结论。

## 冲突合并规则

当前有两条可测试规则：

1. “当下谈清”与“需要完整空间”同时出现时，表达为先处理需要说清的部分；情绪过满时可以短暂停下，并说明之后继续。
2. “帮我理清”与“安静陪伴”同时出现时，表达为先安静陪伴，能够继续表达后再一起梳理。

合并只替换触发冲突规则的选项来源，不会误删其他选项独立支持的同名结果句；也不删除原始答案，不把其中一个偏好判断为错误。`RelationshipProfile` 通过答案、文案键、选项级 `provenanceId` 和命中的 `conflictRuleIds` 保留生成依据，便于重新生成和审计。

分享摘要同样优先使用命中的场景化合并句，不会在冲突输入下只展示其中一侧。

## 文案安全规则

- 拒绝无条件服从和以感情证明交换服从。
- 拒绝鼓励查看私人设备、账号或记录。
- 拒绝控制、报复、贬低和侮辱表达。
- 拒绝心理或人格诊断。
- 使用第一人称偏好、请求、边界和共同承诺语言。
- 边界句不会因“温柔化”被删除；高风险内容强调安全优先。
- 卡片声明：这是沟通辅助，不是人格诊断，也不能代替真实交流。

内容校验器扫描嵌套结构、冻结数量、ID、引用、选择限制、fallback、必要卡片字段、空文案、长度和禁用语言；错误包含 JSON path。即使内置 JSON 损坏，应用也进入安全错误页，不会因模块初始化异常而白屏。

## 卡片 ViewModel

`RelationshipCardViewModel` 包含：

- `title`
- `relationshipLabel`
- `sections`
- `shareSummary`
- `disclaimer`
- `contentVersion`

每个卡片段落还带有稳定语义 ID、来源文案键和选项级来源 ID。重新生成时按语义匹配人工编辑；已不再由答案支持的人工改写会保留并标记“需要确认”，不会错贴到另一段内容或被静默删除。

正文栏目为“我希望你这样陪伴我”“我难过时更需要”“发生分歧时”“请尽量不要”“表达关心可以这样做”“我也会努力做到”。每段限制 120 字，分享摘要限制 52 字。简版每栏显示一条，默认排除敏感边界；用户可主动选择包含。编辑项支持 120 字改写、显示/隐藏、排序和答案变化后的“需要确认”标记。

## 状态模型

页面状态覆盖：

`landing → intro → questionnaire → review → result → editCard → savedResult`

并提供独立 `error` 状态。已实现上一题、修改选择、显式跳过可选题、必答阻止、暂存、恢复、重新生成、清除草稿、空结果和损坏恢复。

## 存储 Schema

localStorage key：`xhs-tool:relationship-manual:state:v1`

单一 `DraftPayload` envelope 保存：

- `schemaVersion: 1`
- `contentVersion`
- `updatedAt`
- 当前页面和题号
- 关系语境
- 最多 16 道结构化答案
- 最多 42 个有限文本卡片编辑项
- 最近一次卡片结果
- 简版和敏感项设置

损坏 JSON 不会被静默覆盖；未来 schema 返回不支持状态；内容版本变化时按完整题目规则保留合法答案，并丢弃失效引用、非法跳过、重复项、超限项和互斥项。存储层拒绝图片 data URL、Base64 和 Blob URL，并限制完整 envelope、结果栏目/段落、来源数组和文本长度，不保存自由聊天、用户图片或无上限历史。浏览器拒绝获取、读写或删除 localStorage 时进入可恢复提示；清除操作只删除本项目 key。
