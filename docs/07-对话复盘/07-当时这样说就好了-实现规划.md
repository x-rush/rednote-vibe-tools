# 当时这样说就好了：实现规划

## 产品定义

正式名：**《当时这样说就好了》**。

副标题：**把那场对话，重新整理一次。**

一句话：不上传聊天记录，不判断谁对谁错，帮助用户把事实、感受、推测、需要和请求分开，重新组织真正想表达的话。

产品必须明确：重新整理表达，不代表问题都在用户，也不代表换一种说法就一定能够解决关系中的问题。

参赛标签：`#小红书vibecoding大赛 #vibetool`。

## 安全定位

- 不是心理咨询、关系诊断、PUA 鉴定或法律意见。
- 不推断对方动机，不生成报复、操纵或攻击话术。
- 不暗示冲突是用户“不会说话”造成的，也不鼓励用户为对方的伤害行为承担责任。
- 所有输入默认只存本机；首屏和输入页清楚说明。
- 提供“不保存本次内容”和“一键清空本地记录”。

## MVP 范围

- 5 步引导：事实、感受、自动解释、需要、具体请求。
- 内置情绪词、需要词和事实/推测示例。
- 输出一段可编辑的沟通草稿。
- 保存最近 3 次复盘或选择无痕模式。

不做：上传聊天截图、自动分析对方、关系评分、心理标签、云同步。

## 核心流程

```text
隐私说明/无痕选择 → 当时发生了什么 → 当时感受到什么
→ 写下脑中解释 → 标记事实或推测 → 选择需要
→ 真正想让对方知道什么 → 如果再说一次 → 生成可编辑表达
```

## 数据模型

```ts
type Debrief = {
  id: string;
  createdAt: string;
  fact: string;
  feelings: string[];
  interpretations: string[];
  needs: string[];
  request: string;
  draft: string;
  saveMode: "local" | "ephemeral";
};
```

## 内容与引导规则

- 事实提示示例：“昨晚 8 点发出的消息，到今天中午未收到回复。”
- 推测提示示例：“他不在乎我”属于解释，不是已确认事实。
- 请求应具体、可执行、允许拒绝，不写“你以后必须懂我”。
- 系统只重组用户提供的信息，不宣称草稿正确。
- 若用户主动输入明显涉及紧急伤害的内容，显示简短安全提示和求助建议；不继续给普通沟通技巧作为唯一答案。

## UI

- 极低刺激、稳定排版、无评分和红绿对错。
- 每步只处理一个认知任务。
- 输入区实时显示“仅本机/无痕模式”。
- 结果页标题使用“如果再说一次，我想这样表达”，并允许逐句编辑和删除。

## 测试

- 无痕模式刷新后不留内容。
- 本地模式正确保存、删除、清空。
- 极长输入、表情符号和换行不破坏布局。
- 模板不会把推测写成事实。
- 安全提示不会在普通争执内容上过度触发。

## 后续迭代

- 工作沟通、朋友误会、家庭沟通等引导版本。
- 复盘前后情绪自评，但不做诊断趋势。
