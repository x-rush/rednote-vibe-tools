# 极端密集场景第二轮性能记录（2026-10-18）

本轮只修改项目09，延续已有三层生态、品系、新形态、破壁和终局吞噬。不新增依赖，不修改敌人数量、AI频率、物理时钟、画布DPR或精细绘制预算。

## 最终保留

1. 控制器按同一模拟帧批量记录事件。120条事件只读取一次HUD、一次形态和一次渲染元数据，事件次序、终止边界和完整归档保持。导出的器官、形态和路线计数独立克隆。
2. 高频HUD同步不再复制整局事件日志；结果页、档案和奖励仍读取完整日志。日志保留在控制器中，没有删减历史。
3. 图鉴和奖励仅在状态真正前进时生成新存档。重复吞噬已完成物种、普通受击等返回原存档引用，避免React持久化effect重复序列化/写入；同批首次吞噬只奖励一次。
4. 普通受击、格挡、吞噬、器官/特质触发的DOM数值合并到原有100ms HUD定时器。破壁、进化、迁徙、死亡、Boss结算和结局立即刷新。Canvas、声音、输入和模拟仍按原时序处理。

## 未采用的探测

内构栅格图层、遮挡裁剪、常量缓存、装甲Path2D分组、远处细胞图层复用、非透明Canvas上下文，以及自动30/60帧节奏控制均未证明稳定收益，已撤回。没有为通过测试删减已实现功能；原型与对应新测试保存在本目录的discarded/探测文本中供追溯，生产源码没有引用这些原型。声音禁用仅用于诊断，没有进入生产。

## 测量边界

使用独立桌面Chrome、390×844 CSS px、DPR2、balanced画质，CDP CPU降速4×和6×。这不是低端手机或小红书宿主实测。

极端压力场景在第三层成熟状态注入120个真实AI追击者，持续补充可吞噬食物并保护玩家存活；实际经过地形破坏、追击和吞噬绘制。它用于压力定位，不是正常通关。固定16.67ms模拟步与真实RAF追赶分别记录，预热30帧；追赶场景可能在预热时已经发生部分破壁重叠，不能把其全部测量帧称为三事件重叠。

初始完整App诊断脚本曾在环境字段初始化后覆盖参数，实际停留第一层；`app-unpaced.json`、`app-paced.json`、`app-silentprobe.json`不用于第三层结论。已将覆盖移至初始化之前，并加入第三层environmentId断言；有效记录带correct/hud/repeat或final标签。

本轮最初目标为4×压力下P95≤33ms、P99≤50ms；6×为附加严苛测试。现有记录没有证明完整App在此120AI组合负载下稳定达到该目标，不能声称低端手机稳定30/60fps。4×/6×重复测量有波动，因此不使用单次最好值作为承诺，也不把render指令提交耗时等同于屏幕帧间隔。

最终构建、全量测试、正常完整流程与新产物的压力数据记录于本目录最终验证文件。真实Android/iOS、小红书宿主和低端手机长时间温升验收仍未完成。
