# 《物华录：文物寻踪》UI/UX 重设计 V2

状态：`DESIGN HANDOFF / NO BUSINESS CODE`
版本：`2026-08-25`
适用画布：`375 / 390 / 430 CSS px`

## 1. 设计结论

V2 是一张“闭馆后的文物档案工作台”，不是套着博物馆皮肤的四选一题库。用户与闭馆整理员许照共同完成一份卷宗：接案、观察、选择证据成本、落印判断、开柜揭晓、读完五段故事、回答离柜一问，再把文物送进专题藏格。

体验关键词：`暗柜`、`工作灯`、`档案机关`、`证据边界`、`安静的发现感`。

视觉层级必须始终满足：

1. 文物或“需要权威参考”的资源占位是第一主角。
2. 当前任务与证据成本是第二层。
3. 许照是持续在场的搭档，但主动给文物让位。
4. 装饰、纹理和动效只解释空间与状态，不制造稀有度。

## 2. 冻结范围

- 20 件文物、5 个四件专题、每件五段故事和许照设定不可改写。
- 一轮仍为 5 件，目标时长 5–8 分钟；长故事允许稍后继续。
- 不回退为“逐条线索＋普通四选一＋弹窗答案”。
- 不出现抽卡、SSR、金币、卡池、连续签到、伪 3D 大厅或鉴宝估价。
- 预览不得生成、描摹或想象文物图；无合格资源时必须显示“需要权威参考”。
- 现有许照三张资源优先复用；表情差分是增强项，不阻塞 V2。

## 3. 产品结构

```text
首页
├─ 继续上次 → 精确恢复到观察／线索／故事章节／离柜一问
├─ 接取今晚五件 → 接案 → 模式任务板
├─ 专题卷宗 → 五个专题柜
└─ 物华录 → 时间轴＋专题藏格

单件卷宗
接案 → 轻触观察签 → 线索印 → 选项＋盖章
     → 答错回看／开柜揭晓 → 五段故事
     → 离柜一问 → 入藏 → 相关文物／下一件

回合收束
五件完成 → 本轮档案 → 专题完成（条件触发） → 首页／图鉴
```

主动作规则：首页只突出“继续上次”或“接取今晚五件”之一。模式不使用四张同权卡片；它们是任务板中的抽屉、索引签或专题柜入口。

## 4. 视觉系统

### 4.1 色彩

```css
--museum-night: #121615;
--cabinet: #1d2321;
--cabinet-raised: #29302d;
--label: #eee8d9;
--label-strong: #f6f1e5;
--ink: #202522;
--muted: #737a74;
--line: #c9c0ad;
--bronze: #9b7950;
--light: #e8d5aa;
--jade: #607d70;
--cinnabar: #a3483f;
--error: #8e4a42;
```

朱砂只用于“当前选择、落印、重要纠错”；铜色用于编号和档案结构；暖光用于揭晓，不使用大面积金色渐变。

### 4.2 字体与数字

- 文物名、故事标题：本地宋体栈，字重 600；断网可用系统宋体。
- 正文、按钮、许照台词：本地黑体栈，字重 400–700。
- 卷宗号、年代、进度：等宽字体栈；内部英文枚举不得暴露给用户。
- 375px 下主标题 28–36px，不再使用会把选项推离首屏的 10vw 巨型标题。

### 4.3 材质

- 柜体：纯 CSS 深色层、细边线和低对比径向光，不请求纹理图。
- 纸签：象牙色实底、1px 边线、极轻微 CSS 噪点；不能做破旧卷轴。
- 印章：CSS/SVG 几何章面，不烧入文物名或未经核验古文字。
- 玻璃：只在揭晓用一层低对比反光，不长期覆盖观察细节。

## 5. 手机画布与响应式

### 5.1 通用壳

- 基准 390×844；内容列最大 430px，桌面居中显示。
- 页面左右安全边距：375px 为 16px，390px 为 18px，430px 为 20px。
- 顶栏 52–60px；主触控目标最小 48×48px。
- 底部动作区不覆盖正文；有固定操作时，为滚动内容预留 `按钮高度＋安全区＋20px`。
- 横向器物允许使用宽图 `contain`，不得为填满竖屏而放大裁两端。

### 5.2 观察页首屏预算

| 区域 | 375px | 390px | 430px |
|---|---:|---:|---:|
| 顶栏＋进度 | 56 | 56 | 58 |
| 观察台 | 300 | 320 | 344 |
| 线索印 | 92 | 96 | 100 |
| 选项可见部分 | ≥176 | ≥188 | ≥204 |

观察台采用 `aspect-ratio` 与 `contain`。许照头像固定在观察台外侧纸签上，不得占用观察图的安全区。

### 5.3 长故事

- 单列连续滚动；每段正文 80–180 汉字，行宽不超过 36 个汉字。
- 顶部五段目录为可横向滚动书签，不固定遮挡正文。
- 每一段可穿插 1 张观察图或“需要权威参考”占位；图片与正文属于同一阅读流。
- 底部主动作进入文档流，禁止固定按钮遮住最后一段。
- 返回后恢复到最近章节标题，而不是粗暴恢复像素位置。

## 6. 许照陪伴系统

### 6.1 身份统一

用户-facing 身份统一为“闭馆整理员 · 许照”；背景说明保留“修复学徒兼图录助理”。她尊重证据、不冒充亲历、不替馆方下结论。

### 6.2 三级露出

| 层级 | 资源 | 使用节点 | 规则 |
|---|---|---|---|
| A 主立绘 | `guide-master-v1.webp` | 首次引导、接案、入藏、套组完成 | 只在仪式节点使用；人物最多占宽 42%，手和道具完整 |
| B 半身裁切 | 主立绘 CSS 裁切 | 首页、答错、揭晓、恢复 | 靠侧边或桌后，不压文物；可随断点变化文案 |
| C 头像／书签 | `guide-avatar-v1.webp` | 观察、线索、故事、记忆题、图鉴 | 40–56px；配短札记，不悬浮遮挡按钮 |

`guide-placeholder-v1.webp` 只用于人物资源失败，不用作日常低清图。

### 6.3 出场职责

| 节点 | 动作语言 | 文案职责 |
|---|---|---|
| 首页 | 把卷宗推到桌面 | 报告今晚任务或上次断点 |
| 接案 | 解开档案绳、指向五格 | 说明主题和可得印记 |
| 观察 | 指向首枚编号观察签 | 提醒看形、材、痕迹；点亮后展开札记 |
| 线索 | 递出三枚线索印 | 解释三类证据与信息成本 |
| 求助 | 把一张干扰项移入排除栏 | 只排除一个选项并解释理由 |
| 答错 | 压住决定性证据纸条 | 共情混淆点，邀请回看 |
| 揭晓 | 说一句故事钩子后退侧 | 把视觉中心让给文物 |
| 故事 | 作为章节书签 | 每段末尾可补一个观察问题 |
| 离柜一问 | 抽出记忆卡 | 主持无惩罚题并解释答案 |
| 入藏 | 扶住图录、写编号 | 宣布所属专题和最佳星级 |
| 套组完成 | 盖专题印 | 总结四件关系，引出下一专题 |
| 图鉴 | 移动筛选签 | 推荐空缺套组与相关文物 |
| 恢复 | 夹住完好页面 | 解释保留了什么、将修复什么 |

常规台词采用 12–42 字；故事钩子可放宽到 70 字。同一节点至少三条轮换，默认可跳过，不能变成连续对话弹窗。

## 7. 核心玩法界面

### 7.1 轻触观察签

- `observationSpots` 直接在一张统一坐标校准的 `observation` 底图上显示为编号按钮；拆线索不换底图。触控目标不小于 48×48 CSS px，页面保持正常纵向滚动，不要求拖动、悬停或追逐隐藏位置。
- 首次进入只强调 01 号签，其余两枚降低强调但仍可点击；许照在图外提示“先点亮 01”，第一次点亮后开放任意顺序。
- 点亮后观察签转为朱砂色，在图下展开编号、标题与观察札记；进度持续显示“已观察 n / 3”。
- 三处全部点亮后许照引向线索印。观察仍不是作答或通关门槛，不调用设备振动，也不放大、扭曲或补画图像证据。
- 图上观察签本身就是键盘与屏幕阅读器入口，避免维护一套重复按钮。

### 7.2 三枚线索印

三枚印固定同区并可任意顺序选择：

- `看形`：轮廓与构造；首枚免费或遵循当前题的 0 成本配置。
- `辨材`：材料、表面与工艺；开启前明确星级变化。
- `问来历`：出土、时代或馆藏来历；不直接写答案。

开启后的印留在原位并显示摘要，选项不得因线索展开跳动。

### 7.3 选项与盖章

- 四个选项是同一张“判断底板”上的档案标签，单选语义。
- 选中后显示短解释标签，如“时代接近”“同为礼器”，帮助理解干扰设计。
- 盖章按钮紧接选项，仍在同一视觉容器；不在页面底部重复选中文字。
- 按住 320ms 可获得压章手感，但轻点必须同样可提交；提交后立即锁定，防止双计分。

### 7.4 答错回看

- 不立即播放完整揭晓。
- 错误选项移入“已排除”轨道，说明为何容易混淆。
- 观察台重新点亮，保留已点亮观察签和线索成本。
- 许照只指出一个决定性证据；用户可“再观察”或“仍然揭晓”。

### 7.5 开柜揭晓

- 不是弹窗。原观察台在同一位置由窄光扩成完整展柜。
- 顺序：锁定答案 → 柜灯展开 → 完整资源 → 名称标签 → 星级／事实边界。
- 新收集显示“标签入册”；已收集显示是否刷新最佳星级。
- 正误都获得同等完整知识，错误不追加惩罚。

## 8. 五段故事与收集

### 8.1 五段故事

固定章节：`第一眼`、`怎样被造出来`、`曾在怎样的世界`、`如何来到今天`、`今天为何还要看`。

首屏先给 90 秒故事概览；用户可连续读完或按章节跳转。`verified-fact`、`bounded-context`、`open-question` 通过文字标签区分，不只靠颜色。

### 8.2 离柜一问

- 从刚读内容出题，不计星、不计失败。
- 答对获得观察札；答错即时解释关键事实。
- 观察札是学习路径记录，不具货币、付费或稀有度语义。

### 8.3 入藏

- 文物缩略标签从揭晓区沿短路径落入专题藏格。
- 同时显示时间轴位置、专题 `已归档 n / 4` 与 1–2 件相关文物。
- 可选择下一份卷宗或继续读故事，不能强制跳过长内容。

## 11. 错误与恢复

### 11.1 资源失败

降级顺序：当前角色图 → 已核验剪影 → CSS 通用结构＋文字。最终状态不显示破图；观察、作答、揭晓、故事和入藏仍可完成。失败不扣星，不把损坏 URL 写入收藏。

### 11.2 坏存档

- 当前题损坏：保留已完成题、星级、图鉴和故事进度，只重建未完成部分。
- 内容版本变化：稳定 ID 仍有效则迁移，不因扩写故事清空进度。
- 无法恢复：允许放弃当前局，但“清空当前局”和“清空图鉴”必须分开。

## 12. 无障碍与 reduced-motion

- 每个图上观察签都是可聚焦按钮，具有编号、按下状态和 48px 目标；札记与进度通过 `aria-live="polite"` 播报稳定结果。
- 选项使用单选语义，盖章使用普通按钮；不能只有拖拽或长按路径。
- 猜谜阶段图片 alt 不含答案；揭晓后更新为准确名称与结构描述。
- 星级同时显示数字文字；事实边界同时显示文本标签。
- 所有焦点态 3px 可见描边；抽屉、帮助层和章节导航管理焦点与 Escape。
- `prefers-reduced-motion` 下取消聚光跟随、立绘推入、印章回弹、开柜光束和入藏飞行，改为直接换态＋120ms 交叉淡化。

## 13. 验收清单

- [ ] 25 个状态均可在设计预览中定位；不少于 16 个完整手机画面。
- [ ] 许照至少覆盖 6 个有效节点，且同一屏不遮文物、答案或主操作。
- [ ] 375／390／430px 无横向溢出；按钮不小于 48px。
- [ ] 聚光、线索印、盖章、开柜、故事、离柜一问、入藏均有明确视觉区域。
- [ ] 长故事可以滚到底，返回能恢复章节。
- [ ] 竖器、横器和组合器都使用 `contain` 与独立焦点策略。
- [ ] 资源失败、坏存档和 reduced-motion 可以走完一件文物。
- [ ] 所有文物占位明确标“需要权威参考”；不出现想象文物形象。
- [ ] 视觉与文案不出现抽卡、稀有度、金币或伪古风大厅语义。

## 14. 工程交接边界

本文件描述 V2 UI、状态与交互。实现只能消费类型化 ViewModel 与 `content.json`；观察点坐标、线索成本、故事章节、相关文物和许照台词不得硬编码在 JSX。正式扩展内容前必须先完成内容契约、资源门禁与存储迁移计划。
