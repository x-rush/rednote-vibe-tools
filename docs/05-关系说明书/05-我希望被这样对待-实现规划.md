# 我希望被这样对待：关系说明书实现规划

## 产品定义

一句话：把难以开口的相处偏好整理成一份可编辑的关系说明书。

正式名：**《我希望被这样对待｜关系说明书》**。

参赛标签：`#小红书vibecoding大赛 #vibetool`。

产品不是心理诊断，也不是向他人提出单向要求；它同时表达“我需要什么”和“我愿意怎么做”。

## MVP 范围

- 首发只做一个关系版本：亲密关系或好友关系，二选一。
- 12-16 个偏好问题。
- 7 个结果章节，可逐条编辑、隐藏、排序。
- 本地保存一个草稿、恢复默认、清空数据。
- 简版和完整版预览，方便用户直接截图。

不做：心理类型标签、账号同步、自动发送、双人匹配、关系好坏评分。

## 核心流程

```text
选择关系 → 回答偏好题 → 初始说明书 → 编辑/隐藏/排序
→ 简版/完整版预览 → 本地保存 → 随时回来修改
```

## 结果章节

1. 我累的时候。
2. 我难过的时候。
3. 发生矛盾时。
4. 我如何感受到被重视。
5. 哪些安慰对我无效。
6. 我的边界和提醒方式。
7. 我愿意怎样对待你。

## 数据模型

```ts
type PreferenceQuestion = {
  id: string;
  section: string;
  prompt: string;
  options: { id: string; text: string; outputIds: string[] }[];
};
type ManualItem = {
  id: string;
  section: string;
  text: string;
  editable: boolean;
  sensitive: boolean;
};
```

## 内容规则

- 不把任何偏好描述为更成熟、更健康或更高级。
- 不使用回避型、焦虑型、人格障碍等标签。
- 句子使用第一人称，避免命令式：“我会更舒服，如果……”
- 每个需要尽量搭配一个自己的承诺。
- 敏感内容默认不进入简版。

## UI

- 温和、清晰、非测试感；避免粉色情感营销模板。
- 编辑页像一封可以整理的信，而不是心理报告。
- 明确显示“内容仅保存在本设备”。
- 结果区设计为手机截图比例，但核心功能不依赖下载。

## 测试

- 每种答案组合都能生成非空说明书。
- 编辑、隐藏、排序和恢复默认可靠。
- 清空数据后无残留。
- 长文本不会溢出；输入法收起后按钮可见。
- 无任何对用户心理状态的确定性判断。

## 后续迭代

- 好友、室友、合作伙伴版本。
- “我们可以一起讨论的三个问题”。
- 多份说明书本地管理，仍不上传云端。
