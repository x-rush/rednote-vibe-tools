# SHBTI Q版异兽认兽小札设计

状态：已确认
日期：2026-08-26
范围：`projects/01-sbti`

## 1. 目标

为 16 种兽格结果各增加一张“山海司认兽小札”，用原创Q版异兽、原典辨识点和一句俏皮祝福，解决用户不认识异兽或将其误认成普通动物的问题，同时形成统一、可收藏的结果页彩蛋。

成功标准：

- 用户在进入长篇结果前，能快速说出异兽名称及一个关键形貌；
- Q版形象保留原典辨识特征，不把异兽改造成普通萌宠；
- 16 种结果体验完整一致，但文案不重复使用同一套“这不是……”模板；
- 新卡片不挤占正式兽志分享卡，也不削弱长结果页的主叙事；
- 375、390、430 CSS px 下无横向溢出，文案和主体均完整可见。

## 2. 非目标

- 不替换现有正式异兽画像；
- 不修改题目、计分、结果映射或本地存档结构；
- 本阶段不新增Q版分享卡模板；
- 不增加音效、小游戏、收集册或额外点击任务；
- 不临摹参考图的线稿、姿势、挂饰或具体构图。

## 3. 页面位置与信息层级

结果页顺序调整为：

1. 兽格标题与正式画像；
2. 闻山批注；
3. 现有闻山帮助入口；
4. **山海司认兽小札**；
5. 卷一至卷六长篇解读；
6. 现有正式兽志签与生成卡片入口。

认兽小札位于卷一之前，让辨识发生在用户第一次看到异兽时。它不进入现有 Canvas 分享卡，避免一张卡同时承载正式画像与Q版形象。

### 移动端布局

- 375–430px：左侧 Q 版异兽占 96–116px，右侧为眉题、辨识句和祝福；
- 图片可轻微越出内框，但不得越出页面；
- 文字区使用 `minmax(0, 1fr)`，长句自然换行，不挤压图片；
- 卡片整体使用暖宣纸底、淡金细框和朱砂“丰/安/明”等单字印；
- 小于 360px 时允许改为上图下文，但本项目正式门禁仍为 375/390/430px。

## 4. 组件与内容结构

新增独立展示组件 `BeastRecognitionCard`，由 `ResultPage` 在所有结果中渲染。组件不判断具体兽格，也不硬编码文案。

每个 `PersonalityType` 在 `src/content/content.json` 中增加必填内容：

```ts
recognitionCard: {
  kicker: string
  hook: string
  blessing: string
  seal: string
  alt: string
}
```

资源映射继续由 `src/ui/beastAssets.ts` 管理，为每只异兽增加 `chibiSrc`。业务文案只存在 `content.json`，符合项目内容约束。

图片加载失败时显示文字完整的宣纸札和 CSS 兽形印记，不替换成其他异兽，也不阻断结果页阅读。

## 5. 统一美术规范

- 形式：原创Q版中国水墨设色异兽，透明背景；
- 比例：1:1，建议母版 1024×1024 PNG，发布版 768×768 WebP；
- 构图：主体完整，四周至少 12% 安全边距，头部与关键器官不得贴边；
- 色彩：米白、墨灰、暖金为基底，每只保留正式画像的主色；朱砂只作小面积点睛；
- 线条：松弛手绘墨线，轮廓清楚，避免现代扁平矢量感和三维玩具感；
- 表情：可亲但不幼儿化，不使用夸张大眼、腮红贴纸或表情包文字；
- 原典：必须保留下表所列关键形貌；不得为方便可爱化而补错肢体、删头、删尾或改变物种；
- 图内不生成汉字、英文、印章文字或水印，所有文字由 HTML/CSS 渲染；
- `research/ODL.jpg` 只用于可爱比例和水墨松弛感参考，不复制其姿势、挂饰和线稿。

## 7. 动效与交互

认兽小札不增加操作任务。第一次进入视口时：

1. Q版异兽从下方 6px 淡入并轻跃一次，约 420ms；
2. 辨识句随后淡入，延迟约 80ms；
3. 朱砂单字印以轻微缩放落下，延迟约 160ms；
4. 动效结束后保持静止，不循环、不闪烁、不发声。

实现可使用 `IntersectionObserver` 在首次进入视口时添加状态类；开启减少动态时直接显示最终状态，不执行位移和缩放。

## 8. 无障碍与降级

- 卡片使用有标题的 `section`，眉题可作为可访问名称；
- 图片 `alt` 必须描述名称和关键形貌，不能只写“Q版异兽”；
- 辨识信息全部作为真实文本出现，不依赖图中文字；
- 祝福与原典事实分成两个段落，避免用户把创意祝福误认为典籍原文；
- 图片失败时保留名称、辨识句、祝福和印记；
- 不使用自动播放声音，不要求手势操作，不设置固定或粘性控件。

## 9. 美术生成与复核流程

1. 先冻结统一提示词骨架和负面约束；
2. 以现有正式画像约束原典特征，以 `ODL.jpg` 只约束Q版比例与水墨松弛感；
3. 按四组生成，每组四只：
   - 第一组：陆吾、耳鼠、当康、狌狌；
   - 第二组：英招、帝江、讙、凤凰；
   - 第三组：旋龟、毕方、精卫、鹿蜀；
   - 第四组：开明兽、烛阴、朏朏、九尾狐；
4. 每只先检查头、肢、翼、尾数量和物种结构，再检查可爱度与风格一致性；
5. 每组通过后转换为本地 WebP，禁止运行时 CDN；
6. 最后输出 16 图总览，逐只验收，不使用“一套裁切参数套全部异兽”。

## 10. 测试与验收

### 内容门禁

- 16 个结果都必须有完整 `recognitionCard`；
- 16 个 `chibiSrc` 唯一且指向本地 WebP；
- 辨识句必须包含异兽名或可明确回指名称；
- 印记必须为单个中文字符；
- 不改变题库、计分映射、结果代码和存档版本。

### 组件门禁

- 16 种结果都显示对应小札；
- 不得把某只异兽的Q版图映射到另一只；
- 图片失败时文字内容仍完整；
- 现有正式画像与 Canvas 分享卡保持不变；
- 减少动态模式不执行位移动画。

### 视觉门禁

- 375、390、430 CSS px 逐一检查；
- 图片、文字、印记均在卡片与页面边界内；
- 当康獠牙、帝江无面六足四翼、讙一目三尾、毕方一足、开明兽九首等关键特征必须可辨；
- 非零顶部安全区验证结果页无新增遮挡；
- 16 张图全部加载成功，0 错配、0 损坏、0 图中文字乱码。
