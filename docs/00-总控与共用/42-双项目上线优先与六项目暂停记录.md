## 3. 执行阶段与顺序

### A. SBTI 上线闭环

1. 盘点 WSL 实际代码、冻结文档、正式资源和内容 JSON 的差距。
2. 完成 48 题、单轮 24 题、四维计分、16 型结果、近邻型、历史结果与来源说明的完整路径。
3. 将已审核的 16 张兽像及降级资源装入真实应用；不再为同一兽重复生成相似背景图。
4. 执行 lint、test、build，以及 375／390／430 CSS px 的交互和裁切验证。
5. 检查存储损坏回退、刷新恢复、图片失败降级、包体、控制台与网络请求。
6. 完成部署、线上冒烟测试、比赛提交信息与首轮问题修复。

### B. 物华录上线闭环

1. 盘点 20 件文物内容、三线索谜题、来源抽屉、图鉴状态与正式资产的真实差距。
2. 完成猜谜、揭晓、收藏、图鉴、来源与图片性质声明的完整路径。
3. 只按真实页面和首发内容补齐资源；所有历史实物图像必须先有实际参考与可追溯证据，再艺术化生成并二检。
4. 执行与 SBTI 相同的静态构建、三宽、异常恢复、性能和线上验证。
5. 完成部署、线上冒烟测试、比赛提交信息与首轮问题修复。

默认执行次序为 SBTI 先上线、物华录随后上线。若两者代码工作已经并行进行，可以继续并行修复，但发布门禁和验收记录分别执行，不能用一个项目通过代替另一个项目通过。

## 4. “上线完成”的统一门禁

单个项目必须同时满足以下条件，才记为已上线：

- 核心玩法从入口到结果／收藏完整可达，无占位按钮和阻断路径。
- `src/content/content.json` 的生产内容通过 Schema、计数、唯一 ID、引用与安全校验。
- 在项目目录执行 `pnpm lint && pnpm test && pnpm build` 全部通过，不通过删测试绕过。
- 375、390、430 CSS px 下无关键内容溢出、误裁切或不可操作控件。
- 静态部署可访问；刷新、返回、存储为空或损坏、图片加载失败时不白屏。
- 无必需后端、运行时 CDN 或外部 API；不保存用户图片、Base64、音视频或 Blob。
- 正式资源有来源／生成记录，且在真实页面完成事实、风格、构图与降级二检。
- 官方比赛规则、构建方式、包体和提交要求在提交当日重新联网核验。
- 线上版本完成至少一轮真机／等效移动端冒烟测试，并记录发现的问题及处理结果。

## 5. 六项目恢复门禁

项目 03–08 只有在以下条件全部满足后才可恢复：

1. SBTI 已上线并通过第 4 节全部门禁。
2. 物华录已上线并通过第 4 节全部门禁。
3. 两个线上版本均完成首轮问题修复，没有阻塞核心路径的 P0／P1 问题。
4. 比赛提交所需链接、说明、截图／录屏与版本记录已经归档。
5. 用户确认进入下一阶段，并重新选择第 3–8 项的恢复顺序与并行度。

满足门禁后也不自动一次性恢复六项。先复核届时剩余时间、比赛规则、已验证的技术母版和资源生产速度，再决定一次恢复一个还是少量并行。
