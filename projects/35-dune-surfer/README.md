# 沙丘速降（35 号）

复刻自 eazo.ai 的 `Dune Surfer`，改造成纯前端静态小红书小工具。

- **一句话**：按住屏幕左右滑动切弯，跟着坡上最陡的那条线跑，身后那堵雪崩一直咬着你不放。
- **平台简介**：贴着雪崩，甩出一道漂亮的尾迹
- **来源**：[eazo.ai Dune Surfer](https://eazo.ai/apps/dune-surfer-arcade-game-hx4egj0p)
- **批次方案**：见 `projects/31-shuttlecock-kick/PLAN.md`（31–35 号批量复刻方案）

## 玩法

1. 竖屏单指操作：**按住屏幕左右滑动**，手指偏多少玉板就横移多少（横向速度有上限）。
2. 坡面上有一条**发亮的落水线**，那是最陡的一条线，也是坡上的**快车道**。贴着它跑速度最快，偏出去就掉速——这条线会左右游走，必须一直追。
3. 快车道上偶尔横着一道窄石脊，得轻轻绕一下；快车道之外则是成片的岩体，不追线的人才会被它们绊住（撞上就大减速并被雪崩咬一口）。
4. 雪崩在身后按**固定速率**吃掉你的缓冲（每个海拔带速率不同，越往下越快）；你要是慢下来，它咬得就更快。
5. **左右快速甩一下**（横向速度反向且够快）就是一次「甩尾」，能把雪崩推开一段。这是唯一的回血手段。
6. 穿过两根旗子中间得分并把雪崩推远一点；旗门和跳台都挂在快车道上，追线的人顺手就吃到。
7. 越往下坡越暗、障碍越密、雪崩追得越紧：五个海拔带（黄昏起势 → 玫瑰暮色 → 暮紫长坡 → 深蓝夜行 → 极光终程）。
8. 结束时生成一张 720×960 的**山脊线**纪录卡，画出你这一趟的横向轨迹，危险段会标红。

## 手感设计

这一款是纯手感向的，所以「技术到底有没有回报」是必须用数据说话的事，不能靠感觉。

### 三个机制，一条主线

| 机制 | 玩家看到什么 | 换来什么 |
|---|---|---|
| 落水线（快车道） | 坡上一条会游走的亮带 | 更快（贴线 vs 离线终端速度差约 30%） |
| 甩尾 | 左右反向快甩 | 把雪崩推开（唯一能主动回血的手段） |
| 旗门 | 两面小旗子 | 得分 + 把雪崩推远一点 |

三者都直接作用在「雪崩离你多远」这一个数上，所以玩得好不好是可以被量出来的。

### 这里返工过两次，都值得写下来

**第一版**：熟练玩家和随手玩家的平均距离只差 5%——等于技术没有回报。查出两个原因：

1. **「随手玩家」模型其实很会玩**：它照样追着落水线跑，所以两个模型的速度几乎一样。真实的随手玩家并不知道那条线在哪，只会在屏幕中间晃。把这一点写进模型之后（`trackLine: false` + 守在中间），差距才显出来。
2. **雪崩推进速率是玩家速度的函数**（`speed × (wallRatio - 1) + wallPush`）：跑得越快雪崩咬得越紧，「追线更快」被自己抵消了，早段甚至变成越慢越好。改成雪崩按每个难度段的**固定速率**推进后，速度才重新变成「跑得远」的筹码。

**第二版**：修完上面两条，差距有了（24%），但仍然只有 4% 的速度差——技术回报几乎全靠旗门，多米诺骨牌式的。继续排查发现三个更隐蔽的问题：

3. **落水线游走得太快，玩家根本贴不住**：横向漂移率 0.38，按 600 的速度换算要每秒 228 单位的横移，而横向速度上限才 210。玩家一直在追一条追不上的线，「快车道」根本不成立。把游走放慢到 0.24 之后才追得上。
4. **躲岩脊吃掉了全部决策时间**：玩家模型写成「只要前方有岩脊就往边缘靠」，哪怕自己根本不在岩脊上——实测 84% 的决策都在做无谓躲避，追线行为几乎没机会发生。改成「真的会被这块石头挡住才躲」之后，追线占比才回到 40%。
5. **旗门把人从快车道上拽下来**：旗门挂在快车道**前方**（那里的线已经移走了最多 120 单位），模型一头扎过去追旗门，反而离开了快车道。改成「只捡顺路的旗门」。

**还重构了世界布局**：早先是「岩脊压在玩家身上」，逼人往两边躲——躲石头占满了时间，玩家没机会追线。现在快车道两侧留出走廊，**坡侧岩体一律放在离快车道 `WALL_CLEAR = 90` 以外**，只有横在快车道上的窄石脊才需要绕。于是：

- 追线的人：速度全开、旗门顺手吃到、只在窄石脊上轻轻绕一下；
- 不追线的人：全程在慢坡上磨速度，还会被坡侧岩体拦下。

这两条差距合起来，才终于让「会不会用画面上给出的信息」变成一件有分量的事。

改完之后：

| 模型 | 平均距离 | 最差一局 | 平均秒 | 旗门 | 甩尾 | 撞岩脊 |
|---|---|---|---|---|---|---|
| 熟练玩家（追线、反应 220ms） | 3034 米 | 1772 米 | 47 | 19.9 | 16.6 | 4.6 |
| 随手玩家（守中间、反应 380ms） | 1757 米 | 1029 米 | 30 | 5.8 | 10 | 2.3 |

熟练玩家远 73%、多拿三倍旗门、一局长 17 秒——技术有回报；但随手玩家也玩得下去（最差一局 1029 米）。这些数字被写进 `qa-balance-check.cjs` 当硬断言，以后改参数一旦把手感改坏，回归会直接失败。

### 另外两个真 bug

- **撞岩脊的判定根本没检查玩家是否在岩脊范围内**，导致每道岩脊必撞（命中率 100%）。玩家模型的「撞岩脊」指标第一版是 12–17 次／局，修掉之后降到 1–3 次。
- **特征结算的遍历用了「遇到远处的就 break」**，隐含假设特征列表按距离有序。手工塞进去的岩脊排在末尾就被整段跳过——真实游戏里列表恰好有序，所以线上没炸，但这个假设太脆，改成不依赖顺序。

## 工程约束

- 纯前端静态：经典脚本加载链，禁 `type="module"` / `import` / `eval` / 内联脚本 / 行内事件。
- Chrome 61 / Android 8.1 WebView 61 基线：ES2017，CSS 不使用 flex `gap`、`clamp()`、`aspect-ratio`、逻辑属性、`:has()`、`inset`、`dvh`；Canvas `roundRect` 手写路径。
- 无后端、无运行时 CDN、无必需外部 API、无音频文件：音效全部由 Web Audio 实时合成（风声跟着速度走，雪崩轰鸣跟着距离走）。
- 业务内容集中在 `src/content/content.json`（含 `brand` / `xiaohongshuDraft` / 5 段难度参数 / 5 套配色 / 文案）。
- 只在 localStorage 保存结构化状态（最高分、最好成绩、静音偏好），不保存任何用户媒体。
- 宿主按钮避让：顶部左右各留 `--host-side: 76px`，标题与 HUD 在 `--host-top: 56px` 之下；横屏改成左栏 + 场地两栏，左栏让开左上返回键。
- 上架素材不复用任何历史条目素材，logo 为本项目原创。

src/app.js            单指切弯、HUD、危险提示、结算、山脊线纪录卡

qa-mobile-check.cjs   375/390/430 + 安全区 + 宿主覆盖层 + 横屏宿主避让 + 真实拖拽切弯

## 本地运行

```powershell
npm run lint
npm test
npm run build
node verify-artifact.cjs dist
node qa-mobile-check.cjs
node qa-flow.cjs
node qa-balance-check.cjs
node tools/probe.cjs            # 手感探针：改难度参数后先跑它看曲线
node tools/logo-png.cjs          # 由 assets/logo.svg 重渲染 512 PNG
node tools.mjs preview 4335      # http://127.0.0.1:4335
pwsh -NoProfile -ExecutionPolicy Bypass -File pack.ps1
```
