# 八项目 UI 与美术自检验收规范

状态：`MANDATORY VISUAL QA`  
生效日期：2026-08-24  
最近修订：2026-08-25（新增“项目需求适配卡”硬门禁）

## 1. 完成的定义

资源被生成出来不等于完成。只有同时通过以下检查，才可标记为 `reviewed`：

1. **事实正确**：与 reference dossier 的不可变项一致。
2. **结构正确**：数量、肢体、器型、透视、文字和材质无明显错误。
3. **审美合格**：主体清楚、构图稳定、风格统一，不以猎奇或堆特效掩盖问题。
4. **项目风格适配**：符合该项目的世界观、时代、情绪、媒介与系列基准；不能是脱离产品仍然“单独好看”的通用 AI 图。
5. **功能适配**：资源必须服务已冻结的页面目标和交互任务。无法说明它帮助用户完成什么、为何出现在这个状态、视觉焦点应落在哪里的资源，不得生成或采用。

> 生成前提醒：先读对应项目 `DESIGN.md`、当前页面状态与已批准系列基准，再写提示词。禁止八个项目共用一套泛化的“高级感”“国风”或“游戏感”提示词；每个项目必须保持自己的世界观、材质、色彩、构图、角色气质和信息层级。
6. **页面功能适配**：资源确实服务当前玩法和交互时刻，在实际 UI 裁切和缩略尺寸中仍然可辨，不抢夺标题、选项、数值、证据或主操作，安全区正确。
7. **技术合格**：尺寸、格式、透明通道、体积、命名和 fallback 达标。
8. **版权可用**：参考图用途与最终资源性质记录清楚，最终资源不包含水印或受保护标识。

任一项失败，状态保持 `generated` 或退回 `reference-required`，不得接入正式发布界面。

## 1.1 项目需求适配卡（每张正式资源必填）

正式提示词、manifest 条目与视觉复检记录必须能够共同回答以下六项；缺一项即禁止生成正式稿，任一项验收失败即禁止发布：

| 字段 | 必须回答的问题 | 失败示例 |
|---|---|---|
| `projectStyle` | 它为何一眼属于这个项目？对应哪些世界观、时代、色板、材质和表现媒介？ | 只写“高级国风”“治愈插画”“精美 RPG”，换到其他项目仍成立 |
| `pageRole` | 它在具体页面承担识别、叙事、证据、反馈、引导还是装饰？ | 画面漂亮，但无法说明对页面有什么帮助 |
| `interactionMoment` | 用户在看到它之前做了什么，看到后应理解什么或执行什么？ | 结果图被放进答题页，提前泄露答案；氛围背景遮住当前操作 |
| `emotionalGoal` | 当前时刻应建立怎样的情绪，强度是否符合玩法节奏？ | 检查清单制造焦虑；温和沟通工具使用审判或警报语气 |
| `seriesBaseline` | 它与哪些已批准资源保持轮廓、光照、笔触、材质和角色比例一致？ | 单图优秀，但放进同系列后像来自另一款产品 |
| `avoid` | 该项目、该页面及该事实原型明确不能出现什么？ | 跨朝代元素、泛古装影楼感、廉价抽卡光效、无功能装饰、事实结构错误 |

这六项不是提示词装饰字段，而是资源是否符合项目需求的判定依据。**“好看但不适用”“准确但不像本项目”“风格一致但妨碍交互”均判失败。**

验收分两关：

1. **单资源适配检查**：在透明/中性检查背景上核对事实、结构、项目风格、页面角色和系列一致性。
2. **实际 UI 二检**：装回目标页面，在 375、390、430 三档移动端宽度检查裁切、缩略识别、文字对比、焦点顺序、主操作让位和情绪强度。只有两关均通过，manifest 才可写 `reviewed` 或 `shipped`。

## 2. AI 图片逐张自检

### 通用检查

- [ ] 主体数量正确，没有重复、融合或凭空增加的对象。
- [ ] 肢体、尾、翼、角、眼、手指、爪等结构合理。
- [ ] 前后遮挡关系和透视可信。
- [ ] 没有乱码、伪文字、水印、签名或模型残留。
- [ ] 没有无依据的现代物件、盔甲、饰品和建筑。
- [ ] 背景没有抢夺主体，移动端缩略仍可读。
- [ ] 色板、线条、颗粒和光线与同系列基准一致。
- [ ] 第一眼能判断它属于目标项目，而不是可替换到任意古风、治愈或 RPG 产品的通用素材。
- [ ] 资源的视觉重量符合页面角色：主视觉可建立情绪，辅助图不得压过题干、证据、选项、数值与主按钮。
- [ ] 画面动作、道具和环境能支持实际玩法，不为展示模型能力添加无功能的复杂场景。
- [ ] 未挪用其他七个项目的画风；同一题材跨项目时仍按目标项目的设计系统重新判断。
- [ ] 没有为了“漂亮”改写文化事实。
- [ ] 没有为了“准确”保留明显丑陋、错误或难以辨认的生成缺陷。

### 异兽

- [ ] 逐项核对原典器官组合与数量。
- [ ] 对比至少一张可追溯历史图像。
- [ ] 标明历史图像的版本年代，不宣称复原先秦原貌。
- [ ] 人面兽身等组合既保留怪异性，也避免无意义恐怖化。

### 文物/器物

- [ ] 器型轮廓、口沿、足、耳、盖、柄、纹饰位置与馆藏实物一致。
- [ ] 缺损不得被 AI 随意补全；补全必须标“重构”。
- [ ] 材质光泽正确，不把青铜画成黄金、陶器画成塑料。
- [ ] 产品中明确区分实物图、公共领域图、自绘示意和 AI 重构。

### 人物/服饰/建筑

- [ ] 朝代、身份和场景对应。
- [ ] 服装形制、发式、器具和建筑构件有参考依据。
- [ ] 不混入清宫、日式、韩式、武侠影楼或泛古装元素。
- [ ] 不用现代审美妆造抹掉身份差异。

## 3. UI 自检

每个项目至少检查：

- 375 × 812
- 390 × 844
- 430 × 932
- 768px 以上居中移动端画布

检查项：

- [ ] 首要动作在首屏可见。
- [ ] 无横向滚动。
- [ ] 刘海和底部安全区不遮挡操作。
- [ ] 点击区域至少 44 × 44px。
- [ ] 正文至少 16px，辅助文字至少 12px。
- [ ] 文字与背景满足可读性，不能靠纹理遮盖低对比。
- [ ] 所有加载、空、错误、离线和图片失败状态可恢复。
- [ ] 键盘焦点可见。
- [ ] `prefers-reduced-motion` 下功能完整。
- [ ] 资源延迟加载不造成严重布局跳动。
- [ ] 分享卡在目标比例内无截字和关键裁切。

## 5. 批量生成门禁

同类资源必须先通过一张基准图：

- 异兽：陆吾通过后再扩展其他兽；四种差异形态通过后再生成完整 16 兽。
- 文物：一件青铜器、一件陶瓷/玉器分别通过后再批量。
- 人物：一个基础立绘与两种表情通过后再扩展角色。
- 场景：一个白天与一个夜间/天气变体通过后再扩展。
- 徽章/图标：先通过一组 3 个，确认线宽、视角和色板后再扩展。

批量中任何三张连续出现结构错误或风格漂移，暂停批量，回到提示词和参考包修订。

## 6. 交付物

每项目最终必须具有：

- `DESIGN.md`
- `UI-HANDOFF.md`
- `design/preview.html`
- `public/assets/<project>/asset-manifest.json`
- `public/assets/<project>/PROMPTS.md`
- `research/*-reference-dossier.md`（涉及事实原型时）
- `VISUAL-QA.md`
- 发布图与轻量 fallback

缺少任一强制交付物时，项目视觉状态不得标记为 `VISUAL READY`。
