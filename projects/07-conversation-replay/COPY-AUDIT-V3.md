## 陪伴邀请链

19 个时刻按“建立边界 → 缩小选择 → 区分事实与推测 → 命名感受与需要 → 形成可拒绝的请求 → 练习但不预测 → 输出但不催发送”的顺序衔接。每个时刻同时包含邀请和自主权提示；需要安抚时才增加 reassurance，避免迟言喧宾夺主。

- landing / privacy / guide：先说明不必上传聊天记录、保存方式与跳过权，再邀请开始。
- relationship / goal / scenario：每次只做一个低负担选择，不要求讲完整故事。
- fact / feeling / inference / need / request：从可核对事实进入体验，把推测明确标记为待核对，再把需要转成可拒绝、可协商的请求。
- draft / practice / comparison / result：草稿默认不发送；演练明确不是预测；对照不是评分；结果不承诺被理解或答应。
- saved / exit / recovery：解释本机保存、会话丢失和失败恢复，不制造留存压力。
- safety：迟言主动退到辅助位置，现实安全与现实支持优先，不引导继续演练或对质。
