# 技术、容器与交付约束

状态：立项设计，2026-09-19。下列性能、概率与手感数值均为初始设计目标，尚无原型或真机实测，不代表已验证效果。

## 1. 技术决策

- 语言：TypeScript strict；界面用语义化 DOM + CSS；模拟层为无 DOM 的纯函数/状态机。渲染层不决定奖励、鱼获、隐藏物或成绩。
- 构建：Rolldown 输出单一 app.js IIFE 经典脚本，目标 chrome61/ES2017；TypeScript 单独 --noEmit 类型检查。开发服务器用项目内 Node 工具；Node 仅构建/开发使用。
- 游戏运行时不选 React/Vue：当前只有场景、少量工具和图鉴，逐帧状态不进入组件树。无需引入通用游戏引擎、刚体引擎或复杂路由。
- 四个水景项目选原生 WebGL 1 + 小型项目内渲染适配层，GLSL ES 1.00；找菌子选 Canvas 2D 分层绘制。WebGL 项目均需同一逻辑驱动的 Canvas 2D 简化渲染。
- 原生 WebGL 的代价是材质和资源生命周期需要自己维护。因此限定固定/受控镜头、少量绘制通道和专用效果，不自建通用 3D 引擎。若实测效果不足，先调整构图与材质，不能直接堆全屏后处理。
- Three.js 当前 WebGLRenderer 要求 WebGL 2，r163 起不支持 WebGL 1，不适合作为本仓库默认兼容链路。PixiJS 虽适合精灵管理，本次不为少量场景额外引入整套依赖及渲染版本审计。WebGPU 不作基线。
- 不使用物理流体、逐粒沙子全碰撞、屏幕空间反射、体积光线步进作为基础功能；通过低维模拟、法线贴图、静态环境反射、局部扰动获得画面。
- 测试：Vitest 用于确定性模拟/状态机/存档；浏览器自动化选 Playwright，仅开发使用。oxlint + tsc 做静态检查。测试工具若未声明或未安装，由总控统一增依赖。
- 已读到工作区现有工具：TypeScript 6.0.3、Rolldown 1.2.5、Vitest 4.1.11、oxlint 1.79.0。它们是现有环境记录，不等于新项目已声明或获得依赖权限。实施前逐项目声明经总控确认的精确版本，不靠扫描 .pnpm 找传递依赖。
- 本次不安装依赖、不创建假 package.json、不更新锁文件。新增运行时依赖预期为零；开发依赖需求单：typescript、rolldown、vitest、oxlint，以及开发期 @playwright/test（工作区不可用时再由总控添加）。

## 2. 模块和数据边界

建议模块：
- src/core/model.ts：类型、状态转换、固定时间步、命令处理。
- src/core/random.ts：可注入 seeded PRNG；内容生成、物理扰动、纯视觉粒子各用独立随机流。
- src/input/gestures.ts：pointer/touch 归一化、取消、坐标映射。
- src/render/：高低画质渲染与资源释放；找菌子不需要 GL 模块。
- src/ui/：图鉴、结果页、设置、无声提示、首次引导。
- src/storage.ts：版本化结构化存档、去重提交与迁移。
- src/audio.ts：用户手势解锁、按需解码、节点清理。
- src/content/content.json：唯一业务内容源。物种/物件、文案、权重、场景、挑战、手感调参、音频映射都在这里；构建时导入内联，运行时不 fetch。
- assets/：合法本地图片；源音频置于开发素材目录，构建成经典 JS 静态数据。着色器可开发期保存为源码，构建成 JS 字符串，不将 .glsl 放入 ZIP。
- tests/、qa/、scripts/ 仅开发期；dist/ 与 release/ 待实施时产生。

模拟用固定 1/60 秒时间步，限制单帧追赶步数，渲染插值；隐藏后暂停，不补算后台时间。随机结果须在进入区域/生成一盘/生成一次咬口时确定并留在会话状态，不能每次点击、重绘或切换画质重新抽奖。保留 seed + contentVersion + simulationVersion，复现以同版本为前提，不承诺跨版本浮点逐位一致。

## 3. 手势、布局与宿主避让

- 首版全部竖屏优先，真实横屏自适应；不提供 CSS 模拟横屏开关。即使将来加入，也必须把物理屏幕宿主矩形逆变换到内容坐标，另行验收。
- 375 / 390 / 430 CSS px 竖屏；横屏至少 667×375、844×390、932×430。横屏将工具列放可用侧区，缩减无关环境，不隐藏必要操作。
- 系统安全区使用 var(--safe-area-inset-top, env(safe-area-inset-top, 0px))；底部同理。所有顶部 fixed/sticky 控件及锚点偏移都叠加安全区。
- 宿主左右按钮是额外物理屏幕占位。配置 hostLeftRect、hostRightRect、hostTouchMargin，归入内容配置的布局段；测试参数非真实几何声明。默认中下部操作，顶部两侧仅背景，不用大块顶部空白。
- 测试覆盖层使用 CSS px 场景组：左右宽 56/72/88、高 44/60/76、边缘偏移 8/16、触摸外扩 12/20；再叠加 top=0/24/44、bottom=0/34 系统安全区。这些是压力测试组合，不代表所有宿主设备尺寸。
- 暂停、返回场景、设置、关闭抽屉必须远离占位；抽屉关闭放底部明确按钮。首页、游玩、结果、图鉴、设置、错误页及实际新增状态逐个检查。
- 场景手势不从宿主遮挡区起手。按钮触区最低 44×44 CSS px；小物件可放宽命中区域，但重叠物必须按可见深度和距离裁决，不自动选到被遮挡物。
- Pointer Events 能力检测，缺失时用 touch + mouse 适配；记录单个活动触点，忽略额外触点。pointercancel、丢失捕获、移出、旋转、暂停都终止动作；取消不等同松手确认。
- 手势距离按有效操作区归一化；不用设备 pressure、不要求摇手机、不调用陀螺仪、振动或全屏 API。
- touch-action:none 只在游戏操作区；图鉴保留垂直滚动。先位移超过 6～10 CSS px 再判拖拽。交互立即给光标/物件反馈，惯性仅施加到模拟对象，不能让手指指示点落后。
- 提供单指慢速/辅助操作方案，各项目详述。动画减弱模式取消镜头摇晃与大幅转场，保留判断所需反馈；声音信息有视觉等价提示。

## 4. 视觉与素材标准

整体为自然写实的轻游戏场景：画面占首屏主要面积，工具控制收在中下方。禁用占满屏幕的卡片菜单、金币商店、霓虹 HUD 和大号任务条。
- 景物可写实，交互边界必须可读；金砂不能只靠金色、鱼咬钩不能只靠声音、稀有物不能只靠发光判断。
- 静态远景允许高质量原创/授权贴图，水纹、揭露遮罩、粒子、受力和互动对象必须实时响应，不能用一张风景图加随机结果冒充玩法。
- 若后续使用 AI 生成，只作为本地背景/材质/精灵素材来源，记录素材来源、提示词和使用权；无运行时 AI 请求。
- 开发先验证灰盒操作，再做一张完整视觉样板；视觉样板过关后扩展内容。规划中的“逼真”是目标，不是完成承诺。
- 避免照片与简单卡通图标在同一操作层混搭；对象接触阴影、湿润程度、环境色与主光方向一致。
- 所有运行期图片保持瞬态，不写入 localStorage/IndexedDB。首版使用可截图结果视图，不依赖下载、剪贴板、Web Share 或未核验 bridge。

## 5. 性能预算和降级

以仓库规范为硬边界；以下为各项目首版目标上限，须真实测量：
- 默认 drawing buffer DPR≤1.5，≤150万像素；低档 DPR=1，≤80万像素；随视口重算。
- 默认纹理+FBO预算≤48 MiB，低档≤24 MiB；单纹理≤2048，低档≤1024。逐资源估算 w×h×4，mipmap 另计 1/3，不能当作实际系统显存查询。
- 默认 draw calls≤40、三角形≤30k，低档≤24/15k。Canvas 项目无意义指标不套用，控制脏区重绘及解码图片总内存≤32 MiB。
- 默认目标稳定30 FPS，低档24～30 FPS；60 FPS 只在实测后启用。交互到可见反馈目标≤80ms，不能仅用脚本执行时间冒充触摸延迟。
- 开局预热材质，静态背景缓存；粒子池/typed arrays 重用，不每帧创建大数组。禁止逐帧 getImageData/readPixels/toDataURL。
- 运行时滑动窗口观测帧间隔：排除加载、后台和旋转阶段；连续两个2秒窗口平均>40ms则降档；低档持续>55ms则切简化渲染。初版不自动升档抖动，设置页允许手动重试。
- 降级顺序：粒子/透明叠层→扰动分辨率→DPR→关闭细节反射→Canvas 2D。每一级保留游戏对象、状态与命中结果。
- WebGL 1 仅 RGBA8 必需，NPOT纹理 clamp + 非mipmap；不要求 float texture、instancing、derivatives 扩展。片元精度检查，低精度下缩小坐标与噪声范围。
- getContext/编译/链接失败直接非GL路径；contextlost 停止并保留模型，contextrestored 最多尝试一次受控重建，重复丢失切Canvas；不能黑屏无限重试。
- 页面隐藏/离开停止动画、音频、计时器；恢复重置 dt，不能出现后台鱼逃跑、计时耗尽或一次动作重复结算。
- 热机连续运行15分钟，记录设备/系统/宿主版本、档位、帧时、资源估算、异常；再做50次会话循环检查对象/节点/纹理释放。

## 6. 音频、存档和包结构

- 每项操作配短促、克制、可区分音色；避免每个粒子发声。关闭声音后可完整游玩。
- window.AudioContext || window.webkitAudioContext 能力检测；首次用户操作创建/恢复。恢复/解码失败给一次可理解提示并继续无声游玩。
- 内置音频构建为 Base64 JS；atob→Uint8Array→decodeAudioData，按需缓存；每次新建 BufferSource，GainNode调音量；会话标记防止取消后异步响起。旧内核兼容回调解码。
- 单段解码前的原始音频字节≤1 MiB，>100 KiB需风险记录并压缩；不能拆串绕过；解码后的 PCM 内存单独估算和限量。原始 MP3/WAV 不进 ZIP，无 data/blob audio 标签。
- localStorage 仅保存设置、图鉴统计、纪录、种子/版本与少量进行中逻辑状态；建议≤200 KiB。每个项目独立 key。写入仅在暂停/提交/设置变化时，不每帧写。
- 结果提交有 sessionId 去重；写失败进入本次会话模式并提示。损坏存档隔离/重置，不白屏；升级定义迁移，未知高版本不覆盖。
- 运行时无 fetch/XHR、远程字体/CDN、Worker、WASM、Service Worker、eval/new Function、动态脚本、模块脚本、Blob下载、未确认设备接口。
- index.html 位于ZIP根，脚本为外置经典JS，资源相对路径。仅 jpg/css/gif/svg/png/js/jpeg/json/html/woff2/webp/woff。
- 单项目ZIP目标≤2 MiB，2～4 MiB须报告素材取舍，硬上限10 MiB。单文本>2 MiB及文本总计>5 MiB触发风险审计。
- dist目录与最终ZIP分别递归审计文件类型和根入口；不能只看ZIP体积。源文件、.map、.ts、.glsl、文档、node_modules 不进入交付包。

## 7. 实施里程碑与退出标准

M0 手感灰盒：一条完整核心循环、可注入seed、取消/暂停/重试。5位首次体验者中至少4位能在一次轻提示后完成核心动作；样本仅内部验证，不代表市场留存。
M1 视觉切片：一个场景和一种代表对象，默认/低档各录15秒。要求材质在静止、慢操作、快操作三态都正确响应；不接受只截图好看。
M2 首版内容：完成本项目PROJECT.md的P0内容与图鉴、恢复、结果页面。保留无声、辅助操作和非GL完整循环。
M3 发布候选：项目目录执行 pnpm lint、pnpm test、pnpm build，失败须修复不得删除测试。随后包审计、浏览器尺寸/宿主遮挡/性能测试及真机测试。
- 文档阶段无应用脚本，不能声称已执行上述命令；本次只验证规划文档和目录边界。
- 真机至少覆盖一台受限Android、一台常用Android和一台iOS宿主；没有设备时记录“待真机验收”，不把普通浏览器通过写成宿主通过。
- 通用自动化：同seed同输入复现、渲染档位不改业务结果、30/60/不规则渲染帧下模拟等价容差、事件取消、重复提交、存档损坏/配额失败、背景暂停、音频异步取消、context丢失和恢复。
- 证据存于项目内 qa/；报告分开写设计预算、浏览器实测、宿主真机实测。
