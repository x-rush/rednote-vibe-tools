# 《器华录》十件文物统一完整体验设计

## 目标

先把已有完整静态美术资源的十件文物统一制作成可测试的完整体验。题局中的每件文物都必须拥有可见观察签、三类线索印、五段档案故事、离柜一问、相关文物与许照全流程引导。运行时不再兼容旧版观察或旧版故事流程。

本阶段完成后，玩家从任意题局进入任意一件可玩文物，都能经历同一种闭馆档案工作流：观察器物、拆阅线索、落印辨认、查看揭晓、阅读故事、完成记忆回钩并收入专题图鉴。

## 本阶段文物范围

以下十件文物已有完整的揭晓图、局部图、剪影和缩略图，因此进入完整体验题池：

1. 鹰形陶鼎
2. 人面鱼纹彩陶盆
3. 贾湖骨笛
4. 红山玉龙
5. 后母戊青铜方鼎
6. 四羊方尊
7. 莲鹤方壶
8. 云纹铜禁
9. 曾侯乙编钟
10. 曾侯乙尊盘

其余十件文物继续保留在内容库中，但不进入题局。它们不是“旧版可玩文物”，也不会触发任何降级页面；待美术资源与完整体验字段补齐后，再加入完整体验题池。

## 统一玩家流程

### 1. 观察

- 每件文物显示一张稳定的完整观察底图。
- 图上始终显示三个 48 × 48 CSS px 的编号观察签。
- 01 为许照首推观察点，02、03 初始弱化但保持清楚可见和可点击。
- 玩家点击观察签后，在图下得到“可见细节 + 识别意义”，不能直接泄露文物名称。
- 许照提示从“先看 01”逐步变为“再找两处证据”和“可以拆印判断了”。
- “请许照帮我看一眼”只排除一个错误答案，不替玩家完成观察。

### 2. 拆阅线索

- 三枚线索印固定为“看形 / 辨材 / 问来历”。
- 三枚线索必须来自不同证据维度，不能是同一句话的改写。
- 首枚不扣星，继续拆印会降低本题最高星档。
- 每枚线索都带一条许照提示，提示观察方法，不冒充历史人物或亲历者。

### 3. 落印辨认与揭晓

- 选项与落印按钮维持在同一视觉区。
- 答错时先进入证据回看，再进入揭晓；答对直接亮柜。
- 揭晓使用完整文物图，并明确标注“创意重构”及资料边界。

### 4. 五段档案故事

每件文物固定包含五段，段落 ID 与导航顺序一致：

1. `first-look`：第一眼能看见的器形、纹饰或结构。
2. `making`：材料、制作工艺和结构组织。
3. `lived-world`：器物可能承担的实际用途与时代关系。
4. `journey`：出土、发现、收藏或名称变化。
5. `why-now`：今天观看它的知识价值、争议或仍未解决的问题。

每段 80–180 个汉字，五段总计 480–800 个汉字。资料不足时使用 `open-question` 明确说明未知，不用虚构对白、姓名、动机或精确生活场景补足篇幅。

### 5. 离柜一问与入藏

- 每件文物提供一道无惩罚记忆题，问题聚焦一个最值得带走的证据。
- 作答后立即显示解释；解释说明正确选项为什么成立，也纠正常见误解。
- 完成后文物进入所属专题藏格，并显示至少两件相关文物及关联理由。

## 内容与事实规则

每件完整体验文物必须具有：

- 1 条具体故事钩子；
- 5 段档案故事；
- 3 个观察签；
- 3 枚线索印；
- 1 道离柜一问，含 3 个选项；
- 至少 2 件相关文物；
- 观察前、拆印后、答对、答错、入藏五个阶段各至少 3 条许照台词；
- 故事事实检查状态和独立内容版本。

事实性内容优先使用博物馆、文物主管机构、联合国教科文组织等 A 级来源。`verified-fact` 每段至少关联一个 A 级来源；时代背景可使用 `bounded-context`；解释仍有争议时使用 `open-question`。不生成铭文原文，不把创意重构图称为复原图或实拍。

首轮研究按十件文物逐件核对现有来源记录。红山玉龙与云纹铜禁当前标记为待复核，只有在找到足以支撑具体表述的权威页面后，相关段落才能标记为 `verified-fact`；否则明确保留为开放问题。

## 数据契约与运行时边界

### 完整体验类型

新增 `CompleteArtifact` 类型，表示同时具备基础文物字段和必需的 `experienceV2`。完整体验守卫负责验证运行时对象，而不是在页面中判断是否存在字段。

`filterPlayableArtifacts` 只返回同时满足以下条件的记录：

1. ID 存在于本地静态美术清单；
2. `experienceV2` 完整通过内容校验。

本阶段完成时，上述十个静态美术 ID 必须全部成为 `CompleteArtifact`；缺少任一完整体验字段应在应用启动时形成可恢复内容错误，而不是展示旧页面。

### 删除旧版分支

从运行时删除：

- `ObservationViewModel.kind` 的 `legacy` 分支；
- `legacyObservationInstruction`；
- 无观察签时自动使用基础 `clues` 的逻辑；
- `legacyStoryPending` 与“档案摘记 · 完整故事整理中”页面；
- `legacyArchiveAction`；
- `guideLegacyLine`；
- 页面内所有 `hasArtifactExperienceV2` 条件渲染。

基础 `clues` 字段仍可留作内容索引和题目元数据，但不再驱动可玩页面。

## 观察图与移动端布局

### 资源复用

- 九件普通文物以现有 `reveal` 图作为观察底图，使用资源清单中的 900 × 1125 尺寸。
- 曾侯乙编钟继续使用现有 1200 × 800 横向观察图。
- 本阶段不生成新的文物图，避免测试玩法时同时引入未经核验的新构图。
- 局部图继续用于拆印后的线索展示，不作为三个观察签共用底图。

### 不裁切坐标系

- 观察容器从资源元数据读取宽高比。
- 图片使用 `object-fit: contain`，完整显示，不使用 `cover`。
- 观察签坐标相对于完整图片内容盒计算，不能相对于包含留白的外层容器计算。
- 删除观察台固定 `min-height: 260px`，避免窄屏由纵向最小值反推横向宽度。
- 320 / 360 / 375 / 390 / 430 CSS px 均不得产生横向滚动。

九件竖向底图在手机上会形成较高的观察区域，这是本阶段有意选择：优先保证主体完整、热点准确和手指可点。测试反馈确认玩法后，再决定是否生成统一横向观察图。

## 组件与数据流

### 内容层

- `src/content/content.json` 保存全部新增故事与业务文本。
- `src/content/types.ts` 定义完整体验类型。
- `src/content/validate.ts` 校验十件完整体验的计数、唯一 ID、引用、长度和来源等级。

### 题局层

- `src/ui/artifact-assets.ts` 只负责静态资源映射和观察图尺寸。
- 题局选择只消费 `CompleteArtifact[]`。
- 题目、状态和图鉴继续只保存稳定 ID，不把故事正文写入本地存储。

### 页面层

- `SpotlightStage` 接收完整文物与稳定观察底图，统一显示三个观察签。
- `ArtifactStory` 只接受五段完整故事，不再渲染旧摘记。
- `PlayExperience` 只处理完整体验，许照台词从当前文物内容读取。
- 资源加载失败时显示不泄露答案的占位状态，并保留退出和重试路径。

## 测试与验收

### 自动化门禁

- 可玩文物恰好为上述十件。
- 十件全部具有完整体验，不存在运行时旧版分支。
- 共 30 个观察签，每件恰好 3 个，坐标位于 0–1 范围且 ID 唯一。
- 共 50 段故事，每件五段、顺序固定、长度和来源符合契约。
- 共 30 枚线索印，每件标签固定为看形、辨材、问来历。
- 共 10 道离柜一问，每题恰好一个有效答案。
- 每件至少两个有效相关文物引用。
- 五个阶段的许照台词均满足数量和长度要求。
- 内容和 UI 中不再出现旧版提示或“完整故事整理中”。
- 观察图加载失败时不泄露答案。

### 浏览器验收

在 320 / 360 / 375 / 390 / 430 CSS px 逐项验证：

- 页面 `scrollWidth` 等于视口宽度；
- 三个观察签同时可见，点击目标至少 48 × 48 CSS px；
- 文物主体不被裁切，观察签不落在图片留白之外；
- 许照不遮挡文物或操作按钮；
- 五段故事导航可点，长文不横向溢出；
- 从任意一件文物完成观察、拆印、作答、故事、离柜一问和入藏全流程；
- reduced-motion 下不依赖动画传达状态；
- 控制台无错误、资源无 404。

提交前在项目目录运行 `pnpm lint && pnpm test && pnpm build`，不得删除测试或修改根锁文件。

## 本阶段明确不做

- 不开放另外十件缺少完整美术资源的文物。
- 不生成新的文物观察图或更换现有创意重构图。
- 不新增依赖、后端、运行时 API、CDN 或设备权限。
- 不改变计分、专题数量、五件一局和本地结构化存储原则。
