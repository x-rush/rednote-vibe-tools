# 我希望被这样对待 UX Specification

状态：`SECOND-PASS UX SPEC`

## 1. 体验目标

- 5 秒：这是帮我整理相处偏好的工具，不是关系评分或人格诊断。
- 30 秒：清楚内容只保存在本机，并开始第一个容易回答的问题。
- 3–5 分钟：零散选择逐步被整理成一封成熟、具体、可以修改的关系说明书。
- 完成后：能安全地选择完整版或排除敏感项的简洁版。

## 2. 流程

```text
封面 → 使用边界 → 关系情境 → 分章问答
→ 生成说明书 → 编辑/隐藏/排序
→ 完整预览 / 简洁预览 → 本机保留 / 清空
```

问答允许返回，结果实时重算；用户手工改写不可被静默覆盖。拖拽结束后才保存。

## 3. 页面规格

### R01 封面｜首次

第一视觉：`我希望被这样对待`；第二信息：把难开口的相处偏好整理成一份可编辑说明书。主动作 `开始整理`。

显著但克制显示 `内容仅保存在本设备`。不出现情侣插画、关系分数、心理类型。

### R02 封面｜草稿存在

显示：已完成章节数、更新时间、已手工编辑句数。主动作 `继续整理`；次动作 `查看当前说明书`、`重新开始`。

重新开始确认会替换问答草稿，但应询问是否保留用户手工编辑稿。

### R03 使用边界

三点：不是诊断；不替你发送；结果是表达偏好而非要求别人服从。主动作 `我知道了`。

### R04 关系情境

选择当前关系版本；首发一个版本时仍用一页解释适用对象，不伪装多选。后续版本以结构化卡加入。

### R05 分章问答

7 章节进度；每屏一个主题；单/多选规则明确。返回修改实时重算建议稿。

- 两端选择都体面。
- 可以跳过的题明确显示“暂不确定”。
- 不用“最真实的你”等测试话术。

### R06 生成过场

不是假加载条。将 7 个章节标题依次从零散便签排列成一封信；可跳过。结果已在进入过场前计算并保存。

### R07 说明书总览

7 章节：陪伴、安慰、分歧、边界、关心、建议、我也会努力。第一视觉是一句话摘要；其次是章节目录和敏感项提示。

### R08 章节编辑

显示系统建议稿、当前编辑稿、隐藏开关、恢复建议。手工编辑有长度限制和本地保存说明。

当答案变化导致建议不再适用：章节标记 `需要确认`，提供：保留我的编辑 / 采用新建议 / 查看差异。不得自动覆盖。

### R09 排序

拖拽只改变视觉顺序；拖动结束后保存。键盘用户提供上移/下移按钮。拖动中不频繁写存储。

### R10 完整预览

包含全部可见章节和用户编辑；敏感章节有克制标识。可返回编辑。

### R11 简洁预览

默认排除标记为敏感的边界细节，仅保留适合截图分享的核心偏好。顶部明确 `简洁版不包含全部内容`。

### R12 保存/清空

保存只写本地，无“已上传”语言。清空分别说明草稿、编辑稿、排序与设置，将被删除；二次确认。

### R13 空/错误/恢复

无结果：提示从第一个主题开始。  
损坏草稿：保留可解析手工编辑段落，提供恢复/重新开始。  
存储不可用：允许当前会话完成并截图，但明确关闭后不会保留。

## 4. 状态矩阵

| 功能 | Empty | Error | Success | Partial |
|---|---|---|---|---|
| 草稿 | 开始整理 | 修复/临时模式 | 继续 | 部分题恢复并标记 |
| 生成 | 未完成必答题定位 | 文案键缺失用安全 fallback | 7 章节 | 某章节无偏好显示“暂未确定” |
| 编辑冲突 | 无冲突 | 不覆盖 | 用户选择版本 | `需要确认` 持续可见 |
| 简洁版 | 无可见项则建议编辑 | 不导出空白 | 可截图 | 排除敏感项有说明 |

## 5. 响应式/无障碍

- 375/390：问答与编辑单栏；底部动作不遮键盘。
- 430：信纸最大 390px；批注可在侧边小栏出现。
- 桌面：信件居中，编辑工具栏固定在侧边但不改变顺序。
- 多选、隐藏、拖拽都有语义和键盘替代。
- 内容不能只用红/绿表示“需要确认”。

## 6. 资源结论候选

- 7 个章节符号：项目内 SVG，来源于偏好语义，不需要 AI 位图。
- 信纸、批注、折痕：CSS/SVG；最多 3 种底纹。
- 封面位图：功能不必要，除非高保真封面证明能显著提升品牌且不造成情感刻板。
- 不生成情侣、家庭或人物关系插画。
