# 大理寺字案录 · 32 件全 AI 史料感证物升级规格

状态：已确认设计

日期：2026-08-26

范围：`projects/03-dalisizian`

## 1. 目标

将现有 8 案 × 4 类共 32 件证物全部升级为独立的 AI 生成 WebP。每张图都应首先像一件真实放在案头上的古籍、拓片、卷宗或器物，其次才承担界面装饰；玩家不再看到现代产品结构图。

本轮“全 AI”指 32 张正式证物图均由图像生成或参考图编辑流程产出，不直接把真实史料扫描件作为游戏图版。真实资料只作为生成输入与核验基准，事实来源继续登记并在玩家详情中披露。

## 2. 不可突破的真实性边界

1. 不允许模型凭记忆生成可辨认的甲骨文、金文、小篆、异体字或古籍正文。
2. 凡正式图中出现可辨认古文字，生成前必须取得授权明确的参考图，并采用参考图编辑／合成方式，提示中要求保持主体轮廓不变。
3. 生成后必须将关键轮廓与参考图并排核验。屋盖、手、耳、木、皿、止、戈、廌、禾、火等决定释形的结构不得被模型补笔、删笔或融合。
4. 无法稳定保持的长篇古文不进入图片。字书图只允许出现由参考输入保真的单字、短标题或局部原文，其余正文使用折叠、遮挡、焦外、残损或留白处理；完整释文仍由 HTML 展示。
5. 不把 AI 生成图称为原件、原拓或馆藏扫描。统一披露为“依据所列资料进行的 AI 复原装帧，并非馆藏原件”。
6. 来源不足、许可不明或轮廓核验失败时，该图不得进入资源映射；继续使用现有本地回退图，直到合格版本生成。

## 3. 采用路线

采用“权威资料建档 → 参考输入标准化 → AI 参考生成／编辑 → 轮廓核验 → 移动端装回”的单一路线。

不采用纯提示词从零绘制古文字，也不采用把真实扫描件直接装进游戏的方式。字形来源优先级为：

1. 明确标注 Public Domain／CC0 的古文字矢量或图版；
2. 权威数据库中许可允许作为生成参考的公开预览；
3. 公开古籍条目、学术机构材料和现有 `content.json` 已登记来源；
4. 只有文字说明而无可用图形时，正式图不展示可辨认的古文字形体。

## 4. 统一视觉系统

### 4.1 规格

- 正式资源：32 张 1080×720、3:2 横向 WebP；
- 文件命名：`asset-evidence-<case>-<subject>-v3.webp`；
- 单张目标 100–170KB，32 张合计不超过 5.5MB；
- 最终 ZIP 必须小于 8MB；
- 不使用运行时网络、CDN、外部字体或外部 API；
- 每张图必须保留中央观察区和两处热点的安全范围；
- 不在生成图中加入水印、现代 UI、拉丁占位文、随机汉字或可识别的现代办公用品。

### 4.2 共同场景语言

- 唐代虚构大理寺案房作为装帧语境，不声称是历史官署复原；
- 深色旧木案、暖褐纸张、褪色靛青衬布、朱砂批注、铜镇纸与红线；
- 使用自然磨损：折痕、纤维、虫蛀、烟熏、铜锈、墨晕和边角缺损；
- 光线为窗格侧光或低位灯火，避免棚拍塑料感；
- 画面不出现人物，焦点始终是证物本身。

### 4.3 四类证物的实物形态

- `glyph-timeline`：甲骨片、青铜铭文拓影、石刻、木简、帛书或篆形摹本并置；关键字形必须来源保真。
- `lexicon-scroll`：残卷、册页、简牍、雕版页或抄本；只保留经核验的短文字，长文残缺或焦外。
- `semantic-map`：把关系图转换为实物调查陈列，用签筹、系线、印章、器物碎片和分期标签表达关系。
- `myth-verdict`：传闻札、残纸、封条、朱批和互相覆盖的案卷层，表现“材料能证／不能证／仍有争议”。

## 6. 参考档案与生成记录

每案建立一个 `research/<case>-ai-evidence-dossier.md`，至少记录：

- 4 件证物的事实主张与不可越界内容；
- 参考页面标题、直接 URL、访问日期、许可与著录号；
- 下载到本地的参考图文件名、SHA-256 和用途；
- 每张正式图的最终提示词、参考输入角色和生成方式；
- 字形轮廓检查结果、发现的问题、重生成次数和审核日期；
- AI 复原声明与不确定性说明。

参考图属于研究材料，不直接进入发布包；只有 32 张审核通过的正式 WebP、必要的回退资源和运行代码进入 `dist`。

## 7. 生成与验收流程

每张图单独执行以下闭环：

1. 从当前证物事实主张反推需要呈现的物件，不让画面泄露推理答案。
2. 为可辨认字形准备来源明确的参考输入；将 SVG 标准化为高对比 PNG 供 AI 编辑参考。
3. 使用内置图像生成工具，一张图一次调用；不同证物使用独立提示词，不用同一提示词批量换名。
4. 检查画面物件、时代氛围、手工材质、构图安全区、随机文字与多余物体。
5. 对出现的每个关键字形与参考输入逐项比对。任何结构性变化都判定失败并重生成。
6. 转换为 1080×720 WebP，在保持轮廓可辨的前提下压缩至预算。
7. 更新资源映射并在 375／390／430 CSS px、非零安全区下检查热点、裁切和文字对比。

## 8. 代码与数据边界

- 业务事实、证物说明、来源与披露继续只放在 `src/content/content.json`；
- `src/evidence/assets.ts` 只维护稳定资源 ID 到本地文件的映射；
- 组件不复制来源文案，不在代码里写案件专属提示；
- 现有 32 张 SVG 保留为加载失败时的安全回退，不再作为正常流程主图；
- 新增“正式 WebP／回退 SVG”双层解析，缺图时仍能继续游戏；
- 不改变案件状态结构、评分、存档版本或观察点 ID。

## 9. 交互与动效

- 热点继续使用真实按钮，最小短边 44 CSS px；
- 根据证物类型增加不影响判断的轻动效：拓片侧光、纸张微浮、朱砂显影、铜器反光；
- 动效只作用于容器与遮罩，不扭曲生成图中的字形；
- `prefers-reduced-motion: reduce` 与游戏设置开启后全部即时呈现；
- 不依赖 hover，不引入陀螺仪、相机、Worker 或 WebGL。

## 10. 测试与发布门禁

### 内容与资源

- 32/32 证物正式映射均指向 `-v3.webp`；
- 32 个 WebP 内容哈希互不相同；
- 尺寸全部为 1080×720，文件头有效，单图不超过 200KB；
- 研究档案、正式资源和 `content.json` 来源引用一一对应；
- 正常流程中不出现旧 SVG，阻断 WebP 时能够回退且无破图。

### 浏览器

- 逐件打开 32 件证物，确认图片加载、两处观察点、返回焦点和观察状态；
- 在 375×667、390×844、430×932 下模拟 47px 顶部安全区；
- 无横向溢出，页头不被遮挡，热点最小 44px；
- 获取证物、证据簿、推理复核、结案图鉴流程均能展示对应新图；
- 减少动态模式下无动画残留，控制台无 error／warning。

### 发布

在项目目录运行：

```bash
pnpm lint && pnpm test && pnpm build
```

随后覆盖 `release-assets/大理寺字案录-小工具包-20260826.zip`，验证 ZIP 根目录入口、支持的文件类型、包内离线引用、与 `dist` 逐文件一致，以及总包小于 8MB。

## 11. 完成标准

- 32 件证物全部呈现独立且可信的古籍、拓片、卷宗或器物实景；
- 每一处可辨认古文字都有参考输入与轮廓核验记录；
- 没有模型自由生成的乱码、假古文或无来源古文字；
- 玩家仍能清楚理解证据关系，但画面不再像现代产品示意图；
- 旧存档、观察进度、推理和评分无回归；
- 三档手机、完整测试、生产构建、离线包和代码审查全部通过。
