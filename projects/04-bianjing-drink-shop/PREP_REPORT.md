## 经济公式

### 客流

```text
stageBase = 按 1–10 / 11–30 / 31–60 / 61–85 / 86–100 日取值
reputationBonus = min(R, 70) / 10 + max(R - 70, 0) / 20
baseVisitors = stageBase + reputationBonus + eventVisitorDelta
visitors = round(baseVisitors × weatherMultiplier)
提前打烊时 visitors = round(visitors × 0.65)
```

阶段基础客流 `8 / 10 / 12 / 13 / 14`、提前打烊乘数 `0.65` 属于缺失参数 fallback。天气乘数严格来自文档：`1 / 1.15 / 0.95 / 0.8 / 0.9 / 0.85`。

### 购买分

```text
purchaseScore =
  priceFit × 0.35
  + drinkPreference × 0.30
  + reputation × 0.20
  + serviceCapacity × 0.15
```

权重从 `content.balance` 读取。`priceFit` 在基准价时为 1，价格相对偏离 40% 时降为 0；偏好命中天气/季段/活动标签时为 1，否则使用中性 0.5；声望按 0–100 归一；服务能力由当前体力和饮子复杂度计算。顾客混合的具体季节权重原文未给，因此没有虚构逐顾客比例。

### 销量、收入与成本

```text
sold = min(demand, prepared)
income = Σ sold × integerPrice
stockCost = Σ prepared × unitCost
wasteReturn = Σ floor(unsold × unitCost × keepRate)
dailyMoneyDelta = income - stockCost + wasteReturn - dailyFixedCost
  + dueScheduledMoney + eventMoney + activeDailyMoneyModifiers

energyCost = ceil(baseOpenEnergy
  + Σ sold × complexityEnergy
  - earlyCloseProtection
  - activeEnergyModifier)
```

复杂度精力系数严格使用 `1→0.5、2→0.8、3→1.1`。固定成本 `2`、基础开门精力 `3`、提前打烊保护 `4`、统一保存率 `25%` 是原文范围内的显式 provisional fallback。钱不 clamp；口碑、体力、人情 clamp 到 `0–100`；库存始终不低于 0。体力为 0 时，次日必须提前打烊休息半日。

账簿逐项保存 `kind / labelId / amount / entityId`。测试断言所有金额明细之和严格等于当日现金变化。

## 取整规则

- 客流：最终乘数计算后使用 `Math.round`，最低 0。
- 需求：各商品按购买分份额先向下取整，剩余人数按小数余量降序、商品 ID 稳定排序分配。
- 备货、售价和销量：仅接受整数。
- 损耗返还：每种饮子分别向下取整，再求和。
- 精力：先累计小数消耗，日终向上取整。
- 钱：所有商品收入和备货成本是整数乘法，不作 clamp。
- 状态：事件与日结后统一将口碑、体力、人情限制在 `0–100`。

这些边界由手算经济测试覆盖，包括错误取整、遗漏成本和负库存会导致失败的断言。

## RNG / Seed

字符串 seed 使用稳定的 32 位 FNV-1a 风格散列初始化；随后使用可序列化的 uint32 状态生成 `[0,1)`。接口返回 `{ value, state }`，不修改全局状态。天气和事件权重只消费传入状态，业务逻辑不调用 `Math.random()`。

存档同时保存原始 `seed` 与当前 `rngState.value`。测试覆盖同 seed 同序列、不同 seed 分离、保存状态续接以及完整 100 日终态重放一致。

## 事件引擎

有限条件集合支持：日期、属性上下限、资金上下限、flag、有无事件历史、连锁状态、已完成连锁数、库存，以及 `all / any / not`。有限效果集合支持：资金、三项属性、库存、flag、商品解锁、期限修正、延期效果、连锁推进和中断。没有 `eval` 或表达式字符串执行。

普通事件候选依次过滤日期、前置条件、一次性、冷却、冲突标签、第 90 日链入口限制及既有链状态，再按权重使用 seed 选择。冷却判定为：

```text
currentDay - lastTriggeredDay >= cooldownDays
```

链节点优先于普通事件；多链同时满足时按启动日、链 ID 稳定排序。超出下一节点最大等待日会把链标记为 `interrupted / timeout`。候选为空返回显式 `none`，不写伪事件历史。

原文没有逐事件权重，正式 JSON 统一使用基础权重 `1` 并标记 provisional。原文的“风险、波动、库存+、销量+”等非数值效果保留为 flag 或期限修正，不擅自改成钱或属性数字。

## 平衡风险

- 优势路线在 100 日达到 8033 文，说明首轮 fallback 的基础客流、固定成本、价格适配和事件收益存在明显资金膨胀；按任务边界没有重做最终平衡。
- 现金缓冲路线虽以 231 文活到第 100 日，但体力为 0；它依靠低体力时提前打烊满足强制休息规则，仍显示体力恢复来源偏少。
- 原文没有基础客流、季节顾客混合、保存率、租金/工资常量和结局阈值，所有新增可计算值均集中标为 provisional。
- 多个定性风险只保留 flag，因为文档没有发生概率、期限或数值后果；这些 flag 可供后续内容版本接续，当前不会凭隐藏随机数直接致使倒闭。
- `capacity`、部分供货折扣和品质风险没有可靠数值契约，只保存结构化状态，不擅自产生额外收益或损失。
- 历史饮子名称尚需发布前来源核验；配方、成本、售价、偏好和事件均明确属于游戏虚构。

## 存档 Schema

IndexedDB 数据库：`xhs_bianjing_shop`，版本 `1`。建立 `saves`、`eventHistory` 和 `endingCollection` 三个 object store；当前完整有限历史随安全快照保存在 `saves` 中。localStorage 仅使用精确键：

```text
xhs-tool:bianjing:state:v1
```

`SavePayload` 保存 schema/content 版本、save ID、更新时间、当前快照和上一日快照。游戏快照保存天数、钱、库存、价格、商品解锁、四项属性、事件历史、冷却、flags、连锁、延期效果、最近决策摘要、seed/RNG、已解锁结局、待结算营业上下文和重复结算 ID。

事件历史最多 120 条，决策摘要最多 30 条，flags 最多 500 条。读取执行 JSON 解析、版本、白名单形状、数值、数组上限、媒体禁用和内容引用校验。当前快照坏而上一日有效时自动返回 `recovered-previous`；两份都坏或未来版本时进入可恢复错误页。新游戏创建新 save ID，不删除旧存档；测试验证两个存档可并存。

不保存图片、Base64、音视频或 Blob。
