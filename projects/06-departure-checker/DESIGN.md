# 出门检查官基础实现设计

## 目标

在不依赖后端、在线 API、定位或用户媒体的前提下，实现一套由单一内置 JSON 驱动、结果可解释且确定性的出门检查清单基础系统。

## 架构

- `src/content/` 保存唯一业务内容包、TypeScript 契约、运行时校验与索引。
- `src/domain/` 保存纯函数规则引擎、清单转换和页面状态 reducer。
- `src/storage/` 保存版本化 localStorage 读写、上限控制和损坏恢复。
- `src/App.tsx` 只消费类型化 view model，提供可走通的语义页面骨架。
- 所有业务名称、问题、提示和规则原因只存在于 `src/content/content.json`。

## 内容契约

内容包包含 8 个场景、60–90 个去重项目、分类、位置、条件定义与规则。项目优先级使用 `must / should / optional`；确认事项通过 `entryType: confirmation` 独立成组，不引入第四种优先级。规则支持添加、删除、升降级、替代、冲突、显式优先级、安全保护和解释原因。

## 规则顺序

1. 加载场景基础项。
2. 匹配条件规则并收集添加项。
3. 应用安全必带规则。
4. 按去重键合并项目与原因。
5. 按规则优先级处理移除、替代和冲突；安全必带项不可被较低规则删除。
6. 计算最终优先级，升级与降级冲突时选择更高保护结果。
7. 按分组、项目排序值、首次加入次序和稳定 ID 排序。
8. 生成去重后的解释列表。

相同输入始终得到相同结果；不使用随机评分、`eval` 或动态表达式执行。

## 状态与存储

页面状态覆盖 `landing`、`scenarioSelect`、`conditionWizard`、`generating`、`checklist`、`itemDetail`、`savedLists`、`summary`、`error`。修改条件时保留仍存在项目的勾选状态；显式“全部重置”清除勾选。

localStorage 只保存 schema/content 版本、稳定场景与项目 ID、结构化条件、勾选状态和最多 30 字的自定义项。最近清单最多 3 份，第四份覆盖更新时间最早的一份。非法 JSON、未来 schema、错误字段和失效关键引用返回可恢复错误，不白屏、不静默采集数据。

## 页面骨架

页面提供首页、场景选择、条件向导、生成状态、三种查看方式、优先级分区、建议理由、最近清单、完成摘要、空状态和错误恢复。视觉只建立移动端语义层级与 44px 触控区，图标使用内容中的 asset ID 占位。

## 测试

测试覆盖内容唯一性和引用、规则执行顺序、安全保护、去重、理由合并、冲突、替代、稳定排序、空条件、多条件、保存恢复、损坏恢复、10 个以上黄金组合、重复生成确定性和状态 reducer。最后运行 `pnpm lint`、`pnpm test`、`pnpm build`。
