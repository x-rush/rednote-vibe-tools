# 星风来信｜交互规范

## 用户流程

1. 首屏保持安静、昏暗，不显示或滚动候选文案。
2. 用户点击主画面，立即锁定一条随机星语并触发风声。
3. 风从上向下揭开窗帘，固定窗框后的月亮与月光逐渐变亮。
4. 星星持续沿右上到左下的方向进入室内；文字碎片与星流同向飞行。
5. 字符在前景按原顺序组成完整句子，结果按钮出现。
6. 结果态帘子和星星始终运动；点击“再听一次星空”后倒放视觉状态并回到首屏。

## 状态反馈

- `idle`：全屏透明按钮可点击，提示为“点击，让星风捎来一句话”。
- `wind`：首个 300ms 给出可见的上沿风压反馈。
- `curtain-opening`：帘线顶部先离开窗口，尾部随后跟进；亮度同步提升。
- `stars-and-letters`：字符保持模糊、旋转和错位，不能在中段提前读出完整句子。
- `result`：句子清晰且最多两行，星流继续，主星落地闪烁后消散。
- `resetting`：月光和帘子连续返回，粒子关闭；结束后不保留半开或残余内容。

## 输入与边界

- 动画过程中重复点击不重新抽取，也不跳过阶段。
- 页面隐藏时暂停时钟和音频，恢复时从原位置继续，不追赶后台时间。
- 音效初始遵循本地静音偏好；取消静音必须由用户手势激活。
- 320px 以上竖屏可用，验收宽度为 375、390、430 CSS px。
- 顶部控件须在 32px 模拟安全区下仍完整可见和可操作。

## 无障碍

- 主画面按钮具备明确的中文可访问名称。
- 飞行文字 `aria-hidden="true"`，避免逐字重复朗读。
- 只有结果句使用 `aria-live="polite"` 播报。
- 声音与重播均使用语义化按钮和可见焦点样式。
