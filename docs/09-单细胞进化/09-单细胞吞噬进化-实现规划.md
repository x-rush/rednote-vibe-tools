# 单细胞吞噬进化｜实现规划

状态：**DESIGN READY / 待首轮手感原型验证**

暂定名：**《原生：一滴水的战争》**

传播副标题：**从一个细胞开始，你最后会进化成什么？**

## 1. 产品定义

一款手机竖屏、单指控制、纯前端运行的吞噬进化 Roguelite。玩家从一个原始细胞开始，在持续变化的培养皿中捕食比自己弱小的生命，躲避或反制天敌，通过有限身体空间装配器官，并在 8–15 分钟内完成一次从诞生到灭亡或跃迁的生命史。

产品不是“题目换皮”，也不是只有粒子特效的互动演示。首发必须同时成立：

- **即时好玩**：追、吃、躲、抢、反杀形成连续操作反馈。
- **局内成长**：体型、身体轮廓、器官、运动和能力共同变化。
- **局外积累**：死亡带回基因，解锁新的玩法可能性而非无限数值碾压。
- **持续挑战**：环境、生态、Boss 与自选词缀要求不同构筑。
- **前端炫技**：软体形变、膜波纹、触手、分裂、折射、粒子与程序化声音服务于玩法。
- **自然传播**：每局生成独特形态、真实事件死因和可复现的培养皿种子。

## 2. 目标用户与体验目标

目标用户是希望随手杀 5–30 分钟、喜欢成长与收集、但不愿阅读复杂规则的移动端用户。

首局体验目标：

1. 3 秒内理解“追小躲大”。
2. 20 秒内完成第一次吞噬。
3. 60 秒内完成第一次器官变异。
4. 3 分钟内第一次遭遇明显生态危机或精英生物。
5. 首局无论成败，8 分钟内出现一次完整结算。
6. 结算后用户能用一句话描述自己的独特经历。

## 3. 体验原则

### 3.1 少字宪法

- 首次开局前正文不超过 12 个汉字。
- 不弹出教程页；通过猎物逃跑、捕食者阴影与手势示意教学。
- 战斗中单条提示不超过 8 个汉字，2 秒内自动消失。
- 器官候选仅显示名称、动态图示和最多 6 字的作用说明。
- 详细图鉴全部主动展开，不阻塞下一局。

### 3.2 成长必须可见

关键升级不得只改变数字，至少改变以下一项：身体轮廓、材质、运动方式、光照范围、攻击反馈、可进入区域或对生态的影响。

### 3.3 强大必须有代价

- 体型增大：吞噬范围增加，但转向变慢、目标更明显。
- 器官增多：能力增强，但代谢消耗和不稳定度上升。
- 分裂：增加控制范围和生存机会，但单体变弱。
- 装甲：防御增加，但速度和能量回复下降。
- 发光：扩大视野并吸引猎物，同时暴露位置。

### 3.4 失败必须推动下一局

失败展示真实原因、保留有限基因样本、揭示一个未完成方向；不扣除已有永久收藏，不设置断签惩罚或等待体力。

## 4. 核心操作

默认竖屏单指：

- **拖动空白处**：细胞以弹性惯性朝目标方向游动。
- **快速划动**：消耗能量冲刺；速度路线可改变冲刺效果。
- **点按自身**：切换收缩/展开状态；收缩减少碰撞体积但降低吞噬范围。
- **双击空白处**：释放当前主动器官能力。
- **进化时拖动器官**：把候选器官放到兼容的身体锚点；不兼容位置立即回弹。

浏览器手势要求：游戏区域禁用页面滚动、双击缩放和长按选择；暂停、设置和返回仍使用可访问的 DOM 控件。

## 5. 单局核心循环

```text
孵化
  → 吞噬营养体与弱小细胞
  → 积累生物质
  → 三选一器官变异
  → 进入更危险环境
  → 捕食、寄生、潜伏或逃生
  → 遭遇生态事件与区域主宰
  → 跃迁成功或死亡
  → 带回基因样本并生成生命档案
  → 解锁新的可能性后重新孵化
```

节奏预算：

- 3–5 秒：一次小反馈，如吞噬、擦身躲避、资源争夺。
- 30–50 秒：一次器官选择或显著形态变化。
- 90–150 秒：一次环境迁移、精英遭遇或生态事件。
- 8–15 分钟：一次完整生命史。

## 6. 三个局内资源

### 6.1 生物质 `biomass`

用于成长体型和触发进化。主要来自吞噬；死亡时不直接带出。

### 6.2 能量 `energy`

用于冲刺、主动器官和快速修复。基础移动不消耗或仅极低消耗，避免玩家因能量耗尽失去控制权。

### 6.3 稳定度 `stability`

代表器官兼容程度。低稳定度会触发可预期的异常：代谢波动、器官短暂失控、身体形变或技能副作用。异常同时存在风险与稀有收益，不做纯粹随机惩罚。

## 7. 身体与器官系统

身体由程序化轮廓、膜、内部核心和器官锚点组成。首发锚点：

- 核心 `core`
- 膜 `membrane`
- 前部 `front`
- 后部 `rear`
- 左侧 `left`
- 右侧 `right`
- 内部 `internal`
- 共生体 `symbiont`

器官分为：感知、移动、吞噬、防御、攻击、代谢、繁殖、共生八类。每个器官必须具备：玩法作用、视觉变化、代价、兼容标签和至少一个潜在组合。

玩家不直接选择“战士/刺客/法师”。路线从器官组合自然形成，例如：

- 鞭毛高速追猎
- 装甲冲撞
- 透明伏击
- 电流连锁
- 寄生吸取
- 分裂虫群
- 滤食成长
- 共生防御

## 8. 分裂与合并

分裂是本项目区别普通大球吃小球的重要机制。

- 玩家可通过器官或事件分裂为 2–4 个子体。
- 子体默认围绕主意识移动，玩家拖动方向控制整体群心。
- 点按某个子体可短暂指定其为主控对象。
- 子体可包围猎物、探索狭缝、分担伤害或保留进化分支。
- 子体靠近并保持稳定可重新融合；不同器官融合可能提高不稳定度。
- 所有子体被消灭才算死亡，除非挑战词缀另有规则。

首发不做复杂群体框选和即时战略操作，防止移动端控制失控。

## 9. 环境与世界结构

世界不是无限平面，而是按种子生成、相互连接的微观区域：

1. **清水滴**：高可见度、营养充足，用于学习基础操作。
2. **藻光层**：光合作用生物密集，昼夜脉冲改变生态。
3. **酸性囊泡**：持续腐蚀，无装甲或修复能力时风险高。
4. **纤维迷宫**：狭窄通道，小体型、分裂和贴附路线占优。
5. **抗体风暴**：追踪性免疫体出现，要求隐蔽、拟态或高速移动。
6. **废弃培养舱**：资源稀少但稀有基因丰富，存在最终 Boss。

环境迁移通过裂隙、渗透膜或宿主通道完成。每次迁移给玩家 2–3 个图形化方向选择，并提前展示主要危险符号。

## 10. 生态 AI

世界中的生物不应全部围绕玩家：

- 猎物会觅食、结群和逃离威胁。
- 捕食者会选择收益更高的目标，也会互相争斗。
- 拾荒者跟随战斗并抢夺碎片。
- 寄生者附着大型生物，不主动追逐健康目标。
- 群体生物通过局部规则形成集群，不逐个运行昂贵路径搜索。
- 区域主宰具有领地、休眠、觅食和狂暴状态。

AI 必须允许“坐山观虎斗”“抢最后一口”“借巨兽清场”等涌现玩法。

## 11. 挑战结构

### 11.1 区域主宰

Boss 不只是一条长血条。首发 Boss 至少允许三种处理方式：正面击败、利用环境驱离、潜伏或寄生通过。

### 11.2 每日培养皿

使用本地日期与固定算法生成相同种子，不宣称在线同步。结果页展示培养皿码，其他用户可手动输入以复现地图、掉落和事件序列。

### 11.3 挑战词缀

通关后解锁自选难度，例如：永久浑浊、能量稀缺、捕食者敏锐、强酸扩散、只能携带三个器官、分裂不可逆。词缀奖励稀有外观、图鉴标记与更高基因收益，不锁死基础内容。

## 12. 局外积累

### 12.1 基因图谱

永久成长以解锁可能性为主：新器官、新出生形态、新环境入口、新异常、新共生体、新结局和新挑战词缀。

### 12.2 图鉴

- 看见剪影：记录未知轮廓。
- 被其击败：解锁危险行为。
- 成功吞噬、寄生或观察：解锁完整档案。
- 文案短而有趣，明确“幻想设定”，不承担科学科普责任。

### 12.3 永久数值限制

纯数值永久增益总幅度应受上限约束，不能让老玩家无视基础生态。高难度成功主要来自知识、构筑和操作。

## 13. 传播设计

结算生成“生命档案”，主体是最终程序化细胞大图，文字最多包含：

- 程序化物种名
- 存活时间
- 最远环境
- 最终体型或吞噬量
- 三个关键器官
- 真实事件推导的死因/结局
- 培养皿码

示例：

> 裂光原生体 0727
>
> 存活 11:42 · 抵达抗体风暴
>
> 电囊 / 透明膜 / 双鞭毛
>
> 结局：它成功躲过了巨噬体，却追上了一束诱饵光。
>
> 培养皿码：7K3M

当前约束下不在本地生成或保存视频、图片、Base64 或 Blob。结果卡在页面实时渲染，支持系统截图；可使用结构化事件日志在结算时回放最近 5–8 秒，但只保存数值与事件，不保存媒体。

## 14. 视觉与声音

视觉方向：显微镜荧光摄影 × 半透明幻想软体，不做写实血腥组织。

关键表现：

- 细胞膜弹性与碰撞波纹
- 内部细胞器缓慢漂移
- 吞噬时的包裹与融合
- 鞭毛、触手的延迟跟随
- 分裂时膜收缩和核心复制
- 电流、酸液、声呐与折射
- 大型生物经过时的视差、阴影和液流扰动
- 进化时身体重新拓扑的高潮动画

声音使用本地音频资源或 Web Audio 程序化合成；首次用户手势后启动。所有玩法必须可在静音状态理解，提供独立音乐/音效开关。

## 15. 技术架构

- React + TypeScript 负责壳层、菜单、图鉴和状态编排。
- Canvas 2D 负责高频游戏对象与效果；首发不依赖 WebGL 才能运行。
- 固定时间步长更新核心模拟，渲染使用 `requestAnimationFrame` 插值。
- 空间哈希或均匀网格处理附近查询与碰撞，禁止全对象两两比较。
- 程序化随机统一使用可注入种子，便于每日挑战、回放和测试。
- 结构化内容放项目 `src/content/content.json`，运行时逻辑不得硬编码内容文案。
- 设置和轻量进度可用 `localStorage`；图鉴、生命档案和较大结构化存档使用 `IndexedDB`。
- 纯前端静态构建；无后端、运行时 CDN、必需外部 API、Service Worker 或 Node 运行时依赖。
- 禁止保存用户图片、Base64、音视频或 Blob。

建议模块边界：

```text
src/
  app/          页面、路由、错误边界
  game/         主循环、时间、输入、相机、空间索引
  entities/     玩家、AI、生物体、资源、投射物
  evolution/    器官、兼容、组合、突变、分裂融合
  world/        区域、生成、环境场、事件、Boss
  rendering/    Canvas 场景、材质、粒子、质量降级
  audio/        Web Audio 与本地音频编排
  progression/  基因图谱、图鉴、挑战、结算
  storage/      版本化存档、迁移、导入导出结构化数据
  content/      content.json 与校验
```

## 16. 性能预算

目标设备以普通手机浏览器为准：

- 正常模式争取稳定 60 FPS，压力场景最低不低于 30 FPS。
- 低性能模式减少远景生物、粒子、模糊、动态阴影与触手节点，但不删除危险提示。
- DPR 上限按设备性能控制，避免高分屏无意义放大画布。
- 同屏高精度实体数量设硬上限；远景群体使用批量绘制或简化代理。
- 页面失焦自动暂停，恢复时不得补算长时间物理。
- 375 / 390 / 430 CSS px 均需验证；固定顶部控件与锚点叠加安全区变量并用非零值测试。

## 17. 可访问性与舒适度

- 重要目标不只依赖颜色，配合轮廓、大小、运动和图形标识。
- 提供低闪烁、低粒子、减弱屏幕震动、静音选项。
- 尊重 `prefers-reduced-motion`，但不能因此隐藏危险反馈。
- 暂停、重开、设置和返回具备键盘焦点与可访问名称。
- 触控目标不小于 44 CSS px；关键文字在最窄宽度下仍可读。

## 18. 存档与隐私

仅保存结构化游戏状态：版本、设置、解锁、图鉴、生命档案摘要、挑战纪录和种子。提供查看存储说明、清空数据与导出/导入 JSON；导入必须校验 schema、版本、大小和字段白名单。

不申请相机、麦克风、位置、通讯录或通知权限，不上传任何数据，不伪装真人在线状态。

## 19. 首发范围

首发完整版本以 43 号内容契约为准，最低包括：

- 4 个环境区域与 1 个终局区域
- 1 个基础出生形态与 2 个可解锁出生形态
- 24 个器官
- 12 个跨器官组合
- 18 种普通/资源生物
- 8 种捕食者或精英
- 4 类生态事件
- 3 个区域主宰
- 3 种成功结局与至少 12 类事件死因
- 基因图谱、图鉴、每日种子、挑战码和生命档案

首发不做：真人联机、账号、广告、付费、在线排行、用户关卡、UGC 素材、复杂剧情树、科学测验或自动生成式 AI 内容。

## 20. 测试与验收

### 20.1 逻辑测试

- 固定种子生成完全可复现。
- 吞噬判定同时考虑体型、护甲、状态和技能，边界条件无抖动。
- 分裂/融合前后总生物质守恒，允许明确记录的消耗。
- 器官锚点、互斥、前置、组合和稳定度计算正确。
- Boss 三种通过路径均可完成。
- 死因从事件日志确定，不出现与实际过程矛盾的文案。
- 存档迁移、损坏降级、清空和 JSON 导入校验完整。

### 20.2 手感验收

- 新用户不读说明可在 20 秒内吞噬第一个目标。
- 输入延迟、角色惯性和转向在小/中/大体型均可控。
- 危险进入视野前有足够的视觉或声音预警。
- 首局失败不能主要由屏幕外不可预知攻击造成。
- 暂停与页面失焦后恢复不会瞬移、连续受伤或加速模拟。

### 20.3 内容与传播验收

- 连续 10 局至少形成 6 种明显不同的最终轮廓或运动方式。
- 生命档案无需阅读游戏说明也能看懂“变成了什么、走了多远、怎么结束”。
- 同一培养皿码复现核心地图、事件与掉落序列。
- 结果卡在 375 / 390 / 430 CSS px 不截断核心信息。

### 20.4 提交门禁

工程创建后，每次提交前在项目目录执行：

```bash
pnpm lint && pnpm test && pnpm build
```

不得删除测试通过门禁。

## 21. 实施里程碑

### M0：手感原型

只验证移动、惯性、吞噬、躲避、体型变化、相机和 60 FPS。没有这些，停止扩内容。

### M1：垂直切片

完成一个 5–8 分钟区域：6 个器官、2 个组合、5 种生态角色、1 个精英、1 个 Boss、结算与重开。验证用户是否主动再玩一局。

### M2：完整首发

补齐 43 号契约的环境、器官、组合、事件、Boss、基因图谱、图鉴、每日种子与生命档案，并完成移动端性能与响应式门禁。

### M3：发布优化

根据真实试玩记录调整前 3 分钟节奏、掉落池、危险预警、结算传播和低性能降级，不以新增系统替代手感问题。

## 22. 成功判据

在不依赖服务器统计的试玩阶段，至少观察 8–12 位目标用户并记录：

- 是否无需解释完成首次吞噬。
- 首局存活时长与首次进化时间。
- 首局结束后是否主动点击再来一次。
- 是否能复述一项器官组合或生态事件。
- 是否愿意截图生命档案或把培养皿码发给别人。
立项继续条件：多数测试者无需引导完成首局，至少一半主动立即重开，且用户讨论的是“我长成了什么/遇到了什么”，而不是“我不知道该点哪里”。
