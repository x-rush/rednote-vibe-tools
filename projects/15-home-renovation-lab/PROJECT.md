# 项目 15 · 装修空间实验室：完整需求与实现约定

整理日期：2026-09-15。状态：完整装修交互已实现，实际交付和运行方式见 README.md。

实现说明：本文件保留需求设计依据。实际采用 Three.js 0.186.0 本地发行文件 + 原生 JavaScript ES Modules + 静态复制构建，未引入原拟定的 TypeScript / Vite 包管理依赖。首页直接进入已布置的示例小家；尺寸采用逐房间确认，不提供单段长度整体缩放。门窗通过沿墙位置参数添加和编辑；本地方案使用 localStorage。美术来源和许可证见 ART-DIRECTION.md。当前成果具备方案对比、复制尝试、真实 3D 家具缩略图及室内观察，实际验证记录见 artifacts/browser-report.json。

## 1. 产品定位

一个可以动手玩的 3D 装修空间。用户不需要懂制图，也不需要先填写尺寸，就能从常见户型开始摆家具、换地板和墙面，再从全屋或室内视角看自己的设计。

主体验为真实 3D 场景，默认采用易观察的斜俯视剖切视角。平面俯视作为精确编辑和成果展示的辅助视图。此前骨架里的“2.5D”不再作为技术限制。

目标流程：选择户型 / 自建空间 → 摆家具 → 换材质 → 查看全屋 → 进入体验 → 导出成果和清单。所有环节属于同一次完整交付，不划分功能阶段。

## 2. 已确认原则

- 视觉优先，大部分屏幕留给空间，说明采用短提示。
- 只有新手模式和进阶模式；展示和体验是查看方式，不增加操作模式。
- 内置常见户型，自建户型尺寸可填可不填。
- 未录入真实尺寸时照常设计，不展示虚假的面积或材料用量。
- 家具和材料清单由设计自动产生，不要求用户再次填写。
- 桌面和手机都能完成主要流程，手机不依赖悬停、右键或键盘。
- 无登录和后台服务，本地自动保存结构化方案。

## 3. 页面和视觉结构

### 开始页

主体是带空间预览的户型卡片，入口包括“选一个户型”“自己搭户型”“继续上次方案”。默认新手模式，可直接进入一个已经有基础装修的示例。

建议交付目录为六种单层户型：开放单间、一室一厅、两室一厅、两室两厅、三室两厅、L 形户型。每种模板必须有实际房间轮廓、门窗和家具摆放数据，名称或示意面积不代替可编辑几何。多层楼梯和复式结构不在本次范围。

### 编辑页

- 桌面：顶部精简操作栏、左侧素材库、中央 3D 空间、按需出现的对象属性面板。
- 手机：顶部返回 / 撤销 / 完成，底部“户型、家具、材质”入口，素材与属性使用半屏抽屉。
- 常驻操作保留撤销、重做、视角复位和完成；选中对象才出现移动、旋转、复制、删除。
- 白暖色工作台，低饱和木色和石色材质，陶土色作为操作强调色；素材卡直接展示家具外形和材料效果。
- 相机平滑过渡，应用材质即时反馈；支持减少动态效果设置。

### 完成展示

收起编辑界面，展示干净的全屋 3D 视角。提供全屋、俯视、房间近景切换；可以进入体验、查看清单、导出图片或返回继续编辑。

## 4. 新手模式与进阶模式

两种模式使用同一套方案数据，切换不清空、不转换或丢失已有内容。

| 能力 | 新手模式 | 进阶模式 |
| --- | --- | --- |
| 起步 | 模板 / 拼房间 | 同左 |
| 家具摆放 | 点击添加，选中后拖动，自动吸附 | 同左，可关闭吸附 |
| 旋转 | 按钮每次旋转 90 度 | 增加旋转角度输入 |
| 房间调整 | 拖边改变大小，尺寸选填 | 增加精确尺寸、位置、墙高和墙厚 |
| 家具调整 | 换色、旋转、复制、删除 | 增加宽深高和位置输入 |
| 材质 | 色板与组合预设 | 增加纹理方向和重复尺度 |
| 门窗 | 墙面点击添加，沿墙移动 | 增加宽高、离地高度及位置 |
| 展示和清单 | 完整提供 | 完整提供 |

进阶面板默认折叠，只在用户主动选择相应对象时显示。尺寸输入必须同时注明宽、深或高，避免把房间平面进深与层高混淆。

## 5. 户型搭建与尺寸

### 简单搭建

用户添加客厅、卧室、厨房、卫生间、阳台等矩形空间，拖拽拼接，拖边调整比例。通过矩形房间组合覆盖常见非矩形整体户型。进阶模式也采用同一搭建方式，不引入 CAD 命令或任意曲线绘墙。

相邻房间共享墙体，不能重复生成两堵墙；编辑时给出对齐辅助线，阻止房间面积重叠和零尺寸房间。门窗绑定墙体，移动限于可容纳的墙段；缩短墙体时提示受影响门窗并保持有效位置。

### 无尺寸也可设计

场景内部始终有坐标和比例，未标定时只是设计比例。界面显示“未标定尺寸”，隐藏平方米、材料平方米用量等真实数量，家具件数仍正常统计。家具目录规格只代表家具默认尺寸，不证明用户房间已经标定。

用户可用一段已知长度进行整体等比标定，或逐房间录入真实宽、深。整体标定明确提示会同时缩放现有布局；逐房间更改尺寸时保留家具规格并提示不再适配的家具。只标定部分房间时显示已标定小计，不输出全屋精确面积。

### 面积口径

- 输出房间室内地面面积、已标定室内面积合计。
- 地面面积按房间内部轮廓计算，房间不能相互重叠。
- 墙面用量仅在平面尺寸和墙高已确认时计算，扣除对应门窗洞口；共享墙两侧按各房间的装修面分别计量。
- 工具不能仅凭房间宽深推算包含墙体、公摊等信息的建筑面积。“建筑面积”如需展示，只允许用户自行填写，并标注“用户填写”。
- 模板尺寸标明“示例尺寸”，不得描述为用户房屋实测值。

## 6. 家具和材料

### 家具

内置至少 24 个可辨识的低多边形家具款式，覆盖沙发、茶几、电视柜、床、床头柜、衣柜、餐桌椅、书桌椅、橱柜、冰箱、洗手台、马桶、淋浴隔断、地毯、灯具与绿植等类别。

桌面可从目录拖入，也可点击添加；手机以“点击家具 → 点击地面落点”为主。提供半透明放置预览和有效落点提示。选中家具后拖动只移动家具，拖动空白处才旋转镜头。地毯、灯具等允许合理叠放，实体家具与墙体或其他实体相交时提示，不能简单禁止所有包围盒重叠。

房间变小后，家具超出边界应高亮并允许移动处理，不静默删除。限制不合理尺寸，操作失败给出短原因。实例包含目录来源、所属空间、位置、旋转、规格及颜色。

### 材料

内置至少 12 种材质，覆盖木地板、瓷砖、石材、水泥、纯色墙漆及壁纸。点击地面或墙面后选择色板即时应用。提供原木、奶油、现代简约三组搭配预设，应用整屋预设可撤销。

材质必须具备纹理或粗糙度表现，目录缩略图与场景结果一致。材质及模型全部随静态产物提供，或在运行时由代码生成，不从运行时 CDN 获取。

## 7. 全屋展示与进入体验

全屋总览默认自动适配户型边界；靠近镜头的遮挡墙采用剖切或淡出策略。俯视可显示房间名称，有标定时可显示尺寸和面积。房间近景通过点击房间进入。

体验使用同一份场景数据，恢复正常室内墙体展示，以人眼高度观察，只读不编辑。默认交互为“选择房间 → 环顾 → 点击可达地面移动”，手机同样可用；键盘移动作为桌面可选补充，不依赖指针锁定或 VR 设备。

落点不能位于墙内或实体家具内；移动不得穿过墙体，门洞参与可达性判断。切换房间采用淡入过渡，避免相机穿墙。提供始终可见的退出按钮，退出后恢复编辑前视角和选中项。

导出 PNG 全屋图和当前视角图；采用用户触发的即时下载，文件数据不写入本地数据库或 localStorage。受当前项目“不保存 Blob”约束，任何为下载临时创建的内存对象仅用于传输并立即释放，不做持久化。若运行环境无法下载，提供明确提示，不显示虚假成功。

## 8. 自动清单

| 清单 | 内容 | 未标定时 |
| --- | --- | --- |
| 家具 | 名称、规格、颜色、房间、数量 | 正常展示 |
| 材料 | 材料名、应用房间、地面 / 墙面、面积 | 展示使用位置，面积为“待标定” |
| 方案摘要 | 户型、房间数、家具件数、尺寸状态 | 不输出伪精确面积 |

家具按目录型号、实际规格和颜色分组，支持按房间查看；材料按材质和使用面汇总。删除、复制、换材质后清单同步更新，清单从当前方案推导，不另维护一套可漂移数据。

支持 CSV 清单和 JSON 方案导出、JSON 方案导入。CSV 做字段转义和公式注入处理；JSON 校验结构、版本、数值范围和对象数量，导入失败保留当前方案。

价格不作为使用前提。用户可选填单价；只有全部相关数量和价格已知才可显示完整合计，缺项时明确显示“已填写项小计”。不内置未经来源支持的品牌报价，不将估算展示为施工预算。

## 9. 保存与恢复

自动保存当前方案，支持命名、另存副本、打开和删除本地方案。保存仅含结构化数据及内容目录 ID，不包含图片、Base64、音视频或 Blob。预览由方案重新渲染。

维护版本化数据结构和有限长度撤销 / 重做记录；拖动结束算一次操作，避免每帧产生历史。模式、家具、房间、材质等影响方案的动作均可撤销。打开新方案或切换模板前保留当前草稿。

存储失败、容量不足或恢复数据损坏时给出状态，不把失败显示为“已保存”；可继续编辑并导出 JSON。

## 10. 技术方案与依赖报告

拟采用 TypeScript + Three.js + Vite，界面使用原生 DOM/CSS，状态使用轻量类型化 store 和命令历史。该选择基于本项目单编辑器、3D 画布为主的特点，不代表存在适用于所有产品的“最佳技术栈”。

- Three.js：真实三维几何、光照、材质、射线选取和相机；使用 WebGLRenderer 与 OrbitControls。
- TypeScript：约束房间、家具、材质引用、尺寸标定及版本化方案，减少跨功能数据不一致。
- Vite：开发与静态资源打包，部署路径兼容子目录；不引入服务端运行需求。
- 原生 DOM/CSS：工具栏、抽屉、目录和属性编辑；避免 UI 全量重建影响画布和拖拽。
- IndexedDB：本地结构化方案；localStorage 可用于轻量设置。
- 本地程序化家具 / 静态材质资源：无需外部模型服务和用户上传图片。

拟新增运行依赖 `three`，开发依赖 `typescript`、`vite`、`@types/three`。当前未安装；实施前向总控报告，由总控统一处理根锁文件，不自行修改根 package.json、pnpm-workspace.yaml 或 pnpm-lock.yaml。版本在实施时统一确定。

技术参考：[Three.js WebGLRenderer](https://threejs.org/docs/pages/WebGLRenderer.html)、[OrbitControls](https://threejs.org/docs/pages/OrbitControls.html)、[Vite 静态部署](https://vite.dev/guide/static-deploy)。

## 11. 模块与数据约定

建议职责划分（路径为待实现规划，不表示文件已存在）：

- `src/content/content.json`：所有业务文案、户型、家具、材料和搭配目录。
- `src/core/`：方案类型、数据校验、几何约束、面积和清单计算、撤销 / 重做。
- `src/scene/`：场景构建、相机、程序化家具、材质、选取、摆放和体验。
- `src/ui/`：开始页、编辑器、素材抽屉、属性面板、成果和清单。
- `src/storage/`：方案持久化、恢复和版本迁移。
- `src/export/`：图片、CSV、JSON 导出与 JSON 导入。
- `tests/`：面积、共享墙、标定、清单合并、历史和导入等有意义的逻辑测试。

方案保存稳定 ID、schemaVersion、名称、单位 / 标定状态、房间几何、墙体与门窗、家具实例、材质引用和视角。逻辑数据作为唯一事实来源，3D 场景与清单都是它的派生结果。历史中不存放 Three.js 实例。

现有 `app.js` 内硬编码目录和业务文案应在功能实施时统一迁入 content.json；当前两份模板定义不一致，不能直接作为后续数据基线。

## 12. 性能、兼容与验收

性能目标为常见手机单层户型、约 60 件家具可流畅编辑；实际以测试结果为准，不预先承诺帧率。复用几何和材质、限制像素比和阴影尺寸、静止时按需渲染，切换方案释放旧 GPU 资源。WebGL 不可用时提供可读错误和保留方案导出路径。

完整交付必须满足：

- 六种模板均可编辑，自建房间能拼接、缩放并添加门窗。
- 不填尺寸可以完成装修；标定后面积正确；部分标定不冒充全屋面积；建筑面积不自动推断。
- 家具可添加、移动、旋转、复制、删除，两种模式切换不丢数据。
- 材质即时应用，撤销 / 重做后场景和清单一致。
- 全屋、俯视、房间近景、进入体验和退出均可用，体验不会修改方案。
- 家具和材料清单完整，PNG、CSV、JSON 导出可用，JSON 导入错误不覆盖当前方案。
- 刷新可恢复；存储失败有反馈；不持久化媒体或 Blob。
- 静态构建无必需外部请求，无运行时 CDN、后端、Service Worker 或未经确认的设备 API。
- 验证桌面以及 375 / 390 / 430 CSS px 下的完整主要流程。
- 所有顶部 sticky / fixed 控件和锚点偏移叠加 `var(--safe-area-inset-top, env(safe-area-inset-top, 0px))`；以非零模拟安全区检查遮挡。
- 在项目目录执行 `pnpm lint`、`pnpm test`、`pnpm build`，保留原有测试，不以删除测试规避失败。
