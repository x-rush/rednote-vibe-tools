# SHBTI 山海兽格 · UI/UX 重设计会话提示词

你在 `~/project/www/rednote-vibe-tools` 工作，本轮只为 `projects/01-sbti` 重新设计 UI/UX、玩法呈现和交互特效，不写 React/TypeScript 业务代码，不修改其他项目、根配置、锁文件或 `docs/`。

先完整阅读根/项目 `AGENTS.md`、`TODO.md`、`PROJECT_BRIEF.md`、`DESIGN.md`、`UX-SPEC.md`、`UI-HANDOFF.md`、`NPC-SPEC.md`、`PROMPTS.md`、`VISUAL-QA.md`，再检查现有 `design/preview.html` 与真实页面。保留冻结的 48 题、16 型、四维计分、历史记录和纯前端约束，不重新发明人格模型。

目标：把“答题—维度变化—异兽显形—结果解读”设计成一场渐进式山海识灵仪式，但不能像算命、抽卡或普通 MBTI 表单。高级玩法重点考虑：回答时四维迹象只做含蓄反馈；章节过渡呈现山海卷轴探索；计算阶段以四维纹章汇合形成兽格；结果页支持维度剖面、相邻兽格对照、题目证据回看与可分享结果卡；引导 NPC 在首次进入、犹豫、进度恢复和结果讲解中发挥作用。动效必须有意义、短促、可降级，不允许全屏粒子轰炸。

必须设计所有状态：首次访问、继续测评、答题、选择后反馈、章节完成、计算、结果、相邻类型、历史、图片失败、坏存档、空历史、`prefers-reduced-motion`。同时验证 375 / 390 / 430 CSS px、长文案、底部安全区和单手操作。

只允许修改或创建本项目设计交付物：`UI-REDESIGN-V2.md`、`INTERACTION-MOTION-SPEC.md`、`design/preview-v2.html`、`ART-REQUEST.md`。预览必须覆盖至少 12 个关键手机状态。不要生成图片，也不要用第三方图片占位；使用明确标注尺寸的色块/线框占位。

`ART-REQUEST.md` 必须逐项写明：资源 ID、页面、功能、主体、真实参考要求、风格、比例、像素建议、透明背景与否、主体安全区、文字留白、裁切规则、状态差分、复用范围、优先级和“没有该资源时如何降级”。结尾明确区分 `必须生成 / 可用 SVG-CSS / 后续迭代`。

完成后不要开发。报告设计改变、玩法增益、预览路径、动效清单、无障碍策略和需要交给 Windows 美术会话的资源数量。
