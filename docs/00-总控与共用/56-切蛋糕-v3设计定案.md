# 切蛋糕 · v3 设计定案（项目转向 + 能力边界声明）

日期：2026-09-30。状态：**设计定稿，待用户批准后动工**（用户指示：先设计、说清能实现到什么程度；不达预期则放弃项目）。触发：v2.7 截面卡方案视觉失败（截图：棕色平面以怪异角度穿插糕体）；用户定向——月饼过时改**切蛋糕**、操作要**显式模式按钮**（转视角/拿刀）、刀要**实时影响蛋糕**而不是松手播动画、先做**一个**做到极致。

## 1. 失败复盘（为什么 v2.x 质量低）

| 问题 | 根因 |
|---|---|
| 截面"卡"穿插在糕体上，像 bug | 浮空结果卡方案失败：billboard 平面与 3D 糕体互相穿插，破坏空间真实感——**已判死刑，v3 移除** |
| 月饼/蛋糕分不清 | 一个印花模板套所有族 + 棕褐色系无食欲 |
| 材质塑料感 | MeshStandardMaterial 平色 + 噪声贴图 ≠ 食物质感；缺 clearcoat/sheen/次表面/环境反射的经营 |
| "松手才播动画"诡异 | 切割被实现成"手势→判定→脚本回放"，刀与糕体零交互 |
| 手势歧义（一切就转视角） | 同一拖动两种含义靠不可见条件区分——已改为显式模式按钮（本轮正确方向） |
| 环境空/脏 | 背景渐变+一只茶杯撑不起"甜品店"场景 |

**共同根因**：我把力气花在工程门禁和交互架构上，**美术与手感从未做过一轮真正的迭代**——每轮都是"新功能+新方案"，没有一个元素被反复打磨到"对"为止。

## 2. 项目重新定义：切蛋糕（Strawberry Shortcake Slicer）

**一句话**：一只松软的草莓奶油蛋糕摆在瓷盘上，玩家拿刀实时切开它——刀到哪，蛋糕开到哪，奶油截面和果酱流心实时可见；切完转着欣赏，收进甜品柜。

- **题材**：奶油蛋糕永不过季（月饼中秋后即过时，用户判断正确）；白+粉+棕的配色天然有食欲。
- **对标**：果冻慢慢的"柔软有生命 + 场景精致"，切切乐的"切开即爽"。
- **目标质感**：**精致风格化 3D（甜品玩具感）**——干净、柔软、有食欲。**不是照片级**（当前约束无摄影资产，不可达，不再承诺）。

## 3. 交互设计（用户指定的方向，全部采纳）

**两个显式模式按钮**（底部大按钮，拇指可达，果冻慢慢同款模式切换）：

- **🔪 拿刀**（默认）：按下=刀落在指尖位置并压入蛋糕；**拖动=刀实时在蛋糕里划**——切缝实时加深、两侧奶油微微被刀挤开、蛋糕实时沿刀路分离（clipping plane 进度实时跟随刀的位置，非松手回放）；刀痕全程可见。切满一刀（进度 100%）= 两半轻缓分开、果酱从截面缓缓淌下聚在盘上、镜头缓推截面。切一半随时可以松手——蛋糕就停在切一半的状态（真实！）。
- **🖐 转**：拖动环绕；不动时缓慢自转展示。

**明确删除**：浮空截面卡（v2.7）、粒子雨、自动降档提示打断（静默降档）。

## 4. 能实现到什么程度（能力边界，逐项诚实）

| 项 | 我能做到 | 做不到/不承诺 |
|---|---|---|
| 蛋糕体 | 松软海绵：暖黄体色+气孔法线细节+边缘圆角柔化；切面=海绵层+奶油层+果酱夹心的分层插画（程序绘制，可控可迭代） | 真实烘焙扫描材质 |
| 奶油 | 白色奶油顶面（裱花管道扭曲造型）+ clearcoat 湿润光泽 + 按压微陷 | 真实奶油流体模拟 |
| 果酱流心 | 切开后沿切面缓流+滴落+盘上持久液泊（v2.4 物理保留复用） | 大规模 SPH 流体 |
| 刀与切割 | 刀 1:1 跟手；切缝实时可见；两半随进度实时分离+软体 jiggle | 刀刃真实压弯/碎屑物理全解算 |
| 场景 | 陶瓷盘（clearcoat）+ 木桌 + 摄影棚三点光 + 雾 + 泛光后处理；构图以美食摄影为对照逐轮调 | 电影级景深/光线追踪 |
| 帧率 | 真机 60fps（栅格化管线，场景 <30 draw call） | 软渲染环境（内置浏览器）满帧 |
| 音效 | 本轮不做（宁缺毋滥维持静音） | 真实 ASMR 素材（待采办） |

**总体上限声明**：目标是对标果冻慢慢的**风格化质感档位**，预计可达其 70-85% 的观感（差距在细节打磨轮数）；**明确不会是照片级写实**。如果这个上限不可接受，现在就是放弃点。

## 5. 技术栈（v3）

- **保留** three.js r158 vendor（已验证可跑）；**新增 vendor**：EffectComposer + UnrealBloomPass（three examples，约 40KB）做柔光——质感跃升的关键一档。
- 蛋糕=Lathe/Cylinder 分层网格（海绵体+奶油顶+果酱核），**实时切割=双 clipping plane 随刀进度扫描**（v2.7 已验证 clipping 可用）；刀=跟随手指的网格+屏幕光轨。
- 软体感=整糕弹簧抖动（juice.ts 保留）+ 奶油顶面按压微陷（顶点位移，范围小成本低）。
- 果酱流心=v2.4 有限体积物理**原样复用**（已验证守恒/终结/确定性）。
- 材质=MeshPhysicalMaterial（sheen/clearcoat）+ 程序 CanvasTexture（海绵气孔、奶油纹、草莓切片——可迭代）。
- 其余约束不变：纯前端、无 wasm、ZIP≤2MiB（预计 ~1.2MB）、宿主避让、静音。

## 6. 范围裁剪（做深不做宽）

- **v3 只有 1 只蛋糕**（草莓奶油）。月饼 11 款、货架、图鉴、收集**全部移出 v3**（代码保留不删，P2 再作为"新口味=换材质参数+贴图"回来）。
- P1 若成立：+2 种口味（巧克力/抹茶，纯参数与贴图替换）+ 甜品柜（图鉴极简版）。
- 真实音源素材采办独立推进，进了就加，不进保持静音。

## 7. 里程碑与验收

- **P0 原型门禁（一只蛋糕，迭代到达标为止）**：真 GPU 截图三张（全景/切割中/切开后）+ 切割录屏。验收线：①截图给 3 个不知情人看，至少 2 人认出"草莓奶油蛋糕"且觉得"想吃/想切"；②切割全程无"诡异动画感"（刀到哪开到哪）；③中端机 60fps。**P0 不过 = 项目放弃，按 55 号预案止损。**
- **P1 打磨**：材质/灯光/构图对照美食摄影逐轮调 + 泛光 + 奶油按压。
- **P2 内容与传播**：口味扩展 + 甜品柜 + 结果卡（此时用真实 3D 截面构图，不再浮空平面）。
- **P3 发布**：QA 全矩阵 + 真机三步。

## 8. 与用户的约定

1. P0 交付物只有**三张真 GPU 截图 + 一段录屏**，不发"门禁全绿"式的自我表扬；
2. 用户不点头，不进入内容铺开；
3. 每轮迭代只打磨这只蛋糕，不加新功能；
4. 若两轮 P0 迭代后仍达不到 §4 上限描述，项目放弃（55 号预案），止损止损点明确。
