# 湖边打水漂｜玩法视角与运镜

日期2026-09-19；状态：设计补充，待可操作原型与实机验收。

## 核心决策

默认必须跟着石头前进：出手后切入石头后上方略偏侧的跟拍，让玩家看见前方水面、石头每次触水和身后短段涟漪。相机跟水平行程，避免跟着每次弹跳上下颠簸。不是岸边看石头越变越小，也不是把摄像机绑在石头上。

## 一投的镜头分镜

| 阶段 | 视角与构图 | 转场与玩法 |
|---|---|---|
| 脚边挑石 | 第一人称向下约45°～55°，6块石位于可触范围 | 点石后进入查看；不能全景里石子细得点不到 |
| 手中查看 | 石占R宽约20%～28%，湖岸虚化感用静态美术层实现 | 手指旋转石头；确认后抬头 |
| 望湖准备 | 300～450ms抬头，地平线约R高30%，石在下方 | 调石面角与蓄力；开始拖拽后相机锁定 |
| 出手衔接 | 石离手后，180～320ms平滑到后上方跟拍 | 不改变石轨迹；第一触水发生得早也必须看见 |
| 连跳跟拍 | 石投影位于R宽约48%、R高约60%；前方留足水面 | 自动跟随，不增加空中控制 |
| 最后沉水 | 不立即停镜头；减速滑行约250～400ms，视线落在终点波纹 | 600～900ms沉水余韵后显示结果 |
| 结果 | 留在最后水面上显示成绩，小卡不盖涟漪中心 | 用户点再来才回岸 |
| 再来一投 | 120ms淡出/回岸/120ms淡入，默认不高速倒飞 | 同石再试或重新捡石，目标≤500ms可准备 |

不自动在每次弹跳切侧面，不反复慢动作，不用摄像机抖动冒充冲击。第一次水花强弱通过粒子/声音体现。回岸淡切避免长距离倒退眩晕。

## 跟拍算法与渲染要求

采用简易真3D相机和世界坐标水面，仍在既定WebGL1专用渲染内；投影矩阵、视图矩阵、远山/天空层由小型适配模块负责。原先固定远景构图需升级，不能直接放大同一张湖面背景假装飞行。

定义水面为水平平面，p为石头当前渲染插值位置，d为平滑水平运动方向，r为其水平右向量。期望相机位置：
C*=ground(p) - d·D + r·S + up·H
视线目标：
T*=ground(p) + d·L + up·hAim
初值D=3～5游戏米、S=0.5～1.0米、H=1.8～2.6米、L=1～3米；与石参数尺度一同标定。hAim只取很小的平滑高度分量，不照搬石头竖直位置。
- d低速时保持上一有效方向，禁止速度接近0出现180°翻转。
- 相机位置用时间步无关临界阻尼或指数平滑，半衰期80～140ms起测；旋转变化限制防急甩；地平线roll恒0。
- 不仅看平滑目标：每帧投影检测石头和下一段预计触水区域是否在R安全框。快投超框时优先适当拉远/增加前视，不能一直慢慢追而丢石。
- 超框保护只用短期轨迹预测构图，不向玩家显示总跳数或落点答案。旋转/镜头不反馈物理。
- 初始视场固定约50°～60°垂直FOV，速度变化通过世界水纹移动表达；首版无动态变焦“冲刺”。横屏重算安全构图，不能只沿用同距离。
- 水面细纹保持世界坐标连续，随相机分块复用；移动origin时同时移动石、水花、相机/模型参考，或首版用有限足够大的水面，避免纹理游泳和接缝。
- 远山与天空在远层提供低视差，岸边渐渐离开画面；倒影方向与太阳一致，不允许太阳像贴在相机上的图标。
- 石头不能过小：跟拍阶段目标屏幕可见尺寸约10～18 CSS px（随设备实测），优先调跟拍距离/投影；必要的展示比例辅助不改物理尺寸，并限制变化连续。
- 触水点/水花中心使用同世界坐标投影。水花短时间可遮部分石头，但不得连续>150ms完全看不见主体。
- 声音距离以跟拍相机计，不能因石头远离岸边就听不清；尾部旧水花自然变远，新接触保持近景触感。
- 页面暂停保存相机阶段与状态；读档可根据当前石位置恢复到稳定跟拍位，给准备提示后继续，不播放出手衔接第二遍。

## 第一触水与特殊情况

超短投掷在出手转场结束前触水：转场目标同时包含石和接触点，必要时缩短衔接，不延迟物理/隐藏第一跳。直接入水的0跳也跟短轨迹看见沉点，不能硬播3秒飞行。
长连跳不会突然拉远到看不见石头；低速末尾相机逐渐停止前视，沉水后视线留在终点，不继续追踪下沉模型。
方位左右极限、强弱投、不同石尺寸、0/1/5/15跳各制作可复现样例。结果距离仍为既有水面滑行距离，与相机走了多远无关。

## 减弱动态与Canvas降级

减弱动态为可选“岸边远观”：固定稳定相机、清楚轨迹标记和落点水花，成绩完全一致；UI明确这是视角选项。默认仍为跟拍。
Canvas2D低配保留同一3D逻辑相机投影，简化水面/山影/粒子，不因为关WebGL就悄悄回岸边固定视角。如设备无法流畅跟拍，提示可手动选岸边远观，而非无解释强切。

## 专项验收

录完整“挑石→出手→跟拍→沉水→回岸”一投，第一触水不得遗漏。石头及当前触点除短暂水花遮挡外持续在R内，镜头不跟弹跳抖，地平线稳定。
不同fps渲染下取同模拟时刻的相机位置作容差比较；暂停/旋转/读档不重置成绩、风浪或产生镜头飞跃。
5名试玩者至少4名认为能持续看清石头，记录是否眩晕/丢失落点；若出现不适先减侧偏、锁FOV、限制镜头角速度，不以大幅运动模糊掩盖。

## 通用镜头契约

本文件为PROJECT.md的视角细化；存在冲突时以本文件的镜头规则为准。所有数值是原型调参起点，未经过实机验证。
- 镜头由游戏状态驱动，维护viewState、position、target、zoom/FOV、transition、sessionId；不修改物理、奖励、随机流和判定时间。
- 输入用当前camera矩阵逆变换至世界/局部操作坐标。抓取开始锁定交互平面；操作中不偷偷换镜头。相机变化不能造成挖掘路径突跳、错选、自动抛投。
- 转场先终止或完成当前手势，再切新视角；pointercancel是取消，禁止当松手提交。不可操作转场不接收积压点击，允许立即暂停。
- 相机用渲染插值后的模型位置和时间步无关平滑，避免不同帧率跟随速度不同；不得按“每帧加固定距离”移动。暂停/后台冻结相机，恢复重置dt，不补跑轨迹。
- 默认不摇晃地平线、不自动滚转、不用全屏运动模糊、不反复改变焦距。近景展示停留可跳过，收获弹窗不遮关键动作。
- 所有屏幕目标位置相对于扣除系统安全区、宿主左右按钮及底部控件后的有效场景矩形R定义；再检查物体包围盒与宿主矩形不相交。不是简单给整个场景加一段顶部留白。
- 实际横屏重算R及构图距离，不仅把竖屏裁宽；首版无CSS模拟横屏。横竖切换时暂停手势和模拟、重建投影，再由用户继续。
- 相机和手势的调参写入src/content/content.json的cameraProfiles/transitions/inputBounds；运行期只保存结构化阶段/参数，不存图像。
- DOM工具和提示固定屏幕空间，不随3D相机漂移。减弱动态模式是用户选择；低画质不得自行改用另一种相机导致游戏线索变化。
- 声像/远近声使用当前相机的相对位置，不能还按旧岸边观察点衰减；关键声保留最低可听清层，平滑更新。声音不跟镜头转场重复触发。
- 验收必须录完整一局，不用单张截图代替。检查默认/减弱动态、30/60fps渲染、375/390/430竖屏、真实横屏、安全区与宿主覆盖层。
