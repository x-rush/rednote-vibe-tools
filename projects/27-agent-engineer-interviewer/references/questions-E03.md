# E03 上下文与记忆

正式提问仅展示场景和问题，锚点用于内部校准。

## Q07 上下文与会话

能力 E03；前提：知道该模块的输入输出；没有生产经验可按题面假设回答，语言与框架不限定。

场景：假设客服会话80轮，模型可用上下文预算16000token；订单号必须准确，摘要有可能把o123误写为o132。

问题：多轮客服对话越聊越贵，用户早先的订单信息还不能丢。你怎样管理上下文？

- 若仅截断旧消息时：摘要把订单号记错如何发现并修正？
  - 期待证据：给错误订单号的冲突处理与可回查来源字段。
- 若已讲清核心流程但缺少可验证证据：请给出一个能检验“上下文与会话”方案是否有效的失败样例和预期结果。
  - 期待证据：给错误订单号的冲突处理与可回查来源字段。 需要明确失败输入、预期终态和可观察断言，不能仅列工具名称。
- 若自报已经在项目中实现：在你负责的部分，“上下文与会话”具体有什么输入、输出和可提供的证据？没有资料也可以说明限制。
  - 期待证据：给错误订单号的冲突处理与可回查来源字段。 还需区分本人实现与团队结果，给输入输出或脱敏材料；未提供材料只记自报，不声称核实。

最低合格：原文/事实/摘要来源分离；关键ID回查；预算与输出余量

- 未体现：未回答核心问题，或坚持“上下文越长效果一定越好”且无法解释；只记录当前答案缺口。
- 基础理解：能解释窗口预算和必要事实，但尚未把情景处理流程说清。
- 可应用：能结合题目说明窗口预算和必要事实和摘要来源与过期处理，给出可执行处理。
- 较完整：在可应用基础上覆盖会话隔离和原文追溯，给出验证方法并解释取舍。

### Q07-V1

原创假设：半年前偏好摘要未经独立授权，当前正文v2不同。

用户半年后再次登录，旧记忆里写“允许自动发邮件”；这是否足以授权今天发送新内容？你如何分离偏好与动作授权？

期待证据：偏好不是授权、当前动作审阅与期限检查。

课程补练 E03：设计保留事实、摘要、原文指针和删除规则

验收：产出可审阅方案及至少一个失败样例；说明窗口预算和必要事实、摘要来源与过期处理与会话隔离和原文追溯。

## Q08 记忆策略

能力 E03；前提：知道该模块的输入输出；没有生产经验可按题面假设回答，语言与框架不限定。

场景：假设用户明确说“我偏好中文”，模型从一次英文资料误推其偏好英文；长期记忆存储可被用户查看、更正和删除。

问题：Agent想长期记住用户偏好，其中包含误识别的信息。你如何设计可更正和可删除的记忆？

- 若所有聊天永久保存时：错误记忆怎样失效而不是越记越牢？
  - 期待证据：给语言偏好冲突处理、source字段和删除后召回断言。
- 若已讲清核心流程但缺少可验证证据：请给出一个能检验“记忆策略”方案是否有效的失败样例和预期结果。
  - 期待证据：给语言偏好冲突处理、source字段和删除后召回断言。 需要明确失败输入、预期终态和可观察断言，不能仅列工具名称。
- 若自报已经在项目中实现：在你负责的部分，“记忆策略”具体有什么输入、输出和可提供的证据？没有资料也可以说明限制。
  - 期待证据：给语言偏好冲突处理、source字段和删除后召回断言。 还需区分本人实现与团队结果，给输入输出或脱敏材料；未提供材料只记自报，不声称核实。

最低合格：显式自报与推断区分；checkpoint与跨会话store；更正删除传播

- 未体现：未回答核心问题，或坚持“记忆就是保存全部对话”且无法解释；只记录当前答案缺口。
- 基础理解：能解释短期与长期区分，但尚未把情景处理流程说清。
- 可应用：能结合题目说明短期与长期区分和来源、置信及更新，给出可执行处理。
- 较完整：在可应用基础上覆盖用户授权、隔离和删除，给出验证方法并解释取舍。

## Q09 长任务与上下文交接

能力 E03；前提：知道工具调用、结构化状态和基本失败处理；允许框架无关设计。

场景：资料研究助手要处理30份政策文件；每次模型上下文有限，任务跨三个会话运行。上一会话声称已完成10份，但只保存了报告草稿，没有来源清单或处理状态。禁止把整套原文件无限塞进上下文。

问题：如何设计可恢复的长任务状态和上下文交接，并避免把上一轮摘要当已完成证据？

- 若回答已覆盖正常路径但未解释失败时：恢复时工件存在，但引用的政策已经更新，你如何处理？
  - 期待证据：核对源版本与依赖，失效的结论重新验证，保留旧版本审计记录而非把旧答案当现行政策。
- 若自报在项目中实现过：请给出你负责部分的一次失败输入、实际状态变化和验证方式；没有材料可说明限制。
  - 期待证据：区分自报与已提供工件，指出输入、输出和可观察断言，不编造运行结果。

最低合格：用结构化任务清单、来源及工件记录进度；摘要只辅助定位；恢复时检查实际工件与完成条件，按需载入资料，未证实的完成项重新核对。

- 未体现：不能解释核心流程，或允许未授权/无证据的写操作。
- 基础理解：用结构化任务清单、来源及工件记录进度；摘要只辅助定位；恢复时检查实际工件与完成条件，按需载入资料，未证实的完成项重新核对。
- 可应用：能具体表达状态、失败分支和验证断言，并满足题面预算。
- 较完整：在可应用基础上说明替代方案取舍、故障窗口和回归验证。

### Q09-V1

30份文件任务恢复时，清单称前10份完成，工件索引仅有8份，其中两份来源版本变更。只剩6次读取预算。

如何选择复核项、记录未完成状态，并让下一次接手者看懂你实际验证了什么？

期待证据：清单与工件交叉检查、来源版本失效、预算优先级、已验证与待验证分开，不凭摘要跳到第11份。

课程补练 E03：使用题面数据画状态与失败分支，写两个正例和三个失败例。

验收：每个例子包含输入、预期状态和可观察断言；不得仅列术语。
