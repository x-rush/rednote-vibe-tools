更新：2026-10-18。下表根据各项目 package.json 核对，新增或修改脚本时应同步更新。

## 环境与安装

根目录声明 pnpm@11.19.0；Node.js 需要满足当前 Vite、rolldown 等工具要求。先在完整仓库根执行 pnpm install。部分项目 tools.mjs 使用根工作区安装的构建工具，不能假定复制单个目录后即可构建。

~~~bash
git clone https://github.com/x-rush/rednote-vibe-tools.git
cd rednote-vibe-tools
pnpm install
~~~

## 检查范围

普通应用修改在项目目录执行 pnpm lint、pnpm test、pnpm build；额外 qa、打包、验证脚本按项目规范运行。05 的 pnpm check 还包含 verify:minitool，而根目录同名 check 不会自动调用它。

根 pnpm check 等于依次执行 pnpm lint、pnpm test、pnpm build，后三者各使用 pnpm -r --if-present。它覆盖有对应脚本的工作区包，不会检查无 package.json 的静态原型，也不自动执行 qa / qa:single / pack / package:minitool / build:minitool。

## 打包路径与交付类型

- 04 使用 build:minitool；08 有 build:minitool、validate:minitool、package:minitool。
- 05 的 verify:minitool、06 的 validate:mini 是验证入口，不能仅凭命令名称就认定已生成 ZIP。
- 12 有 package；14 有 scripts/build-minitool.mjs 音频与平台构建链路；其他项目按自己的构建脚本和 release 说明处理。
- 23 有 build:single；单篇与完整版是不同交付范围，分别检查内容和产物。
- 27 面试官 pnpm build 生成 Skill 分发 ZIP，遵循 SKILL.md 与项目说明，不套用 H5 文件白名单。
- 28 由自身 tools.mjs 生成静态阅读器与 release ZIP；先看 README / DELIVERY 对应版本。
- 29 有 pnpm pack（PowerShell pack.ps1）；local-preview 产物属于本地预览状态。

## H5 ZIP 与界面验证

以 [AGENTS.md](../../AGENTS.md) 和 [.codex/SKILL.md](../../.codex/SKILL.md) 为准，确认根 index.html、相对路径、包内资源、经典 JS 与兼容性，无运行时 CDN / 必需外部 API。文件扩展名只允许 jpg、css、gif、svg、png、js、jpeg、json、html、woff2、webp、woff；原始音频不能直接入包。目录审计与最终 ZIP 审计都要执行，不能只看体积。

ZIP 不超过 10 MiB，建议不超过 2 MiB；单段解码音频不超过 1 MiB。内置音频在构建期转为静态 JS 数据，用户手势后由 Web Audio 解码播放，能力缺失或失败时保留无声路径。

界面覆盖 375 / 390 / 430 CSS px、非零安全区、左右宿主按钮覆盖层及实际存在的横屏与 CSS 模拟横屏状态。顶部固定/吸附控件与锚点叠加安全区变量，宿主按钮单独避让。普通浏览器结果只证明对应浏览器范围，平台模拟器、Android 与 iOS 真机结果分别记录；尚未完成的明确写待验收。
