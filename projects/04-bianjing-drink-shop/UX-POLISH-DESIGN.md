# 汴京饮子铺：全局体验重构设计

> 日期：2026-08-26
> 范围：仅 `projects/04-bianjing-drink-shop`
> 状态：用户已确认页面架构、视觉系统和交互保障三部分方向

## 1. 目标

在不改变百日经营引擎、剧情内容、数值平衡和 V2 存档结构的前提下，对整个游戏体验层做系统性重构，达到：

- 深色场景与浅色纸面的文字、按钮和边框始终可读；
- 实机宿主导航栏、刘海安全区和页内吸顶元素不互相遮挡；
- 页面信息密度合理，不出现空旷的过渡页或无意义的重复确认；
- 页面切换、决策、存档、事件和结算的反馈连续、可理解且不重复执行；
- 375、390、430 CSS px 下共用同一套响应式规则，同时完整支持减少动效偏好。

## 2. 已证实的系统性问题

### 2.1 表面语义缺失

全局 `.secondary-action` 默认为深棕文字、透明背景，原本只适用于浅色纸面，却被直接用在首页、引导页和恢复页的深色背景上。实测“跳过引导”为深棕 `rgb(75, 52, 40)` 对深色背景，静态对比度约 `1.30:1`。深色页面上的梅红小标题对比度约 `2.21:1`。

根因不是单个颜色值，而是“按钮角色”没有同时表达“所在表面”。

### 2.2 顶部偏移不完整

`.app-shell` 当前只在 `18px` 与 `safe-area-inset-top` 之间取较大值，无法叠加实机宿主导航栏。游戏状态栏在 390px 实测仅距视口顶部 `18px`；如导航栏覆盖网页，首行必然被挡。备货预算条另有一套顶部值，也会与导航栏冲突。

### 2.3 恢复流程重复

点击“继续上次经营”后会进入一个只含状态栏和短卡片的二次确认页。该页面既缺少场景信息，又没有新的用户决策，因此形成空旷和节奏中断。

### 2.4 页面状态反馈分散

当前页面切换由多个 `setDisplayPage` 分支触发，没有共用的滚动复位、标题焦点和页面进入规则。视觉过渡也集中在局部人物和流水条目，缺少页面级连续性。

## 3. 页面架构设计

### 3.1 统一页面外壳

为页面根节点建立统一的体验契约，至少包含：

- `surface-dark`：首页、引导、恢复、游戏场景周围；
- `surface-paper`：备货、清单、营业流水、事件、账簿和结局卡片；
- 统一顶部偏移、底部安全区、页面进入动画和焦点目标；
- 同一页面内的主操作只保留一个最强视觉层级。

不为每个页面创建一套独立颜色，而是让组件在明确的表面上选择对应状态。

### 3.2 实机导航与安全区

定义统一变量：

```css
--host-nav-height: 56px;
--safe-top: env(safe-area-inset-top, 0px);
--content-top: calc(var(--host-nav-height) + var(--safe-top) + 18px);
```

- 页面外壳使用 `--content-top` 作为顶部起点；
- 备货预算条的粘性顶部使用同一导航高度与安全区基线；
- 通过 CSS 自定义属性保留宿主覆写高度的能力；
- 在 `0px / 56px / 72px` 导航高度和非零安全区下都做浏览器验收。

### 3.3 直接续接经营

首页“继续上次经营”直接执行已有的恢复路由：

- 无待结算内容：回到存档记录的页面；
- 待开门事件：进入事件情境；
- 待营业或收摊事件：返回营业或事件节点；
- 已进入破产或终局：直接回到对应结果；
- 只有迁移、上一日恢复或存档错误需要说明时，才显示恢复信息。

删除无新决策价值的 `continueGame` 中间显示页，但保留存档解码和安全快照机制。

## 4. 视觉系统

### 4.1 颜色与对比度

- 深色表面：暖白正文、米金边框、提亮后的红金小标题；
- 浅色纸面：墨色正文、梅红主操作、深木色次操作；
- 普通尺寸文字与背景目标对比度不低于 `4.5:1`；
- 颜色不作为选中、正负数值或错误的唯一区别。

### 4.2 操作层级

保留三种操作语义：

1. `primary`：当前页面的推进操作；
2. `secondary`：返回、跳过、快速结算等可选分支；
3. `danger/text`：清除数据等低频且高风险操作。

每种语义在 `dark` 和 `paper` 表面上都定义 default、hover、pressed、focus-visible 和 disabled，不再通过页面临时覆盖单个按钮。非文字操作高度不低于 46px。

### 4.3 页面密度

- 首页：保留居中标题、店铺场景和明确的续玩／新开层级；
- 引导：人物、说明、进度和操作形成一张完整卡片，减少无效留白；
- 晨间：去掉重复提示，按“状态→天气／情报→备货”阅读；
- 备货：强化已选商品、可选商品和不可选原因，保留安全吸顶预算；
- 开门清单：保留纸面核对的紧凑节奏；
- 营业、事件、日结：统一为“场景→当前状况→决策／结果”；
- 里程碑和结局：允许更宽松的留白，但主操作始终可达。

## 5. 交互与反馈

### 5.1 页面级过渡

- 页面进入：180–240ms 淡入与小幅纵向位移；
- 按钮：100–160ms 颜色、边框和小幅位移反馈；
- 数量、售价、选项与账目展开提供即时反馈，但不增加连续点击玩法；
- `prefers-reduced-motion: reduce` 下将动画缩短至近乎为零，不删除状态文字。

### 5.2 页面切换契约

每次页面节点改变时：

1. 滚动位置回到新页面顶部；
2. 程序焦点移至新页面标题或主容器；
3. 不清空已确认需保留的备货草稿；
4. 存档失败进入可恢复说明，不假装成功；
5. 事件确认继续使用提交锁，不允许双击重复结算。

## 6. 逻辑边界

本轮会检查页面路由、返回、续接、提交锁、草稿保留和恢复反馈，但不重新设计已通过平衡审计的经济与剧情数值。如浏览器巡检发现真实的剧情路由错误，必须单独建立失败复现后才能修正。

## 7. 验收设计

### 7.1 自动化验收

- 深色／纸面操作角色与标题颜色契约；
- 续玩按钮直接路由到晨间、营业、事件、日结和结局；
- 页面切换后的滚动复位与焦点；
- 顶部导航偏移、吸顶预算和底部安全区；
- 备货草稿返回保留、存档恢复和事件单次结算；
- 现有全量单元、内容、存储和 1,000 局平衡审计继续通过。

### 7.2 真实浏览器验收

在 375×812、390×844、430×932 下覆盖：

- 无存档首页、有存档首页和直接续接；
- 引导三步与跳过；
- 晨间、长备货页、开门清单、营业流水；
- 开门／营业／收摊／连锁事件的情境、选择和结果；
- 日结、里程碑、破产和八类结局；
- 导航高度 `0 / 56 / 72px` 与非零顶部安全区；
- 正常、hover、键盘焦点、disabled 和减少动效状态。

每个组合至少断言：无横向溢出、主操作可达、无断图、无控制台 error／warning、无远程运行时请求、关键文字不被导航栏遮挡。

## 8. 不在范围内

- 不新增后端、远程 API、CDN、Service Worker 或设备 API；
- 不新增项目依赖或修改根锁文件；
- 不修改 04 目录外的项目；
- 不重画已验收的经营美术，除非真实页面验收证明现有裁切无法满足布局；
- 不用华丽动效替代信息层级，不让动画成为完成经营的必要条件。
