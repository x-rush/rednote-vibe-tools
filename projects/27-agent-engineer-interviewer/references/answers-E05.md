# E05 解法与教学示例

## Q13 文档清洗与切分

假设200页政策PDF含重复页眉、跨页费用表和扫描页；每片目标400-800中文字符，必须保留页码与原文位置，不能丢列名。

### 最低合格

PDF/OCR质量分流；语义与表头保留；版本页码位置元数据

### 完整参考解法

我会先抽样检查PDF类型，区分可提取文本、扫描图片和混合页面；扫描页的OCR只是识别结果，要保留原页与识别质量提示，不能把识别出的数字直接当真值。清洗去除重复页眉页脚，但保留政策标题、版本、生效时间与表格语义。跨页费用表应把列名、币种、适用条件与每行值关联起来，必要时把表转成带字段的记录，而不是把数值单独切成一片。每片携带doc_id、版本、页码、字符范围和权限元数据，引用可回到原位置。
400-800字符只是目标，切分优先按标题、段落和完整表行，允许合理重叠以保持语境；过长表可按行分组并重复表头，不能为满足固定大小破坏条件与例外关系。过小片段可能检索到孤立数字，过大片段可能引入无关条款，两者需用具体查询评估而非选一个“最佳切片长度”。验证选收费、退款例外和跨页表问题，观察召回片段能否独立支撑正确答案与引用，统计解析缺失和OCR错误。重复资料可以用内容哈希去重，但不要因此丢掉不同版本来源。替代方案是保留完整表并单独建立表格索引，成本更高但结构更稳定。我的交付会包含清洗前后样例、片段元数据和失效样例；未实际处理PDF时不说已验证200页全部准确。

### 关键点

- PDF/OCR质量分流
- 语义与表头保留
- 版本页码位置元数据
- 查询验证片段独立性

### 可接受替代

- 完整表格独立索引适合费用表；需处理跨索引召回与引用
- 文本按段落切片可作为基线，不要求固定框架

### 常见错误

- 按500字符硬切所有页面
  - 原因：按500字符硬切所有页面：可能分开表头与金额，导致金额属于错误项目。

## Q14 向量与关键词检索

假设知识库有AB-120与AB-120S两种型号；精确型号命中率低，语义同义问法也重要。目标top-10召回，不允许用相似型号替代。

### 最低合格

精确标识不能语义替代；混合分数不直接相加；分层查询集Recall@10

### 完整参考解法

我会先把“找型号”与“理解问题语义”分开。AB-120和AB-120S是不同实体，向量相似度高不能证明型号相同；先提取明确标识并标准化连字符和大小写，保留原值，查询精确字段或关键词索引，再用语义检索召回与该型号有关的解释。提取不确定时让用户确认，不能自动删掉尾部S。若用户未给型号，则通过关键词和向量混合召回，再按业务过滤或重排选择候选。
两路分数不是同一量纲，不能直接相加；可用基于排名的融合方法或经过验证的分数校准，并给精确字段匹配明确约束。top-10不是越大越好，要观察正确资料覆盖率和噪声；构造精确型号、同义描述、拼写变化、不存在型号四类查询，标注相关文档，比较关键词、向量、混合的Recall@10与最终引用正确性。过滤必须同时包含权限与版本。若只有AB-120S资料，回答应说缺少AB-120证据，而不是输出相似型号说明书。对非精确问题，纯向量可能是合理简单基线，但不能推广为所有场景唯一方案。调优一次只改一个环节，记录索引、embedding和查询集版本。最终面试证据应包含一次错误召回列表和修复后的预期，不要求背向量库名称或随口给相似度阈值。

### 关键点

- 精确标识不能语义替代
- 混合分数不直接相加
- 分层查询集Recall@10
- 缺资料明确拒答

### 可接受替代

- 型号丰富且结构化可先SQL/精确过滤，再做文本检索
- 纯关键词适合全部问题精确且语料稳定；同义覆盖需额外评估

### 常见错误

- AB-120S很相似所以可回答
  - 原因：AB-120S很相似所以可回答：相似度不是实体一致性，可能提供错误型号安全说明。

### 未运行示例

```

exact_id_filter: AB-120
候选AB-120S：entity mismatch，不因高相似度进入答案证据。
无AB-120资料：缺证据，不自动替换型号。
```

## Q15 重排与检索评估

100条查询，每条有一个已核实、存在且有权读取的标准相关文档。top-20中30条查询命中该文档；重排top-5后20条仍命中。最终18条回答正确，所有时间与权限相同。

### 最低合格

Hit@20=30%，Hit@5=20%，命中保留率约66.7%；单相关文档假设下等于宏Recall，MRR/nDCG需排名标注；逐阶段诊断而非直接换模型。

### 完整参考解法

我会先把100条查询按“库里没有答案”“解析或索引缺失”“召回没找到”“重排丢掉”“生成不忠于证据”分类。题目中top-20只有30条含相关资料，在题面已保证语料存在且有权的条件下，首先诊断解析、索引和召回；实际项目才另检查语料缺口；重排不能把不在候选中的文档创造出来。top-5只剩20条说明重排或截断还有损失，但不能直接以18%正确率断定生成模型太弱。本题标准文档、时间与权限已经给定，不用这些解释已有失败；真实项目需要再核对标注、时效和合理权限过滤。
检索层记录每查询命中率Hit@20=30/100=30%、Hit@5=20/100=20%；候选命中保留率20/30≈66.7%。本题每查询恰有一个相关文档，因此Hit@K也等于宏平均Recall@K；一般多相关文档任务须逐查询计算相关文档召回比例，不能混用口径。没有相关文档排名和分级标注，不能从30/20直接推出MRR或nDCG，需补采这些数据，生成层看证据支持和任务正确率。评价应给出分母、资料缺失比例与拒答情况，不能只报一个总成功率。先抽样观察失败查询与具体候选，测试关键词/向量混合、切片或query改写的单项变更；然后在相同召回集合对比重排器，记录额外延迟和费用。给生成模型喂正确证据的小实验可以隔离生成失败，但这只是诊断，不是实际线上性能。开发样本用于调优，保留独立测试集和历史失败回归，避免只把100条题背进提示。若业务预算紧，可只对难查询启用重排，但路由也要验证。面试中的好答案会展示一条问题从资料到候选再到答案的追踪，而非列出十种检索优化名词。

### 关键点

- 五类阶段归因
- 分母与无答案比例
- Recall/MRR/证据支持分层
- 相同候选对照及预算
- 查询命中与多相关文档Recall口径区分；不能凭数量推算MRR

### 可接受替代

- 小样本人工相关性判定可做初始诊断，需记录一致性与局限
- 不启用重排也可，前提基线质量满足目标并说明复杂度收益

### 常见错误

- 换更强生成模型即可
  - 原因：换更强生成模型即可：70条召回没有相关资料，模型只能猜，不能可靠修复证据缺失。

## Q16 引用与拒答

假设当前问2026退款政策，仅召回2025版第4页“7天可退”；文档未注明2026仍有效。用户要求“直接告诉我能退”。

### 最低合格

时效与适用范围检查；局部说明而非无差别拒答；引用逐陈述支持

### 完整参考解法

我不能把旧政策自动推广到今年。先检查资料的版本、生效日期、是否有废止声明和最新源；如果当前仅有2025第4页，则可明确说明“找到的旧资料写7天可退，但不足以确认2026规则”，附能定位的引用并建议获取当前政策或联系负责人。拒答的是确定的当年资格结论，而不是把所有相关信息都隐藏。用户要求直接回答也不能补造新政策，若能查询官方新文件应实际核查；没有工具则说明未核实，不声称已经搜索过。
引用校验要逐项检查陈述是否被原文支持。链接能打开仅证明位置可访问，不能证明该页支持所有句子。答案中的例外条件、地区与产品范围也要匹配，不把条件句缩成通用规则。检索分数不是“可以回答”的充分门槛，可能高分但过期；应用可加入时效与证据完备检查，生成后再检查引用与陈述关系。测试构造无答案、旧版本、新旧冲突、同政策不同产品以及带错误链接五种情况，观察是否正确拒绝确定结论、是否说明可补证据。替代方式是给用户一个资格核查清单，但清单不能暗示已满足条件。岗位面试中，愿意说不知道且能指出缺的是哪份证据，通常比凭常识给肯定答案更可靠；这不是因为保守永远最好，而是退款决定需要适用版本支持。

### 关键点

- 时效与适用范围检查
- 局部说明而非无差别拒答
- 引用逐陈述支持
- 高分不等于足证据

### 可接受替代

- 有官方实时政策查询工具可补查后答，必须记录实际来源
- 提供资格核查清单但不确定裁定，可作为无工具路径

### 常见错误

- 去年7天可退，今年大概也一样
  - 原因：去年7天可退，今年大概也一样：缺少适用证据，可能让用户错过退款时限。

## Q17 权限与索引更新

假设租户甲乙共享向量服务；甲私有文档被删除，索引和回答缓存五分钟后才更新。任何乙用户不得读取甲内容。

### 最低合格

可信身份强制权限过滤；缓存与原文也授权；删除立即tombstone

### 完整参考解法

我会把租户与用户身份放在可信服务端会话，检索前强制绑定tenant_id和授权条件，不能接受模型自由传来的租户字段。文档元数据保存所属租户、访问范围、版本与删除状态，向量候选、原文读取和缓存命中都必须经过授权；只在前端隐藏结果会让数据已经进入模型或网络。缓存键包含权限域和内容版本，不能只用问题文本共享答案。
删除采用可立即生效的tombstone或权威文档状态检查，避免五分钟异步更新窗口继续泄漏；后台再删除索引向量、原文副本和相关缓存，记录同步进度与失败重试。对权限撤销也采取相同策略，旧会话引用和已生成答案的展示需按产品规则处理，不能保证已经发给用户的数据能被远程收回。索引构建流程使用事件版本或更新时间防止旧任务晚到复活文档；批量更新可先构建新索引、验证再切换，但权威权限检查仍保留。测试至少涵盖乙查询甲关键词、共享缓存命中、撤权后旧链接、删除延迟以及旧更新事件重放。简单小项目可用物理隔离索引降低误配风险，规模扩大再评估共享过滤方案；两者都需权限测试，不能凭向量库声称隔离已成立。这里安全目标是没有未经授权的证据进入模型上下文，而不只是最终回答不提名字。

### 关键点

- 可信身份强制权限过滤
- 缓存与原文也授权
- 删除立即tombstone
- 旧任务版本防复活

### 可接受替代

- 每租户独立索引易理解但成本更高
- 共享索引加服务端过滤可行，需验证过滤能力与拒绝默认行为

### 常见错误

- 五分钟后删向量即可
  - 原因：五分钟后删向量即可：窗口内缓存和原文仍可泄漏，旧更新还可能把文档写回。
